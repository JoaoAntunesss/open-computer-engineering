Uma API só serve quando está num servidor acessível. Hoje dá para fazer deploy de um projeto pequeno **sem pagar**, desde que saibas separar o código da configuração.

## Configuração fora do código

A mesma imagem tem de correr no teu PC, nos testes e em produção, com bases de dados e chaves diferentes. Por isso, tudo o que muda entre ambientes vem de **variáveis de ambiente** (uma das regras do *Twelve-Factor App*):

```python
import os

DATABASE_URL = os.environ["DATABASE_URL"]
SENTRY_DSN = os.environ.get("SENTRY_DSN")       # opcional
MODO = os.environ.get("MODO", "dev")
```

Localmente, guardas os valores num ficheiro `.env` que **nunca** vai para o Git (está no `.gitignore`). Em produção, defines as variáveis no painel do serviço. Acompanha o projeto com um `.env.example` sem valores reais, para os outros saberem o que é preciso.

## Opções gratuitas (confirma os limites atuais nas páginas de preços)

| Precisas de | Opções com plano gratuito |
|---|---|
| Correr a API (contentor) | Google Cloud Run, Render, Fly.io, Koyeb |
| PostgreSQL | Neon, Supabase |
| Servidor próprio (VM) | Oracle Cloud "Always Free" |
| Site estático | GitHub Pages, Cloudflare Pages, Netlify |

Os planos gratuitos têm limites (pedidos, horas, memória) e alguns "adormecem" o serviço sem tráfego. Para aprender e para projetos pequenos chegam. Ativa sempre **alertas de faturação** quando pões um cartão.

## Exemplo: Cloud Run

Com a imagem Docker da lição anterior:

```text
gcloud run deploy marcacoes \
  --source . \
  --region europe-west1 \
  --allow-unauthenticated \
  --set-env-vars MODO=prod \
  --set-secrets DATABASE_URL=database-url:latest
```

O Cloud Run constrói a imagem, arranca contentores quando há pedidos e desliga-os quando não há (pagas zero com pouco uso, dentro da quota gratuita). Os segredos vêm do Secret Manager, não da linha de comandos.

## Deploy automático

Junta ao CI da cadeira de Testes um passo que faz deploy quando o `main` muda e os testes passam. Assim, o que está no `main` é o que está em produção, e cada deploy é um commit identificável (que podes reverter).

## Antes de pôr no ar

- Testes verdes e migrações aplicadas.
- Variáveis e segredos definidos no serviço.
- HTTPS (os serviços acima tratam disso).
- Um endpoint `/saude` que devolve 200, para o serviço saber que a API arrancou.
- Logs e alertas de erros (próxima lição).
