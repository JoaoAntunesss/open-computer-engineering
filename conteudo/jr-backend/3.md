Na cadeira de Bases de Dados aprendes SQL e modelação. No trabalho, aparecem duas coisas que raramente se praticam no curso: **migrações** (mudar a estrutura de uma base de dados que já tem dados e está a ser usada) e **índices** (fazer com que as queries continuem rápidas quando há milhões de linhas).

- **Online**: Neon e Supabase têm planos gratuitos com PostgreSQL a sério.

Liga-te com `psql`, com o DBeaver ou com a extensão de bases de dados do VS Code.

## Migrações

Nunca mudes a estrutura de produção à mão. Cada mudança é um ficheiro de migração, guardado no Git e aplicado por ordem em todos os ambientes (o teu PC, testes, produção). Em Python, com SQLAlchemy, a ferramenta é o **Alembic**:

```text
alembic revision -m "acrescenta telefone aos clientes"
```

```python
def upgrade():
    op.add_column("clientes", sa.Column("telefone", sa.String(20), nullable=True))

def downgrade():
    op.drop_column("clientes", "telefone")
```

```text
alembic upgrade head      # aplica todas as migrações em falta
```

## Migrações sem parar o serviço

Com utilizadores a usar o sistema, algumas mudanças partem tudo se forem feitas de uma vez. Renomear uma coluna, por exemplo, faz-se em passos:

1. Acrescentar a coluna nova (o código antigo ignora-a).
2. Pôr o código a escrever nas duas.
3. Copiar os dados antigos para a nova.
4. Pôr o código a ler da nova.
5. Só no fim, apagar a antiga.

Parece trabalho a mais, mas é assim que se muda uma base de dados de um sistema que não pode parar.

## Índices

Sem índice, para encontrar as marcações de um cliente, a base de dados lê **todas** as linhas da tabela. Com 1000 linhas não se nota; com 10 milhões, demora segundos.

```sql
CREATE INDEX idx_marcacoes_cliente ON marcacoes (cliente_id);
```

Para saberes se uma query usa um índice:

```sql
EXPLAIN ANALYZE
SELECT * FROM marcacoes WHERE cliente_id = 42 AND inicio >= '2027-01-01';
```

Se vires `Seq Scan` numa tabela grande, falta um índice. `Index Scan` é o que queres.

Regras práticas:

- Indexa as colunas usadas em `WHERE`, `JOIN` e `ORDER BY` frequentes.
- Chaves estrangeiras quase sempre precisam de índice.
- Índices tornam as escritas um pouco mais lentas e ocupam espaço: não indexes tudo.
- Restrições de unicidade (`UNIQUE`) também criam índices, e protegem os dados (dois clientes com o mesmo email).

## Transações

Quando várias alterações têm de acontecer todas ou nenhuma (tirar um lugar e criar a marcação), usa uma transação:

```sql
BEGIN;
UPDATE horarios SET livre = false WHERE id = 7 AND livre = true;
INSERT INTO marcacoes (cliente_id, horario_id) VALUES (42, 7);
COMMIT;
```

Se algo falhar a meio, `ROLLBACK` desfaz tudo.
