Quase todas as apps que usas falam com um servidor por **HTTP**: o browser ou a app pede, o servidor responde. Uma **API REST** é uma forma organizada de expor dados e ações por HTTP. Perceber isto é a base de qualquer backend.

## Um pedido e uma resposta

```text
GET /api/marcacoes?dia=2027-01-10 HTTP/1.1
Host: salao.exemplo.pt
Authorization: Bearer eyJhbGciOi...
Accept: application/json
```

```text
HTTP/1.1 200 OK
Content-Type: application/json

[{"id": 41, "cliente": "Ana", "hora": "15:00", "servico": "corte"}]
```

- **Método**: o que queres fazer.
- **Caminho** (e parâmetros): sobre o quê.
- **Cabeçalhos**: informação extra (quem és, que formato aceitas).
- **Código de estado**: como correu.
- **Corpo**: os dados, normalmente em JSON.

## Os métodos

| Método | Para quê | Exemplo |
|---|---|---|
| `GET` | Ler | `GET /marcacoes/41` |
| `POST` | Criar | `POST /marcacoes` com os dados no corpo |
| `PUT` / `PATCH` | Substituir / alterar parte | `PATCH /marcacoes/41` com `{"hora": "16:00"}` |
| `DELETE` | Apagar | `DELETE /marcacoes/41` |

`GET` nunca deve mudar nada. Pedir a mesma coisa duas vezes com `GET`, `PUT` ou `DELETE` deve dar o mesmo resultado (são *idempotentes*); com `POST`, cria duas.

## Os códigos de estado que importam

| Código | Quer dizer |
|---|---|
| 200 / 201 / 204 | Correu bem / criado / sem conteúdo |
| 400 | O pedido está mal (dados inválidos) |
| 401 | Não te identificaste |
| 403 | Identificaste-te, mas não tens permissão |
| 404 | Não existe |
| 409 | Conflito (por exemplo, hora já ocupada) |
| 422 | Dados com formato certo mas inválidos |
| 429 | Demasiados pedidos |
| 500 | Erro no servidor (um bug teu) |

Devolver o código certo é parte do contrato: o frontend decide o que mostrar a partir dele.

## Desenhar os recursos

Recursos são **substantivos no plural**; as ações são os métodos:

- `GET /clientes`, `POST /clientes`, `GET /clientes/7`
- `GET /clientes/7/marcacoes` (as marcações de um cliente)
- Evita verbos no caminho (`/criarCliente`, `/apagarMarcacao`).

## Experimentar

No terminal:

```text
curl -s https://api.github.com/repos/python/cpython | head -20
```

No browser, F12 → **Network** mostra todos os pedidos que um site faz. Abre um site teu e vê os pedidos ao Firebase: é HTTP por baixo.
