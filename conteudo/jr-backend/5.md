"Na minha máquina funciona" acontece porque cada computador tem versões diferentes de Python, bibliotecas e configurações. O **Docker** empacota a tua aplicação com tudo o que ela precisa numa **imagem**, que corre igual em qualquer lado: no teu PC, no CI e no servidor.

## Os conceitos

| Conceito | O que é |
|---|---|
| **Imagem** | O pacote: sistema base, linguagem, bibliotecas e o teu código. Não muda. |
| **Contentor** | Uma imagem a correr. Podes ter vários da mesma imagem. |
| **Dockerfile** | A receita para construir a imagem. |
| **Registo** | Onde se guardam imagens (Docker Hub, GitHub Container Registry). |
| **Volume** | Uma pasta que sobrevive quando o contentor é apagado (dados da base de dados). |

## Um Dockerfile para a API

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["fastapi", "run", "main.py", "--port", "8080"]
```

Lê-se de cima para baixo: parte de uma imagem com Python 3.12, entra na pasta `/app`, instala as dependências, copia o código e define o comando que arranca a API. As dependências vêm antes do código para o Docker reaproveitar esse passo quando só mudas o código.

```text
docker build -t marcacoes .
docker run -p 8080:8080 marcacoes
```

`-p 8080:8080` liga a porta do teu PC à do contentor.

## API e base de dados juntas: Docker Compose

```yaml
# compose.yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: dev
      POSTGRES_DB: marcacoes
    volumes:
      - dados:/var/lib/postgresql/data
  api:
    build: .
    ports:
      - "8080:8080"
    environment:
      DATABASE_URL: postgresql://postgres:dev@db:5432/marcacoes
    depends_on:
      - db
volumes:
  dados:
```

`docker compose up` arranca as duas coisas. Repara que a API chega à base de dados pelo nome `db`. Qualquer pessoa da equipa põe o projeto a correr com um só comando.

## Comandos do dia a dia

```text
docker ps                     # contentores a correr
docker logs -f <nome>         # ver o que o contentor escreve
docker exec -it <nome> bash   # entrar no contentor
docker compose down           # parar tudo
```

## Erros comuns

- Pôr passwords e chaves dentro da imagem. Passam por variáveis de ambiente.
- Esquecer o `.dockerignore` e copiar `.git`, `.venv` e `node_modules` para a imagem.
- Perder os dados da base de dados por não usar um volume.

## Exercício

Põe a API de marcações e o PostgreSQL a correr com `docker compose up`. Apaga os contentores, volta a criá-los e confirma que os dados continuam lá (por causa do volume).
