**Modelar ameaças** é pensar como um atacante **antes** de construir (ou durante): o que estamos a construir, o que pode correr mal, o que vamos fazer em relação a isso, e se fizemos um bom trabalho. É a forma mais barata de evitar falhas de desenho (a categoria A04 do OWASP), que nenhuma ferramenta automática encontra.

## As quatro perguntas (Shostack)

1. **O que estamos a construir?** Um diagrama do sistema.
2. **O que pode correr mal?** As ameaças.
3. **O que vamos fazer?** Mitigar, eliminar, transferir ou aceitar cada uma.
4. **Fizemos um bom trabalho?** Rever, testar, repetir quando o sistema muda.

## 1. Diagrama de fluxo de dados

Desenha os componentes, os fluxos de dados entre eles, os armazenamentos e, sobretudo, as **fronteiras de confiança** (onde os dados passam de uma zona com um nível de confiança para outra):

```
 [Cliente: browser] ──HTTPS──▶ ║ [Site estático] ──▶ [Firebase Auth]
                               ║        │
       fronteira: Internet ───▶║        ▼
                               ║ [Realtime Database: marcações, clientes]
 [Dona: painel] ──HTTPS──────▶ ║        │
                               ║        ▼
                               ║ [Cloud Function: envia SMS] ──▶ [Fornecedor de SMS]
```

Tudo o que atravessa uma fronteira de confiança tem de ser verificado do outro lado.

## 2. STRIDE

Para cada elemento e cada fluxo, percorre as seis categorias de ameaça (Microsoft):

| | Ameaça | Propriedade violada | Exemplo no site de marcações |
|---|---|---|---|
| **S** | *Spoofing* (falsificar identidade) | autenticação | alguém entra no painel com a palavra-passe da dona |
| **T** | *Tampering* (adulterar) | integridade | um cliente altera o preço no pedido |
| **R** | *Repudiation* (negar) | não repúdio | uma funcionária apaga marcações e nega |
| **I** | *Information disclosure* (fuga) | confidencialidade | as regras da base de dados deixam ler os telefones de todos |
| **D** | *Denial of service* (negação de serviço) | disponibilidade | um script cria 10 000 marcações falsas |
| **E** | *Elevation of privilege* (elevação) | autorização | um cliente consegue escrever no nó de configuração da dona |

## 3. Priorizar e decidir

```python run
ameacas = [
    # (elemento, STRIDE, descrição, probabilidade 1-3, impacto 1-3, mitigação)
    ("Realtime Database", "I", "regras deixam ler todos os clientes", 3, 3, "regras por $uid; testar com o emulador"),
    ("Painel", "S", "palavra-passe da dona roubada (phishing)", 2, 3, "2FA; palavra-passe única"),
    ("Formulário", "D", "bots criam milhares de marcações", 2, 2, "App Check, limite por telefone, CAPTCHA"),
    ("Formulário", "T", "cliente muda o preço do serviço", 2, 2, "preço calculado no servidor"),
    ("Cloud Function SMS", "E", "qualquer pessoa chama a função e envia SMS pagos", 2, 3, "exigir autenticação; quotas"),
    ("Painel", "R", "funcionária apaga marcações sem rasto", 1, 2, "registo de alterações com autor e data"),
    ("Fornecedor SMS", "D", "o fornecedor fica em baixo", 1, 1, "aceitar: email como alternativa"),
]
print(f"{'risco':>5}  {'elemento':20} {'S':1} ameaça → mitigação")
for el, s, d, p, i, m in sorted(ameacas, key=lambda a: -a[3] * a[4]):
    print(f"{p * i:>5}  {el:20} {s} {d} → {m}")
```

Prevê as três primeiras da lista. A ordem diz por onde começar.

## 4. Rever

Um modelo de ameaças não é um documento para a gaveta: revê-se quando o sistema muda (um pagamento novo, uma integração, uma app móvel) e transforma-se em **requisitos** e **testes** (por exemplo, um teste automático que confirma que um cliente não consegue ler as marcações de outro).

## Outras ferramentas

- **Árvores de ataque:** o objetivo do atacante na raiz ("ler os dados de clientes"), os caminhos possíveis nos ramos; permitem ver o caminho mais barato.
- **Casos de abuso:** como as histórias de utilizador, mas do atacante: "Como bot, quero criar marcações falsas para bloquear a agenda".
- **LINDDUN:** a versão do STRIDE para ameaças à privacidade (útil para o RGPD).
- **OWASP Threat Dragon** e **Microsoft Threat Modeling Tool**: ferramentas gratuitas para desenhar e registar.
