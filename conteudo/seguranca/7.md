O **OWASP Top 10** é a lista das categorias de falhas mais graves e comuns em aplicações web, publicada pela OWASP (uma fundação aberta) a partir de dados de milhares de aplicações. Em Tecnologias Web viste XSS, CSRF e injeção de SQL em pormenor; aqui está o mapa completo (edição de 2021), com o que procurar em cada uma ao rever código e como o testar.

## A lista

| # | Categoria | Exemplo | Defesa principal |
|---|---|---|---|
| A01 | **Controlo de acesso partido** | mudar `/api/marcacoes/41` para `/42` e ver a de outra pessoa | verificar a autorização no servidor, em cada pedido; negar por omissão |
| A02 | **Falhas criptográficas** | HTTP sem TLS, palavras-passe em MD5, dados sensíveis sem cifra | TLS em tudo, Argon2id, cifrar dados sensíveis em repouso |
| A03 | **Injeção** | SQL, comandos da shell, XSS | consultas parametrizadas, escapar à saída, não juntar texto a comandos |
| A04 | **Desenho inseguro** | recuperação de conta com "pergunta secreta" | modelação de ameaças (lição 9) desde o início |
| A05 | **Configuração insegura** | regras do Firebase abertas, erros com a pilha completa, contas por omissão | configurações seguras, revistas e automatizadas |
| A06 | **Componentes vulneráveis** | uma biblioteca npm com uma falha conhecida | inventário de dependências, `npm audit`, Dependabot |
| A07 | **Falhas de autenticação** | sem limite de tentativas, sessões que não expiram | 2FA, limitar tentativas, sessões seguras |
| A08 | **Falhas de integridade** | atualizações sem assinatura, desserializar dados não confiáveis | assinaturas, verificar a origem, CI segura |
| A09 | **Falhas de registo e monitorização** | ninguém repara que houve 10 000 tentativas de login | registar eventos de segurança e alertar |
| A10 | **SSRF** | o servidor vai buscar uma URL dada pelo utilizador e chega à rede interna | lista de destinos permitidos, bloquear endereços internos |

## Rever código à procura de falhas

Encontra pelo menos seis problemas neste servidor antes de correres o verificador:

```python run
codigo = '''
from flask import Flask, request
import sqlite3, os, pickle, requests

app = Flask(__name__)
app.config["DEBUG"] = True
SEGREDO = "chave-super-secreta-123"

@app.get("/marcacao")
def ver():
    mid = request.args["id"]
    db = sqlite3.connect("salao.db")
    return str(db.execute(f"SELECT * FROM marcacoes WHERE id = {mid}").fetchone())

@app.post("/importar")
def importar():
    dados = pickle.loads(request.data)
    return "ok"

@app.get("/pre-visualizar")
def pre():
    return requests.get(request.args["url"]).text

@app.get("/relatorio")
def relatorio():
    os.system("gerar_relatorio " + request.args["mes"])
    return "a gerar"
'''

verificacoes = [
    ('"DEBUG"] = True', "A05: modo de depuração ligado (mostra a pilha e permite executar código)"),
    ('SEGREDO = "', "A02/A05: segredo escrito no código (deve vir de uma variável de ambiente)"),
    ('execute(f"', "A03: SQL construído com f-string (injeção de SQL)"),
    ('pickle.loads(request', "A08: desserializar pickle de dados do utilizador (executa código)"),
    ('requests.get(request.args', "A10: SSRF (o servidor vai a qualquer URL, incluindo internas)"),
    ('os.system(', "A03: injeção de comandos da shell"),
    ('def ver(', "A01: qualquer pessoa vê qualquer marcação (não há autenticação nem verificação do dono)"),
]
for padrao, problema in verificacoes:
    if padrao in codigo:
        print("•", problema)
```

O verificador só procura padrões de texto (como um *linter* de segurança muito simples, por exemplo o **Bandit** ou o **Semgrep**): encontra os casos óbvios e falha os subtis. O A01 (falta de autorização) é o mais grave e o mais difícil de detetar automaticamente, porque depende das regras do negócio.

## Testar

- **SAST** (análise estática): Semgrep, Bandit, CodeQL, SonarQube, na CI.
- **SCA** (análise de dependências): `npm audit`, `pip-audit`, Dependabot, Snyk.
- **DAST** (análise dinâmica): **OWASP ZAP** ou **Burp Suite** contra uma versão de teste do site, a enviar pedidos maliciosos.
- **Testes manuais:** mudar ids nos pedidos, repetir pedidos, alterar campos escondidos e preços, testar com dois utilizadores diferentes.
- Para praticar legalmente: **OWASP Juice Shop**, **DVWA**, **PortSwigger Web Security Academy** (gratuito). Testar sites de outras pessoas sem autorização escrita é crime.
