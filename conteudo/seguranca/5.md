O **TLS** (*Transport Layer Security*) é o protocolo que põe o "S" no HTTPS. Garante três coisas sobre a ligação entre o browser e o servidor: **confidencialidade** (ninguém no caminho lê), **integridade** (ninguém altera) e **autenticação do servidor** (estás mesmo a falar com o `banco.pt` e não com um impostor). A última é a mais difícil, e é resolvida com **certificados** e uma cadeia de confiança.

## O aperto de mão TLS 1.3 (simplificado)

```
cliente → servidor: ClientHello (versões, cifras suportadas, chave Diffie-Hellman do cliente)
servidor → cliente: ServerHello (cifra escolhida, chave DH do servidor)
                    + certificado + assinatura com a chave privada do certificado
                    + "terminado"
cliente: verifica o certificado e a assinatura; calcula a chave de sessão
cliente → servidor: "terminado", e a partir daqui dados cifrados (AES-GCM ou ChaCha20)
```

- **Diffie-Hellman efémero:** cliente e servidor combinam uma chave secreta sem a enviarem. Como as chaves DH são novas em cada ligação, mesmo que a chave privada do servidor seja roubada mais tarde, as conversas antigas continuam seguras (**sigilo futuro**, *forward secrecy*).
- O TLS 1.3 faz isto numa só ida e volta (o TLS 1.2 precisava de duas) e retirou todas as cifras antigas e fracas.

## Diffie-Hellman em miniatura

```python run
import secrets

# números públicos (na prática: grupos de 2048+ bits, ou curvas elípticas como X25519)
p = 0xFFFFFFFFFFFFFFC5          # um primo de 64 bits, só para ilustrar
g = 5

a = secrets.randbelow(p - 2) + 1       # segredo do cliente (nunca é enviado)
b = secrets.randbelow(p - 2) + 1       # segredo do servidor (nunca é enviado)
A = pow(g, a, p)                       # enviado pelo cliente, à vista de todos
B = pow(g, b, p)                       # enviado pelo servidor, à vista de todos

chave_cliente = pow(B, a, p)
chave_servidor = pow(A, b, p)
print("A e B (públicos):", hex(A), hex(B))
print("as duas chaves são iguais?", chave_cliente == chave_servidor)
```

Prevê a última linha. Quem escuta vê p, g, A e B, mas calcular a chave exigiria resolver o **logaritmo discreto** (descobrir a a partir de gᵃ mod p), impraticável com números grandes. Atenção: DH sozinho não sabe **com quem** está a falar; sem autenticação, um atacante no meio faz um DH com cada lado. É para isso que serve o certificado.

## Certificados e cadeia de confiança

Um certificado (X.509) diz: "a chave pública X pertence ao domínio `salaoaurora.pt`", e vem **assinado** por uma **autoridade de certificação** (CA).

```
CA raiz (ISRG Root X1)         ← vem instalada no sistema operativo / browser
  └ CA intermédia (Let's Encrypt R11)
      └ certificado de salaoaurora.pt
```

O browser verifica:

1. a assinatura de cada certificado da cadeia, até chegar a uma raiz em que confia;
2. que o nome do site corresponde ao certificado;
3. que está dentro da validade e não foi revogado.

Para emitir, a CA verifica que controlas o domínio (o Let's Encrypt pede para pores um ficheiro no site ou um registo DNS: protocolo ACME). A **Certificate Transparency** obriga as CA a publicar todos os certificados que emitem em registos públicos: um certificado emitido indevidamente para o teu domínio é detetável (por exemplo, em crt.sh).

## Erros comuns

- Ignorar erros de certificado no código (`verify=False` em Python, `rejectUnauthorized: false` em Node): desliga a autenticação e permite ataques "man in the middle". Nunca em produção.
- Certificado expirado (a renovação automática falhou): o site fica inacessível.
- Conteúdo misto: uma página HTTPS que carrega scripts por HTTP.
- Não ativar o **HSTS** (o cabeçalho que obriga o browser a usar sempre HTTPS), deixando a primeira visita exposta.

## Ver por dentro

```bash
openssl s_client -connect www.uab.pt:443 -servername www.uab.pt </dev/null | head -20
```

Mostra a cadeia de certificados, a versão do TLS e a cifra negociada. No browser, o cadeado na barra de endereço também mostra o certificado.
