A segurança de redes protege o tráfego e os serviços acessíveis pela rede: decide o que pode entrar e sair (**firewalls**), deteta comportamentos suspeitos (**IDS/IPS**) e cria ligações seguras através de redes que não são de confiança (**VPN**). Em Redes viste NAT e firewalls do ponto de vista do funcionamento; aqui, do ponto de vista de quem defende.

## Firewalls

Filtram o tráfego por regras, avaliadas por ordem; a primeira que corresponde decide.

```
# iptables / nftables (Linux), ufw (mais simples), grupos de segurança (cloud)
1. permitir ligações já estabelecidas e relacionadas
2. permitir TCP 443 de qualquer origem          (HTTPS)
3. permitir TCP 22 de 85.240.10.7               (SSH só de casa)
4. permitir ICMP echo, limitado a 5 por segundo (ping)
5. negar tudo o resto                           ← política por omissão
```

```python run
import ipaddress

regras = [
    ("permitir", "tcp", 443, "0.0.0.0/0"),
    ("permitir", "tcp", 22, "85.240.10.7/32"),
    ("permitir", "tcp", 80, "0.0.0.0/0"),
    ("negar",    "tcp", 5432, "0.0.0.0/0"),
    ("permitir", "tcp", 5432, "10.0.0.0/8"),      # nunca é alcançada: a regra anterior apanha tudo
]
POR_OMISSAO = "negar"

def decide(protocolo, porta, origem):
    ip = ipaddress.ip_address(origem)
    for i, (acao, proto, p, rede) in enumerate(regras, 1):
        if proto == protocolo and p == porta and ip in ipaddress.ip_network(rede):
            return f"{acao} (regra {i})"
    return f"{POR_OMISSAO} (por omissão)"

for pacote in [("tcp", 443, "203.0.113.9"), ("tcp", 22, "203.0.113.9"), ("tcp", 22, "85.240.10.7"),
               ("tcp", 5432, "10.0.3.4"), ("tcp", 3306, "10.0.3.4"), ("udp", 53, "8.8.8.8")]:
    print(pacote, "→", decide(*pacote))
```

Prevê cada decisão. A quarta mostra um erro clássico: regras pela ordem errada (a base de dados devia aceitar a rede interna, mas a regra de negar vem antes).

Tipos: **filtragem de pacotes** sem estado; **com estado** (sabe que pacotes pertencem a ligações abertas); **de aplicação** / **WAF** (entende HTTP e bloqueia padrões de ataque); **firewalls de próxima geração** (identificam aplicações e utilizadores).

## Segmentação

Não pôr tudo na mesma rede: separar os servidores web, as bases de dados, os computadores dos funcionários, a rede de convidados e as câmaras (VLANs, sub-redes, grupos de segurança na cloud). Se uma parte for comprometida, o atacante não chega diretamente ao resto. A ideia levada ao limite é o **Zero Trust**: nenhum pedido é de confiança só por vir da rede interna; tudo é autenticado e autorizado.

## IDS e IPS

- **IDS** (deteção): observa o tráfego (ou os registos) e alerta. **IPS** (prevenção): também bloqueia.
- **Por assinaturas:** procura padrões conhecidos de ataques (Snort, Suricata). Rápido e preciso, não deteta o desconhecido.
- **Por anomalias:** aprende o que é normal e alerta para desvios (de repente, um servidor envia 10 GB para um país estranho às 3h). Deteta o novo, com mais falsos alarmes.
- Também nos servidores: **fail2ban** bloqueia IPs com muitas tentativas de login falhadas.

## VPN

Um túnel cifrado entre duas pontas, por cima de uma rede não confiável:

- **De acesso remoto:** um funcionário em casa liga-se à rede da empresa.
- **Site a site:** liga dois escritórios.
- Protocolos: **WireGuard** (moderno, simples, rápido), IPsec, OpenVPN. Serviços como o **Tailscale** montam redes privadas sobre WireGuard sem configurar routers.

Uma VPN "comercial" de consumo só muda **em quem confias**: em vez do teu fornecedor de Internet, o fornecedor da VPN vê o teu tráfego (o que não for HTTPS).

## Reconhecimento: ver o que está exposto

Os atacantes começam por descobrir o que está aberto. Faz o mesmo aos **teus** sistemas, para fechares o que não devia estar:

```bash
nmap -sV o-teu-servidor.pt      # que portas estão abertas e que serviços (só em sistemas teus!)
```

Motores como o Shodan e o Censys indexam continuamente todos os serviços expostos na Internet. Uma base de dados com a porta aberta é encontrada em horas.
