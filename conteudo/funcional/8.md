Se as funções são puras, como é que um programa Haskell lê do teclado ou escreve no ecrã? A resposta é o tipo `IO`, e a ideia geral por trás dele é a **mónada**. Antes disso vem o **functor**. Os nomes vêm da matemática, mas as ideias são práticas e aparecem noutras linguagens (Promises em JavaScript, `Optional` em Java).

## Functor: aplicar uma função "dentro" de uma caixa

`map` aplica uma função a cada elemento de uma lista. `fmap` generaliza isto a qualquer "contentor":

```haskell
ghci> fmap (+ 1) [1, 2, 3]
[2,3,4]
ghci> fmap (+ 1) (Just 5)
Just 6
ghci> fmap (+ 1) Nothing
Nothing
```

Um tipo é instância de `Functor` se tiver um `fmap` que **não altera a estrutura**: só os valores lá dentro. Também se escreve `(+ 1) <$> Just 5`.

## Maybe como mónada: encadear passos que podem falhar

Imagina três passos e cada um pode falhar:

```haskell
import qualified Data.Map as M

idades :: M.Map String Int
idades = M.fromList [("ana", 30), ("rui", 0)]

idadeDe :: String -> Maybe Int
idadeDe n = M.lookup n idades

divide :: Int -> Int -> Maybe Int
divide _ 0 = Nothing
divide a b = Just (a `div` b)

-- sem mónada: escadas de case
racio1 :: String -> String -> Maybe Int
racio1 a b = case idadeDe a of
  Nothing -> Nothing
  Just x  -> case idadeDe b of
    Nothing -> Nothing
    Just y  -> divide x y

-- com mónada: notação do
racio2 :: String -> String -> Maybe Int
racio2 a b = do
  x <- idadeDe a
  y <- idadeDe b
  divide x y

-- racio2 "ana" "ana" == Just 1
-- racio2 "ana" "rui" == Nothing   (divisão por zero)
-- racio2 "ana" "zé"  == Nothing   (não existe)
```

O `do` faz o trabalho chato: se algum passo dá `Nothing`, o resto não corre e o resultado é `Nothing`. O operador por trás é `>>=` ("bind"): `m >>= f` tira o valor de `m` (se existir) e passa-o a `f`.

## IO: ações que interagem com o mundo

Um valor do tipo `IO a` é uma **descrição** de uma ação que, quando executada, produz um `a`. O programa é a ação `main`:

```haskell
main :: IO ()
main = do
  putStrLn "Como te chamas?"
  nome <- getLine
  let saudacao = "Olá, " ++ nome ++ "!"
  putStrLn saudacao
  putStrLn ("O teu nome tem " ++ show (length nome) ++ " letras.")
```

- `nome <- getLine` executa a ação e dá o nome `nome` ao resultado (`String`).
- `let` serve para valores puros dentro do `do`.
- Não há forma de tirar um `String` de dentro de um `IO String` numa função pura. É isso que mantém o resto do programa puro: o tipo diz onde há efeitos.

Boa organização: `main` lê e escreve; toda a lógica fica em funções puras, fáceis de testar.

## A mesma ideia noutras linguagens

```js run
const passo = (v, ok) => new Promise((res, rej) => ok ? res(v) : rej("falhou em " + v));
passo(1, true)
  .then(x => passo(x + 1, true))
  .then(x => passo(x * 10, false))
  .then(x => console.log("fim", x))
  .catch(e => console.log(e));
```

Prevê a mensagem. O `.then` faz o papel do `>>=`: se um passo falha, os seguintes não correm.
