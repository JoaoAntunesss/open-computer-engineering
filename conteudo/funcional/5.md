Os **tipos algébricos** permitem criar os teus próprios tipos de dados, dizendo exatamente que formas um valor pode ter. Com **pattern matching** tratas cada forma, e o compilador avisa-te se te esqueceres de alguma. É uma das ideias mais copiadas da programação funcional: existe em Rust, Swift, Kotlin, Scala, TypeScript e, desde 3.10, em Python (`match`).

## Tipos soma: uma de várias alternativas

```haskell
data Cor = Vermelho | Verde | Azul
  deriving (Show, Eq)

data Forma
  = Circulo Double
  | Retangulo Double Double
  | Triangulo Double Double Double
  deriving Show
```

Um valor `Forma` é **ou** um círculo com um raio, **ou** um retângulo com largura e altura, **ou** um triângulo com três lados. `Circulo`, `Retangulo` e `Triangulo` são **construtores**.

## Pattern matching

```haskell
area :: Forma -> Double
area (Circulo r)       = pi * r * r
area (Retangulo l a)   = l * a
area (Triangulo a b c) = sqrt (s * (s - a) * (s - b) * (s - c))
  where s = (a + b + c) / 2

-- area (Retangulo 3 4)  ==  12.0
-- area (Triangulo 3 4 5) ==  6.0
```

Compila com `-Wall`: se acrescentares `Quadrado Double` a `Forma` e te esqueceres de o tratar em `area`, o GHC avisa "Pattern match(es) are non-exhaustive".

## Tipos produto e registos

```haskell
data Aluno = Aluno { nome :: String, numero :: Int, nota :: Double }
  deriving Show

aprovado :: Aluno -> Bool
aprovado a = nota a >= 9.5

-- aprovado (Aluno "Rita" 2500001 14.2)  ==  True
```

## Tipos recursivos: árvores

Um tipo pode referir-se a si próprio. Uma expressão aritmética é um número, ou uma soma de duas expressões, ou um produto de duas:

```haskell
data Expr
  = Num Int
  | Soma Expr Expr
  | Mult Expr Expr

avalia :: Expr -> Int
avalia (Num n)    = n
avalia (Soma a b) = avalia a + avalia b
avalia (Mult a b) = avalia a * avalia b

-- (2 + 3) * 4
exemplo :: Expr
exemplo = Mult (Soma (Num 2) (Num 3)) (Num 4)

-- avalia exemplo  ==  20
```

Esta é a base de todos os compiladores e interpretadores: o programa é uma árvore, e avaliá-lo é percorrer essa árvore.

## Maybe: quando pode não haver resultado

```haskell
data Maybe a = Nothing | Just a      -- já vem no Prelude

divide :: Int -> Int -> Maybe Int
divide _ 0 = Nothing
divide a b = Just (a `div` b)

mostra :: Maybe Int -> String
mostra Nothing  = "sem resultado"
mostra (Just n) = "resultado: " ++ show n
```

Em vez de devolver `null` ou rebentar, o tipo diz que pode não haver resultado e obriga quem chama a tratar os dois casos.

## O mesmo em Python

```python run
from dataclasses import dataclass
import math

@dataclass
class Circulo:
    r: float

@dataclass
class Retangulo:
    l: float
    a: float

def area(f):
    match f:
        case Circulo(r):
            return math.pi * r * r
        case Retangulo(l, a):
            return l * a

print(round(area(Circulo(1)), 2), area(Retangulo(3, 4)), area("quadrado"))
```

O que mostra a última chamada? Em Python não há aviso: o `match` deixa passar o caso esquecido sem aviso.
