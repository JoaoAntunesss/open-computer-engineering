Em Haskell, todas as expressões têm um tipo, e o compilador verifica-os **antes** de o programa correr. Se compila, uma grande família de erros (somar um número a um texto, esquecer um caso) já não pode acontecer. E quase nunca precisas de escrever os tipos: o compilador **deduz** os tipos.

## Tipos básicos

```haskell
ghci> :type True
True :: Bool
ghci> :type 'a'
'a' :: Char
ghci> :type "ola"
"ola" :: [Char]          -- String é o mesmo que [Char]
ghci> :type (3, "tres")
(3, "tres") :: Num a => (a, String)
```

- `Int` (inteiro de 64 bits), `Integer` (inteiro sem limite), `Double`, `Bool`, `Char`.
- `[a]`: lista de elementos do tipo `a`. Todos os elementos têm o mesmo tipo.
- `(a, b)`: par. Os elementos podem ter tipos diferentes.

## Tipos de funções

`a -> b` é o tipo de uma função que recebe um `a` e devolve um `b`. Uma função de dois argumentos tem tipo `a -> b -> c`, que se lê `a -> (b -> c)`: recebe um `a` e devolve **outra função**, que espera o `b`. Chama-se **currying**.

```haskell
soma :: Int -> Int -> Int
soma x y = x + y

somaDez :: Int -> Int
somaDez = soma 10          -- aplicação parcial

-- somaDez 5  ==  15
```

## Inferência de tipos

Sem anotações, o GHC deduz o tipo mais geral possível:

```haskell
ghci> let dobro x = x + x
ghci> :type dobro
dobro :: Num a => a -> a
```

Raciocínio do compilador: usamos `+` em `x`, por isso `x` tem de ser de um tipo numérico (`Num a`). O resultado é do mesmo tipo. Escreve, mesmo assim, os tipos das funções de topo: documentam o código e dão mensagens de erro mais claras.

## Polimorfismo

Algumas funções funcionam para **qualquer** tipo. A letra minúscula é uma variável de tipo:

```haskell
primeiro :: (a, b) -> a
primeiro (x, _) = x

comprimento :: [a] -> Int
comprimento []     = 0
comprimento (_:xs) = 1 + comprimento xs
```

`comprimento` funciona com `[Int]`, `[String]` ou `[[Bool]]`. Isto é **polimorfismo paramétrico**: a função não olha para os elementos, por isso não precisa de saber o tipo deles.

Muitas vezes, o tipo quase diz o que a função faz. Uma função `a -> a` que funciona para qualquer `a` só pode devolver o próprio argumento: não sabe criar outro valor de um tipo que desconhece.

## Ler uma mensagem de erro de tipos

```haskell
ghci> "idade: " ++ 30
<interactive>: error:
    • No instance for (Num [Char]) arising from the literal ‘30’
```

Lê-se assim: "puseste o literal 30 onde era esperada uma `String` (`[Char]`), e `String` não é um tipo numérico". A correção é `"idade: " ++ show 30`.

## Exercícios

1. Qual é o tipo de `not`, de `(&&)` e de `fst`? Confirma no `ghci` com `:type`.
2. Sem correr, diz o tipo de `\x -> (x, x)`.
3. Escreve `trocar :: (a, b) -> (b, a)`.
4. Porque é que `[1, 'a']` dá erro?
5. Que funções podem ter o tipo `[a] -> Int`? Dá dois exemplos com comportamento diferente.

??? Soluções
1: `not :: Bool -> Bool`, `(&&) :: Bool -> Bool -> Bool`, `fst :: (a, b) -> a`.

2: `a -> (a, a)`.

3:

```haskell
trocar :: (a, b) -> (b, a)
trocar (x, y) = (y, x)
```

4: numa lista, todos os elementos têm de ter o mesmo tipo, e `1` é numérico enquanto `'a'` é `Char`. Para juntar valores de tipos diferentes, usa um par `(1, 'a')`.

5: `length`, ou `const 0` (devolve sempre 0). A função não sabe nada dos elementos, por isso só pode depender da **forma** da lista: o comprimento, ou nada.
