Como as funções Haskell são puras, podes **provar** propriedades dos programas com o mesmo raciocínio da álgebra do secundário: substituir iguais por iguais. Não é só teoria: é assim que se justifica uma otimização, e é a base de ferramentas de testes por propriedades como o QuickCheck.

## Raciocínio equacional

Com as definições:

```haskell
dobro x = x + x
quadrado x = x * x
```

Prova que `dobro (quadrado 3) = 18`:

```
dobro (quadrado 3)
= quadrado 3 + quadrado 3      -- definição de dobro
= (3 * 3) + (3 * 3)            -- definição de quadrado
= 9 + 9
= 18
```

Cada passo é justificado por uma definição ou por uma regra da aritmética. Isto só funciona porque não há efeitos: `quadrado 3` vale sempre o mesmo.

## Prova por indução sobre listas

Para provar que uma propriedade `P(xs)` vale para **todas** as listas finitas, basta provar:

1. **Caso base:** `P([])`.
2. **Passo:** se `P(xs)` (hipótese de indução), então `P(x : xs)`.

Definições:

```haskell
[]     ++ ys = ys                     -- (++.1)
(x:xs) ++ ys = x : (xs ++ ys)         -- (++.2)

length []     = 0                     -- (len.1)
length (_:xs) = 1 + length xs         -- (len.2)
```

**Propriedade:** `length (xs ++ ys) = length xs + length ys`.

*Caso base*, `xs = []`:

```
length ([] ++ ys)
= length ys                 -- (++.1)
= 0 + length ys
= length [] + length ys     -- (len.1)
```

*Passo*, `xs = x : zs`, assumindo `length (zs ++ ys) = length zs + length ys`:

```
length ((x:zs) ++ ys)
= length (x : (zs ++ ys))         -- (++.2)
= 1 + length (zs ++ ys)           -- (len.2)
= 1 + (length zs + length ys)     -- hipótese de indução
= (1 + length zs) + length ys
= length (x:zs) + length ys       -- (len.2)
```

## Leis úteis

Muitas otimizações de compiladores funcionais são leis provadas assim:

- `map id = id`
- `map f . map g = map (f . g)` (fusão: percorrer a lista uma vez em vez de duas)
- `reverse (reverse xs) = xs` (para listas finitas)
- `sum (xs ++ ys) = sum xs + sum ys`

## Testar propriedades

Uma prova cobre todos os casos; um teste por propriedades verifica a propriedade em centenas de casos aleatórios. Em Haskell usa-se o QuickCheck:

```haskell
import Test.QuickCheck

prop_len :: [Int] -> [Int] -> Bool
prop_len xs ys = length (xs ++ ys) == length xs + length ys

prop_rev :: [Int] -> Bool
prop_rev xs = reverse (reverse xs) == xs

-- ghci> quickCheck prop_len
-- +++ OK, passed 100 tests.
```

A mesma ideia, em Python, sem bibliotecas. Uma das três propriedades é falsa: qual?

```python run
import random
def testa(nome, prop):
    for _ in range(500):
        xs = [random.randint(-5, 5) for _ in range(random.randint(0, 6))]
        ys = [random.randint(-5, 5) for _ in range(random.randint(0, 6))]
        if not prop(xs, ys):
            print(nome, "FALHA com", xs, ys)
            return
    print(nome, "ok")

testa("len", lambda xs, ys: len(xs + ys) == len(xs) + len(ys))
testa("rev", lambda xs, ys: list(reversed(xs + ys)) == list(reversed(ys)) + list(reversed(xs)))
testa("sort", lambda xs, ys: sorted(xs + ys) == sorted(xs) + sorted(ys))
```
