Quando várias threads mexem nos mesmos dados, o resultado pode depender da ordem exata em que as instruções correm: é uma **condição de corrida**. Estes erros são dos mais difíceis de encontrar, porque aparecem uma vez em mil execuções. As ferramentas para os evitar são os **trincos** (*mutexes*), os **semáforos** e as **variáveis de condição**.

## O problema

```c
// corrida.c
#include <stdio.h>
#include <pthread.h>

long contador = 0;
pthread_mutex_t trinco = PTHREAD_MUTEX_INITIALIZER;
int usar_trinco = 0;

void *incrementa(void *arg) {
    (void)arg;
    for (int i = 0; i < 1000000; i++) {
        if (usar_trinco) pthread_mutex_lock(&trinco);
        contador++;                       // ler, somar 1, escrever: três passos
        if (usar_trinco) pthread_mutex_unlock(&trinco);
    }
    return NULL;
}

int main(void) {
    for (usar_trinco = 0; usar_trinco <= 1; usar_trinco++) {
        contador = 0;
        pthread_t a, b;
        pthread_create(&a, NULL, incrementa, NULL);
        pthread_create(&b, NULL, incrementa, NULL);
        pthread_join(a, NULL);
        pthread_join(b, NULL);
        printf("%s trinco: %ld (esperado 2000000)\n", usar_trinco ? "com" : "sem", contador);
    }
    return 0;
}
```

Compila **sem otimizações** (`gcc -O0 -pthread corrida.c`) para veres o problema. `contador++` é, em assembly, `lw`, `addi`, `sw`. Se as duas threads lerem o mesmo valor antes de qualquer uma escrever, um incremento perde-se.

## Secção crítica e exclusão mútua

A **secção crítica** é o código que acede aos dados partilhados. Uma solução correta garante:

1. **Exclusão mútua:** no máximo uma thread na secção crítica.
2. **Progresso:** se ninguém está lá dentro, quem quer entrar acaba por entrar.
3. **Espera limitada:** ninguém espera para sempre.

## Trincos (mutex)

`pthread_mutex_lock` bloqueia se outra thread tiver o trinco; `unlock` liberta-o. Por baixo, usam instruções atómicas do processador (como *compare-and-swap*) e, quando têm de esperar, pedem ao kernel para dormir.

Regras:

- Protege **todos** os acessos aos dados partilhados, incluindo as leituras.
- Mantém a secção crítica curta: nada de E/S lenta lá dentro.
- Liberta sempre o trinco, também nos caminhos de erro.

## Semáforos

Um contador com duas operações atómicas:

- `wait` (ou P): se o contador é > 0, decrementa; senão, bloqueia.
- `post` (ou V): incrementa e acorda alguém que esteja à espera.

Um semáforo iniciado a 1 funciona como um trinco. Iniciado a N, deixa entrar até N threads (por exemplo, N ligações à base de dados).

## Variáveis de condição

Para esperar que uma **condição** seja verdadeira ("a fila tem elementos"), sem gastar processador:

```c
pthread_mutex_lock(&m);
while (fila_vazia())                   // while, nunca if
    pthread_cond_wait(&tem_dados, &m); // liberta m e dorme; ao acordar, volta a ter m
x = retira();
pthread_mutex_unlock(&m);
```

E quem produz:

```c
pthread_mutex_lock(&m);
poe(x);
pthread_cond_signal(&tem_dados);
pthread_mutex_unlock(&m);
```

O `while` é obrigatório: a thread pode acordar sem a condição ser verdadeira (outra thread chegou primeiro, ou um despertar espúrio).

## O padrão produtor-consumidor

Um buffer limitado entre threads que produzem e threads que consomem: o produtor espera se o buffer estiver cheio, o consumidor espera se estiver vazio. É a base de filas de tarefas, *pipelines* de processamento e do próprio `|` da shell. Em Python, `queue.Queue` já faz isto. As threads não funcionam no browser, por isso corre este no teu computador (`python3 fila.py`):

```python
import threading, queue, time

fila = queue.Queue(maxsize=3)
feitos = []

def produtor():
    for i in range(6):
        fila.put(i)                  # bloqueia se a fila tiver 3
        print("produzi", i)
    fila.put(None)                   # sinal de fim

def consumidor():
    while (x := fila.get()) is not None:
        time.sleep(0.01)             # trabalho lento
        print("  consumi", x)
        feitos.append(x * x)

t1, t2 = threading.Thread(target=produtor), threading.Thread(target=consumidor)
t1.start(); t2.start(); t1.join(); t2.join()
print(feitos)
```

Prevê a ordem das mensagens: o produtor consegue produzir os 6 antes de o consumidor acabar o primeiro?
