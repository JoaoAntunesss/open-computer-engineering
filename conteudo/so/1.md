O **sistema operativo** (SO) é o programa que gere o hardware e o partilha entre os outros programas. O seu núcleo, o **kernel**, corre com privilégios totais; as aplicações correm com privilégios limitados e pedem-lhe tudo o que envolva hardware ou outros processos: abrir um ficheiro, enviar dados pela rede, criar um processo. Nesta cadeira usamos Linux e C, porque é aí que se vê o SO "por dentro".

## O que faz um sistema operativo

1. **Abstração:** esconde os detalhes do hardware. Um programa escreve num "ficheiro", sem saber se é um SSD, uma pen ou um disco de rede.
2. **Partilha:** vários programas usam o mesmo processador, a mesma memória e os mesmos discos sem se atrapalharem.
3. **Proteção:** um programa não pode ler a memória de outro nem apagar ficheiros que não são seus.

## Modo utilizador e modo kernel

O processador tem (pelo menos) dois modos:

- **Modo kernel (supervisor):** pode executar qualquer instrução, aceder a qualquer memória, configurar a MMU e os dispositivos.
- **Modo utilizador:** as instruções privilegiadas são proibidas. Se um programa tentar, o processador gera uma exceção e o kernel trata do assunto (normalmente termina o programa).

Sem esta separação, qualquer programa podia desligar as interrupções e nunca mais devolver o processador, ou escrever na memória do kernel.

## Chamadas ao sistema

Para pedir um serviço, o programa executa uma instrução especial (`syscall` no x86-64, `ecall` no RISC-V):

1. Põe o número da chamada e os argumentos em registos.
2. A instrução muda para modo kernel e salta para um ponto de entrada fixo.
3. O kernel verifica os argumentos (nunca confia no programa), faz o trabalho e põe o resultado num registo.
4. Volta a modo utilizador, para a instrução seguinte.

Normalmente não as chamas diretamente: a `libc` tem funções com o mesmo nome (`open`, `read`, `write`, `fork`), e o `printf` acaba por chamar `write`.

```c
// ola.c
#include <unistd.h>
#include <string.h>
#include <fcntl.h>
#include <stdio.h>

int main(void) {
    const char *msg = "olá, kernel\n";
    write(1, msg, strlen(msg));                  // 1 = saída padrão

    int fd = open("/etc/hostname", O_RDONLY);    // devolve um descritor de ficheiro
    if (fd < 0) { perror("open"); return 1; }
    char buf[100];
    ssize_t n = read(fd, buf, sizeof buf - 1);
    close(fd);
    if (n >= 0) { buf[n] = '\0'; printf("li %zd bytes\n", n); }

    int erro = open("/nao/existe", O_RDONLY);
    if (erro < 0) perror("open");                 // mostra o motivo
    return 0;
}
```

Compila com `gcc ola.c -o ola`. Um **descritor de ficheiro** é um pequeno inteiro que identifica, no processo, um ficheiro aberto (0 = entrada, 1 = saída, 2 = erros).

## Ver as chamadas: strace

```
$ strace ./ola
write(1, "olá, kernel\n", 13)          = 13
openat(AT_FDCWD, "/etc/hostname", O_RDONLY) = 3
read(3, "portatil\n", 99)               = 9
close(3)                                = 0
write(1, "li 9 bytes\n", 11)            = 11
openat(AT_FDCWD, "/nao/existe", O_RDONLY) = -1 ENOENT (No such file or directory)
...
```

O `strace` é das ferramentas de depuração mais úteis no Linux: mostra que ficheiros um programa tenta abrir, porque é que falha e onde fica parado.

## Custo de uma chamada ao sistema

Mudar de modo custa centenas de ciclos. Por isso a `libc` usa *buffers*: o `printf` junta o texto em memória e só faz `write` quando o buffer enche ou aparece um `\n` (no terminal). Ler um ficheiro byte a byte com `read` é muito mais lento do que com `fread`, que lê blocos.

## Tipos de kernel

- **Monolítico:** tudo (sistemas de ficheiros, drivers, rede) dentro do kernel. Rápido. Linux, BSD.
- **Micronúcleo:** o kernel faz o mínimo (memória, escalonamento, comunicação); o resto corre como processos. Mais robusto. MINIX, seL4, QNX.
- **Híbrido:** Windows, macOS.

??? Soluções
1: normalmente aparecem `mmap`, `openat`, `read`, `close`, `fstat`, `getdents64` (ler o conteúdo de diretórios) e `write`.

2: a instrução é privilegiada: o processador gera uma exceção, o kernel trata-a e termina o processo (por exemplo, com SIGILL ou SIGSEGV).

3: se não verificasse, um programa podia pedir ao kernel para escrever em memória do kernel ou de outro processo, contornando a proteção. O kernel copia os dados com funções que verificam os endereços (`copy_to_user`).

4: `write` é uma chamada direta ao sistema: os dados vão logo para o kernel. O `printf` guarda o texto num buffer da `libc` e só o envia mais tarde; se o processo terminar de forma anormal, o buffer perde-se.
