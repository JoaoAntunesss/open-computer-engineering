Um disco é só uma sequência enorme de blocos numerados. O **sistema de ficheiros** transforma isso em pastas, nomes, permissões e ficheiros que crescem e encolhem. Também tem de sobreviver a cortes de energia a meio de uma escrita. No Linux, os mais comuns são o **ext4**, o **Btrfs** e o **XFS**; no Windows, o **NTFS**; nas pens, o **FAT32** e o **exFAT**.

## A interface (o que o programa vê)

```c
int fd = open("notas.txt", O_WRONLY | O_CREAT | O_APPEND, 0644);
write(fd, "15\n", 3);
fsync(fd);          // garante que os dados chegaram ao disco
close(fd);
rename("notas.tmp", "notas.txt");    // atómico: ou o antigo ou o novo
unlink("velho.txt");                 // apaga o nome
```

- `0644` são as **permissões**: dono lê e escreve (6), grupo lê (4), outros leem (4).
- O `write` normalmente só copia para a **cache de páginas** do kernel; o disco é escrito mais tarde. `fsync` força a escrita. Bases de dados e editores fazem `fsync` antes de dizer "guardado".
- O padrão "escreve num ficheiro temporário, `fsync`, `rename`" garante que nunca fica um ficheiro meio escrito.

## Inodes e diretórios (Unix)

Cada ficheiro tem um **inode** com os metadados: tamanho, dono, permissões, datas e os números dos blocos onde estão os dados. O **nome não está no inode**.

Um **diretório** é um ficheiro especial que contém uma tabela "nome → número do inode". Daí:

- **Ligações fixas** (`ln a b`): dois nomes para o mesmo inode. O ficheiro só é apagado quando o último nome desaparece (o inode tem um contador de ligações).
- **Ligações simbólicas** (`ln -s a b`): um pequeno ficheiro que contém o **caminho** de outro. Se o original desaparecer, fica a apontar para nada.
- Mover um ficheiro dentro do mesmo disco é instantâneo: só muda a entrada no diretório.

Abrir `/home/ana/notas.txt` obriga a ler o inode da raiz, o diretório `/`, o inode de `home`, o diretório `home`, e assim sucessivamente. Os SO guardam estas traduções numa cache (*dentry cache*).

## Onde estão os blocos

- **Contígua:** rápida de ler, mas os ficheiros não podem crescer facilmente e o disco fragmenta-se.
- **Lista ligada / FAT:** cada bloco aponta para o seguinte (numa tabela à parte, no FAT). Aceder ao meio do ficheiro obriga a percorrer a lista.
- **Indexada:** o inode tem apontadores diretos para os primeiros blocos e apontadores indiretos (para blocos cheios de apontadores) para ficheiros grandes. Ext2/3.
- **Extents:** "do bloco 1000 ao 1999". Um ficheiro grande e contíguo cabe numa única entrada. Ext4, XFS, NTFS.

Prevê o tamanho máximo de ficheiro de um inode clássico:

```python run
bloco = 4096                 # bytes
apontador = 4                # bytes por número de bloco
por_bloco = bloco // apontador
diretos = 12
total_blocos = diretos + por_bloco + por_bloco ** 2 + por_bloco ** 3
print("apontadores por bloco:", por_bloco)
print("só diretos:", diretos * bloco // 1024, "KB")
print("com indireto simples:", (diretos + por_bloco) * bloco // 2**20, "MB")
print("máximo (até ao triplo indireto):", round(total_blocos * bloco / 2**40, 1), "TB")
```

## Consistência depois de uma falha

Criar um ficheiro mexe em vários blocos (o inode, o mapa de blocos livres, o diretório). Se a energia falhar a meio, o disco fica inconsistente. Soluções:

- **fsck:** verificar tudo no arranque. Lento em discos grandes.
- **Journaling** (ext4, NTFS, XFS): antes de alterar a estrutura, escreve no **diário** o que vai fazer. Depois de uma falha, basta repetir ou deitar fora as operações do diário. Normalmente só os metadados vão para o diário.
- **Copy-on-write** (Btrfs, ZFS, APFS): nunca escreve por cima; escreve a versão nova noutro sítio e troca o apontador no fim. Dá *snapshots* quase gratuitos.
