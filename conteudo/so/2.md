Um **processo** é um programa em execução: o código, mais a memória, os registos, os ficheiros abertos e o estado. No Unix, os processos criam-se com três chamadas ao sistema que vale a pena perceber bem, porque explicam como funciona a própria shell: **fork** (copiar o processo), **exec** (trocar o programa) e **wait** (esperar que um filho termine).

## O que o SO guarda de cada processo

No **PCB** (*process control block*): o PID (identificador), o estado, os registos guardados, a tabela de páginas, os ficheiros abertos, o diretório atual, o utilizador, o processo pai.

Estados: **novo → pronto ⇄ a executar → terminado**, e **bloqueado** (à espera de disco, rede, teclado) que volta a pronto quando o evento chega.

## fork: duplicar

`fork()` cria um processo filho que é uma **cópia** do pai: mesmo código, cópia da memória, mesmos ficheiros abertos. Os dois continuam a executar a partir da linha seguinte. A única diferença é o valor devolvido:

- no **pai**: o PID do filho;
- no **filho**: 0;
- −1 se falhar.

```c
// fork.c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    int x = 10;
    pid_t pid = fork();
    if (pid == 0) {                         // filho
        x += 5;
        printf("filho: x = %d\n", x);
        return 3;                           // código de saída
    }
    int estado;
    waitpid(pid, &estado, 0);               // pai espera pelo filho
    printf("pai: x = %d, filho terminou com %d\n", x, WEXITSTATUS(estado));
    return 0;
}
```

O pai mostra `x = 10`: depois do `fork`, cada processo tem a **sua** memória. (Na prática, o Linux não copia logo: as páginas são partilhadas e só se copiam quando alguém escreve, *copy-on-write*.)

## exec: trocar de programa

`execvp(programa, argumentos)` substitui o código do processo atual por outro programa. Se correr bem, **não volta**: o código antigo deixou de existir.

## wait: esperar e recolher

`wait`/`waitpid` bloqueia até o filho terminar e devolve o código de saída. Um filho que terminou mas cujo pai ainda não fez `wait` fica **zombie** (ocupa uma entrada na tabela de processos). Um filho cujo pai morreu é adotado pelo processo `init` (PID 1).

## Uma mini-shell

Todo o funcionamento de uma shell cabe nisto: ler um comando, `fork`, no filho `exec`, no pai `wait`.

```c
// minishell.c
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    const char *comandos[] = {"echo olá da mini-shell", "ls /nao/existe", "true"};
    for (int c = 0; c < 3; c++) {
        char linha[100], *args[10];
        strcpy(linha, comandos[c]);              // numa shell real: fgets(linha, ...)
        int n = 0;
        for (char *p = strtok(linha, " "); p && n < 9; p = strtok(NULL, " ")) args[n++] = p;
        args[n] = NULL;

        pid_t pid = fork();
        if (pid == 0) {
            execvp(args[0], args);
            perror("exec");                      // só chega aqui se o exec falhar
            _exit(127);
        }
        int estado;
        waitpid(pid, &estado, 0);
        printf("[%s terminou com %d]\n", args[0], WEXITSTATUS(estado));
    }
    return 0;
}
```

A separação entre `fork` e `exec` permite ao filho preparar o ambiente **antes** do `exec`: redirecionar a saída para um ficheiro (`>`), ligar um pipe (`|`), mudar de diretório. É assim que a shell implementa `ls > lista.txt`.
