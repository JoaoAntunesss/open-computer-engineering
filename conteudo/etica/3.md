Cada vez que instalas uma biblioteca, copias um excerto de código ou publicas um projeto no GitHub, estás a lidar com direitos de autor e licenças. Errar aqui pode obrigar uma empresa a abrir o código do seu produto, ou a reescrever partes inteiras. Esta lição dá-te o essencial para escolher e respeitar licenças.

## Tipos de propriedade intelectual

- **Direito de autor** (copyright): protege a **expressão** de uma obra — o código fonte, a documentação, os desenhos da interface. Nasce automaticamente quando a obra é criada, sem registo. Não protege as ideias nem os algoritmos em si.
- **Patentes**: protegem **invenções** técnicas, com registo e por um prazo limitado (em regra 20 anos). Na Europa, programas de computador "enquanto tais" não são patenteáveis, mas invenções implementadas por computador com efeito técnico podem ser.
- **Marcas**: protegem nomes e logótipos (ninguém pode lançar um "Pythonn Pro" que confunda com Python).
- **Segredos comerciais**: informação valiosa mantida em segredo (o algoritmo de pesquisa de uma empresa, por exemplo).

Em Portugal, o direito de autor está no Código do Direito de Autor e dos Direitos Conexos, e os programas de computador têm regime próprio (Decreto-Lei n.º 252/94, que transpõe a diretiva europeia). A proteção dura, em regra, toda a vida do autor e mais 70 anos.

## Quem é o dono do código

- O que escreves no teu tempo, com os teus meios, é teu.
- O que escreves para uma empresa, no âmbito do teu contrato, normalmente pertence ou é licenciado ao empregador — lê o contrato.
- Código **sem licença** num repositório público **não é livre**: por defeito, "todos os direitos reservados". Podes lê-lo, mas não copiá-lo para o teu projeto.

## Software livre e open source

Uma licença é a autorização que o autor dá para usar a sua obra em certas condições. As licenças open source dividem-se em duas famílias:

**Permissivas**: podes fazer quase tudo, incluindo usar em software fechado, desde que mantenhas o aviso de copyright e a licença.

**Copyleft**: podes usar e modificar, mas se **distribuíres** uma obra derivada, ela tem de ser distribuída com a mesma licença e com o código fonte.

| Licença | Família | O que exige | Observação |
|---|---|---|---|
| MIT | permissiva | manter o aviso | a mais simples e popular |
| BSD 2/3 cláusulas | permissiva | manter o aviso | a de 3 proíbe usar o nome do autor em publicidade |
| Apache 2.0 | permissiva | aviso, ficheiro NOTICE, indicar alterações | inclui **licença de patentes** explícita |
| MPL 2.0 | copyleft fraco | ficheiros alterados ficam MPL | podes juntar a código fechado |
| LGPL | copyleft fraco | a biblioteca alterada fica LGPL | podes ligar a programas fechados |
| GPL v3 | copyleft forte | toda a obra derivada distribuída fica GPL | protege a liberdade dos utilizadores |
| AGPL v3 | copyleft de rede | como a GPL, também para quem usa o software **pela rede** | pensada para serviços web |

Repara que a GPL só é acionada pela **distribuição**: se usas código GPL num serviço interno ou num servidor, não és obrigado a publicar o código. A AGPL fecha esse "buraco".

## Compatibilidade

Não podes juntar tudo com tudo. Código MIT pode entrar num projeto GPL (a obra final fica GPL). Código GPL **não** pode entrar num projeto que vais distribuir como fechado ou com uma licença permissiva. Apache 2.0 é compatível com GPL v3, mas não com GPL v2.

Antes de adicionar uma dependência:

```bash
pip show requests | grep -i license          # Python
npm view express license                      # JavaScript
npx license-checker --summary                 # todas as dependências de um projeto Node
```

## Escolher uma licença para o teu projeto

- Queres que qualquer pessoa use, mesmo em produtos comerciais fechados? **MIT** (ou **Apache 2.0**, se houver risco de patentes ou contribuições de empresas).
- Queres que as melhorias voltem sempre para a comunidade? **GPL v3** (ou **AGPL v3**, se for um serviço web).
- Documentação, imagens, conteúdo de cursos: as licenças **Creative Commons** (CC BY, CC BY-SA) são mais adequadas do que licenças de software.

Para aplicar: um ficheiro `LICENSE` na raiz do repositório com o texto completo, e o ano e o titular do copyright. O GitHub oferece modelos ao criar o ficheiro.

## Código gerado por IA e excertos da internet

- Respostas do Stack Overflow estão sob **CC BY-SA**: para copiar um excerto relevante, deves atribuir a fonte.
- Ferramentas de IA podem reproduzir código de projetos com licença. Trata o resultado com o mesmo cuidado que um excerto copiado da internet: percebe-o, testa-o e, se for longo e parecer reconhecível, verifica a origem.

## Erros comuns

- Achar que "está no GitHub, por isso é livre".
- Apagar os avisos de copyright de código MIT ao copiá-lo.
- Incluir uma biblioteca GPL num produto fechado que vai ser distribuído.
- Inventar uma licença própria ("podes usar para tudo menos coisas más"): é ambígua e ninguém a vai usar.
- Esquecer as licenças das dependências das dependências.
