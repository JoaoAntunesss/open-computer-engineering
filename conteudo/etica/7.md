Muitas questões de ética e de lei (RGPD, acessibilidade, licenças) decidem-se em linhas concretas de código. Ler código com estes olhos é uma competência profissional: é assim que um revisor apanha um problema antes de ele chegar às pessoas.

## Ler e prever: o que fica guardado?

```python run
import logging
logging.basicConfig(level=logging.INFO, format="%(message)s")
log = logging.getLogger("registo")

def registar(utilizador):
    log.info("novo registo: %s", utilizador)
    return {"id": 1, "email": utilizador["email"]}

registar({"nome": "Rita Sousa", "email": "rita@exemplo.pt", "password": "segredo123", "nif": "123456789"})
```

Antes de correr: o que aparece nos logs? Que dados pessoais estão lá que não deviam estar?

## Encontra o problema: um filtro que exclui pessoas

Este código valida nomes num formulário de inscrição:

```python run
import re

def nome_valido(nome):
    return bool(re.fullmatch(r"[A-Za-z ]{2,40}", nome))

for n in ["Ana Silva", "João Gonçalves", "Zoë", "Nguyễn Văn An", "O'Neill"]:
    print(n, nome_valido(n))
```

O código não dá erro, mas recusa nomes reais. Quem fica de fora, e porquê?

**Ler e prever:** o log mostra o dicionário inteiro, com nome, email, **password em texto** e NIF. Logs costumam ser guardados durante meses e lidos por várias pessoas e ferramentas: é uma violação do princípio de minimização do RGPD e um risco de segurança.

**Encontra o problema:** `[A-Za-z ]` só aceita letras sem acentos. Ficam de fora "João Gonçalves", "Zoë", "Nguyễn Văn An" e "O'Neill". Uma regra técnica aparentemente neutra exclui pessoas com nomes portugueses, vietnamitas ou irlandeses.

**Escreve tu:**
```python
def registar(utilizador):
    novo = {"id": 1, "email": utilizador["email"]}
    log.info("novo registo id=%s", novo["id"])
    return novo

def nome_valido(nome):
    nome = nome.strip()
    return 1 <= len(nome) <= 100 and all(c.isalpha() or c in " -'’" for c in nome)
```
