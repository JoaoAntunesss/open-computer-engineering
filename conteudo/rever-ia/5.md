Não consegues rever a olho cada linha de cada ficheiro que a IA gera. O que consegues é ter uma **rede de segurança**: testes escritos por ti, que dizem o que o código tem de fazer. Qualquer código (teu, de um colega ou gerado) só entra se passar.

## Testes primeiro, código gerado depois

1. Escreves os testes com os casos que importam, incluindo os limites e os estranhos.
2. Pedes o código à IA, ou escreves tu.
3. Corres os testes. Se falharem, o código não está pronto, por muito bom aspeto que tenha.

Assim, a decisão sobre **o que é certo** fica contigo. A IA só propõe **como**.

## Exemplo

Precisas de uma função que valida códigos postais portugueses (`4450-123`). Primeiro os testes:

```python run
import re

def cp_valido(cp):
    # imagina que esta versão veio de uma IA
    return bool(re.match(r"\d{4}-\d{3}", cp))

casos = {
    "4450-123": True,
    "1000-001": True,
    "4450123": False,
    "4450-12": False,
    "44501-123": False,
    "4450-1234": False,
    " 4450-123": False,
    "": False,
}
falhas = [c for c, esperado in casos.items() if cp_valido(c) != esperado]
print("Falham:", falhas or "nenhum")
```

A expressão parecia certa, mas aceita `4450-1234`, porque `re.match` só verifica o início. Os testes apanharam-no em segundos. Corrige na caixa com `re.fullmatch` e volta a correr.

## Testes contra o que a IA costuma esquecer

Mantém uma lista mental (ou num ficheiro) de casos que testas sempre:

- vazio (`""`, `[]`, `{}`), `None`, zero e negativos;
- o valor exatamente no limite e um a mais;
- texto com acentos, maiúsculas e espaços à volta;
- dados repetidos;
- muitos dados (é rápido com 100 000 elementos?).

## Pedir testes à IA, com cuidado

Podes pedir à IA que escreva testes, mas lê-os: muitas vezes testa só o caso feliz, ou testa o que o código **faz** em vez do que **devia** fazer (se o código tem um bug, o teste gerado a partir dele "confirma" o bug). Os casos importantes devem ser decididos por ti.
