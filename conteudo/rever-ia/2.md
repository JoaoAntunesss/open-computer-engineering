Rever código é um trabalho com método, não um olhar rápido. Esta lição dá-te uma lista para seguires sempre que aceitares código de uma IA (ou de outra pessoa). Ao início parece lento; com a prática, fazes isto em poucos minutos.

## A lista de revisão

1. **Percebo cada linha?** Se não, pergunta o que faz essa linha (não "explica tudo") e só avança quando perceberes.
2. **Faz o que eu pedi, e só isso?** A IA às vezes muda coisas que não pediste, ou "aproveita" para reescrever outras partes.
3. **Que suposições fez?** Formatos de data, unidades, se um campo pode vir vazio, que tipo de dados entra.
4. **Casos-limite**: vazio, zero, negativo, muito grande, texto com acentos, duplicados.
5. **Usa coisas que existem?** Funções, métodos e bibliotecas, na versão que tens.
6. **Segurança**: dados do utilizador vão parar a uma query SQL, a um comando ou ao HTML sem tratamento? Há passwords ou chaves no código?
7. **Encaixa no projeto?** Nomes, estilo e organização iguais ao resto do código.
8. **Como é que eu sei que funciona?** Há testes? Corri-os?

## Um exemplo para rever

Pediste: "função que recebe uma lista de encomendas e devolve o total faturado em novembro".

```python run
from datetime import datetime

def faturado_novembro(encomendas):
    total = 0
    for e in encomendas:
        data = datetime.strptime(e["data"], "%d/%m/%Y")
        if data.month == 11:
            total += e["valor"] * 1.23
    return round(total)

dados = [
    {"data": "05/11/2026", "valor": 100, "estado": "paga"},
    {"data": "20/11/2025", "valor": 50, "estado": "paga"},
    {"data": "28/11/2026", "valor": 80, "estado": "cancelada"},
]
print(faturado_novembro(dados))
```

Segue a lista antes de leres a resposta.

??? O que a revisão encontra
- **Faz mais do que pedi**: multiplica por 1,23 (IVA), ninguém pediu isso. Os valores já tinham IVA? Decisão tua, não da IA.
- **Suposição de formato**: a data tem de vir como `dd/mm/aaaa`. Se a tua base de dados guarda `2026-11-05`, rebenta.
- **Novembro de qualquer ano**: soma 2025 e 2026 juntos. Faltou o ano.
- **Encomendas canceladas** também contam.
- **Arredonda ao euro** com `round`, perde os cêntimos, e `round` em Python arredonda 0,5 para o par.
- Não tem testes.

O código corre, parece limpo e dá um número, só que está errado de cinco maneiras diferentes, e nenhuma dá mensagem de erro.

## Rever um diff

Quando a IA altera código que já existe, não leias o ficheiro inteiro outra vez: lê o **diff** (as linhas que mudaram). No VS Code, o painel de Source Control mostra-o; no terminal, `git diff`. Procura sobretudo linhas apagadas que não pediste para apagar.

## Exercício

Corrige a função de cima para: aceitar datas `aaaa-mm-dd`, receber o ano como parâmetro, ignorar canceladas, não aplicar IVA e manter os cêntimos. Escreve 3 `assert` antes.

??? Solução
```python
from datetime import date

def faturado(encomendas, ano, mes):
    total = 0
    for e in encomendas:
        d = date.fromisoformat(e["data"])
        if d.year == ano and d.month == mes and e["estado"] != "cancelada":
            total += e["valor"]
    return total

dados = [
    {"data": "2026-11-05", "valor": 100, "estado": "paga"},
    {"data": "2025-11-20", "valor": 50, "estado": "paga"},
    {"data": "2026-11-28", "valor": 80, "estado": "cancelada"},
]
assert faturado(dados, 2026, 11) == 100
assert faturado(dados, 2025, 11) == 50
assert faturado([], 2026, 11) == 0
```
