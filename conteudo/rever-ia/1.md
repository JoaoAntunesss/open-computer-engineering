Para usares bem uma ferramenta, ajuda saber como funciona. Um modelo de linguagem (o que está por trás do ChatGPT, do Claude ou do Copilot) não "sabe" programar como uma pessoa sabe. Percebendo como gera código, percebes onde vai errar.

## O que um modelo faz, em simples

O modelo foi treinado com enormes quantidades de texto e código. A partir do teu pedido, gera a resposta **um bocadinho de cada vez**, escolhendo em cada passo o que é mais provável vir a seguir. O resultado parece muito com código que alguém escreveria, porque aprendeu com milhões de exemplos.

Daqui saem as forças e as fraquezas:

| Forte em | Fraco em |
|---|---|
| Padrões comuns (CRUD, formulários, ordenações) | Regras específicas do teu negócio que nunca viu |
| Explicar código e conceitos | Saber o que está instalado no teu computador |
| Gerar muito código depressa | Garantir que está tudo certo |
| Sintaxe de muitas linguagens | Casos-limite que não pediste |
| Primeiros rascunhos | Versões recentes de bibliotecas |

## Porque erra com tanta confiança

O modelo gera o que **parece** uma boa resposta. Se uma função `pandas.read_excel_fast()` "parecer" plausível, pode aparecer no código, mesmo não existindo. O tom é sempre seguro, quer a resposta esteja certa ou não. Por isso, a confiança da resposta não te diz nada sobre se está certa.

```python run
# Uma IA pode gerar algo assim, com bom aspeto:
def percentagem(parte, total):
    return parte / total * 100

print(percentagem(25, 200))
print(percentagem(0, 0))
```

Funciona no exemplo "normal" e rebenta no caso que ninguém pediu.

## O contexto que ela não tem

Quando pedes "faz uma função para calcular os portes", a IA não sabe: a tua regra dos portes, que versão de Python usas, como está organizado o resto do projeto, que dados reais vão entrar. Preenche essas lacunas com **suposições prováveis**. Muitos bugs vêm de suposições que nunca viste, porque não leste o código.

## Ela não corre o código (normalmente)

Na maioria das ferramentas, o modelo escreve o código mas não o executa nem o testa. Algumas ferramentas mais recentes já correm testes, mas mesmo aí só testam o que alguém pensou testar. A verificação final és tu.

## O que isto quer dizer para ti

- Trata o código gerado como trabalho de um **colega novo e muito rápido**: útil, mas tens de rever.
- Quanto mais específico o teu pedido (dados de exemplo, regras, versão), menos suposições.
- Quanto menos percebes do código, maior o risco. É por isso que esta fase começa por ler.

## Exercício

Pede a uma IA à tua escolha: "escreve uma função Python que diz se uma password é segura". Antes de correr, lê o código e responde:

1. Que regras é que a IA **inventou** para "segura"? Alguma delas és tu que devias decidir?
2. O que acontece com uma password vazia? E com espaços? E com acentos?
3. Escreve 5 `assert` com casos que achas que vão falhar. Corre-os.

??? Notas
Não há uma solução única, porque depende do que a IA gerou. Normalmente vais encontrar: um comprimento mínimo escolhido pela IA (8? 12?), uma lista de símbolos aceites que deixa de fora alguns, e nenhuma verificação de passwords conhecidas (como `Password1!`, que costuma passar as regras e é péssima). O objetivo é perceberes que "segura" era uma decisão tua, e a IA tomou-a por ti sem dizer.
