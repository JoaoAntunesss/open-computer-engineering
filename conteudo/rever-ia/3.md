Há erros que a IA comete muito mais do que uma pessoa. Se os conheceres, sabes onde olhar primeiro. Esta lição é um catálogo, com exemplos para treinares o olho.

## 1. Funções e bibliotecas inventadas

A IA mistura nomes de várias bibliotecas e versões. O código parece certo e falha ao importar ou ao chamar.

```python run
texto = "Olá Mundo"
print(texto.reverse())
```

Strings em Python não têm `.reverse()` (as listas têm). O certo é `texto[::-1]`. Quando vires uma função que não conheces, confirma na documentação oficial antes de acreditar.

## 2. O caso feliz e só o caso feliz

```python run
def primeira_letra_maiuscula(nome):
    return nome[0].upper() + nome[1:]

print(primeira_letra_maiuscula("rita"))
print(primeira_letra_maiuscula(""))
```

Funciona com o exemplo do pedido, falha com texto vazio. Pergunta sempre: vazio, zero, negativo, `None`, um só elemento, muitos elementos.

## 3. Falhar por um

```python run
def ultimos_dias(n):
    """Devolve os números dos últimos n dias de um mês de 30 dias."""
    return list(range(30 - n, 30))

print(ultimos_dias(3))   # esperado: [28, 29, 30]
```

`range` exclui o fim. Dá `[27, 28, 29]`. Corrige com `range(31 - n, 31)`.

## 4. Injeção de SQL

```python
def procura_cliente(cursor, nome):
    cursor.execute(f"SELECT * FROM clientes WHERE nome = '{nome}'")
    return cursor.fetchall()
```

Se alguém escrever `' OR '1'='1` no campo do nome, recebe a tabela inteira. Nunca juntes dados do utilizador ao texto de uma query. O certo é usar parâmetros:

```python
cursor.execute("SELECT * FROM clientes WHERE nome = %s", (nome,))
```

## 5. HTML sem escapar (XSS)

```js
lista.innerHTML += `<li>${comentario.texto}</li>`;
```

Se o texto tiver `<img src=x onerror=...>`, corre código no browser de quem vê. Usa `textContent` ou escapa os carateres especiais.

## 6. Segredos no código

A IA escreve muitas vezes `API_KEY = "sk-..."` ou a password da base de dados diretamente no ficheiro, para "funcionar já". Se isso for para o GitHub, fica público. Segredos vão para variáveis de ambiente ou ficheiros fora do repositório.

## 7. Apanhar todos os erros e calar

```python run
def ler_idade(txt):
    try:
        return int(txt)
    except Exception:
        return 0

print(ler_idade("vinte"))
```

O erro desapareceu, mas agora "vinte" vale 0 anos e ninguém sabe. Apanha só os erros que esperas (`ValueError`) e decide o que fazer com eles.

## 8. Complicar o que é simples

A IA gosta de classes, padrões e camadas mesmo quando chegavam 5 linhas. Código mais comprido não é código melhor: é mais sítios para errar e mais coisas para manter.

## 9. Mudar o que não pediste

Ao pedires "corrige este bug", a IA pode reescrever outras funções, renomear variáveis ou apagar comentários. Lê sempre o diff.

## Exercício

Encontra pelo menos 4 problemas neste código "gerado por IA" para registar um utilizador. Não precisas de o correr.

```python
import sqlite3

DB_PASSWORD = "admin123"

def registar(nome, email, idade):
    try:
        con = sqlite3.connect("app.db")
        con.execute(f"INSERT INTO users VALUES ('{nome}', '{email}', {idade})")
        con.commit()
        return True
    except:
        return False
```

??? Problemas
1. Injeção de SQL: os valores entram diretamente no texto da query. Usar `?` e parâmetros.
2. `except:` sem tipo apanha tudo e devolve `False` sem dizer porquê: um email repetido, a base de dados em falta e um erro de escrita parecem iguais.
3. Uma password escrita no código (`DB_PASSWORD`), e nem sequer é usada.
4. Nenhuma validação: email sem `@`, idade negativa ou texto passam.
5. A ligação nunca é fechada (`con.close()` ou `with`).
6. `INSERT INTO users VALUES (...)` sem nomes de colunas parte se a tabela ganhar uma coluna.
