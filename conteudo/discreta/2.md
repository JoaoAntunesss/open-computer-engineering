A indução é a técnica de demonstração dos programadores: é a mesma ideia que garante que um ciclo ou uma função recursiva estão corretos. Se uma propriedade vale no início e passa sempre de um passo para o seguinte, vale para todos.

## Indução simples

Para demonstrar P(n) para todo o n ≥ n₀:

1. **Base**: demonstra P(n₀).
2. **Passo**: assume P(k) (a **hipótese de indução**) e demonstra P(k + 1).

**Teorema.** 1 + 2 + … + n = n(n + 1)/2.
**Base.** n = 1: 1 = 1·2/2. ✓
**Passo.** Assume 1 + … + k = k(k + 1)/2. Então
1 + … + k + (k + 1) = k(k + 1)/2 + (k + 1) = (k + 1)(k + 2)/2,
que é a fórmula para k + 1. ∎

## Indução forte

No passo, podes assumir P para **todos** os valores de n₀ até k, não só para k. É útil quando P(k + 1) depende de casos mais atrás.

**Teorema.** Todo o inteiro n ≥ 2 é um produto de primos.
**Demonstração.** Se n é primo, está feito. Senão, n = a·b com 2 ≤ a, b < n. Pela hipótese forte, a e b são produtos de primos, logo n também é. ∎

## Indução e programas

A indução prova funções recursivas. Para

```python
def soma(n):
    return 0 if n == 0 else n + soma(n - 1)
```

a base é soma(0) = 0 e o passo é: se soma(k) devolve k(k+1)/2, então soma(k+1) = (k+1) + k(k+1)/2 = (k+1)(k+2)/2.

Para ciclos usa-se um **invariante**: uma afirmação verdadeira antes do ciclo e preservada por cada iteração. No fim, o invariante mais a condição de paragem dão o resultado.

## Indução estrutural

Também se faz indução sobre estruturas: árvores, listas, fórmulas. Base: a estrutura mais simples (lista vazia, folha). Passo: se vale para as partes, vale para o todo. Exemplo: uma árvore binária com n nós internos tem n + 1 folhas.

## Erros comuns

- Esquecer a base: o passo sozinho "prova" que todos os cavalos têm a mesma cor.
- Usar P(k + 1) para demonstrar P(k + 1).
- Escolher mal o n₀: a fórmula pode só valer a partir de certo ponto.
- No passo, não usar a hipótese de indução, sinal de que algo está mal.
