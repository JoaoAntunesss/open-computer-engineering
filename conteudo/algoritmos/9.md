Há problemas para os quais ninguém conhece um algoritmo rápido, apesar de décadas de tentativas: o caixeiro-viajante, a coloração de grafos, o horário de uma escola, a satisfação de fórmulas lógicas. A teoria da **NP-completude** explica porquê: estes problemas são todos "igualmente difíceis", e resolver depressa um deles resolveria todos. Saber reconhecer um problema NP-completo poupa semanas à procura de um algoritmo que provavelmente não existe.

## P e NP (a ideia)

Fala-se de **problemas de decisão** (resposta sim ou não): "há um caminho que visita todas as cidades com menos de 1000 km?"

- **P:** problemas que se **resolvem** em tempo polinomial (O(n), O(n³)…). Ordenar, caminhos mais curtos, fluxo máximo, emparelhamentos.
- **NP:** problemas em que uma resposta "sim" se **verifica** em tempo polinomial, se te derem uma prova (um *certificado*). Dado um percurso, verificar que passa por todas as cidades e tem menos de 1000 km é fácil; encontrá-lo parece difícil.

P ⊆ NP. Se **P = NP** é o problema em aberto mais famoso da informática (há um prémio de um milhão de dólares). Quase toda a gente acredita que P ≠ NP.

## Reduções

Um problema A **reduz-se** a B (A ≤ B) se qualquer instância de A se transforma, em tempo polinomial, numa instância de B com a mesma resposta. Então B é **pelo menos tão difícil** como A: um algoritmo rápido para B dava um para A.

Já usaste reduções: o emparelhamento bipartido reduz-se a fluxo máximo; a arbitragem de câmbio reduz-se a ciclos negativos.

## NP-completo

Um problema é **NP-completo** se está em NP e **todos** os problemas de NP se reduzem a ele.

- **Teorema de Cook-Levin (1971):** o problema **SAT** (há valores para as variáveis que tornam uma fórmula lógica verdadeira?) é NP-completo.
- Depois, para provar que um problema novo X é NP-completo, basta: (1) mostrar que X está em NP; (2) reduzir **um problema NP-completo conhecido** a X.

Karp mostrou em 1972 que 21 problemas clássicos são NP-completos. Hoje conhecem-se milhares.

## Problemas NP-completos que vais encontrar

| Problema | Pergunta |
|---|---|
| 3-SAT | uma fórmula em que cada cláusula tem 3 literais é satisfazível? |
| Clique | o grafo tem k vértices todos ligados entre si? |
| Cobertura de vértices | há k vértices que tocam todas as arestas? |
| Coloração | os vértices pintam-se com k cores sem vizinhos iguais? (k ≥ 3) |
| Ciclo hamiltoniano / caixeiro-viajante | há um ciclo que passa uma vez por cada vértice (com custo ≤ k)? |
| Soma de subconjunto / mochila | algum subconjunto soma exatamente T? |

## Uma redução simples: conjunto independente e cobertura de vértices

S é um **conjunto independente** (nenhuma aresta entre vértices de S) se e só se os vértices **fora** de S são uma **cobertura** (tocam todas as arestas). Logo: "há um conjunto independente de tamanho k?" é o mesmo que "há uma cobertura de tamanho n − k?". Uma redução de uma linha.

```python run
from itertools import combinations

def e_independente(arestas, s):
    return all(not (u in s and v in s) for u, v in arestas)

def e_cobertura(arestas, c):
    return all(u in c or v in c for u, v in arestas)

vertices = list(range(6))
arestas = [(0, 1), (0, 2), (1, 2), (2, 3), (3, 4), (4, 5), (3, 5)]

# força bruta: experimenta todos os subconjuntos (2^n)
maior = max((set(s) for k in range(7) for s in combinations(vertices, k)
             if e_independente(arestas, set(s))), key=len)
cobertura = set(vertices) - maior
print("maior independente:", maior, " cobertura correspondente:", cobertura,
      e_cobertura(arestas, cobertura))
```

Prevê o tamanho do maior conjunto independente: o grafo são dois triângulos ligados por uma aresta.

## Verificar é fácil, encontrar parece difícil

O código acima experimenta 2⁶ = 64 subconjuntos. Com 100 vértices seriam 2¹⁰⁰ ≈ 10³⁰: nem todos os computadores do mundo, durante a idade do universo. Verificar uma resposta, no entanto, é O(arestas).

## O que fazer na prática

Um problema NP-completo não é o fim:

- **Instâncias pequenas:** força bruta inteligente, *backtracking*, programação dinâmica exponencial mas aceitável.
- **Casos especiais** fáceis: coloração com 2 cores, 2-SAT e grafos em árvore estão em P.
- **Algoritmos de aproximação** com garantia: cobertura de vértices com no máximo o dobro do ótimo; caixeiro-viajante métrico a 1,5 do ótimo.
- **Heurísticas:** pesquisa local, *simulated annealing*, algoritmos genéticos. Sem garantias, mas boas na prática.
- **Solvers SAT e de PL inteira:** resolvem instâncias industriais com milhões de variáveis (verificação de hardware, horários, planeamento).
