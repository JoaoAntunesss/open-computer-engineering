Um **algoritmo aleatorizado** usa números aleatórios para tomar decisões. Parece estranho deixar a sorte decidir, mas muitas vezes dá algoritmos mais simples, mais rápidos ou imunes a entradas "maliciosas". Há dois tipos: os que dão **sempre a resposta certa**, com tempo aleatório (*Las Vegas*), e os que são **sempre rápidos**, com uma pequena probabilidade de erro (*Monte Carlo*).

## Las Vegas: quicksort com pivô aleatório

Com o pivô fixo (o primeiro elemento), há entradas que dão sempre O(n²), por exemplo, uma lista ordenada. Um atacante que conheça o algoritmo pode enviá-las de propósito. Com o pivô **aleatório**, não há entradas más: para **qualquer** entrada, o tempo esperado é O(n log n), e a probabilidade de ser muito pior é minúscula.

A aleatoriedade passou dos **dados** para o **algoritmo**: deixa de interessar que os dados sejam "aleatórios".

## Quickselect: o k-ésimo menor em O(n) esperado

Para a mediana, não é preciso ordenar tudo (O(n log n)). Parte-se como no quicksort, mas só se continua do lado onde está o k-ésimo:

```python run
import random

def quickselect(v, k):                # k-ésimo menor, a contar de 0
    while True:
        pivo = random.choice(v)
        menores = [x for x in v if x < pivo]
        iguais  = [x for x in v if x == pivo]
        if k < len(menores):
            v = menores
        elif k < len(menores) + len(iguais):
            return pivo
        else:
            k -= len(menores) + len(iguais)
            v = [x for x in v if x > pivo]

dados = random.sample(range(1_000_000), 100_001)
print(quickselect(dados, 50_000) == sorted(dados)[50_000])
```

Tempo esperado: n + n/2 + n/4 + … ≈ 2n: O(n).

## Monte Carlo: o teste de primalidade de Miller-Rabin

Para gerar chaves RSA, é preciso encontrar primos com centenas de algarismos. Testar todos os divisores é impossível. O teste de **Miller-Rabin** escolhe bases aleatórias e verifica uma propriedade que todos os primos têm:

- se responder "composto", é **certo**;
- se responder "primo", erra com probabilidade ≤ 1/4 em cada ronda. Com 40 rondas independentes, o erro é ≤ 4⁻⁴⁰ ≈ 10⁻²⁴, muito menos provável do que uma falha de hardware.

```python run
import random

def miller_rabin(n, rondas=40):
    if n < 4:
        return n in (2, 3)
    if n % 2 == 0:
        return False
    d, s = n - 1, 0
    while d % 2 == 0:
        d //= 2; s += 1
    for _ in range(rondas):
        a = random.randrange(2, n - 1)
        x = pow(a, d, n)
        if x in (1, n - 1):
            continue
        for _ in range(s - 1):
            x = pow(x, 2, n)
            if x == n - 1:
                break
        else:
            return False
    return True

print([n for n in range(2, 60) if miller_rabin(n)])
print(miller_rabin(2 ** 127 - 1), miller_rabin(2 ** 128 + 1))
print(miller_rabin(561))          # número de Carmichael: engana testes mais simples
```

Prevê as três linhas. 2¹²⁷ − 1 é um primo de Mersenne famoso; 2¹²⁸ + 1 não é primo.

## Estruturas aleatorizadas

- **Tabelas de dispersão com função aleatória** (hashing universal): sem entradas que causem colisões em massa.
- **Skip lists:** listas ligadas com "atalhos" escolhidos ao acaso; O(log n) esperado, como uma árvore equilibrada, mas muito mais simples. Usadas no Redis.
- **Filtros de Bloom:** respondem "talvez esteja" ou "de certeza que não está", com pouca memória. Usados em bases de dados e browsers.
- **HyperLogLog:** conta elementos distintos em milhares de milhões de dados com poucos KB.

## Amplificação

Um algoritmo Monte Carlo com erro 1/3 repetido k vezes (votação por maioria, ou "basta uma resposta certa") tem erro que cai exponencialmente com k. É por isso que se aceitam probabilidades de erro em produção: torna-se tão pequena quanto se quer.
