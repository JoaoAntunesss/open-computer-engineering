Algumas operações são quase sempre baratas e, de vez em quando, muito caras. A **análise amortizada** calcula o custo **médio por operação numa sequência**, no pior caso. Não é uma média probabilística: é uma garantia. É ela que justifica dizer que `append` numa lista do Python é O(1), embora às vezes tenha de copiar a lista inteira.

## O exemplo: vetor dinâmico

Começa com capacidade 1. Quando está cheio, aloca o **dobro** e copia tudo. Um `append` custa 1 (normalmente) ou k + 1 (quando há k elementos a copiar).

Em n `append`s, as cópias acontecem nos tamanhos 1, 2, 4, 8, …, até n: total de cópias = 1 + 2 + 4 + … + n < 2n. Mais n escritas: menos de 3n operações para n `append`s. **Custo amortizado: O(1) por operação.**

Se, em vez de duplicar, o vetor crescesse **10 posições** de cada vez, as cópias seriam 10 + 20 + 30 + … ≈ n²/20: O(n) amortizado. Crescer por um **fator** é o que faz funcionar.

```python run
def simula(n, crescimento):
    capacidade, tamanho, copias = 1, 0, 0
    for _ in range(n):
        if tamanho == capacidade:
            copias += tamanho
            capacidade = crescimento(capacidade)
        tamanho += 1
    return copias

for n in (1_000, 10_000, 100_000):
    dobra = simula(n, lambda c: 2 * c)
    soma10 = simula(n, lambda c: c + 10)
    print(f"n = {n:>7}: duplicar → {dobra / n:.2f} cópias por append;  +10 → {soma10 / n:.1f}")
```

Prevê os valores antes de correr. Repara que, com duplicação, o custo por operação não cresce com n.

## Três métodos

1. **Agregado:** soma o custo total de n operações e divide por n (como acima).
2. **Contabilístico:** cobra a cada operação um custo fixo ("3 moedas por `append`"). As operações baratas guardam o excedente, que paga as caras. Se o saldo nunca fica negativo, o custo cobrado é um limite. No vetor: 1 moeda para escrever, 2 de poupança; quando o vetor duplica de k para 2k, os k/2 elementos inseridos desde a última duplicação pouparam k moedas, exatamente o preço de copiar os k.
3. **Potencial:** define-se uma "energia" Φ do estado da estrutura; custo amortizado = custo real + ΔΦ. Para o vetor, Φ = 2·tamanho − capacidade.

## Outros exemplos

- **Contador binário:** incrementar pode mudar muitos bits (0111 → 1000), mas em n incrementos o bit 0 muda n vezes, o bit 1 muda n/2, o bit 2 muda n/4… Total < 2n: O(1) amortizado.
- **Fila com duas pilhas** (de AED): cada elemento é movido no máximo uma vez de uma pilha para a outra: O(1) amortizado.
- **Union-find** com compressão de caminhos e união por tamanho: quase O(1) amortizado (O(α(n)), em que α é a inversa da função de Ackermann, menor do que 5 para qualquer n realista).
- **Tabelas de dispersão** que duplicam quando enchem.
- **Splay trees:** cada acesso reorganiza a árvore; O(log n) amortizado, sem guardar informação de equilíbrio.

## Cuidado: amortizado não é "sempre rápido"

Uma operação individual pode ser lenta. Num sistema de tempo real (um travão ABS, um jogo a 60 imagens por segundo), uma pausa de 50 ms para duplicar um vetor enorme pode ser inaceitável, mesmo que a média seja ótima. Nesses casos, usam-se estruturas com garantias **por operação**, ou reserva-se a capacidade à partida (`reserve` em C++, `new ArrayList<>(n)` em Java).

## E a remoção?

Se o vetor encolher para metade quando fica a metade, uma sequência a alternar `append` e `pop` no limite faz duplicar e encolher em todas as operações: O(n) cada. A solução é encolher só quando fica a **um quarto**: depois de encolher, está a metade, longe dos dois limites.
