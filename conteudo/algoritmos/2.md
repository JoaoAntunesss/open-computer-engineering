Um **algoritmo ganancioso** (*greedy*) constrói a solução passo a passo, escolhendo sempre a opção que parece melhor **agora**, sem voltar atrás. Quando funciona, é simples e rápido. O difícil é saber **quando** funciona: muitas vezes a escolha óbvia dá uma resposta errada, e é preciso uma prova.

## Exemplo que funciona: escalonar atividades

Tens várias reuniões, cada uma com início e fim, e uma sala. Queres marcar o maior número possível sem sobreposições.

Estratégias possíveis: a mais curta primeiro? A que começa mais cedo? A que tem menos conflitos? A correta é: **escolher sempre a que acaba mais cedo** entre as compatíveis.

```python run
def max_atividades(atividades):
    escolhidas, fim_atual = [], float("-inf")
    for nome, inicio, fim in sorted(atividades, key=lambda a: a[2]):   # por fim
        if inicio >= fim_atual:
            escolhidas.append(nome)
            fim_atual = fim
    return escolhidas

reunioes = [("A", 1, 4), ("B", 3, 5), ("C", 0, 6), ("D", 5, 7), ("E", 3, 9),
            ("F", 5, 9), ("G", 6, 10), ("H", 8, 11), ("I", 8, 12), ("J", 2, 14)]
print(max_atividades(reunioes))

def mais_curta_primeiro(atividades):
    escolhidas = []
    for a in sorted(atividades, key=lambda a: a[2] - a[1]):
        if all(a[2] <= b[1] or a[1] >= b[2] for b in escolhidas):
            escolhidas.append(a)
    return [a[0] for a in escolhidas]

contra = [("longa1", 0, 5), ("curta", 4, 6), ("longa2", 5, 10)]
print("por fim:", max_atividades(contra), " mais curta:", mais_curta_primeiro(contra))
```

Prevê as reuniões escolhidas antes de correr. A segunda linha mostra porque é que "a mais curta primeiro" falha.

**Porque funciona (argumento de troca):** pega numa solução ótima qualquer. A primeira atividade dela acaba no mesmo instante ou depois da que o algoritmo escolheu (que é a que acaba mais cedo de todas). Troca-a pela do algoritmo: continua compatível com as restantes e tem o mesmo número de atividades. Repetindo o argumento, a solução gananciosa é ótima.

## Os dois ingredientes

1. **Propriedade da escolha gananciosa:** existe uma solução ótima que inclui a escolha gananciosa.
2. **Subestrutura ótima:** depois da escolha, o resto do problema é um problema do mesmo tipo, e a sua solução ótima, junta à escolha, dá a solução ótima do todo.

## Mais exemplos que funcionam

- **Código de Huffman** (compressão): junta sempre os dois símbolos menos frequentes. Dá o código de prefixo ótimo; é usado em ZIP, JPEG e MP3.
- **Dijkstra, Prim e Kruskal** (que viste em AED): todos gananciosos.
- **Mochila fracionária:** podes levar frações dos objetos; leva primeiro os de maior valor por quilo.
- **Trocos em euros:** dar sempre a maior moeda possível usa o mínimo de moedas.

## Exemplo que falha: trocos noutro sistema

Com moedas de 1, 3 e 4, para fazer 6: a escolha gananciosa dá 4 + 1 + 1 (3 moedas); o ótimo é 3 + 3 (2 moedas). O sistema de moedas do euro foi desenhado para que a estratégia gananciosa funcione; nem todos os sistemas são assim.

Outro: a **mochila 0/1** (cada objeto vai inteiro ou não vai). Pegar pela ordem do valor por quilo pode deixar espaço vazio que um objeto pior teria aproveitado. Este resolve-se com programação dinâmica (lição seguinte).

def mochila_fracionaria(objetos, capacidade):
    total = 0
    for peso, valor in sorted(objetos, key=lambda o: o[1] / o[0], reverse=True):
        leva = min(peso, capacidade)
        total += valor * leva / peso
        capacidade -= leva
        if capacidade == 0:

    return total

troco(99) == [50, 20, 20, 5, 2, 2]
solucao:
def troco(centimos):
    moedas = [200, 100, 50, 20, 10, 5, 2, 1]
    out = []
    for m in moedas:
        while centimos >= m:
            out.append(m)
            centimos -= m
    return out
