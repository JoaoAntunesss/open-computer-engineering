Em algoritmos, ler código serve para responder a duas perguntas: **está certo?** e **quanto custa?** Uma boa forma de treinar é prever quantas operações um programa faz antes de o correr.

## Ler e prever: contar operações

```python run
def a(n):
    c = 0
    for i in range(n):
        c += 1
    return c

def b(n):
    c = 0
    for i in range(n):
        for j in range(i):
            c += 1
    return c

def d(n):
    c = 0
    while n > 1:
        n //= 2
        c += 1
    return c

print(a(1000), b(1000), d(1000))
```

Antes de correr: qual é a complexidade de cada função (O(n), O(n²), O(log n))? E os números exatos para n = 1000?

## Encontra o erro: Fibonacci com memória

```python run
def fib(n, memo={}):
    if n <= 1:
        return n
    if n in memo:
        return memo[n]
    resultado = fib(n - 1) + fib(n - 2)
    return resultado

import time
t = time.time()
print(fib(30), round(time.time() - t, 2), "s")
```

O objetivo era guardar resultados (memoização) e ser instantâneo, mas demora. O que falta?

## Escreve tu

Escreve uma solução para "dada uma lista de números e um alvo, existem dois números cuja soma dá o alvo?" Primeiro em O(n²) com dois ciclos, depois em O(n) com um conjunto. Mede as duas com 5000 números.

??? Soluções
**Ler e prever:** `a` é O(n): `1000`. `b` é O(n²): 0 + 1 + … + 999 = `499500`. `d` é O(log n): divide por 2 até chegar a 1, `9` vezes.

**Encontra o erro:** o resultado nunca é guardado. Falta `memo[n] = resultado` antes do `return`. Sem isso, é a recursão exponencial normal (mais de um milhão de chamadas para n = 30). Com a correção, fib(30) = 832040 é imediato.

**Escreve tu:**
```python
def par_soma(nums, alvo):
    vistos = set()
    for x in nums:
        if alvo - x in vistos:
            return True
        vistos.add(x)
    return False
```
