A **programação linear** (PL) otimiza uma função linear sujeita a restrições lineares: maximizar o lucro com recursos limitados, minimizar o custo de uma dieta, planear turnos, encaminhar tráfego. Há algoritmos eficientes e bibliotecas excelentes, por isso o trabalho difícil é **modelar** o problema: passar da descrição em palavras para variáveis, objetivo e restrições.

## Um exemplo

Uma fábrica faz mesas (lucro 30 €) e cadeiras (lucro 20 €). Uma mesa precisa de 4 h de carpintaria e 1 h de pintura; uma cadeira, 2 h e 1 h. Há 100 h de carpintaria e 40 h de pintura por semana. Quantas fazer?

- **Variáveis:** x = mesas, y = cadeiras.
- **Objetivo:** maximizar 30x + 20y.
- **Restrições:**
  - 4x + 2y ≤ 100 (carpintaria)
  - x + y ≤ 40 (pintura)
  - x ≥ 0, y ≥ 0

## A geometria

Cada restrição é um semiplano. A interseção é um **polígono convexo** (a região admissível). As retas de nível do objetivo (30x + 20y = constante) são paralelas; empurra-se a reta na direção de crescimento até ao último ponto da região. **O ótimo está sempre num vértice** (ou numa aresta inteira, se houver empate).

Vértices da região: (0, 0), (25, 0), (0, 40) e a interseção de 4x + 2y = 100 com x + y = 40, que é (10, 30).

```python run
from fractions import Fraction as F
from itertools import combinations

# restrições a·x + b·y <= c (incluindo x >= 0 e y >= 0 como -x <= 0, -y <= 0)
restricoes = [(4, 2, 100), (1, 1, 40), (-1, 0, 0), (0, -1, 0)]
lucro = lambda x, y: 30 * x + 20 * y

vertices = []
for (a1, b1, c1), (a2, b2, c2) in combinations(restricoes, 2):
    det = a1 * b2 - a2 * b1
    if det == 0:
        continue
    x = F(c1 * b2 - c2 * b1, det)
    y = F(a1 * c2 - a2 * c1, det)
    if all(a * x + b * y <= c for a, b, c in restricoes):
        vertices.append((x, y))

for v in sorted(set(vertices)):
    print(f"vértice ({v[0]}, {v[1]}): lucro {lucro(*v)}")
melhor = max(vertices, key=lambda v: lucro(*v))
print("ótimo:", melhor, lucro(*melhor))
```

Prevê qual dos vértices é o ótimo antes de correr. Enumerar todos os vértices só funciona com poucas variáveis (com n variáveis e m restrições, pode haver C(m, n) vértices).

## Algoritmos

- **Simplex** (Dantzig, 1947): anda de vértice em vértice vizinho, sempre a melhorar o objetivo, até nenhum vizinho ser melhor. No pior caso é exponencial, mas na prática é muito rápido e é o mais usado.
- **Pontos interiores** (Karmarkar, 1984): atravessa o interior da região. Polinomial no pior caso; bom para problemas enormes.

## Dualidade

Cada problema de PL tem um **dual**. No exemplo, o dual pergunta: "quanto vale uma hora de carpintaria e uma de pintura?" (os **preços-sombra**). O ótimo do dual é igual ao do primal, e os preços-sombra dizem quanto aumentaria o lucro com mais uma hora de cada recurso. Aqui, a carpintaria vale 5 € por hora e a pintura 10 €.

## Programação linear inteira

Se as variáveis tiverem de ser **inteiras** (não se fazem 10,5 mesas), o problema fica **NP-difícil** em geral. Usa-se *branch and bound*: resolve-se a PL relaxada e, se der um valor fracionário, divide-se em dois casos (x ≤ 10 e x ≥ 11). Os solvers comerciais (Gurobi, CPLEX) e livres (HiGHS, CBC) resolvem problemas com milhões de variáveis na prática.

## Em Python

```python
from scipy.optimize import linprog
# linprog minimiza, por isso troca-se o sinal do lucro
r = linprog(c=[-30, -20], A_ub=[[4, 2], [1, 1]], b_ub=[100, 40], bounds=[(0, None)] * 2)
print(r.x, -r.fun)          # [10. 30.] 900.0
```

Para modelos maiores, o `PuLP` ou o `OR-Tools` permitem escrever as restrições de forma legível.

## Muitos problemas são PL disfarçados

- **Fluxo máximo** e **caminho mais curto** escrevem-se como PL.
- **Afetação** de tarefas a pessoas (cada pessoa uma tarefa, custo mínimo).
- **Dieta:** a mistura de alimentos mais barata que cumpre os mínimos nutricionais (foi um dos primeiros usos, nos anos 40).
- **Transporte:** que armazém abastece que loja, ao menor custo.
