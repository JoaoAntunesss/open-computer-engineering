SQL é diferente de todas as outras: não dizes **como** fazer, dizes **o que** queres, e a base de dados decide como o ir buscar. É a linguagem de todas as bases de dados relacionais (PostgreSQL, MySQL, SQLite, Oracle) e uma das mais pedidas em empregos.

## O mesmo programa em SQL

Imagina uma tabela `medicoes` com uma coluna `valor`:

```sql
SELECT COALESCE(AVG(valor), 0) AS media_positivos
FROM medicoes
WHERE valor > 0;
```

Não há ciclos nem variáveis. Lê-se quase como uma frase: "seleciona a média do valor, das medições, onde o valor é maior que zero". `COALESCE(x, 0)` devolve 0 quando não há nenhuma linha (porque nesse caso `AVG` dá `NULL`).

## Como se lê uma query

Lê-se **pela ordem em que a base de dados a executa**, que não é a ordem em que se escreve:

1. `FROM` (e `JOIN`): de que tabelas vêm os dados.
2. `WHERE`: que linhas ficam.
3. `GROUP BY`: como se agrupam.
4. `HAVING`: que grupos ficam.
5. `SELECT`: que colunas se mostram.
6. `ORDER BY`: por que ordem.

```sql
SELECT c.cidade, COUNT(*) AS clientes, SUM(e.total) AS faturado
FROM clientes c
JOIN encomendas e ON e.cliente_id = c.id
WHERE e.estado = 'paga'
GROUP BY c.cidade
HAVING SUM(e.total) > 1000
ORDER BY faturado DESC;
```

Pela ordem: junta clientes com as suas encomendas, fica só com as pagas, agrupa por cidade, fica com as cidades que faturaram mais de 1000 €, mostra cidade, número e total, da maior para a menor.

## NULL: o "não sei"

`NULL` não é zero nem texto vazio: quer dizer "sem valor". Qualquer comparação com `NULL` dá "desconhecido", por isso `WHERE telefone = NULL` nunca encontra nada. Usa-se `IS NULL` e `IS NOT NULL`. `COUNT(coluna)` ignora os `NULL`; `COUNT(*)` conta todas as linhas.

## Armadilhas

- Juntar dados do utilizador ao texto da query: **injeção de SQL** (vê a cadeira Programar com IA sem Perder o Controlo).
- `JOIN` em vez de `LEFT JOIN`: perdes as linhas sem correspondência (clientes sem encomendas, por exemplo).
- Contar linhas repetidas depois de um `JOIN` em vez de `COUNT(DISTINCT ...)`.
- Usar `WHERE` com `COUNT`/`SUM` em vez de `HAVING`.

## Exercício

Com uma tabela `bilhetes(id, evento_id, cliente_id, preco)`, escreve uma query que mostre, para cada evento, quantos clientes **diferentes** compraram bilhete, só para eventos com pelo menos 3 clientes diferentes.

??? Solução
```sql
SELECT evento_id, COUNT(DISTINCT cliente_id) AS clientes
FROM bilhetes
GROUP BY evento_id
HAVING COUNT(DISTINCT cliente_id) >= 3
ORDER BY clientes DESC;
```
O `DISTINCT` é essencial: um cliente com 4 bilhetes conta uma vez.
