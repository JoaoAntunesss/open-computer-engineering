Vais passar mais tempo a perceber porque é que o código não funciona do que a escrevê-lo. A diferença entre um principiante e um programador experiente não é errar menos: é encontrar o erro mais depressa, com método em vez de tentativas ao acaso.

## Ler a mensagem de erro (a sério)

A maior parte dos erros diz-te exatamente o que está mal. Um exemplo em Python:

```text
Traceback (most recent call last):
  File "notas.py", line 12, in <module>
    print(media(notas))
  File "notas.py", line 4, in media
    return sum(valores) / len(valores)
ZeroDivisionError: division by zero
```

Lê-se **de baixo para cima**:

1. A última linha diz o tipo de erro e a causa: divisão por zero.
2. A linha anterior diz onde aconteceu: linha 4, na função `media`.
3. Subindo, vês quem chamou essa função: a linha 12.

A pergunta seguinte não é "como faço para o erro desaparecer", é "**porque é que `valores` estava vazio na linha 4?**".

Em C, o compilador avisa-te antes de correres:

```text
main.c:7:12: warning: variable 'total' is uninitialized when used here
```

Ficheiro, linha, coluna e o problema. Compila sempre com `-Wall -Wextra`: os avisos são erros que ainda não aconteceram.

## O método

1. **Reproduz o erro** de forma fiável. Se não consegues fazê-lo acontecer de propósito, não consegues confirmar que o corrigiste.
2. **Reduz o caso**: corta código e dados até ficares com o exemplo mais pequeno que ainda falha. Muitas vezes, a meio desta redução, o erro torna-se óbvio.
3. **Forma uma hipótese** concreta: "acho que `ler_ficheiro` devolve uma lista vazia quando o ficheiro tem uma linha em branco no fim".
4. **Testa a hipótese** olhando para o estado do programa (prints, depurador). Não mudes código ao acaso para "ver se resolve".
5. **Corrige a causa**, não o sintoma. Pôr um `if len(valores) == 0: return 0` esconde o problema se a lista nunca devia estar vazia.
6. **Escreve um teste** que falhava antes da correção, para o erro não voltar.

## Prints com intenção

O `print` é um depurador legítimo, desde que mostres o que precisas:

```python
print(f"DEBUG media: valores={valores!r} len={len(valores)}")
```

O `!r` mostra a representação exata: vês a diferença entre `'7'` (texto) e `7` (número), ou espaços escondidos como `'7\n'`.

## O depurador

O depurador para o programa numa linha à tua escolha e deixa-te ver todas as variáveis, avançar linha a linha e entrar nas funções.

**No VS Code**: clica à esquerda do número da linha para criar um *breakpoint* (aparece um ponto vermelho) e carrega em `F5`.

- `F10` avança uma linha (sem entrar nas funções);
- `F11` entra na função chamada nessa linha;
- `Shift+F11` termina a função atual e volta a quem a chamou;
- o painel **Variables** mostra tudo o que existe nesse momento.

**Em Python, no terminal**: escreve `breakpoint()` na linha onde queres parar e corre o programa normalmente. Abre-se o `pdb`:

```text
(Pdb) p valores        mostra uma variável
(Pdb) n                próxima linha
(Pdb) s                entra na função
(Pdb) c                continua até ao próximo breakpoint
(Pdb) q                sai
```

**Em C**, compila com `-g` e usa o `gdb`:

```bash
gcc -g -Wall main.c -o main
gdb ./main
(gdb) break media
(gdb) run
(gdb) print n
(gdb) next
(gdb) backtrace        # quem chamou quem, até aqui
```

Quando um programa em C rebenta com *Segmentation fault*, corre-o no `gdb` e escreve `backtrace`: ficas a saber em que linha foi.

## Explicar o problema em voz alta

Explicar o código linha a linha a outra pessoa, ou a um patinho de borracha em cima da secretária, obriga-te a dizer o que cada linha faz em vez do que achas que faz. É surpreendente quantas vezes o erro aparece a meio da explicação.

## Pedir ajuda bem

Quando precisares de ajuda (num fórum, a um professor), leva:

- o que estavas a tentar fazer;
- o código mínimo que reproduz o problema;
- a mensagem de erro completa, copiada e não resumida;
- o que já tentaste.

## Erros comuns

- Ler só a última linha do erro e ignorar onde aconteceu.
- Mudar várias coisas ao mesmo tempo: se passa a funcionar, não sabes o que resolveu.
- Ignorar os avisos do compilador.
- Corrigir o sintoma (`try: ... except: pass`) e deixar a causa.

## Exercícios

O programa seguinte devia mostrar a média das notas positivas, mas rebenta. Encontra o erro com o depurador, sem adivinhar.

```python
def ler_notas(texto):
    return [int(x) for x in texto.split(",")]

def media_positivas(notas):
    positivas = [n for n in notas if n > 10]
    return sum(positivas) / len(positivas)

print(media_positivas(ler_notas("8,9,10,9")))
```

1. Qual é o erro e em que linha acontece?
2. Qual é a causa (não o sintoma)?
3. Corrige-o e escreve um teste que o apanhe.

??? Soluções
1: `ZeroDivisionError` na linha do `return` de `media_positivas`.

2: ao parar nessa linha, `positivas` é `[]`. Há duas causas possíveis e convém perguntar qual é a regra: uma nota de 10 é positiva? Na escala portuguesa, sim (aprovado com 10). A condição devia ser `n >= 10`. Mesmo corrigida, uma turma sem nenhuma positiva continua a dar divisão por zero, por isso é preciso decidir o que devolver nesse caso.

3:
```python
def media_positivas(notas):
    positivas = [n for n in notas if n >= 10]
    if not positivas:
        return None          # não há média de uma lista vazia
    return sum(positivas) / len(positivas)

def test_media_positivas():
    assert media_positivas([8, 9, 10, 9]) == 10
    assert media_positivas([5, 6]) is None
```
Repara que o `if not positivas` não esconde o erro: torna explícito um caso que existe na vida real.
