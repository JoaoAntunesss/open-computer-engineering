Vais passar milhares de horas a escrever código. Investir algumas horas a dominar o editor paga-se depressa. Esta lição cobre dois: o **VS Code**, que vais usar no dia a dia, e o **Vim**, que vais encontrar em qualquer servidor e em qualquer `git commit` sem configuração.

## VS Code

Instala-o a partir de code.visualstudio.com. Se usas WSL, instala também a extensão **WSL** e abre as pastas com `code .` a partir do terminal do Ubuntu.

### O essencial

- **Abrir uma pasta, não ficheiros soltos**: `code .` no terminal. O VS Code passa a conhecer o projeto todo (pesquisa, Git, depuração).
- **Paleta de comandos**: `Ctrl+Shift+P` (`Cmd+Shift+P` no Mac). Tudo o que o editor faz está aqui; escreve parte do nome.
- **Abrir ficheiro pelo nome**: `Ctrl+P`, escreve parte do nome e Enter.
- **Terminal integrado**: ``Ctrl+` ``.
- **Pesquisar em todo o projeto**: `Ctrl+Shift+F`.

### Atalhos que poupam horas

| Ação | Windows/Linux | macOS |
|---|---|---|
| Ir para a definição | `F12` | `F12` |
| Mudar o nome de um símbolo em todo o lado | `F2` | `F2` |
| Comentar a linha | `Ctrl+/` | `Cmd+/` |
| Mover a linha | `Alt+↑/↓` | `Option+↑/↓` |
| Duplicar a linha | `Shift+Alt+↓` | `Shift+Option+↓` |
| Selecionar a próxima ocorrência | `Ctrl+D` | `Cmd+D` |
| Vários cursores | `Alt+clique` | `Option+clique` |
| Formatar o ficheiro | `Shift+Alt+F` | `Shift+Option+F` |

O `Ctrl+D` repetido seleciona a palavra seguinte igual, e passas a escrever em todas ao mesmo tempo. É a forma mais rápida de mudar o nome de uma variável dentro de uma função.

### Extensões que valem a pena

- **Python** (Microsoft) e **Pylance**: completar, erros enquanto escreves, depurador.
- **C/C++** (Microsoft) ou **clangd** para C.
- **GitLens**: mostra quem mudou cada linha e quando.
- **Error Lens**: põe as mensagens de erro na própria linha.

Instala só as extensões de que precisas. Cada uma torna o editor mais lento e mais confuso.

### Formatar ao guardar

Abre as definições (`Ctrl+,`), procura *format on save* e ativa. Com um formatador (Black para Python, clang-format para C), nunca mais discutes espaços e alinhamentos.

## Vim

O Vim abre em quase qualquer máquina Linux, incluindo servidores sem interface gráfica. Mesmo que não o uses como editor principal, tens de saber sair dele e fazer pequenas edições.

### Modos

A ideia que confunde toda a gente: o Vim tem **modos**.

- **Normal** (o modo em que abre): as teclas são comandos, não texto.
- **Inserção**: escreves texto normalmente. Entras com `i` e sais com `Esc`.
- **Linha de comandos**: começa por `:`, para guardar, sair, pesquisar e substituir.

### Sobreviver

```text
vim notas.txt     abrir
i                 começar a escrever
Esc               voltar ao modo normal
:w                guardar
:q                sair
:wq               guardar e sair
:q!               sair sem guardar
```

### Ser rápido

No modo normal, os comandos combinam-se como uma pequena linguagem: **verbo + movimento**.

```text
h j k l      esquerda, baixo, cima, direita
w  b         palavra seguinte / anterior
0  $         início / fim da linha
gg  G        início / fim do ficheiro
dd           apagar a linha        yy   copiar a linha     p   colar
dw           apagar até à palavra seguinte
ci"          mudar o texto dentro das aspas
u            desfazer              Ctrl+r   refazer
/palavra     pesquisar (n para a próxima)
:%s/velho/novo/g   substituir em todo o ficheiro
.            repetir o último comando
```

`d` (apagar), `c` (mudar) e `y` (copiar) combinam com qualquer movimento: `d$` apaga até ao fim da linha, `c3w` muda as três palavras seguintes. Quando percebes a gramática, deixas de decorar atalhos.

Para treinar, corre `vimtutor` no terminal. Demora 30 minutos e é o melhor tutorial que existe. Se gostares, a extensão **Vim** para o VS Code dá-te estes comandos dentro do VS Code.

## Erros comuns

- Ficar preso no Vim depois de um `git commit`: `Esc`, depois `:wq` para guardar a mensagem, ou `:q!` para cancelar.
- Abrir ficheiros soltos no VS Code em vez da pasta do projeto: perdes a pesquisa global e o Git.
- Instalar dezenas de extensões e o editor ficar lento.

3. Num ficheiro com 20 linhas `x = 1`, usa vários cursores (ou `Ctrl+D`) para as transformar em `y = 1` de uma só vez.
