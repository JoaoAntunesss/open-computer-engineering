Os prints obrigam-te a adivinhar onde os pôr e a correr tudo outra vez. O **depurador** (*debugger*) deixa-te parar o programa numa linha à tua escolha e ver **todas** as variáveis nesse momento, avançando uma linha de cada vez. É a ferramenta que separa quem tenta à sorte de quem investiga.

## Os conceitos

| Conceito | O que faz |
|---|---|
| **Ponto de paragem** (*breakpoint*) | O programa para antes de correr essa linha |
| **Step over** (F10) | Corre a linha atual e para na seguinte |
| **Step into** (F11) | Se a linha chama uma função, entra nela |
| **Step out** (Shift+F11) | Acaba a função atual e para em quem a chamou |
| **Continue** (F5) | Corre até ao próximo ponto de paragem |
| **Variables / Watch** | Mostra os valores atuais (podes acrescentar expressões) |
| **Call stack** | Mostra que função chamou que função até aqui |

## No VS Code, com Python

1. Abre o ficheiro `.py`.
2. Clica à esquerda do número de uma linha: aparece um ponto vermelho (o ponto de paragem).
3. Carrega em **F5** e escolhe "Python File".
4. O programa para nessa linha. À esquerda vês as variáveis.
5. Usa F10 para avançar linha a linha e observa os valores a mudar.

## Sem instalar nada: o Python Tutor

O site [pythontutor.com](https://pythontutor.com/) mostra o mesmo, desenhado: cada variável numa caixa, as listas com setas, e um botão para avançar e recuar. É excelente para ciclos e listas. Experimenta lá este programa:

```python run
def inverte(lista):
    resultado = []
    for x in lista:
        resultado.insert(0, x)
    return resultado

print(inverte([1, 2, 3, 4]))
```

## Também dá para usar no código: breakpoint()

Em Python podes escrever `breakpoint()` numa linha. Ao correr no terminal, o programa para aí e abre o `pdb`, o depurador de texto:

```python
def total(carrinho):
    soma = 0
    for item in carrinho:
        breakpoint()          # para aqui em cada volta
        soma += item["preco"] * item["qtd"]
    return soma
```

Comandos do `pdb`: `n` (próxima linha), `s` (entrar na função), `p soma` (mostrar valor), `c` (continuar), `q` (sair). Não funciona nas caixas desta página, só no teu terminal.

## No browser: DevTools

Para JavaScript dos teus sites: F12 → separador **Sources** → abre o ficheiro → clica no número da linha. Também podes escrever `debugger;` no código: com as DevTools abertas, o browser para aí. É assim que se investiga porque é que um botão não faz nada ou um formulário envia os dados errados.

## Pontos de paragem condicionais

Num ciclo com 10 000 voltas, não queres parar em todas. Clica com o botão direito no ponto de paragem → "Edit Breakpoint" → escreve uma condição, por exemplo `item["preco"] < 0`. O programa só para quando a condição for verdadeira, ou seja, exatamente quando aparece o dado estranho.

## Exercício (no VS Code ou no Python Tutor)

Este programa devia encontrar o produto mais caro, mas devolve o errado. Põe um ponto de paragem dentro do ciclo, observa `mais_caro` em cada volta e descobre o bug sem adivinhar.

```python run
produtos = [("caneta", 1.5), ("mochila", 25.0), ("caderno", 3.2), ("estojo", 8.0)]

def mais_caro(lista):
    melhor = lista[0]
    for nome, preco in lista:
        if preco > melhor[1]:
            melhor = (nome, preco)
        else:
            melhor = melhor
    return nome

print(mais_caro(produtos))   # esperado: mochila
```

??? Solução
A variável `melhor` está sempre certa (chega a `("mochila", 25.0)`), mas a função devolve `nome`, que é a variável do ciclo e fica com o último nome da lista, `"estojo"`. Corrige com `return melhor[0]`. A linha `else: melhor = melhor` não faz nada e pode sair. Repara que, a ler à pressa, os dois parecem "quase iguais": o depurador mostra a diferença sem margem para dúvidas.
