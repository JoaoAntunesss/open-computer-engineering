O Git funciona no teu computador. O **GitHub** guarda uma cópia do repositório na internet e acrescenta o que é preciso para trabalhar em equipa: pull requests, revisões de código, issues e automação. É também o teu portefólio: muitas empresas olham para o GitHub de um candidato antes de olharem para o currículo.

## Ligar o repositório local ao GitHub

Cria um repositório vazio em github.com (botão **New**) e depois, no teu projeto:

```bash
git remote add origin git@github.com:o-teu-utilizador/projeto.git
git push -u origin main      # envia o main e passa a segui-lo
```

Daí em diante:

```bash
git push          # envia os teus commits
git pull          # traz os commits dos outros e junta-os
git clone URL     # copia um repositório existente para o teu computador
```

Para te autenticares, o mais simples é uma **chave SSH** (vê a lição de SSH) ou a ferramenta oficial `gh auth login`. O GitHub já não aceita a palavra-passe da conta no terminal.

## O fluxo de trabalho com pull requests

Em equipa, ninguém faz `push` diretamente para o `main`. O fluxo é este:

1. Crias um ramo: `git switch -c corrige-media`.
2. Fazes commits e envias o ramo: `git push -u origin corrige-media`.
3. No GitHub, abres um **pull request** (PR): um pedido para juntar o teu ramo ao `main`.
4. Os colegas leem as alterações, comentam linhas concretas e pedem mudanças.
5. Fazes mais commits no mesmo ramo; o PR atualiza-se sozinho.
6. Quando está aprovado e os testes passam, alguém faz o merge.

### Um bom pull request

- Faz **uma coisa**. Um PR com 2000 linhas não é revisto a sério, é aprovado às cegas.
- O título diz o que muda; a descrição diz porquê e como testar.
- Liga-o à issue que resolve escrevendo `Closes #12` na descrição. Quando o PR entra, a issue fecha-se sozinha.

### Rever código dos outros

Rever não é encontrar defeitos para mostrar que se leu. Procura erros de lógica, casos que não estão tratados, nomes confusos e testes em falta. Faz perguntas em vez de dar ordens ("o que acontece se a lista estiver vazia?") e distingue o que é obrigatório do que é gosto pessoal.

## Issues

Uma **issue** regista um problema ou uma tarefa: um erro encontrado, uma funcionalidade a fazer, uma dúvida. Uma boa issue sobre um erro diz:

- o que fizeste (os passos para reproduzir);
- o que esperavas que acontecesse;
- o que aconteceu (mensagem de erro, captura de ecrã);
- a versão e o sistema.

Usa **labels** (`bug`, `melhoria`) e o separador **Projects** para organizar o trabalho de um grupo num quadro Kanban.

## O README

O `README.md` é a primeira coisa que alguém vê no repositório. Deve responder a quatro perguntas:

```markdown
# Gestor de Horários

Gera o horário semanal de uma turma a partir das disciplinas e salas disponíveis.

## Instalar
    pip install -r requirements.txt

## Usar
    python horario.py dados/turma.json

## Testes
    pytest
```

O que é, como se instala, como se usa e como se testa. Uma captura de ecrã vale mais do que três parágrafos.

## GitHub Actions: testes automáticos

Uma *action* corre comandos nos servidores do GitHub sempre que alguém faz push ou abre um PR. O caso mais comum é correr os testes. Cria `.github/workflows/testes.yml`:

```yaml
name: Testes
on: [push, pull_request]
jobs:
  testes:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: pytest
```

A partir daí, cada PR mostra um visto verde ou uma cruz vermelha. Ninguém tem de se lembrar de correr os testes.

## GitHub Pages

Um repositório com HTML pode ser publicado como site em **Settings → Pages**. Fica em `https://utilizador.github.io/repositorio/`. É assim que este próprio site é publicado.

## Erros comuns

- `git push` rejeitado com *"Updates were rejected"*: alguém enviou commits que não tens. Faz `git pull` primeiro.
- Fazer commit de chaves de API num repositório público. Bots varrem o GitHub e usam-nas em minutos. Se acontecer, revoga a chave imediatamente; apagá-la do código não chega.
- PRs gigantes que ninguém consegue rever.
