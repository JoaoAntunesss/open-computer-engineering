Num projeto real, o bug pode estar em qualquer uma de centenas de linhas. Ler tudo não é opção. Duas técnicas resolvem isto: **reproduzir** o problema de forma fiável e **cortar ao meio** até encontrar o culpado.

## 1. Reproduzir

Antes de mexer em código, consegue fazer o erro acontecer **de propósito**. Escreve os passos exatos:

1. Abre o formulário de marcação.
2. Escolhe o dia 31.
3. Carrega em Marcar.
4. Esperado: marcação criada. Obtido: erro 500.

Se não consegues reproduzir, não consegues confirmar que corrigiste. "Às vezes falha" quase sempre quer dizer "falha com certos dados": procura o que esses casos têm em comum (um dia 31? um nome com acento? uma lista vazia?).

## 2. O exemplo mínimo

Corta tudo o que não é preciso para o erro aparecer, até ficarem poucas linhas. Isto muitas vezes revela o bug sozinho, e é o que deves mandar quando pedes ajuda (a colegas, num fórum ou à IA).

```python run
from datetime import date

def proximo_mes(d):
    return date(d.year, d.month + 1, d.day)

print(proximo_mes(date(2026, 1, 15)))
print(proximo_mes(date(2026, 1, 31)))
```

Num sistema de marcações com 2000 linhas, o "erro 500 no dia 31" reduz-se a isto: não existe 31 de fevereiro. (E em dezembro, `month + 1` dá 13.)

## 3. Cortar ao meio (bisseção)

Se o programa faz 8 passos e o resultado final está errado, verifica o valor a **meio** (depois do passo 4). Se aí já está errado, o bug está nos passos 1 a 4; se está certo, está nos 5 a 8. Repete. Com 8 passos chegas lá em 3 verificações; com 1000 linhas, em cerca de 10.

```python run
def limpar(txt): return txt.strip()
def minusculas(txt): return txt.lower()
def tirar_acentos(txt):
    trocas = {"á": "a", "à": "a", "ã": "a", "é": "e", "ê": "e", "í": "i", "ó": "o", "õ": "o", "ú": "u", "ç": "c"}
    return "".join(trocas.get(c, c) for c in txt)
def espacos_para_hifen(txt): return txt.replace(" ", "-")
def so_letras(txt): return "".join(c for c in txt if c.isalnum() or c == "-")

def slug(titulo):
    t = limpar(titulo)
    t = so_letras(t)
    t = minusculas(t)
    t = tirar_acentos(t)
    t = espacos_para_hifen(t)
    return t

print(slug("  Café da Manhã em Lisboa "))   # esperado: cafe-da-manha-em-lisboa
```

Põe um `print(t)` a meio (depois do 3.º passo) e vê se já está errado. Depois corta outra vez.

## Bisseção no tempo: git bisect

Se "ontem funcionava e hoje não", o mesmo método aplica-se aos commits. O `git bisect` vai-te mostrando commits a meio do caminho e tu dizes "bom" ou "mau":

```text
git bisect start
git bisect bad               # o commit atual tem o bug
git bisect good a1b2c3d      # este commit antigo funcionava
# o Git muda para um commit a meio; testas e respondes:
git bisect good   # ou: git bisect bad
# ... repetes até o Git dizer qual foi o primeiro commit mau
git bisect reset
```

## O pato de borracha

Explicar o código em voz alta, linha a linha, a alguém (ou a um pato de borracha na secretária) força-te a dizer o que cada linha **faz**, e não o que achas que faz. Muitas vezes o bug aparece a meio da frase. Explicar à IA sem lhe pedir a solução funciona da mesma forma.
