Quase tudo o que vais fazer neste curso — compilar C, correr testes, usar o Git, ligar-te a um servidor — faz-se num terminal. Uma interface gráfica mostra-te os botões que alguém decidiu criar; o terminal dá-te acesso direto ao sistema, e cada comando pode ser combinado com outros, guardado num script e repetido mil vezes.

## O que é o terminal

O **terminal** é a janela onde escreves texto. Dentro dele corre uma **shell**: o programa que lê o que escreves, interpreta-o e executa os comandos. No Linux a shell mais comum é o `bash`; no macOS é o `zsh`. Para o que vamos fazer, comportam-se da mesma forma.

No Windows, instala o **WSL** (Windows Subsystem for Linux) com `wsl --install` numa PowerShell de administrador. Ficas com um Ubuntu completo dentro do Windows, que é o ambiente que a maioria das cadeiras assume.

Quando abres o terminal vês uma linha como esta, chamada *prompt*:

```text
joao@portatil:~/projetos$
```

Diz-te o utilizador (`joao`), a máquina (`portatil`) e a pasta onde estás (`~/projetos`). O `~` é uma abreviatura da tua pasta pessoal, por exemplo `/home/joao`.

## Onde estou e o que há aqui

```bash
pwd                 # mostra a pasta atual (print working directory)
ls                  # lista o que está na pasta
ls -l               # lista em formato longo: permissões, dono, tamanho, data
ls -la              # inclui ficheiros escondidos (os que começam por ".")
```

Os sistemas Unix organizam tudo numa única árvore que começa em `/`, a **raiz**. Um caminho pode ser:

- **absoluto**, se começa em `/`: `/home/joao/projetos/site/index.html`
- **relativo**, se parte da pasta atual: `site/index.html`

Há dois nomes especiais em todas as pastas: `.` é a própria pasta e `..` é a pasta de cima.

```bash
cd projetos         # entra na pasta projetos (caminho relativo)
cd ..               # sobe um nível
cd ~                # vai para a pasta pessoal (também basta "cd")
cd -                # volta à pasta onde estavas antes
```

> Carrega em **Tab** a meio de um nome e a shell completa-o. Carrega duas vezes para ver as opções. Escrever caminhos inteiros à mão é lento e dá erros.

## Criar, copiar, mover e apagar

```bash
mkdir relatorios              # cria uma pasta
mkdir -p a/b/c                # cria a pasta e as pastas intermédias
touch notas.txt               # cria um ficheiro vazio (ou atualiza a data)
cp notas.txt copia.txt        # copia um ficheiro
cp -r relatorios backup       # copia uma pasta inteira (-r = recursivo)
mv copia.txt relatorios/      # move (também serve para mudar o nome)
rm notas.txt                  # apaga um ficheiro
rm -r backup                  # apaga uma pasta e tudo o que tem dentro
```

O `rm` **não manda para o lixo**: o ficheiro desaparece. Antes de usares `rm -r` com caminhos que escreveste à pressa, corre primeiro `ls` com o mesmo caminho para veres o que vais apagar.

## Ver o conteúdo de ficheiros

```bash
cat notas.txt          # mostra o ficheiro todo
less registo.log       # mostra página a página (q para sair, / para pesquisar)
head -n 20 dados.csv   # primeiras 20 linhas
tail -n 20 dados.csv   # últimas 20 linhas
tail -f servidor.log   # fica a mostrar as linhas novas à medida que aparecem
wc -l dados.csv        # conta linhas
```

## Procurar

```bash
find . -name "*.py"            # todos os ficheiros .py a partir daqui
grep "TODO" main.c             # linhas de main.c que contêm TODO
grep -rn "malloc" src/         # procura em toda a pasta, com número de linha
```

## Permissões

Corre `ls -l` e repara na primeira coluna:

```text
-rwxr-xr--  1 joao alunos  812 out 12 10:03 backup.sh
```

Os dez caracteres lêem-se assim: o primeiro diz o tipo (`-` ficheiro, `d` pasta). Depois vêm três grupos de três, para o **dono**, o **grupo** e **os outros**. Em cada grupo, `r` é ler, `w` é escrever e `x` é executar (numa pasta, `x` significa poder entrar nela).

Aqui o dono pode tudo, o grupo pode ler e executar, e os outros só podem ler.

```bash
chmod +x backup.sh     # torna o script executável
chmod 600 chave.txt    # só o dono pode ler e escrever
```

A forma numérica soma `r=4`, `w=2`, `x=1` para cada grupo: `755` é `rwxr-xr-x`, `644` é `rw-r--r--`, `600` é `rw-------`.

Alguns comandos precisam de privilégios de administrador. Para isso existe o `sudo`:

```bash
sudo apt install tree    # instala um programa no Ubuntu
```

Usa `sudo` só quando o comando o exige. Correr tudo como administrador é a forma mais rápida de estragar o sistema.

## Pedir ajuda ao próprio sistema

```bash
man ls          # manual completo do comando (q para sair)
ls --help       # resumo das opções
```

## Erros comuns

- **"No such file or directory"**: o caminho está errado ou não estás na pasta que pensas. Corre `pwd` e `ls`.
- **Espaços em nomes de ficheiros**: `cd Os meus documentos` falha porque a shell vê três palavras. Usa aspas, `cd "Os meus documentos"`, ou evita espaços nos nomes.
- **"Permission denied" ao correr um script**: falta a permissão de execução. Corre `chmod +x script.sh`.
- **Apagar com `rm -r *` na pasta errada**: confirma sempre com `pwd` primeiro.

## Exercícios

1. Cria a estrutura `curso/ano1/{prog,mat}` com um só comando e confirma com `ls -R curso`.
2. Na tua pasta pessoal, encontra todos os ficheiros `.pdf` e conta quantos são.
3. Cria um ficheiro `segredo.txt` que só tu consigas ler e escrever. Confirma com `ls -l`.

??? Soluções
```bash
# 1
mkdir -p curso/ano1/{prog,mat}
ls -R curso

# 2
find ~ -name "*.pdf" | wc -l

# 3
touch segredo.txt
chmod 600 segredo.txt
ls -l segredo.txt     # -rw------- ...
```
O `{prog,mat}` é *brace expansion*: a shell transforma-o em `curso/ano1/prog curso/ano1/mat` antes de chamar o `mkdir`. No exercício 2, o `|` envia a lista de ficheiros para o `wc -l`, que conta as linhas; vais ver isto em detalhe na próxima lição.
