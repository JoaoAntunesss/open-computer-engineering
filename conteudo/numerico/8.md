Muitos problemas são "encontra os parâmetros que tornam este valor o menor possível": o erro de um modelo, o custo de uma rota, o consumo de energia, a forma de uma peça. Quando a função não é linear, o simplex não serve. A **otimização não linear** usa a informação local (o declive, a curvatura) para descer até um mínimo. A pergunta difícil é: esse mínimo é o melhor de todos, ou só o melhor ali perto? A **convexidade** responde.

## Descida do gradiente

O **gradiente** ∇f aponta na direção em que f cresce mais depressa. Para descer, dá-se um passo no sentido contrário:

xₖ₊₁ = xₖ − α · ∇f(xₖ)

α é a **taxa de aprendizagem** (o tamanho do passo): pequena demais, demora uma eternidade; grande demais, salta por cima do mínimo e diverge. É o algoritmo que treina as redes neuronais (com variantes: com momento, Adam).

```python run
def descida(grad, x, alfa, passos=60):
    hist = [x]
    for _ in range(passos):
        x = [xi - alfa * gi for xi, gi in zip(x, grad(x))]
        hist.append(x)
    return hist

# f(x, y) = (x - 3)^2 + 10 (y + 1)^2 : um vale alongado, mínimo em (3, -1)
f = lambda p: (p[0] - 3) ** 2 + 10 * (p[1] + 1) ** 2
grad = lambda p: [2 * (p[0] - 3), 20 * (p[1] + 1)]

for alfa in (0.01, 0.05, 0.09, 0.11):
    h = descida(grad, [0.0, 0.0], alfa)
    fim = h[-1]
    print(f"α = {alfa:4}: depois de 60 passos ({fim[0]:9.4g}, {fim[1]:9.4g}), f = {f(fim):.3g}")
```

Prevê o comportamento para cada α. Num vale alongado (a curvatura em y é 10 vezes maior do que em x), α tem de ser pequeno por causa do y, e então o x avança devagar: é o **mau condicionamento** a aparecer outra vez.

## Newton para otimização

Usa também a **segunda derivada** (a matriz **Hessiana**, a curvatura): salta diretamente para o mínimo da aproximação quadrática.

xₖ₊₁ = xₖ − H⁻¹ ∇f(xₖ)

Converge muito depressa (quadraticamente), e num vale quadrático como o de cima chega ao mínimo **num passo**. Mas calcular e resolver com a Hessiana é caro em dimensão alta. Os métodos **quase-Newton** (BFGS, L-BFGS) aproximam-na com os gradientes: são a escolha por omissão em `scipy.optimize.minimize`.

## Mínimos locais e convexidade

Uma função é **convexa** se o segmento entre quaisquer dois pontos do gráfico fica por cima do gráfico (forma de taça). Para funções convexas:

- **todo o mínimo local é global**;
- a descida do gradiente (com α adequado) encontra-o.

Exemplos convexos: x², |x|, eˣ, as funções de erro da regressão linear e logística, a programação linear. Não convexas: as funções de erro das redes neuronais, a maior parte dos problemas de engenharia reais. Nelas, o resultado depende do ponto de partida.

```python run
import math
f = lambda x: x ** 4 - 3 * x ** 2 + x          # dois vales
df = lambda x: 4 * x ** 3 - 6 * x + 1
for inicio in (-2.0, 0.0, 0.5, 2.0):
    x = inicio
    for _ in range(200):
        x -= 0.01 * df(x)
    print(f"partida {inicio:5}: mínimo em x = {x:.4f}, f = {f(x):.4f}")
```

Prevê para que vale vai cada partida. Só um dos dois é o mínimo global. Estratégias: várias partidas aleatórias, *simulated annealing*, algoritmos genéticos; nenhuma dá garantias.

## Restrições

Minimizar com restrições (por exemplo, x + y = 10, ou x ≥ 0) usa **multiplicadores de Lagrange** (as condições KKT generalizam a ideia) ou métodos de **penalização** (somar ao objetivo um termo que cresce quando se viola a restrição). Na prática: `scipy.optimize.minimize` com `constraints`, ou, para problemas convexos, o **CVXPY**, onde escreves o problema quase como na matemática.
