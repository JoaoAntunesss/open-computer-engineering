Um computador não guarda números reais: guarda aproximações com um número fixo de bits. Quase sempre isso não se nota; às vezes dá resultados absurdos. Perceber a representação em **vírgula flutuante** (norma IEEE 754) explica porque é que `0.1 + 0.2 != 0.3`, porque não se guarda dinheiro em `float`, e como evitar que os erros cresçam.

## A representação

Um número em vírgula flutuante é ± mantissa × 2^expoente, como a notação científica mas em binário. Em **precisão dupla** (o `float` do Python, o `double` do C e do Java), 64 bits:

- 1 bit de sinal;
- 11 bits de expoente (de cerca de 10⁻³⁰⁸ a 10³⁰⁸);
- 52 bits de mantissa: cerca de **15 a 16 algarismos significativos**.

Valores especiais: `inf`, `-inf`, `nan` (*not a number*: `0/0`, `inf - inf`), e o zero com sinal.

## Nem tudo é representável

0,1 em binário é uma dízima infinita (0,000110011001100…), tal como 1/3 em decimal. Guarda-se o número representável mais próximo. Os erros pequenos acumulam-se:

```python run
print(0.1 + 0.2, 0.1 + 0.2 == 0.3)
print(f"{0.1:.20f}")

import math, sys
print("épsilon da máquina:", sys.float_info.epsilon)
print("1 + eps/2 == 1?", 1.0 + sys.float_info.epsilon / 2 == 1.0)

print(math.isclose(0.1 + 0.2, 0.3))             # comparar com tolerância
print(2 ** 53, float(2 ** 53) + 1 == float(2 ** 53))   # inteiros grandes deixam de caber

from decimal import Decimal
print(Decimal("0.10") + Decimal("0.20"))       # aritmética decimal exata
total = 0.0
for _ in range(10):
    total += 0.1
print(total, math.fsum([0.1] * 10))
```

Prevê cada linha antes de correr.

## Erros

- **Erro absoluto:** |x̃ − x|. **Erro relativo:** |x̃ − x| / |x|. Em vírgula flutuante, cada operação tem erro relativo de no máximo ε/2 ≈ 1,1 × 10⁻¹⁶ (o **épsilon da máquina**).
- **Cancelamento catastrófico:** subtrair dois números quase iguais perde quase todos os algarismos significativos. `1.0000001 - 1.0000000` dá um resultado com só uns 8 algarismos certos.
- **Absorção:** somar um número muito pequeno a um muito grande perde o pequeno (`1e16 + 1 == 1e16`).
- **Acumulação:** somar milhões de valores acumula erros. O `math.fsum` e a soma de Kahan compensam.

## Exemplo: a fórmula resolvente

Para ax² + bx + c = 0 com b² muito maior do que 4ac, a fórmula clássica (−b + √(b² − 4ac))/(2a) subtrai dois números quase iguais. Uma forma equivalente, sem cancelamento:

```python run
import math

def raizes_ingenuas(a, b, c):
    d = math.sqrt(b * b - 4 * a * c)
    return (-b + d) / (2 * a), (-b - d) / (2 * a)

def raizes_estaveis(a, b, c):
    d = math.sqrt(b * b - 4 * a * c)
    q = -0.5 * (b + math.copysign(d, b))
    return c / q, q / a

a, b, c = 1.0, 1e8, 1.0          # raízes verdadeiras: ≈ -1e-8 e ≈ -1e8
print("ingénua:", raizes_ingenuas(a, b, c))
print("estável:", raizes_estaveis(a, b, c))
```

A raiz pequena (≈ −10⁻⁸) sai completamente errada na fórmula ingénua. Um algoritmo é **numericamente estável** quando não amplifica os erros de arredondamento.

## Condicionamento

Alguns problemas são sensíveis por natureza, independentemente do algoritmo: um pequeno erro nos dados dá um grande erro no resultado. O **número de condição** mede isso. Um sistema linear com matriz mal condicionada (lição 3) perde muitos algarismos mesmo com o melhor algoritmo.

## Regras práticas

- Nunca comparar `float` com `==`: usar uma tolerância (`math.isclose`, `numpy.allclose`).
- Dinheiro: inteiros em cêntimos, ou `Decimal`.
- Evitar subtrair números quase iguais; reorganizar a fórmula.
- Somar do mais pequeno para o maior, ou usar `fsum`.
- Usar precisão dupla, salvo razões fortes (em GPUs e redes neuronais usa-se precisão simples ou meia, de propósito, pela velocidade).
