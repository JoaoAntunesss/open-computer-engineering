Um **compilador** traduz um programa numa linguagem (a de origem) para outra (a de destino), mantendo o significado. O GCC traduz C para código máquina; o `javac`, Java para bytecode; o TypeScript, TypeScript para JavaScript; o Babel, JavaScript moderno para JavaScript antigo. Perceber como funciona explica as mensagens de erro, as otimizações e as diferenças entre linguagens. Nesta cadeira vais construir, passo a passo, um compilador para uma linguagem pequena.

## As fases

```
código-fonte  "x = 2 + 3 * y"
     │  análise léxica          → tokens: ID(x) = NUM(2) + NUM(3) * ID(y)
     │  análise sintática       → árvore sintática
     │  análise semântica       → tipos verificados, nomes resolvidos
     │  geração de código intermédio → t1 = 3 * y ; t2 = 2 + t1 ; x = t2
     │  otimização              → (por exemplo, se y for constante, calcular já)
     │  geração de código final → instruções da máquina
     ▼
programa executável
```

- **Front-end** (dependente da linguagem de origem): léxico, sintaxe, semântica. Produz uma representação intermédia.
- **Back-end** (dependente da máquina): otimiza e gera código.

Esta divisão permite reutilizar: o **LLVM** tem um back-end para x86, ARM, RISC-V, WebAssembly…; Clang (C/C++), Rust, Swift e Zig só precisam de escrever o front-end.

## Compiladores, interpretadores e o meio-termo

- **Compilador:** traduz tudo antes de correr (C, Rust, Go). Execução rápida.
- **Interpretador:** executa o programa diretamente, instrução a instrução (Bash, os primeiros BASIC).
- **Bytecode + máquina virtual:** compila para uma linguagem intermédia simples, que uma VM executa (Python, Java, C#). Portável.
- **JIT** (*just-in-time*): a VM compila para código máquina as partes que correm muitas vezes, durante a execução (JVM, V8 do JavaScript, PyPy). Junta a portabilidade com a velocidade.

O Python mostra o seu bytecode:

```python run
import dis

def media(a, b):
    return (a + b) / 2

dis.dis(media)
```

Prevê, antes de correr, quantas instruções tem e por que ordem: carregar `a`, carregar `b`, somar, carregar 2, dividir, devolver. É uma máquina de pilha (lição 9).

## Erros em cada fase

| Fase | Exemplo de erro |
|---|---|
| Léxica | carácter inválido: `x = 3 @ 4` em C |
| Sintática | `if (x > 3 {` (falta o parêntese) |
| Semântica | `int x = "olá";`, variável não declarada |
| Execução (não é do compilador) | divisão por zero, índice fora do vetor |

Quanto mais cedo uma linguagem deteta os erros, menos chegam a produção: é o argumento a favor dos tipos estáticos.

## Ferramentas

- **Flex/Bison** (C), **ANTLR** (Java, Python, JavaScript…): geram analisadores a partir de gramáticas.
- **LLVM:** a infraestrutura de back-end mais usada.
- **Compiler Explorer** (godbolt.org): vê o código gerado por dezenas de compiladores, em tempo real.
