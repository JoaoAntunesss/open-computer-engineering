Um compilador otimizador transforma o programa noutro **equivalente** (dá sempre os mesmos resultados) mas mais rápido ou mais pequeno. A palavra "otimização" engana: o resultado raramente é ótimo, só melhor. Com `-O2`, o GCC e o Clang aplicam dezenas de transformações; perceber as principais ajuda a escrever código que o compilador consegue melhorar, e a não perder tempo com micro-otimizações que ele já faz.

## Otimizações locais (dentro de um bloco)

- **Dobragem de constantes:** `x = 60 * 60 * 24` → `x = 86400`.
- **Propagação de constantes e de cópias:** depois de `a = 5; b = a;`, os usos de `b` passam a `5`.
- **Eliminação de subexpressões comuns:** `(a + b) * (a + b)` calcula `a + b` uma vez.
- **Simplificações algébricas e redução de força:** `x * 1` → `x`; `x * 8` → `x << 3`; `x / 4` (sem sinal) → `x >> 2`.
- **Eliminação de código morto:** atribuições cujo resultado nunca é usado desaparecem.

## Um otimizador para código de três endereços

```python run
def otimiza(codigo):
    const = {}                                 # variável -> valor constante conhecido
    novo = []
    for dest, op, a, b in codigo:
        a, b = const.get(a, a), const.get(b, b)          # propagação de constantes
        if isinstance(a, int) and isinstance(b, int) and op in "+-*":
            v = {"+": a + b, "-": a - b, "*": a * b}[op]  # dobragem
            const[dest] = v
            novo.append((dest, "=", v, None))
            continue
        if op == "*" and b == 1: op, b = "=", None           # x * 1 → x
        if op == "*" and b == 0: const[dest] = 0; novo.append((dest, "=", 0, None)); continue
        if op == "*" and isinstance(b, int) and b > 0 and b & (b - 1) == 0:
            op, b = "<<", b.bit_length() - 1             # redução de força: * 2^k → << k
        if op == "=" and isinstance(a, int):
            const[dest] = a
        else:
            const.pop(dest, None)
        novo.append((dest, op, a, b))

    # eliminação de código morto: de trás para a frente, só fica o que é usado
    usadas, final = {"resultado"}, []
    for dest, op, a, b in reversed(novo):
        if dest in usadas:
            final.append((dest, op, a, b))
            usadas.discard(dest)
            usadas |= {x for x in (a, b) if isinstance(x, str)}
    return final[::-1]

def mostra(c):
    for d, op, a, b in c:
        print(f"  {d} = {a}" if op == "=" else f"  {d} = {a} {op} {b}")

codigo = [
    ("segundos_dia", "*", 60, 60), ("segundos_dia", "*", "segundos_dia", 24),
    ("t1", "*", "dias", "segundos_dia"),
    ("t2", "*", "t1", 1),
    ("t3", "*", "horas", 8),
    ("lixo", "+", "t3", 99),
    ("resultado", "+", "t2", "t3"),
]
print("antes:"); mostra(codigo)
print("depois:"); mostra(otimiza(codigo))
```

## Otimizações de ciclos

Os programas passam a maior parte do tempo em ciclos, por isso é aí que vale a pena:

- **Mover código invariante para fora:** `for (i…) a[i] = x * y + i;` → calcula `x * y` uma vez antes do ciclo.
- **Redução de força em variáveis de indução:** `a[i * 4]` com `i++` → um apontador que avança 4.
- **Desenrolar** (*unrolling*): fazer 4 iterações por volta, para menos saltos e mais paralelismo.
- **Vetorização:** usar instruções SIMD (Arquitetura, lição 9).

## Otimizações entre funções

- **Embutir** (*inlining*): substituir a chamada pelo corpo da função. Elimina o custo da chamada e, sobretudo, permite otimizar o corpo com os argumentos concretos.
- **Otimização em tempo de ligação** (LTO): otimizar o programa inteiro, através de vários ficheiros.
- **Otimização guiada por perfil** (PGO): compilar, correr com dados reais, e recompilar sabendo que ramos são mais usados.

## O que impede otimizações

- **Aliasing:** se dois apontadores podem apontar para a mesma memória, o compilador não pode reordenar acessos. Em C, `restrict` promete que não.
- **Efeitos secundários:** uma chamada a uma função desconhecida pode mudar qualquer variável global.
- **Comportamento indefinido** em C/C++: o compilador assume que nunca acontece, e às vezes o resultado surpreende (ciclos com overflow de inteiros com sinal que deixam de terminar, verificações de `NULL` apagadas).
