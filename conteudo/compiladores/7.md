A última fase transforma a representação intermédia em instruções da máquina real. Três problemas: **seleção de instruções** (que instruções da máquina usar para cada operação), **alocação de registos** (que valores ficam nos poucos registos e quais vão para a memória) e **escalonamento** (por que ordem, para aproveitar o pipeline).

## Seleção de instruções

Cada instrução da IR corresponde a uma ou mais instruções da máquina, mas muitas vezes há escolhas melhores:

| IR | RISC-V ingénuo | melhor |
|---|---|---|
| `t = x * 8` | `li t1, 8; mul t0, a0, t1` | `slli t0, a0, 3` |
| `t = v[i]` (int) | `slli t1, a1, 2; add t1, a0, t1; lw t0, 0(t1)` | o mesmo, mas num ciclo pode usar um apontador que avança |
| `t = x + 0` | `addi t0, a0, 0` | nada (reutilizar `a0`) |

Os geradores modernos descrevem as instruções da máquina como **padrões** de pequenas árvores e cobrem a árvore da IR com os padrões mais baratos.

## Alocação de registos

O RISC-V tem 32 registos, mas o programa tem centenas de temporários. É preciso decidir quais ficam em registos ao mesmo tempo.

1. **Análise de vida (liveness):** uma variável está **viva** num ponto se o seu valor ainda vai ser lido mais à frente.
2. **Grafo de interferência:** um nó por variável; uma aresta entre duas variáveis vivas ao mesmo tempo (não podem partilhar o registo).
3. **Coloração:** dar a cada nó um registo (uma "cor") diferente dos vizinhos. Com k registos, é colorir o grafo com k cores (NP-completo em geral, mas as heurísticas funcionam muito bem).
4. Se não houver cores suficientes, uma variável vai para a **memória** (*spill*): é guardada na pilha e carregada quando é precisa. Escolhe-se a que é menos usada (de preferência fora dos ciclos).

```python run
# código de três endereços de um bloco básico
codigo = [
    ("a", ["x", "y"]),        # a = x + y
    ("b", ["a", "x"]),        # b = a * x
    ("c", ["y", "y"]),        # c = y * y
    ("d", ["b", "c"]),        # d = b + c
    ("e", ["d", "a"]),        # e = d * a
    ("f", ["e", "c"]),        # f = e - c
]
vivas_no_fim = {"f"}

# 1. análise de vida, de trás para a frente
vivas = set(vivas_no_fim)
vida = []
for dest, usos in reversed(codigo):
    vivas.discard(dest)
    vivas |= set(usos)
    vida.append(set(vivas))
vida.reverse()                      # vida[i] = vivas imediatamente antes da instrução i

# 2. grafo de interferência: definido em i interfere com o que está vivo depois de i
interf = {v: set() for v in {"x", "y"} | {d for d, _ in codigo}}
for i, (dest, _) in enumerate(codigo):
    depois = vida[i + 1] if i + 1 < len(codigo) else vivas_no_fim
    for v in depois - {dest}:
        interf[dest].add(v); interf[v].add(dest)
for v in ("x", "y"):                # entradas vivas juntas no início
    for w in vida[0] - {v}:
        interf[v].add(w)

# 3. coloração gananciosa com k registos (os mais ligados primeiro)
def colorir(k):
    regs = {}
    for v in sorted(interf, key=lambda v: -len(interf[v])):
        livres = [r for r in range(k) if all(regs.get(w) != r for w in interf[v])]
        regs[v] = livres[0] if livres else None          # None: vai para a pilha
    return {v: (f"t{r}" if r is not None else "PILHA") for v, r in sorted(regs.items())}

for i, (d, u) in enumerate(codigo):
    print(f"{d} = f({', '.join(u)})   vivas antes: {sorted(vida[i])}")
print("interferências:", {v: sorted(s) for v, s in sorted(interf.items())})
print("com 3 registos:", colorir(3))
print("com 2 registos:", colorir(2))
```

Prevê: qual é o número máximo de variáveis vivas ao mesmo tempo? Isso diz quantos registos bastam sem *spills*.

## Convenções de chamada e quadros de pilha

O gerador também produz o código de entrada e saída de cada função (prólogo e epílogo): reservar o quadro de pilha, guardar `ra` e os registos `s*` usados, repor tudo no fim (Arquitetura de Computadores, lição 2). Os registos `t*`, que podem ser estragados por chamadas, são preferidos para valores que não sobrevivem a uma chamada; os `s*`, para os que sobrevivem.

## Escalonamento de instruções

O pipeline para quando uma instrução usa o resultado de um `lw` logo a seguir. O compilador **reordena** instruções independentes para preencher esses buracos, sem mudar o resultado. Os processadores fora de ordem fazem parte disto sozinhos, mas nos processadores simples (embebidos) o compilador tem de o fazer.
