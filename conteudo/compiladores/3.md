A **análise sintática** recebe os tokens e verifica se formam um programa válido segundo a **gramática** da linguagem, construindo a sua estrutura em árvore. Há duas grandes famílias de analisadores: **descendentes** (LL), que partem da raiz e tentam prever as regras, e **ascendentes** (LR), que partem dos tokens e os juntam em regras maiores.

## A gramática de Mini

```
programa  → instrucao*
instrucao → ID "=" expr ";"
          | "se" "(" expr ")" bloco ("senao" bloco)?
          | "enquanto" "(" expr ")" bloco
          | "escreve" expr ";"
bloco     → "{" instrucao* "}"
expr      → soma (("<" | "<=" | ">" | ">=" | "==" | "!=") soma)?
soma      → termo (("+" | "-") termo)*
termo     → fator (("*" | "/") fator)*
fator     → NUM | ID | "(" expr ")" | "-" fator
```

A precedência está na própria gramática: `termo` está "abaixo" de `soma`, por isso `*` liga mais do que `+`.

## Análise descendente (LL) por descida recursiva

Uma função por regra. Olha para o próximo token (um token de "espreitadela", daí **LL(1)**) para decidir qual alternativa seguir. É como se escrevem à mão os analisadores do GCC, do Clang, do Go e do TypeScript.

```python run
import re

def lexer(c):
    for m in re.finditer(r"\s*(?:(\d+)|(se|senao|enquanto|escreve)\b|([A-Za-z_]\w*)|(<=|>=|==|!=|[-+*/<>=(){};]))", c):
        n, r, i, o = m.groups()
        yield ("NUM", int(n)) if n else (r, r) if r else ("ID", i) if i else (o, o)
    yield ("FIM", None)

class Parser:
    def __init__(self, codigo):
        self.ts, self.i = list(lexer(codigo)), 0
    def ver(self): return self.ts[self.i][0]
    def come(self, tipo):
        t = self.ts[self.i]
        if t[0] != tipo:
            raise SyntaxError(f"esperava {tipo!r}, encontrei {t[1]!r} (token {self.i})")
        self.i += 1
        return t[1]

    def programa(self):
        corpo = []
        while self.ver() != "FIM":
            corpo.append(self.instrucao())
        return ("programa", corpo)
    def bloco(self):
        self.come("{"); corpo = []
        while self.ver() != "}":
            corpo.append(self.instrucao())
        self.come("}")
        return corpo
    def instrucao(self):
        t = self.ver()
        if t == "se":
            self.come("se"); self.come("("); c = self.expr(); self.come(")")
            entao = self.bloco(); senao = []
            if self.ver() == "senao":
                self.come("senao"); senao = self.bloco()
            return ("se", c, entao, senao)
        if t == "enquanto":
            self.come("enquanto"); self.come("("); c = self.expr(); self.come(")")
            return ("enquanto", c, self.bloco())
        if t == "escreve":
            self.come("escreve"); e = self.expr(); self.come(";")
            return ("escreve", e)
        nome = self.come("ID"); self.come("="); e = self.expr(); self.come(";")
        return ("atribui", nome, e)
    def expr(self):
        e = self.soma()
        if self.ver() in ("<", "<=", ">", ">=", "==", "!="):
            op = self.come(self.ver()); e = ("bin", op, e, self.soma())
        return e
    def soma(self):
        e = self.termo()
        while self.ver() in ("+", "-"):
            op = self.come(self.ver()); e = ("bin", op, e, self.termo())
        return e
    def termo(self):
        e = self.fator()
        while self.ver() in ("*", "/"):
            op = self.come(self.ver()); e = ("bin", op, e, self.fator())
        return e
    def fator(self):
        t = self.ver()
        if t == "NUM": return ("num", self.come("NUM"))
        if t == "ID": return ("var", self.come("ID"))
        if t == "-": self.come("-"); return ("neg", self.fator())
        self.come("("); e = self.expr(); self.come(")")
        return e

print(Parser("x = 2 + 3 * y;").programa())
print(Parser("se (x > 0) { escreve x; } senao { escreve 0 - x; }").programa())
for erro in ["x = (2 + 3;", "enquanto x < 3 { }"]:
    try:
        Parser(erro).programa()
    except SyntaxError as e:
        print("erro:", e)
```

Prevê a árvore da primeira linha: o `*` fica mais fundo do que o `+`.

## Limites do LL

- **Recursão à esquerda** (`soma → soma "+" termo`) põe a função a chamar-se a si própria para sempre; reescreve-se com repetição (como acima).
- Duas alternativas que começam pelo mesmo token obrigam a **fatorizar** a gramática, ou a espreitar mais tokens (LL(k)).

## Análise ascendente (LR)

Lê os tokens da esquerda para a direita, empilha-os (*shift*) e, quando o topo da pilha forma o lado direito de uma regra, substitui-o pelo lado esquerdo (*reduce*). Uma tabela, gerada a partir da gramática, diz quando fazer cada coisa.

```
pilha              entrada        ação
                   2 + 3 * 4      shift
NUM                + 3 * 4        reduce fator → NUM, termo → fator, soma → termo
soma               + 3 * 4        shift
soma +             3 * 4          shift
soma + NUM         * 4            reduce até termo
soma + termo       * 4            shift  (porque * tem prioridade: não reduz ainda)
soma + termo *     4              shift
soma + termo * NUM                reduce termo → termo * fator
soma + termo                      reduce soma → soma + termo
soma                              aceita
```

Os analisadores LR (LALR, como os gerados pelo **Bison** e pelo **yacc**) aceitam mais gramáticas do que os LL, incluindo a recursão à esquerda. O **ANTLR** gera analisadores LL(*) que espreitam quantos tokens forem precisos.

## Mensagens de erro

Um bom analisador diz **onde** e **o que** esperava, e tenta **recuperar** (saltar até ao próximo `;` ou `}`) para mostrar vários erros de uma vez. Muitas das mensagens úteis dos compiladores modernos (Rust, Elm) vêm daqui.
