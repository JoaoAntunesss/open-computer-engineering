A análise sintática pode produzir uma **árvore de derivação** com todos os pormenores da gramática (parênteses, pontos e vírgulas, cada nível de precedência). Para o resto do compilador, interessa uma versão mais limpa: a **árvore sintática abstrata** (AST), que guarda só a estrutura com significado. Quase todas as ferramentas que trabalham com código usam ASTs: compiladores, linters, formatadores (Prettier, Black), editores (renomear uma variável), ferramentas de refatoração e de segurança.

## Árvore de derivação contra AST

Para `(2 + 3) * x`:

```
derivação (concreta)                AST
expr                                  *
└ soma                               / \
  └ termo                           +   x
    ├ fator                        / \
    │ ├ "("                       2   3
    │ ├ expr … (2 + 3)
    │ └ ")"
    ├ "*"
    └ fator → ID(x)
```

Os parênteses desaparecem na AST: a estrutura da árvore já diz que a soma é feita primeiro.

## Representar a AST

Com classes (ou *records*, ou tipos algébricos em Haskell e Rust), um tipo por nó:

```python
from dataclasses import dataclass

@dataclass
class Num:   valor: float
@dataclass
class Var:   nome: str
@dataclass
class Bin:   op: str; esq: object; dir: object
@dataclass
class Atribui: nome: str; expr: object
@dataclass
class Se:    cond: object; entao: list; senao: list
```

Cada nó guarda também a **posição** no código (linha e coluna), para as mensagens de erro.

## Percorrer a AST

Quase tudo no compilador é uma função que percorre a árvore recursivamente: avaliar, verificar tipos, gerar código, imprimir. Em linguagens com objetos, usa-se muitas vezes o padrão **Visitor** (POO, lição 7); em Python moderno, `match`.

O próprio Python dá a AST de qualquer programa, através do módulo `ast`. Prevê o que cada função encontra:

```python run
import ast

codigo = """
def preco(servico, cliente_fiel):
    total = servico["preco"]
    if cliente_fiel and total > 50:
        total = total * 0.9
    print("preço calculado")
    return total

x = preco({"preco": 60}, True)
print(x)
"""
arvore = ast.parse(codigo)

# 1. imprimir a estrutura de uma expressão
print(ast.dump(ast.parse("total * 0.9", mode="eval").body))

# 2. que funções são chamadas, e em que linhas?
for no in ast.walk(arvore):
    if isinstance(no, ast.Call) and isinstance(no.func, ast.Name):
        print("chamada a", no.func.id, "na linha", no.lineno)

# 3. transformar: trocar todos os print(...) por pass (como um "remover logs")
class TiraPrints(ast.NodeTransformer):
    def visit_Expr(self, no):
        if isinstance(no.value, ast.Call) and getattr(no.value.func, "id", "") == "print":
            return ast.Pass()
        return no

nova = ast.fix_missing_locations(TiraPrints().visit(arvore))
print(ast.unparse(nova))
```

É assim que funcionam ferramentas como o `black`, o `ruff` e o `pylint`: leem o código para uma AST, analisam-na ou transformam-na, e voltam a escrever o código.

## Avaliar diretamente a AST

Um **interpretador por árvore** é só uma função recursiva. Para as expressões de Mini:

```python
def avalia(no, ambiente):
    match no:
        case ("num", v): return v
        case ("var", n): return ambiente[n]
        case ("neg", e): return -avalia(e, ambiente)
        case ("bin", "+", a, b): return avalia(a, ambiente) + avalia(b, ambiente)
        case ("bin", "*", a, b): return avalia(a, ambiente) * avalia(b, ambiente)
        # …
```

Simples e fácil de escrever, mas lento (muitas chamadas de funções por cada operação). Linguagens a sério compilam a AST para bytecode (lição 9).
