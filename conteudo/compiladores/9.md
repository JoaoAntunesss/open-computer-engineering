Nem todas as linguagens são compiladas para código máquina. Python, Java, C#, Lua, Ruby e JavaScript são executadas por **máquinas virtuais**: programas que simulam um processador simples, com o seu próprio conjunto de instruções (o **bytecode**). É mais portável e mais fácil de fazer do que gerar código para cada processador real, e com **JIT** pode chegar perto da mesma velocidade.

## Três formas de executar

1. **Interpretador por árvore:** percorre a AST e avalia cada nó (lição 4). Simples, lento.
2. **Compilar para bytecode e interpretar:** a AST é traduzida para instruções compactas; um ciclo lê e executa cada instrução. Mais rápido (menos chamadas, melhor uso da cache). É o CPython e a JVM no arranque.
3. **JIT:** a VM mede que funções e ciclos são "quentes" e compila-os para código máquina, com otimizações baseadas nos tipos que realmente aparecem (V8, HotSpot, PyPy, LuaJIT).

## Uma máquina de pilha

A maioria das VMs (JVM, CPython, WebAssembly, .NET) são **máquinas de pilha**: as instruções tiram os operandos do topo da pilha e põem lá o resultado. Não é preciso alocar registos, e o bytecode fica pequeno.

`2 + 3 * x` vira:

```
PUSH 2
PUSH 3
LOAD x
MUL         ; tira 3 e x, põe 3*x
ADD         ; tira 2 e 3*x, põe a soma
```

## Um compilador e uma VM para Mini

```python run
def compila(no, codigo):
    match no:
        case ("num", v): codigo.append(("PUSH", v))
        case ("var", n): codigo.append(("LOAD", n))
        case ("bin", op, a, b):
            compila(a, codigo); compila(b, codigo); codigo.append((op, None))
        case ("atribui", n, e):
            compila(e, codigo); codigo.append(("STORE", n))
        case ("escreve", e):
            compila(e, codigo); codigo.append(("PRINT", None))
        case ("enquanto", c, corpo):
            inicio = len(codigo)
            compila(c, codigo)
            salto = len(codigo); codigo.append(("JFALSE", None))     # destino preenchido depois
            for i in corpo: compila(i, codigo)
            codigo.append(("JUMP", inicio))
            codigo[salto] = ("JFALSE", len(codigo))
    return codigo

def executa(codigo):
    pilha, vars_, pc, passos = [], {}, 0, 0
    ops = {"+": lambda a, b: a + b, "-": lambda a, b: a - b, "*": lambda a, b: a * b,
           "<": lambda a, b: a < b, "<=": lambda a, b: a <= b}
    while pc < len(codigo):
        instr, arg = codigo[pc]; pc += 1; passos += 1
        if instr == "PUSH": pilha.append(arg)
        elif instr == "LOAD": pilha.append(vars_[arg])
        elif instr == "STORE": vars_[arg] = pilha.pop()
        elif instr == "PRINT": print(pilha.pop())
        elif instr == "JUMP": pc = arg
        elif instr == "JFALSE":
            if not pilha.pop(): pc = arg
        else:
            b, a = pilha.pop(), pilha.pop(); pilha.append(ops[instr](a, b))
    return passos

# fatorial de 6
programa = [
    ("atribui", "n", ("num", 6)), ("atribui", "f", ("num", 1)),
    ("enquanto", ("bin", "<", ("num", 1), ("var", "n")), [
        ("atribui", "f", ("bin", "*", ("var", "f"), ("var", "n"))),
        ("atribui", "n", ("bin", "-", ("var", "n"), ("num", 1))),
    ]),
    ("escreve", ("var", "f")),
]
codigo = []
for i in programa: compila(i, codigo)
for k, (op, arg) in enumerate(codigo):
    print(f"{k:2} {op:7} {'' if arg is None else arg}")
print("instruções executadas:", executa(codigo))
```

Prevê o valor que o programa escreve e quantas instruções de bytecode tem. Repara no truque do `JFALSE`: o destino ainda não é conhecido quando se escreve a instrução, por isso preenche-se depois (*backpatching*).

## Porque é que o bytecode do Python é "lento"

Cada `+` no CPython tem de descobrir, em tempo de execução, os tipos dos operandos (int? float? str? um objeto com `__add__`?), e cada inteiro é um objeto na memória. Um JIT observa que, naquele ciclo, os operandos são sempre inteiros pequenos, e gera código máquina que soma diretamente, com uma verificação: se um dia aparecer outro tipo, volta ao modo lento (**desotimização**). É assim que o JavaScript no V8 chega a velocidades próximas de C em código numérico. O CPython 3.13 introduziu um JIT experimental.

## WebAssembly

Um bytecode de máquina de pilha, desenhado para o browser: seguro (corre isolado), compacto e rápido de compilar para código máquina. C, C++, Rust e Go compilam para WebAssembly. É assim que o **Pyodide** consegue correr Python, e estes exemplos, dentro do teu browser.
