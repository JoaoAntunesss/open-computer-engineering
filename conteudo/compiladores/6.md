Entre a AST (próxima da linguagem de origem) e o código máquina (próximo do hardware), os compiladores usam uma ou mais **representações intermédias** (IR). Uma boa IR é simples, explícita e independente da máquina: é sobre ela que se fazem as otimizações. O **LLVM IR**, o **bytecode da JVM** e o **GIMPLE** do GCC são exemplos.

## Código de três endereços

Cada instrução tem no máximo um operador e três "endereços" (dois operandos e um destino), com **temporários** para os resultados intermédios:

```
x = a + b * (c - 1)

t1 = c - 1
t2 = b * t1
t3 = a + t2
x  = t3
```

O controlo de fluxo vira **saltos** com **rótulos**:

```
enquanto (i < 10) { s = s + i; i = i + 1; }

L1: t1 = i < 10
    se_falso t1 vai L2
    s = s + i
    i = i + 1
    vai L1
L2:
```

## Gerar código de três endereços a partir da AST

```python run
contador = {"t": 0, "L": 0}
def novo(p):
    contador[p] += 1
    return f"{p}{contador[p]}"

codigo = []
def expr(e):
    match e:
        case ("num", v): return str(v)
        case ("var", n): return n
        case ("bin", op, a, b):
            x, y = expr(a), expr(b)
            t = novo("t")
            codigo.append(f"    {t} = {x} {op} {y}")
            return t

def instr(i):
    match i:
        case ("atribui", n, e):
            codigo.append(f"    {n} = {expr(e)}")
        case ("enquanto", c, corpo):
            inicio, fim = novo("L"), novo("L")
            codigo.append(f"{inicio}:")
            codigo.append(f"    se_falso {expr(c)} vai {fim}")
            for x in corpo: instr(x)
            codigo.append(f"    vai {inicio}")
            codigo.append(f"{fim}:")
        case ("se", c, entao, senao):
            l_senao, l_fim = novo("L"), novo("L")
            codigo.append(f"    se_falso {expr(c)} vai {l_senao}")
            for x in entao: instr(x)
            codigo.append(f"    vai {l_fim}")
            codigo.append(f"{l_senao}:")
            for x in senao: instr(x)
            codigo.append(f"{l_fim}:")

programa = [
    ("atribui", "s", ("num", 0)),
    ("atribui", "i", ("num", 1)),
    ("enquanto", ("bin", "<=", ("var", "i"), ("num", 10)), [
        ("se", ("bin", "==", ("bin", "%", ("var", "i"), ("num", 2)), ("num", 0)),
         [("atribui", "s", ("bin", "+", ("var", "s"), ("bin", "*", ("var", "i"), ("var", "i"))))],
         []),
        ("atribui", "i", ("bin", "+", ("var", "i"), ("num", 1))),
    ]),
]
for i in programa: instr(i)
print("\n".join(codigo))
```

Prevê quantos temporários e rótulos são criados. O programa soma os quadrados dos números pares até 10.

## Grafo de fluxo de controlo

O código divide-se em **blocos básicos**: sequências sem saltos para dentro (exceto no início) nem para fora (exceto no fim). Os blocos ligam-se num **grafo de fluxo de controlo** (CFG). É sobre o CFG que se fazem as análises: que variáveis estão vivas, que definições chegam a cada ponto, que código nunca é alcançado.

## SSA: cada variável é atribuída uma só vez

Na forma **SSA** (*static single assignment*), cada variável é atribuída exatamente uma vez; quando é reatribuída, ganha um nome novo (`i1`, `i2`…). Onde caminhos se juntam, uma função **φ** escolhe o valor conforme o caminho:

```
i1 = 1
L1: i2 = φ(i1, i3)      ; i1 se viemos do início, i3 se viemos do fim do ciclo
    t1 = i2 <= 10
    ...
    i3 = i2 + 1
    vai L1
```

A SSA torna muitas otimizações simples (cada uso tem uma única definição). O LLVM, o GCC, o V8 e a JVM usam-na.

## LLVM IR

```llvm
define i32 @quadrado_soma(i32 %a, i32 %b) {
entrada:
  %s = add i32 %a, %b
  %q = mul i32 %s, %s
  ret i32 %q
}
```

Tipado, em SSA, com infinitos registos virtuais. Vê o IR de um programa C com `clang -S -emit-llvm -O1 programa.c`, ou no Compiler Explorer.
