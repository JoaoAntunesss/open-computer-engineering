Um compilador é um programa que lê programas. Ler o código de um analisador (lexer, parser, avaliador) obriga-te a pensar em dois níveis ao mesmo tempo: o texto de entrada e a estrutura que o programa constrói a partir dele.

## Ler e prever: um avaliador de expressões

```python run
import re

def tokens(texto):
    return re.findall(r"\d+|[+*()-]", texto)

def expr(ts):
    v = termo(ts)
    while ts and ts[0] in "+-":
        op = ts.pop(0)
        v = v + termo(ts) if op == "+" else v - termo(ts)
    return v

def termo(ts):
    v = fator(ts)
    while ts and ts[0] == "*":
        ts.pop(0)
        v = v * fator(ts)
    return v

def fator(ts):
    t = ts.pop(0)
    if t == "(":
        v = expr(ts)
        ts.pop(0)          # ")"
        return v
    return int(t)

for e in ["2+3*4", "(2+3)*4", "10-4-3", "2*(3+4)*5"]:
    print(e, "=", expr(tokens(e)))
```

Antes de correr: que valores esperas? Porque é que o `*` fica "mais forte" do que o `+` só pela forma como as funções se chamam umas às outras?

## Encontra o erro: subtração à direita

Uma versão anterior do `expr` era assim:

```python
def expr(ts):
    v = termo(ts)
    if ts and ts[0] in "+-":
        op = ts.pop(0)
        resto = expr(ts)
        return v + resto if op == "+" else v - resto
    return v
```

Calcula à mão `10-4-3` com esta versão. Dá o mesmo que a versão com o ciclo?
