A **análise léxica** é a primeira fase: lê o texto carácter a carácter e agrupa-o em **tokens** (palavras com significado): palavras reservadas, identificadores, números, operadores, pontuação. Também descarta espaços e comentários. É exatamente a aplicação das expressões regulares e dos autómatos finitos de Teoria da Computação.

## Tokens, lexemas e padrões

| Token | Lexemas (exemplos) | Padrão |
|---|---|---|
| `NUM` | `42`, `3.14` | `\d+(\.\d+)?` |
| `ID` | `total`, `x1` | `[A-Za-z_]\w*` |
| `SE` (palavra reservada) | `se` | `se` |
| `OP` | `+`, `<=`, `==` | `<=|>=|==|!=|[-+*/<>=]` |
| `(`, `)`, `{`, `}`, `;` | | |

Duas regras resolvem as ambiguidades:

1. **Maior correspondência** (*maximal munch*): `<=` é um token, não `<` seguido de `=`; `contador` é um identificador, não `conta` + `dor`.
2. **Prioridade:** se dois padrões casam com o mesmo comprimento, ganha o que vem primeiro. Por isso as palavras reservadas vêm antes do padrão de identificador (`se` é `SE`, não `ID`).

## Um analisador léxico completo

A linguagem desta cadeira, **Mini**, tem números, variáveis, `se`/`senao`, `enquanto`, `escreve` e as operações habituais.

```python run
import re

ESPEC = [
    ("NUM",      r"\d+(?:\.\d+)?"),
    ("RESERV",   r"\b(?:se|senao|enquanto|escreve)\b"),
    ("ID",       r"[A-Za-z_]\w*"),
    ("OP",       r"<=|>=|==|!=|[-+*/<>=]"),
    ("PONT",     r"[(){};]"),
    ("COMENT",   r"#[^\n]*"),
    ("ESPACO",   r"[ \t]+"),
    ("LINHA",    r"\n"),
    ("ERRO",     r"."),
]
REGEX = re.compile("|".join(f"(?P<{n}>{p})" for n, p in ESPEC))

def lexer(codigo):
    linha, inicio_linha = 1, 0
    for m in REGEX.finditer(codigo):
        tipo, valor = m.lastgroup, m.group()
        coluna = m.start() - inicio_linha + 1
        if tipo == "LINHA":
            linha, inicio_linha = linha + 1, m.end()
        elif tipo in ("ESPACO", "COMENT"):
            continue
        elif tipo == "ERRO":
            raise SyntaxError(f"carácter inesperado {valor!r} na linha {linha}, coluna {coluna}")
        else:
            yield (tipo, valor, linha, coluna)

programa = """total = 0
i = 1   # contador
enquanto (i <= 10) {
    total = total + i * 2;
    i = i + 1;
}
escreve total;"""

for t in lexer(programa):
    print(t)
```

Prevê os primeiros tokens. Depois experimenta acrescentar `x = 3 @ 4;` ao programa e vê a mensagem de erro, com a linha e a coluna.

## Por dentro: um autómato

Um gerador como o **Flex** transforma todas as expressões regulares num único autómato finito determinista (lições 1 e 2 de Teoria) e gera código C que o percorre: muito rápido, cada carácter é lido uma vez.

```c
/* mini.l — excerto para o Flex */
%%
[0-9]+(\.[0-9]+)?      { return NUM; }
"se"                   { return SE; }
"enquanto"             { return ENQUANTO; }
[A-Za-z_][A-Za-z0-9_]* { yylval.nome = strdup(yytext); return ID; }
"<="                   { return MENOR_IGUAL; }
[-+*/<>=(){};]         { return yytext[0]; }
#.*                    { /* comentário: ignora */ }
[ \t\n]+               { /* espaços: ignora */ }
.                      { erro("carácter inválido"); }
%%
```

## Casos difíceis

- **Strings** com aspas escapadas (`"diz \"olá\""`) e comentários de várias linhas: precisam de estados no analisador.
- **Indentação significativa** (Python): o analisador gera tokens `INDENT` e `DEDENT` comparando a indentação de cada linha com uma pilha.
- **Números:** `1.`, `.5`, `1e-3`, `0x1F`, `1_000_000`.
- Linguagens em que o léxico depende da sintaxe: em C++, `>>` em `vector<vector<int>>` é dois `>`.
