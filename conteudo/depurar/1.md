Quando um programa rebenta, o Python diz-te exatamente **o que** correu mal e **onde**. A maioria das pessoas que usa IA nunca lê essa mensagem: copia tudo e cola no chat. Funciona às vezes, mas não aprendes nada e, em programas grandes, a IA não vê o resto do código. Ler o erro é o primeiro passo de qualquer depuração.

## Anatomia de um traceback

```python run
def media(valores):
    return sum(valores) / len(valores)

def relatorio(turmas):
    for nome, notas in turmas.items():
        print(nome, media(notas))

relatorio({"A": [12, 14], "B": []})
```

O erro (o *traceback*) lê-se **de baixo para cima**:

1. **A última linha** diz o tipo de erro e a mensagem: `ZeroDivisionError: division by zero`. Dividiste por zero.
2. **A linha logo acima** diz onde rebentou: dentro de `media`, na linha do `return`.
3. **Mais acima** está o caminho até lá: `relatorio` chamou `media`, que foi chamada pela última linha do ficheiro.

Agora junta as peças: a turma `B` não tem notas, `len([])` é 0, e dividir por 0 rebenta. O erro não está bem na linha do `return`: está em não pensares no caso de uma turma vazia.

## Três perguntas sempre

1. **Que tipo de erro é?** (a última linha)
2. **Em que linha do meu código?** (o ponto mais baixo que seja código teu, não de uma biblioteca)
3. **Que valores tinham as variáveis nesse momento?** (isto já não vem na mensagem, tens de descobrir)

A terceira pergunta é a que resolve o problema. As próximas lições ensinam-te a responder-lhe.

## Corrigir

```python run
def media(valores):
    if not valores:
        return None
    return sum(valores) / len(valores)

def relatorio(turmas):
    for nome, notas in turmas.items():
        m = media(notas)
        print(nome, "sem notas" if m is None else round(m, 1))

relatorio({"A": [12, 14], "B": []})
```

Repara que a correção não foi "pôr um `try/except` à volta de tudo para o erro desaparecer". Isso esconde o problema. Corrigir é decidir o que **deve** acontecer quando a lista está vazia.

## Erros dentro de bibliotecas

Muitas vezes o traceback tem 30 linhas de código de bibliotecas (pandas, requests, Django…). Procura, de baixo para cima, a **primeira linha que é de um ficheiro teu**: quase sempre o problema está aí, no que passaste à biblioteca.

## Quando pedires ajuda (a pessoas ou à IA)

Inclui sempre: a mensagem de erro completa, o código da função onde rebentou, o que esperavas que acontecesse e o que já tentaste. "Não funciona" não ajuda ninguém.

## Exercícios

Para cada um, sem correr: diz o tipo de erro, a linha onde acontece e porquê. Depois corre e compara.

```python run
precos = [2.5, 3.0, 1.2]
for i in range(4):
    print(precos[i])
```

```python run
cliente = {"nome": "Rui", "email": "rui@exemplo.pt"}
print("Olá", cliente["Nome"])
```

```python run
idade = "30"
print(idade + 1)
```

1: `IndexError: list index out of range` na linha do `print`, na 4.ª volta. A lista tem 3 elementos (posições 0, 1, 2), mas `range(4)` vai até 3. Corrige com `for p in precos:` ou `range(len(precos))`.

2: `KeyError: 'Nome'`. A chave é `"nome"` com minúscula. As chaves são sensíveis a maiúsculas.

3: `TypeError: can only concatenate str (not "int") to str`. `idade` é texto (`"30"`), não número. Converte com `int(idade) + 1`.
