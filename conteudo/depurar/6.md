Os erros mais perigosos não rebentam. O programa corre até ao fim, sem mensagem nenhuma, e dá o resultado **errado**. São erros de lógica, e são os que a IA mais introduz, porque o código gerado "parece" certo. Para os apanhar, precisas de saber qual era o resultado certo **antes** de correr.

## O método: esperado contra obtido

1. Escolhe um caso pequeno onde sabes a resposta de cabeça.
2. Escreve a resposta esperada **antes** de correr.
3. Corre. Se não bater certo, há um erro de lógica. Agora sim, depura (prints, depurador, bisseção).

```python run
def ano_bissexto(a):
    return a % 4 == 0

for a in [2024, 2025, 1900, 2000]:
    print(a, ano_bissexto(a))
```

Esperado: 2024 sim, 2025 não, **1900 não**, 2000 sim. A regra real é: divisível por 4, exceto os divisíveis por 100, a não ser que também sejam por 400. O código está "quase certo", que é o pior tipo de errado: passa nos casos que testaste à pressa.

## Onde se escondem

- **Limites**: `<` em vez de `<=`, `range(n)` em vez de `range(n + 1)`. Testa sempre o valor exatamente no limite (18 anos, 100 €, último dia do mês).
- **Casos vazios ou únicos**: lista vazia, um só elemento, texto vazio.
- **Ordem das operações**: `a + b / 2` não é a média de `a` e `b`.
- **Arredondamentos**: `round(2.5)` em Python dá `2` (arredonda para o par). Em dinheiro isto importa.
- **Variáveis reaproveitadas**: um acumulador que não foi reposto a zero.
- **Comparações de texto**: `"10" < "9"` é `True`, porque compara letra a letra.

```python run
print(round(2.5), round(3.5))
print("10" < "9")
print(sorted(["10", "9", "100", "2"]))
```

## Testes como depuração permanente

Quando encontras um erro de lógica, transforma o caso que falhou num teste. Assim, se o erro voltar (porque tu ou a IA mudaram o código), sabes logo:

```python run
def ano_bissexto(a):
    return a % 4 == 0 and (a % 100 != 0 or a % 400 == 0)

assert ano_bissexto(2024)
assert not ano_bissexto(2025)
assert not ano_bissexto(1900)
assert ano_bissexto(2000)
print("Todos os testes passaram")
```

Se um `assert` falhar, o programa para com `AssertionError` e sabes exatamente que caso partiu.

## Exercícios

Para cada função, escreve 3 casos com o resultado esperado (incluindo um limite e um caso vazio), corre e encontra o erro de lógica. Depois corrige.

```python run
def maior(numeros):
    m = 0
    for n in numeros:
        if n > m:
            m = n
    return m

print(maior([3, 9, 2]))
print(maior([-5, -2, -9]))
```

```python run
def pode_votar(idade):
    return idade > 18

print(pode_votar(17), pode_votar(18), pode_votar(30))
```

```python run
def media(a, b):
    return a + b / 2

print(media(10, 20))
```

??? Soluções
1: Com números todos negativos devolve `0`, que nem está na lista. O erro é começar em `m = 0`. Começa com `m = numeros[0]` (e decide o que fazer com a lista vazia) ou usa `max(numeros)`.

2: `pode_votar(18)` dá `False`, mas em Portugal vota-se aos 18. Deve ser `idade >= 18`. Erro de limite clássico.

3: Dá `20.0` em vez de `15.0`. A divisão acontece antes da soma: é `10 + (20 / 2)`. Corrige com `(a + b) / 2`.
