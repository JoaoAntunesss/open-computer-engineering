Dois programas podem dar o mesmo resultado e um demorar um milésimo de segundo enquanto o outro demora uma semana. A diferença raramente está no computador ou na linguagem: está no **algoritmo**. Esta lição dá-te a primeira forma de pensar nisso: contar quantos passos um programa faz à medida que os dados crescem.

## Contar passos, não segundos

Medir o tempo com um cronómetro depende da máquina, do que mais está a correr e dos dados. Em vez disso, contamos **operações básicas** em função do tamanho da entrada, `n`.

```python
def contem(lista, x):
    for elem in lista:
        if elem == x:
            return True
    return False
```

No pior caso (o elemento não existe), faz `n` comparações. Se a lista duplicar, o trabalho duplica. Dizemos que o custo é **linear**.

```python
def tem_repetidos(lista):
    for i in range(len(lista)):
        for j in range(i + 1, len(lista)):
            if lista[i] == lista[j]:
                return True
    return False
```

Para cada elemento, compara com todos os seguintes: cerca de `n²/2` comparações. Se a lista duplicar, o trabalho quadruplica. O custo é **quadrático**.

## A notação O grande

Para comparar algoritmos, só interessa **como o custo cresce** quando `n` é grande. Ignoramos as constantes e os termos menores: `n²/2 + 3n + 7` comporta-se como `n²` para `n` grande. Escrevemos `O(n²)`.

| Notação | Nome | Exemplo | n = 1 000 | n = 1 000 000 |
|---|---|---|---|---|
| O(1) | constante | aceder a `lista[i]`, procurar num dicionário | 1 | 1 |
| O(log n) | logarítmico | pesquisa binária | 10 | 20 |
| O(n) | linear | percorrer uma lista | 1 000 | 1 000 000 |
| O(n log n) | linearítmico | ordenar bem (`sorted`) | 10 000 | 20 000 000 |
| O(n²) | quadrático | dois ciclos aninhados | 1 000 000 | 10¹² |
| O(2ⁿ) | exponencial | testar todos os subconjuntos | impossível | impossível |

A um milhar de milhão de operações por segundo, `10¹²` operações são cerca de 17 minutos. `2¹⁰⁰⁰` operações não acabariam antes do fim do universo.

## O mesmo problema, três algoritmos

Ver se há repetidos numa lista:

```python
# O(n²): compara todos os pares
def tem_repetidos_1(lista):
    for i in range(len(lista)):
        for j in range(i + 1, len(lista)):
            if lista[i] == lista[j]:
                return True
    return False

# O(n log n): depois de ordenar, os repetidos ficam lado a lado
def tem_repetidos_2(lista):
    ordenada = sorted(lista)
    for i in range(len(ordenada) - 1):
        if ordenada[i] == ordenada[i + 1]:
            return True
    return False

# O(n): um conjunto responde a "já vi isto?" em tempo constante
def tem_repetidos_3(lista):
    vistos = set()
    for x in lista:
        if x in vistos:
            return True
        vistos.add(x)
    return False
```

Experimenta medir:

```python
import random, time

dados = random.sample(range(10_000_000), 20_000)   # 20 000 números sem repetidos
for f in (tem_repetidos_1, tem_repetidos_2, tem_repetidos_3):
    inicio = time.perf_counter()
    f(dados)
    print(f.__name__, f"{time.perf_counter() - inicio:.3f} s")
```

Num portátil normal, o primeiro demora vários segundos e os outros dois milésimos. Com 200 000 elementos, o primeiro passa a demorar minutos; os outros continuam abaixo de um segundo.

## Pesquisa binária: o poder do log n

Numa lista **ordenada**, não precisas de olhar para todos os elementos. Olhas para o do meio: se for maior do que o que procuras, a resposta está na metade da esquerda; se for menor, na da direita. Cada passo corta o problema a metade.

```python
def pesquisa_binaria(ordenada, x):
    inicio, fim = 0, len(ordenada) - 1
    while inicio <= fim:
        meio = (inicio + fim) // 2
        if ordenada[meio] == x:
            return meio
        if ordenada[meio] < x:
            inicio = meio + 1
        else:
            fim = meio - 1
    return -1
```

Para um milhão de elementos, são no máximo 20 passos, porque `2²⁰ ≈ 1 000 000`. É assim que procuras uma palavra num dicionário de papel.

## O custo das operações do Python

Saber o custo das operações das estruturas que usas evita surpresas:

| Operação | Custo |
|---|---|
| `lista[i]`, `lista.append(x)`, `lista.pop()` | O(1) |
| `x in lista`, `lista.index(x)`, `lista.insert(0, x)`, `lista.pop(0)` | O(n) |
| `x in conjunto`, `dic[chave]`, `conjunto.add(x)` | O(1) em média |
| `sorted(lista)`, `lista.sort()` | O(n log n) |
| `lista[a:b]` (fatia) | O(b − a): copia os elementos |

Um `x in lista` dentro de um ciclo sobre outra lista é um `O(n²)` disfarçado. Trocar a lista por um conjunto torna-o `O(n)`.

## Memória também conta

A mesma análise aplica-se à memória. `tem_repetidos_3` é mais rápida mas usa um conjunto que pode crescer até `n` elementos: troca memória por tempo. É uma das trocas mais comuns em informática.

## Erros comuns

- Avaliar algoritmos só com dados pequenos: com 100 elementos, tudo é rápido.
- Esquecer o custo escondido de operações como `in` numa lista, `pop(0)` ou fatias dentro de ciclos.
- Otimizar a linha errada. Mede primeiro onde está o tempo (com `time.perf_counter` ou o módulo `cProfile`) e muda o algoritmo antes de afinar detalhes.
- Achar que um computador mais rápido resolve um algoritmo exponencial.

```python
def par_com_soma_lento(nums, alvo):          # O(n²)
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == alvo:
                return True
    return False

def par_com_soma(nums, alvo):                # O(n)
    vistos = set()
    for x in nums:
        if alvo - x in vistos:
            return True
        vistos.add(x)
    return False
```
A ideia do exercício 3: para cada `x`, o par que procuras é `alvo - x`. Em vez de o procurar na lista toda, perguntas a um conjunto se já o viste. É a mesma troca de memória por tempo de `tem_repetidos_3`, e é das perguntas mais comuns em entrevistas de emprego.
