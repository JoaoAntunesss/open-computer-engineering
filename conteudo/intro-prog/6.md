Uma função **recursiva** é uma função que se chama a si própria. Parece um truque, mas é uma das ideias mais importantes da informática: muitos problemas definem-se naturalmente em termos de versões mais pequenas de si mesmos. Árvores, ordenação, compiladores e inteligência artificial estão cheios de recursão.

## A ideia

O fatorial de `n` é `n! = n × (n-1) × … × 1`. Repara que `n! = n × (n-1)!`. O problema de tamanho `n` resolve-se com o mesmo problema de tamanho `n - 1`:

```python
def fatorial(n):
    if n == 0:                    # caso base
        return 1
    return n * fatorial(n - 1)    # caso recursivo

fatorial(5)   # 120
```

Toda a função recursiva tem duas partes:

1. **Caso base**: um caso tão simples que se responde diretamente, sem recursão.
2. **Caso recursivo**: reduz o problema a um mais pequeno e confia que a chamada recursiva o resolve.

O segundo ponto é o que custa. Não tentes seguir mentalmente todas as chamadas: assume que `fatorial(n - 1)` devolve o valor certo e pergunta apenas "com esse valor, consigo calcular `fatorial(n)`?". Isto chama-se o **salto de fé recursivo**, e é exatamente o raciocínio da indução matemática.

## O que acontece na máquina

Cada chamada tem o seu próprio espaço para variáveis, empilhado por cima da anterior (a **pilha de chamadas**):

```text
fatorial(3)
  3 * fatorial(2)
        2 * fatorial(1)
              1 * fatorial(0)
                    → 1
              → 1
        → 2
  → 6
```

As chamadas descem até ao caso base e depois os resultados sobem. Se esqueceres o caso base, ou se o problema não ficar mais pequeno, as chamadas nunca param:

```text
RecursionError: maximum recursion depth exceeded
```

O Python limita a profundidade a cerca de 1000 chamadas. Para recursões muito fundas, um ciclo é melhor.

## Recursão sobre listas e strings

Uma lista é o primeiro elemento mais o resto da lista:

```python
def soma(lista):
    if not lista:
        return 0
    return lista[0] + soma(lista[1:])

def inverte(s):
    if len(s) <= 1:
        return s
    return inverte(s[1:]) + s[0]
```

São bons exercícios para aprender, mas em Python há formas mais eficientes (`sum`, `s[::-1]`), porque cada `lista[1:]` cria uma cópia.

## Quando a recursão é mesmo a melhor ferramenta

A recursão brilha quando os dados são, eles próprios, recursivos. Uma pasta contém ficheiros e outras pastas:

```python
from pathlib import Path

def tamanho_total(caminho):
    p = Path(caminho)
    if p.is_file():
        return p.stat().st_size
    return sum(tamanho_total(filho) for filho in p.iterdir())
```

Com um ciclo teras de gerir à mão uma lista de pastas por visitar. Com recursão, o código é a definição: o tamanho de uma pasta é a soma do tamanho do que tem dentro.

### Torres de Hanói

Três postes; `n` discos no primeiro, do maior para o menor. Objetivo: passá-los todos para o terceiro, movendo um de cada vez e nunca pondo um disco maior sobre um menor.

Pensado recursivamente é simples: para mover `n` discos de A para C, move os `n - 1` de cima para B, move o maior para C, e move os `n - 1` de B para C.

```python
def hanoi(n, origem="A", destino="C", auxiliar="B"):
    if n == 0:
        return
    hanoi(n - 1, origem, auxiliar, destino)
    print(f"Move o disco {n} de {origem} para {destino}")
    hanoi(n - 1, auxiliar, destino, origem)

hanoi(3)    # 7 movimentos
```

São precisos `2ⁿ - 1` movimentos. Com 64 discos, a um movimento por segundo, demoraria mais de 500 mil milhões de anos.

### Gerar todas as hipóteses

```python
def permutacoes(elementos):
    if len(elementos) <= 1:
        return [elementos]
    resultado = []
    for i, x in enumerate(elementos):
        resto = elementos[:i] + elementos[i + 1:]
        for p in permutacoes(resto):
            resultado.append([x] + p)
    return resultado

permutacoes([1, 2, 3])   # 6 permutações
```

Esta técnica de explorar todas as escolhas (*backtracking*) resolve Sudokus, puzzles e muitos problemas de otimização.

## O perigo: repetir trabalho

A definição de Fibonacci é recursiva: `F(n) = F(n-1) + F(n-2)`.

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

Está certa, mas `fib(40)` demora segundos e `fib(60)` não acaba. Porquê? `fib(5)` chama `fib(4)` e `fib(3)`; `fib(4)` volta a chamar `fib(3)`… O mesmo valor é calculado um número exponencial de vezes.

A solução é **memorizar** os resultados já calculados:

```python
from functools import cache

@cache
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fib(200)   # instantâneo
```

Guardar resultados de subproblemas é a ideia da **programação dinâmica**, uma das técnicas centrais de Análise e Desenho de Algoritmos.

## Erros comuns

- Esquecer o caso base, ou um caso base que nunca é atingido (por exemplo, `fatorial(-1)`).
- O problema não ficar mais pequeno na chamada recursiva.
- Ignorar o valor devolvido pela chamada recursiva (`fatorial(n - 1)` sem `return`).
- Recursão que repete o mesmo trabalho exponencialmente.

```exercicio

def fatorial(n):

testes:

def fatorial(n):
    if n == 0:

    return n * fatorial(n - 1)
```

```exercicio
id: ip6-digitos
titulo: Soma dos algarismos
enunciado: Escreve `soma_digitos(n)`, recursiva, que devolve a soma dos algarismos de um número inteiro não negativo. `1234` dá `10`.
dica: O último algarismo é `n % 10` e o resto do número é `n // 10`. Pára quando `n` for menor do que 10.
proibido: for, while, str, sum
inicio:
def soma_digitos(n):
    return 0
testes:
soma_digitos(0) == 0
soma_digitos(7) == 7
soma_digitos(1234) == 10
soma_digitos(9999) == 36
soma_digitos(1000001) == 2
solucao:
def soma_digitos(n):
    if n < 10:
        return n
    return n % 10 + soma_digitos(n // 10)
```
