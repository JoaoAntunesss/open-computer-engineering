À medida que os programas crescem, o difícil deixa de ser escrever cada linha e passa a ser **organizar** o código para que se perceba e se possa mudar. A ferramenta principal é a **abstração**: esconder os detalhes de *como* algo funciona atrás de operações que dizem *o que* faz.

## O problema

Imagina que representas uma fração como um tuplo `(numerador, denominador)` e o resto do programa usa isso diretamente:

```python
f = (1, 2)
g = (1, 3)
soma = (f[0] * g[1] + g[0] * f[1], f[1] * g[1])
```

Funciona, mas o código que usa as frações sabe como elas estão guardadas. Se um dia decidires simplificá-las sempre, ou guardá-las de outra forma, tens de alterar todos os sítios que mexem em `f[0]` e `f[1]`. E `f[0]` não diz nada a quem lê.

## Tipos abstratos de dados

Um **tipo abstrato de dados** (TAD) define-se pelas **operações** que oferece, não pela forma como os dados estão guardados. Tem três tipos de operações:

- **construtores**: criam valores do tipo;
- **seletores**: obtêm partes de um valor;
- **operações**: fazem algo útil com os valores, usando só construtores e seletores.

```python
from math import gcd

# ---- representação (só estas funções conhecem o tuplo) ----
def fracao(n, d):
    if d == 0:
        raise ValueError("denominador zero")
    g = gcd(n, d) * (1 if d > 0 else -1)
    return (n // g, d // g)

def numerador(f):
    return f[0]

def denominador(f):
    return f[1]

# ---- operações (não sabem que é um tuplo) ----
def soma(f, g):
    return fracao(numerador(f) * denominador(g) + numerador(g) * denominador(f),
                  denominador(f) * denominador(g))

def multiplica(f, g):
    return fracao(numerador(f) * numerador(g), denominador(f) * denominador(g))

def texto(f):
    return f"{numerador(f)}/{denominador(f)}"

print(texto(soma(fracao(1, 2), fracao(1, 3))))   # 5/6
```

A linha que separa as duas partes chama-se **barreira de abstração**. Se amanhã mudares a representação para um dicionário, só mudas as três funções de cima. O resto do programa não nota.

Esta é a ideia central das cadeiras de introdução à programação no IST e em Berkeley (vem do livro *Structure and Interpretation of Computer Programs*), e é a base da programação orientada a objetos.

## Classes: o TAD com sintaxe própria

O Python tem uma forma mais cómoda de juntar dados e operações: as **classes**.

```python
from math import gcd

class Fracao:
    def __init__(self, n, d=1):
        if d == 0:
            raise ValueError("denominador zero")
        g = gcd(n, d) * (1 if d > 0 else -1)
        self.n = n // g
        self.d = d // g

    def __add__(self, outra):
        return Fracao(self.n * outra.d + outra.n * self.d, self.d * outra.d)

    def __mul__(self, outra):
        return Fracao(self.n * outra.n, self.d * outra.d)

    def __eq__(self, outra):
        return self.n == outra.n and self.d == outra.d

    def __repr__(self):
        return f"Fracao({self.n}, {self.d})"

    def __str__(self):
        return f"{self.n}/{self.d}"

a = Fracao(1, 2)
b = Fracao(1, 3)
print(a + b)              # 5/6
print(a * b == Fracao(1, 6))   # True
```

- `class` define um tipo novo; `Fracao(1, 2)` cria um **objeto** desse tipo.
- `__init__` é o construtor. `self` é o objeto que está a ser criado ou usado.
- Os métodos com `__duplo__` ligam a classe aos operadores do Python: `__add__` faz o `+` funcionar, `__eq__` o `==`, `__str__` o `print`.

## Um TAD clássico: a pilha

Uma **pilha** guarda elementos e só deixa mexer no do topo: o último a entrar é o primeiro a sair, como uma pilha de pratos.

```python
class Pilha:
    def __init__(self):
        self._itens = []           # o _ diz: isto é interno, não mexas

    def empilha(self, x):
        self._itens.append(x)

    def desempilha(self):
        if self.vazia():
            raise IndexError("pilha vazia")
        return self._itens.pop()

    def topo(self):
        return self._itens[-1]

    def vazia(self):
        return not self._itens
```

Com ela, verificar se os parênteses de uma expressão estão equilibrados é simples:

```python
def equilibrado(expr):
    pares = {")": "(", "]": "[", "}": "{"}
    p = Pilha()
    for c in expr:
        if c in "([{":
            p.empilha(c)
        elif c in pares:
            if p.vazia() or p.desempilha() != pares[c]:
                return False
    return p.vazia()

equilibrado("f(a[1], {b: 2})")   # True
equilibrado("(]")                # False
```

Os compiladores usam exatamente isto, e a pilha de chamadas da lição anterior é uma pilha.

## Porque é que isto importa

- **Mudar sem partir**: a representação pode mudar sem afetar quem usa o tipo.
- **Pensar a um nível mais alto**: `p.empilha(x)` diz o que queres; `lista.append(x)` diz como.
- **Trabalhar em equipa**: alguém implementa o TAD, outros usam-no, e combinam só as operações.
- **Testar**: testas as operações uma a uma.

## Erros comuns

- Aceder diretamente à representação (`f[0]`, `pilha._itens`) fora do TAD.
- Esquecer o `self` como primeiro parâmetro dos métodos.
- Classes que são só um saco de dados sem operações, ou com uma operação que faz tudo.
- Não validar no construtor e deixar criar valores impossíveis (uma fração com denominador 0).

class Conta:
    def __init__(self, saldo_inicial=0):

testes:

class Conta:
    def __init__(self, saldo_inicial=0):
        self._saldo = saldo_inicial

    def deposita(self, valor):
        if valor <= 0:
            return False
        self._saldo += valor
        return True

    def levanta(self, valor):
        if not 0 < valor <= self._saldo:
            return False
        self._saldo -= valor
        return True

    def saldo(self):
        return self._saldo
