Um programa grande escrito como uma lista enorme de instruções é impossível de perceber e de corrigir. As **funções** permitem dar um nome a um bloco de código, reutilizá-lo e, sobretudo, pensar a um nível mais alto: quando chamas `media(notas)`, não precisas de pensar em como a média é calculada.

## Definir e chamar

```python
def area_retangulo(largura, altura):
    """Devolve a área de um retângulo."""
    return largura * altura

a = area_retangulo(3, 4)     # a = 12
print(area_retangulo(2.5, 2))
```

- `def` define a função; `largura` e `altura` são os **parâmetros**.
- Na chamada, `3` e `4` são os **argumentos**: os valores que os parâmetros recebem.
- `return` termina a função e devolve um valor a quem a chamou.
- A string logo a seguir ao `def` é a **docstring**: documenta o que a função faz. Aparece com `help(area_retangulo)`.

### return não é print

```python
def dobro_errado(x):
    print(x * 2)

def dobro(x):
    return x * 2

y = dobro_errado(5)     # mostra 10, mas y fica None
z = dobro(5)            # não mostra nada; z fica 10
```

O `print` mostra algo ao utilizador; o `return` devolve um valor ao programa. Uma função que calcula algo deve devolvê-lo e deixar a quem a chama a decisão de o mostrar. Uma função sem `return` devolve `None`.

## Parâmetros com valores por omissão e por nome

```python
def saudacao(nome, cumprimento="Olá"):
    return f"{cumprimento}, {nome}!"

saudacao("Ana")                         # 'Olá, Ana!'
saudacao("Ana", "Bom dia")              # 'Bom dia, Ana!'
saudacao(cumprimento="Boa noite", nome="Rui")
```

Os argumentos por nome tornam chamadas com muitos parâmetros legíveis: `enviar(destino, urgente=True)` diz mais do que `enviar(destino, True)`.

> Nunca uses uma lista ou um dicionário como valor por omissão (`def f(x, lista=[])`). O valor é criado uma vez só, quando a função é definida, e é partilhado por todas as chamadas. Usa `lista=None` e cria a lista dentro da função.

## Âmbito: onde vivem as variáveis

As variáveis criadas dentro de uma função são **locais**: existem só enquanto a função corre e não são vistas de fora.

```python
def calcula():
    resultado = 42       # local
    return resultado

calcula()
print(resultado)         # NameError: name 'resultado' is not defined
```

Uma função consegue **ler** variáveis de fora (globais), mas se lhes **atribuir** um valor, o Python cria uma variável local nova com o mesmo nome:

```python
contador = 0

def incrementa():
    contador = contador + 1     # UnboundLocalError
```

Podias resolver com `global contador`, mas não o faças. Funções que mexem em variáveis globais são difíceis de testar e de perceber, porque o resultado depende de coisas que não estão nos parâmetros. A forma limpa é receber e devolver:

```python
def incrementa(contador):
    return contador + 1

contador = incrementa(contador)
```

## Funções puras

Uma função é **pura** quando o resultado depende só dos argumentos e não altera nada fora dela (não escreve ficheiros, não muda variáveis globais, não faz print). As funções puras são fáceis de testar: dás-lhes valores e confirmas o resultado. Tenta que a maior parte do teu programa seja puro e que as partes que leem do teclado, escrevem ficheiros ou mostram coisas fiquem nas bordas.

## Decompor um problema

O verdadeiro poder das funções é permitir resolver um problema grande em partes pequenas. Exemplo: dizer se um número de cartão de cidadão… vamos usar algo mais simples, o **algoritmo de Luhn**, que valida números de cartões e de outros identificadores.

A regra: a partir da direita, duplica um dígito sim e um não; se o dobro passar de 9, subtrai 9; soma tudo; o número é válido se a soma for múltipla de 10.

```python
def digitos(numero):
    """'4539 1488' -> [4, 5, 3, 9, 1, 4, 8, 8]"""
    return [int(c) for c in numero if c.isdigit()]

def contribuicao(d, duplicar):
    if not duplicar:
        return d
    d *= 2
    return d - 9 if d > 9 else d

def luhn_valido(numero):
    ds = digitos(numero)
    total = 0
    for i, d in enumerate(reversed(ds)):
        total += contribuicao(d, i % 2 == 1)
    return len(ds) > 1 and total % 10 == 0

print(luhn_valido("4539 1488 0343 6467"))   # True
print(luhn_valido("4539 1488 0343 6468"))   # False
```

Cada função faz uma coisa e tem um nome que o diz. Lida de cima para baixo, `luhn_valido` é quase a descrição em português do algoritmo.

## Funções como valores

Em Python, uma função é um valor como outro qualquer: pode ser guardada numa variável ou passada a outra função.

```python
def aplica_a_todos(f, valores):
    return [f(v) for v in valores]

aplica_a_todos(abs, [-3, 4, -5])           # [3, 4, 5]
aplica_a_todos(lambda x: x * x, [1, 2, 3]) # [1, 4, 9]

nomes = ["Rui", "ana", "Bea"]
sorted(nomes, key=str.lower)               # ['ana', 'Bea', 'Rui']
```

O `lambda` cria uma função pequena sem nome. Esta ideia é a base da programação funcional, que tem uma cadeira inteira mais à frente.

## Erros comuns

- Fazer `print` em vez de `return` e depois tentar usar o resultado.
- Esquecer o `return` num dos caminhos de um `if`: a função devolve `None` nesse caso.
- Usar variáveis globais para passar informação entre funções.
- Funções enormes que fazem cinco coisas. Se precisas de "e" para descrever o que a função faz, divide-a.
- Listas como valor por omissão.

## Ler e prever: seguir uma chamada

Ao ler uma chamada de função, salta mentalmente para dentro dela com os valores concretos, segue o corpo até ao `return` e volta com o resultado. Três perguntas para qualquer função: **o que entra, o que acontece, o que sai**.

```python run
def soma_com_print(a, b):
    print(a + b)

def soma_com_return(a, b):
    return a + b

x = soma_com_print(2, 3)
y = soma_com_return(2, 3)
print("x =", x, "| y =", y)
```

`print` mostra, mas não devolve nada (`x` fica `None`). `return` devolve o valor a quem chamou. Confundir os dois é dos erros mais comuns ao ler e ao escrever funções.

Para ler uma função desconhecida: lê o nome e os parâmetros, escolhe valores simples, segue o corpo, encontra todos os `return` e testa mentalmente os casos estranhos (lista vazia, zero, texto vazio).

Prevê antes de correr:

```python run
def misterio(a, b):
    if a > b:
        return a - b
    return b - a

print(misterio(10, 3), misterio(3, 10), misterio(5, 5))
```

## Prática com correção automática

Escreve a solução no editor e carrega em **Testar**: o teu código é corrido contra vários casos e vês logo quais passam. Tenta primeiro sem ajuda; a dica e a solução estão lá para quando precisares.

```exercicio
id: ip3-desconto
titulo: Preço com desconto
enunciado: Escreve `preco_final(preco, desconto=10)`, que devolve o preço depois de aplicar a percentagem de desconto. Se não for indicado desconto, usa 10 %. O resultado deve vir arredondado a 2 casas decimais (usa `round`).
dica: O preço final é `preco * (1 - desconto / 100)`.
inicio:
def preco_final(preco, desconto=10):
    return preco
testes:
preco_final(100) == 90.0
preco_final(100, 25) == 75.0
preco_final(19.99, 0) == 19.99
preco_final(59.9, 20) == 47.92
preco_final(10, desconto=50) == 5.0
solucao:
def preco_final(preco, desconto=10):
    return round(preco * (1 - desconto / 100), 2)
```

```exercicio
id: ip3-primo
titulo: É primo?
enunciado: Escreve `e_primo(n)`, que devolve `True` se n for um número primo e `False` caso contrário. Lembra-te: 0 e 1 não são primos, e 2 é.
dica: Experimenta dividir n por todos os números de 2 até n - 1 (ou só até à raiz quadrada de n). Se algum der resto 0, não é primo.
inicio:
def e_primo(n):
    return False
testes:
e_primo(2) == True
e_primo(3) == True
e_primo(4) == False
e_primo(1) == False
e_primo(0) == False
e_primo(17) == True
e_primo(21) == False
e_primo(97) == True
e_primo(7919) == True
solucao:
def e_primo(n):
    if n < 2:
        return False
    d = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += 1
    return True
```

