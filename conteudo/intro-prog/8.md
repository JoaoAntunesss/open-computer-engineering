"Funciona no meu computador" não é uma garantia. Um **teste** é código que verifica outro código: corre a função com valores conhecidos e confirma o resultado. Com testes, podes mudar o programa sem medo de partir o que já funcionava, e descobres os erros em segundos em vez de semanas.

## assert

A forma mais simples de testar é o `assert`: se a condição for falsa, o programa pára com um erro.

```python
def media(valores):
    return sum(valores) / len(valores)

assert media([10, 20]) == 15
assert media([7]) == 7
```

Também serve dentro do código, para documentar e verificar suposições:

```python
def raiz_inteira(n):
    assert n >= 0, "n tem de ser não negativo"
    ...
```

## pytest

Para mais do que meia dúzia de testes, usa o **pytest** (`pip install pytest`). As regras são simples: ficheiros `test_*.py`, funções `test_*`, e `assert` normais.

```python
# estatistica.py
def media(valores):
    if not valores:
        raise ValueError("lista vazia")
    return sum(valores) / len(valores)

def mediana(valores):
    v = sorted(valores)
    meio = len(v) // 2
    return v[meio] if len(v) % 2 else (v[meio - 1] + v[meio]) / 2
```

```python
# test_estatistica.py
import pytest
from estatistica import media, mediana

def test_media_simples():
    assert media([10, 20, 30]) == 20

def test_media_com_floats():
    assert media([0.1, 0.2]) == pytest.approx(0.15)

def test_media_lista_vazia():
    with pytest.raises(ValueError):
        media([])

@pytest.mark.parametrize("valores, esperado", [
    ([3, 1, 2], 2),
    ([4, 1, 3, 2], 2.5),
    ([5], 5),
])
def test_mediana(valores, esperado):
    assert mediana(valores) == esperado
```

```bash
pytest           # encontra e corre todos os testes
pytest -x        # pára no primeiro que falhar
pytest -k media  # só os testes com "media" no nome
```

Quando um teste falha, o pytest mostra os valores envolvidos:

```text
>       assert mediana(valores) == esperado
E       assert 3 == 2.5
```

- `pytest.approx` compara floats com tolerância.
- `pytest.raises` confirma que o código lança o erro certo.
- `parametrize` corre o mesmo teste com vários casos sem repetir código.

## O que testar

Não é possível testar todos os valores. Escolhe casos que representem situações diferentes:

- **o caso normal**: uma lista com alguns elementos;
- **os limites**: lista vazia, um só elemento, zero, números negativos, o maior valor permitido;
- **os casos especiais do problema**: número par e ímpar de elementos na mediana, um ano bissexto, uma string com acentos;
- **entradas inválidas**: o que deve acontecer? Um erro claro, ou um valor especial?

Uma boa pergunta: "se eu tivesse escrito esta função mal, que teste apanhava o erro?". Os erros vivem quase sempre nos limites.

## Testar primeiro

No **desenvolvimento guiado por testes** (TDD), escreves o teste antes do código:

1. Escreve um teste para a próxima coisa que a função deve fazer. Corre: falha.
2. Escreve o código mínimo para o teste passar.
3. Melhora o código (refatora) com os testes a confirmar que continua certo.

Obriga-te a decidir o que a função deve fazer antes de pensar em como. Não precisas de o fazer sempre, mas experimenta: muda a forma como desenhas funções.

## Testes e depuração juntos

Quando encontras um erro, o primeiro passo é escrever um teste que o reproduza. Depois corriges até o teste passar. Assim tens a certeza de que o corrigiste e de que não volta sem dares por isso.

Para depurar, junta o que aprendeste em Ferramentas:

```bash
pytest --pdb      # abre o depurador no ponto onde o teste falhou
```

E torna o código fácil de testar: funções pequenas e puras, que recebem argumentos e devolvem valores, testam-se numa linha. Funções que leem do teclado, usam variáveis globais e fazem `print` são quase impossíveis de testar. Se é difícil escrever o teste, muitas vezes o problema está no desenho da função.

## Erros comuns

- Testar só o caso que já sabes que funciona.
- Comparar floats com `==`.
- Testes que dependem uns dos outros, ou da ordem em que correm.
- Testes que passam sempre (por exemplo, sem nenhum `assert`). Confirma que o teste falha quando o código está errado: estraga o código de propósito uma vez.
- Corrigir um erro sem acrescentar o teste que o apanha.
