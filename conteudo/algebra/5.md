Uma transformação linear é uma função entre espaços vetoriais que respeita somas e múltiplos. Rotações, escalas, projeções e reflexões são lineares, e toda a transformação linear entre espaços de dimensão finita é uma matriz. É assim que um jogo ou um programa de desenho move milhões de pontos por segundo.

## Definição

T: V → W é **linear** quando, para quaisquer vetores u, v e escalar c:

- T(u + v) = T(u) + T(v);
- T(c·v) = c·T(v).

Consequência: T(0) = 0. Por isso uma translação, T(v) = v + (1, 0), **não** é linear.

Exemplos lineares: rodar, escalar, refletir, projetar, derivar um polinómio (a derivada da soma é a soma das derivadas).

## Toda a transformação linear é uma matriz

Se T: ℝⁿ → ℝᵐ é linear, então T(x) = A x, onde a **coluna j de A é T(eⱼ)**, a imagem do j-ésimo vetor da base canónica.

Isto dá uma receita: para saber a matriz de uma transformação, vê para onde vão os vetores da base.

Exemplo: a rotação de 90° no sentido anti-horário leva e₁ = (1, 0) para (0, 1) e e₂ = (0, 1) para (−1, 0). Então

A = [[0, −1], [1, 0]]

## Transformações do plano

| Transformação | Matriz |
|---|---|
| escala por sₓ e sᵧ | [[sₓ, 0], [0, sᵧ]] |
| rotação de θ | [[cos θ, −sin θ], [sin θ, cos θ]] |
| reflexão no eixo x | [[1, 0], [0, −1]] |
| projeção no eixo x | [[1, 0], [0, 0]] |
| cisalhamento horizontal | [[1, k], [0, 1]] |

```python
import numpy as np
import matplotlib.pyplot as plt

casa = np.array([[0, 0], [1, 0], [1, 1], [0.5, 1.5], [0, 1], [0, 0]]).T   # pontos como colunas

def rot(theta):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([[c, -s], [s, c]])

S = np.diag([2, 0.5])
for M, nome in [(np.eye(2), "original"), (rot(np.pi / 4), "rodada 45°"), (S, "escalada"), (rot(np.pi / 4) @ S, "escala e depois roda")]:
    p = M @ casa
    plt.plot(p[0], p[1], label=nome)
plt.gca().set_aspect("equal")
plt.legend()
plt.savefig("casa.png")
```

Uma única multiplicação transforma todos os pontos de uma vez. Repara que `rot @ S` aplica **primeiro** S e depois a rotação: lê-se da direita para a esquerda.

## Composição

Aplicar S e depois R é a transformação R ∘ S, cuja matriz é o produto **R·S**. Isto explica a definição do produto de matrizes da lição 3, e porque é que não é comutativo: rodar e depois escalar na horizontal não dá o mesmo que escalar e depois rodar.

Em computação gráfica, a câmara, a posição de cada objeto e a perspetiva são matrizes que se multiplicam numa só, e depois aplicam-se a todos os vértices na GPU.

## Coordenadas homogéneas

As translações não são lineares, mas os gráficos precisam delas. O truque: acrescenta-se uma coordenada 1 a cada ponto, (x, y) → (x, y, 1). Então a translação por (a, b) passa a ser uma matriz 3 × 3:

[[1, 0, a], [0, 1, b], [0, 0, 1]] · (x, y, 1) = (x + a, y + b, 1)

e pode compor-se com rotações e escalas por multiplicação. É exatamente o que fazem o OpenGL, o WebGL e os motores de jogos, com matrizes 4 × 4 em 3D.

## Núcleo e imagem

Para T(x) = A x:

- o **núcleo** N(T) são os vetores que vão para 0;
- a **imagem** Im(T) é o conjunto dos resultados possíveis, que é o espaço das colunas de A.

T é **injetiva** (não junta pontos diferentes) se e só se N(T) = {0}. Uma projeção não é injetiva: perde uma dimensão, e por isso não tem inversa. Uma rotação é injetiva e invertível; a inversa é a rotação de −θ.

## Matriz numa outra base

A mesma transformação tem matrizes diferentes em bases diferentes. Se P tem como colunas uma nova base, a matriz de T nessa base é **P⁻¹ A P**. Matrizes relacionadas desta forma dizem-se **semelhantes**: descrevem a mesma transformação vista de outro ponto de vista. A lição seguinte procura a base em que a matriz fica mais simples possível.

## Erros comuns

- Achar que uma translação é linear.
- Pôr as imagens dos vetores da base nas **linhas** em vez das colunas.
- Inverter a ordem na composição: "primeiro A, depois B" é B·A.
- Esquecer que o seno negativo da rotação fica na primeira linha.
