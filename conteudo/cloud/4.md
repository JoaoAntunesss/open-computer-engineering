Os fornecedores de cloud (AWS, Azure, Google Cloud) vendem níveis diferentes de abstração. Quanto mais sobes, menos geres, mas também menos controlas.

## Os modelos

| Modelo | Tu geres | O fornecedor gere | Exemplos |
|---|---|---|---|
| **IaaS** | SO, runtime, app | hardware, rede, virtualização | EC2, Compute Engine |
| **PaaS** | só a app | também SO e runtime | Heroku, App Engine, Render |
| **Serverless / FaaS** | funções | tudo, inclusive escalar até zero | Lambda, Cloud Functions |
| **SaaS** | nada (usas) | tudo | Gmail, Slack |

## Serverless

Escreves uma função que responde a um evento (pedido HTTP, ficheiro carregado, mensagem numa fila); pagas por invocação e tempo de execução:

```python
def handler(evento, contexto):
    nome = evento.get("queryStringParameters", {}).get("nome", "mundo")
    return {"statusCode": 200, "body": f"Olá, {nome}"}
```

Vantagens: zero servidores para gerir, escala automática, custo zero sem tráfego. Desvantagens: **arranque a frio** (a primeira invocação pode demorar centenas de ms), limites de tempo de execução, dependência do fornecedor, custos altos com tráfego constante.

## Quando compensa

```python run
def custo_vm(pedidos_mes):
    return 30.0                                    # uma VM pequena: preço fixo por mês

def custo_serverless(pedidos_mes, ms=100, mem_gb=0.25):
    pedidos = pedidos_mes * 0.20 / 1e6             # 0,20 por milhão de pedidos
    computo = pedidos_mes * ms / 1000 * mem_gb * 0.0000167   # por GB-segundo
    return pedidos + computo

for p in [10_000, 1_000_000, 10_000_000, 100_000_000]:
    s = custo_serverless(p)
    print(f"{p:>11,} pedidos: serverless {s:7.2f}  vm {custo_vm(p):.2f}  -> {'serverless' if s < custo_vm(p) else 'vm'}")
```

(Preços aproximados e simplificados; servem para ver a forma da curva.)
