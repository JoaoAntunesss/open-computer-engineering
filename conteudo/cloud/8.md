Na cloud, a infraestrutura também é código: ficheiros YAML, Dockerfiles, Terraform. Ler estes ficheiros com atenção evita custos inesperados, falhas de segurança e serviços que caem às 3 da manhã.

## Ler e prever: um Dockerfile

```dockerfile
FROM python:3.12
COPY . /app
WORKDIR /app
RUN pip install -r requirements.txt
ENV DATABASE_URL=postgresql://admin:Segredo123@db.empresa.pt/prod
CMD python app.py
```

Antes de continuar: o que fica dentro da imagem? O que acontece à cache de construção quando mudas uma linha de código? Que informação sensível fica visível para quem tiver a imagem?

## Encontra o erro: escalar sem limites

```yaml
# configuração de um serviço que escala automaticamente
service: api-marcacoes
min_instances: 1
max_instances: 1000
memory: 4Gi
concurrency: 1
timeout: 3600s
```

Um bug no frontend começa a fazer 50 pedidos por segundo em ciclo. Lê a configuração e prevê o que acontece à fatura ao fim de uma noite. Que valores mudarias?

## Escreve tu

Reescreve o Dockerfile para: usar uma imagem mais pequena, instalar as dependências antes de copiar o código (para aproveitar a cache), não guardar segredos e não correr como root. Depois escreve a configuração do serviço com limites razoáveis para uma API pequena.

??? Soluções
**Ler e prever:** a imagem leva todo o diretório (incluindo `.git`, `.env` e ficheiros de teste, se não houver `.dockerignore`) e a **password da base de dados de produção** num `ENV`, visível com `docker inspect` e no histórico da imagem. Como o código é copiado antes do `pip install`, qualquer alteração ao código obriga a reinstalar todas as dependências.

**Encontra o erro:** com `concurrency: 1`, cada pedido simultâneo precisa de uma instância, e com `max_instances: 1000` de 4 GiB, um ciclo de pedidos pode lançar centenas de instâncias a noite inteira. Limites razoáveis: `max_instances` baixo (por exemplo 5), `concurrency` de 40 a 80, memória de 512 MiB, timeout de 60 s, e alertas de orçamento.

**Escreve tu:**
```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
RUN useradd -m app
USER app
CMD ["python", "app.py"]
```
A `DATABASE_URL` passa a vir de um gestor de segredos, definida no serviço e nunca na imagem.
