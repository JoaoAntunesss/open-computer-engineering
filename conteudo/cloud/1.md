A **cloud** começa na virtualização: correr muitos «computadores» isolados numa só máquina física. Há dois níveis: **máquinas virtuais** (VMs), que emulam hardware completo com o seu próprio sistema operativo, e **contentores**, que partilham o núcleo do anfitrião e isolam só os processos.

## VMs vs contentores

| | Máquina virtual | Contentor |
|---|---|---|
| Isola | hardware (hipervisor: KVM, Xen, Hyper-V) | processos (namespaces + cgroups do Linux) |
| Arranque | dezenas de segundos | milissegundos |
| Tamanho | GB (SO completo) | MB (só a app e as bibliotecas) |
| Isolamento | forte | mais fraco (núcleo partilhado) |

Os contentores usam duas funcionalidades do núcleo Linux: **namespaces** (cada contentor vê a sua própria árvore de processos, rede, sistema de ficheiros) e **cgroups** (limites de CPU e memória).

## Docker

Uma **imagem** é um sistema de ficheiros em **camadas**, descrito num `Dockerfile`:

```dockerfile
FROM python:3.12-slim            # camada base
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt   # camada em cache enquanto requirements não mudar
COPY . .                          # o código muda muito: fica no fim
EXPOSE 8000
CMD ["python", "-m", "uvicorn", "main:app", "--host", "0.0.0.0"]
```

```bash
docker build -t minha-app .
docker run -p 8000:8000 --memory 256m minha-app
docker compose up                 # vários serviços (app + base de dados) de uma vez
```

A ordem importa: cada instrução é uma camada, e o Docker reutiliza a cache até à primeira camada que mudou.

## Cache de camadas

```python run
import hashlib

def build(instrucoes, ficheiros, cache):
    h, reconstruidas = "", []
    for ins in instrucoes:
        conteudo = ins + (ficheiros.get(ins.split()[1], "") if ins.startswith("COPY") else "")
        h = hashlib.sha256((h + conteudo).encode()).hexdigest()[:8]
        if h not in cache:
            cache.add(h); reconstruidas.append(ins)
    return reconstruidas

boa = ["FROM python", "COPY requirements.txt", "RUN pip install", "COPY codigo"]
ma  = ["FROM python", "COPY codigo", "COPY requirements.txt", "RUN pip install"]
for nome, ordem in [("boa", boa), ("má", ma)]:
    cache = set()
    build(ordem, {"requirements.txt": "flask", "codigo": "v1"}, cache)
    print(nome, "->", build(ordem, {"requirements.txt": "flask", "codigo": "v2"}, cache))
```

## Exercícios

1. Prevê a saída.
2. Porque é que um contentor arranca muito mais depressa do que uma VM?
3. Porque não deves correr código não confiável num contentor partilhado sem mais isolamento?

??? Soluções
1: `boa -> ['COPY codigo']`; `má -> ['COPY codigo', 'COPY requirements.txt', 'RUN pip install']`. Na ordem má, a instalação de dependências repete-se a cada alteração de código.

2: não arranca um sistema operativo: é só um processo do anfitrião com namespaces e cgroups.

3: todos os contentores partilham o mesmo núcleo; uma falha no núcleo permite sair do contentor. Para isso usam-se VMs leves (Firecracker, gVisor, Kata).
