Dois programas podem dar o mesmo resultado e um demorar um segundo enquanto o outro demora um dia. A **notação assintótica** mede como o tempo (ou a memória) cresce quando a entrada cresce, sem depender do computador nem da linguagem. É a linguagem comum para comparar algoritmos.

## Contar operações

```python
def soma(v):                  # n = len(v)
    total = 0                 # 1 vez
    for x in v:               # n vezes
        total += x
    return total

def tem_repetidos(v):
    for i in range(len(v)):            # n vezes
        for j in range(i + 1, len(v)): # até n - 1 vezes
            if v[i] == v[j]:
                return True
    return False
```

`soma` faz cerca de n operações. `tem_repetidos`, no pior caso, compara todos os pares: n(n−1)/2 ≈ n²/2. Para n = 1000, são 500 mil comparações; para n = 1 milhão, 500 mil milhões.

## As três notações

- **O(g(n))**, limite superior: a partir de certo n, o custo é no máximo c·g(n). "Não cresce mais depressa do que g."
- **Ω(g(n))**, limite inferior: "cresce pelo menos tão depressa como g."
- **Θ(g(n))**, as duas ao mesmo tempo: "cresce exatamente ao ritmo de g."

Ignoram-se constantes e termos menores: 3n² + 10n + 7 é Θ(n²). Na prática, quando se diz "este algoritmo é O(n log n)", quer-se quase sempre dizer Θ no pior caso.

## As classes que vais ver sempre

| Classe | Nome | Exemplo | n = 10⁶ |
|---|---|---|---|
| O(1) | constante | aceder a `v[i]`, dicionário | 1 |
| O(log n) | logarítmica | pesquisa binária | ~20 |
| O(n) | linear | percorrer uma lista | 10⁶ |
| O(n log n) | linearítmica | merge sort, `sorted` | ~2 × 10⁷ |
| O(n²) | quadrática | dois ciclos encaixados | 10¹² |
| O(2ⁿ) | exponencial | todos os subconjuntos | impossível |

Regra prática: um computador faz cerca de 10⁸ operações simples por segundo. Com n = 10⁶, O(n log n) é instantâneo e O(n²) demora horas.

## Pior caso, melhor caso, caso médio

Na pesquisa linear, o melhor caso é O(1) (o elemento está à frente) e o pior é O(n). Quase sempre se analisa o **pior caso**, porque é uma garantia. O caso médio importa quando o pior é raro (por exemplo, no quicksort).

## Ver o crescimento

Prevê: se n duplica, quanto cresce cada contagem?

```python run
def conta_linear(n):
    c = 0
    for i in range(n):
        c += 1
    return c

def conta_quadratica(n):
    c = 0
    for i in range(n):
        for j in range(n):
            c += 1
    return c

def conta_log(n):
    c = 0
    while n > 1:
        n //= 2
        c += 1
    return c

for n in (100, 200, 400, 800):
    print(n, conta_log(n), conta_linear(n), conta_quadratica(n))
```

## Erros comuns

- Achar que um ciclo dentro de outro é sempre O(n²): se o de dentro corre só 10 vezes, é O(n).
- Esquecer o custo escondido das operações: `x in lista` é O(n), `lista.insert(0, x)` é O(n), `s = s + "a"` num ciclo pode ser O(n²).
- Comparar algoritmos com n pequeno: com 10 elementos, quase tudo é rápido.
