Com pesos nas arestas (distâncias, tempos, custos), a BFS deixa de dar o caminho mais curto. O **algoritmo de Dijkstra** resolve isso quando os pesos não são negativos. Outro problema clássico é a **árvore mínima de suporte**: ligar todos os vértices com o menor custo total, resolvido pelos algoritmos de **Prim** e **Kruskal**. São usados em GPS, encaminhamento na Internet (OSPF), redes elétricas e agrupamento de dados.

## Dijkstra

Mantém, para cada vértice, a melhor distância conhecida. Em cada passo, escolhe o vértice **ainda não fechado com a menor distância** (com uma fila de prioridade), fecha-o e tenta melhorar os vizinhos (**relaxar** as arestas).

```python
import heapq

def dijkstra(grafo, origem):
    dist = {origem: 0}
    fila = [(0, origem)]
    while fila:
        d, v = heapq.heappop(fila)
        if d > dist[v]:
            continue                       # entrada antiga, já melhorada
        for w, peso in grafo[v]:
            nd = d + peso
            if nd < dist.get(w, float("inf")):
                dist[w] = nd
                heapq.heappush(fila, (nd, w))
    return dist
```

Custo: O((V + E) log V) com uma heap.

**Porque funciona:** quando um vértice sai da fila com distância d, nenhum caminho por vértices ainda não fechados pode ser mais curto, porque todos esses têm distância ≥ d e os pesos não são negativos. Com **pesos negativos** isto falha; usa-se o algoritmo de Bellman-Ford (O(V·E)).

## Árvore mínima de suporte

Num grafo não orientado e ligado, uma **árvore de suporte** liga todos os vértices sem ciclos (usa V − 1 arestas). A **mínima** é a que tem menor soma de pesos. Exemplo: que cabos instalar para ligar todos os edifícios de um campus com o mínimo de cabo.

### Kruskal

Ordena as arestas por peso. Percorre-as e aceita cada uma **se não formar um ciclo**. Para verificar ciclos depressa, usa-se a estrutura **union-find**: cada vértice sabe a que grupo pertence; uma aresta forma ciclo se ligar dois vértices do mesmo grupo.

```python
def kruskal(vertices, arestas):           # arestas: (peso, u, v)
    pai = {v: v for v in vertices}
    def raiz(v):
        while pai[v] != v:
            pai[v] = pai[pai[v]]           # compressão do caminho
            v = pai[v]
        return v
    arvore = []
    for peso, u, v in sorted(arestas):
        ru, rv = raiz(u), raiz(v)
        if ru != rv:
            pai[ru] = rv
            arvore.append((u, v, peso))
    return arvore
```

Custo: O(E log E), dominado pela ordenação.

### Prim

Começa num vértice e, em cada passo, junta a aresta mais barata que liga a árvore a um vértice novo (com uma heap, como no Dijkstra). Custo: O(E log V). Melhor para grafos densos.

Ambos são **algoritmos gananciosos**: escolhem sempre o melhor imediato, e aqui isso leva ao ótimo global (propriedade do corte).
