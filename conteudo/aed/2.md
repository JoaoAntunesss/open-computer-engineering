Ordenar é o problema mais estudado da informática. Os algoritmos de ordenação ensinam as técnicas principais do curso: incrementar, dividir para conquistar, usar uma estrutura de dados. Na prática usas `sorted`, mas tens de saber o que está por trás para escolher bem e para perceber os custos.

## Ordenação por inserção — O(n²)

Como ordenar cartas na mão: pega no elemento seguinte e insere-o no sítio certo da parte já ordenada.

```python
def insercao(v):
    for i in range(1, len(v)):
        x = v[i]
        j = i - 1
        while j >= 0 and v[j] > x:
            v[j + 1] = v[j]       # empurra para a direita
            j -= 1
        v[j + 1] = x
    return v
```

Pior caso (lista invertida): Θ(n²). Melhor caso (já ordenada): Θ(n). Muito rápida para listas pequenas ou quase ordenadas: por isso o Timsort (o `sorted` do Python) usa-a em pedaços pequenos.

## Merge sort — O(n log n)

**Dividir para conquistar:** parte a lista ao meio, ordena cada metade (recursivamente), junta as duas metades ordenadas.

```python
def merge_sort(v):
    if len(v) <= 1:
        return v
    meio = len(v) // 2
    a, b = merge_sort(v[:meio]), merge_sort(v[meio:])
    r, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            r.append(a[i]); i += 1
        else:
            r.append(b[j]); j += 1
    return r + a[i:] + b[j:]
```

Há log₂ n níveis de divisão, e em cada nível juntar custa O(n): total Θ(n log n), sempre. É **estável** (elementos iguais mantêm a ordem), mas precisa de memória extra O(n).

## Quicksort — O(n log n) em média

Escolhe um **pivô**, parte a lista em "menores" e "maiores", ordena cada parte.

```python
def quicksort(v):
    if len(v) <= 1:
        return v
    pivo = v[len(v) // 2]
    menores = [x for x in v if x < pivo]
    iguais  = [x for x in v if x == pivo]
    maiores = [x for x in v if x > pivo]
    return quicksort(menores) + iguais + quicksort(maiores)
```

Em média Θ(n log n) e, na versão "no próprio sítio", muito rápido na prática. Pior caso Θ(n²): quando o pivô é sempre o mínimo ou o máximo. Escolher o pivô ao acaso torna esse caso muito improvável.

## Heapsort — O(n log n) garantido, sem memória extra

Constrói uma heap (ver a lição de heaps) e retira o máximo n vezes. Θ(n log n) no pior caso e sem memória extra, mas na prática mais lento do que o quicksort, por usar mal a cache.

## Há um limite

Qualquer ordenação que só **compara** elementos precisa de Ω(n log n) comparações no pior caso. Merge sort e heapsort são, por isso, ótimos. Para inteiros num intervalo pequeno, a **ordenação por contagem** escapa ao limite (O(n + k)) porque não compara.

## Comparar na prática

Prevê, antes de correr: qual dos três é mais rápido com uma lista já ordenada? E com uma lista aleatória?

```python run
import random, time

def insercao(v):
    for i in range(1, len(v)):
        x, j = v[i], i - 1
        while j >= 0 and v[j] > x:
            v[j + 1] = v[j]; j -= 1
        v[j + 1] = x
    return v

def merge_sort(v):
    if len(v) <= 1: return v
    m = len(v) // 2
    a, b = merge_sort(v[:m]), merge_sort(v[m:])
    r, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]: r.append(a[i]); i += 1
        else: r.append(b[j]); j += 1
    return r + a[i:] + b[j:]

n = 3000
for nome, dados in (("aleatória", random.sample(range(n), n)), ("ordenada", list(range(n)))):
    for f in (insercao, merge_sort, sorted):
        t = time.perf_counter(); f(list(dados)); t = time.perf_counter() - t
        print(f"{nome:10} {f.__name__:11} {t * 1000:7.1f} ms")
```
