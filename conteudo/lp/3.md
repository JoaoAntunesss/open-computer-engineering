O que **significa** um programa? A documentação das linguagens responde em português ou inglês, e muitas vezes é ambígua (o que faz `i = i++ + ++i` em C?). A **semântica formal** responde com matemática, sem ambiguidades. A **semântica operacional** descreve o significado através de **regras de execução**: como um programa dá um passo, ou como chega ao seu valor. É a base das especificações de linguagens como o WebAssembly e o Standard ML, e de ferramentas que verificam compiladores.

## Duas formas

- **Passo pequeno** (*small-step*): uma relação e → e' que dá **um** passo de computação. O programa termina quando chega a um **valor**. Mostra a ordem exata das operações, e permite falar de programas que não terminam e de concorrência.
- **Passo grande** (*big-step*, ou semântica natural): uma relação e ⇓ v, "e avalia para v", definida diretamente. Mais próxima de um interpretador recursivo.

## Regras de inferência

Escrevem-se como frações: por cima, as premissas; por baixo, a conclusão.

Passo pequeno para a soma (avaliar da esquerda para a direita):

```
        e₁ → e₁'                     e₂ → e₂'                    n = n₁ + n₂
  ─────────────────────        ─────────────────────        ─────────────────
   e₁ + e₂ → e₁' + e₂            v₁ + e₂ → v₁ + e₂'            n₁ + n₂ → n
```

A primeira regra diz: se e₁ dá um passo, a soma também dá. A segunda só se aplica quando o lado esquerdo já é um valor v₁: isto fixa a ordem (esquerda primeiro). A terceira faz a conta.

Passo grande para o `if`:

```
   e₁ ⇓ true    e₂ ⇓ v                 e₁ ⇓ false    e₃ ⇓ v
 ──────────────────────────        ──────────────────────────
   if e₁ then e₂ else e₃ ⇓ v         if e₁ then e₂ else e₃ ⇓ v
```

Repara que só um dos ramos aparece nas premissas: o outro nunca é avaliado.

## As regras como código

As regras traduzem-se quase diretamente num programa. Este faz a semântica de passo pequeno de uma linguagem com números, somas, comparações, `if` e variáveis com atribuição, e mostra cada passo:

```python run
def valor(e):
    return isinstance(e, (int, bool))

def passo(e, memoria):
    tipo = e[0]
    if tipo == "var":
        return memoria[e[1]], memoria
    if tipo in ("+", "<"):
        _, a, b = e
        if not valor(a):                                  # regra 1: avança a esquerda
            a2, m = passo(a, memoria); return (tipo, a2, b), m
        if not valor(b):                                  # regra 2: depois a direita
            b2, m = passo(b, memoria); return (tipo, a, b2), m
        return (a + b if tipo == "+" else a < b), memoria  # regra 3: calcula
    if tipo == "if":
        _, c, t, f = e
        if not valor(c):
            c2, m = passo(c, memoria); return ("if", c2, t, f), m
        return (t if c else f), memoria
    if tipo == ":=":                                      # atribuição: devolve o valor e muda a memória
        _, nome, ex = e
        if not valor(ex):
            ex2, m = passo(ex, memoria); return (":=", nome, ex2), m
        return ex, {**memoria, nome: ex}
    if tipo == "seq":                                     # e1; e2
        _, a, b = e
        if not valor(a):
            a2, m = passo(a, memoria); return ("seq", a2, b), m
        return b, memoria

def mostra(e):
    if valor(e): return str(e)
    if e[0] == "var": return e[1]
    if e[0] in ("+", "<"): return f"({mostra(e[1])} {e[0]} {mostra(e[2])})"
    if e[0] == "if": return f"if {mostra(e[1])} then {mostra(e[2])} else {mostra(e[3])}"
    if e[0] == ":=": return f"{e[1]} := {mostra(e[2])}"
    if e[0] == "seq": return f"{mostra(e[1])}; {mostra(e[2])}"

# x := x + 1; if x < 3 then x + 10 else 0      com x = 1
programa = ("seq", (":=", "x", ("+", ("var", "x"), 1)),
            ("if", ("<", ("var", "x"), 3), ("+", ("var", "x"), 10), 0))
e, m = programa, {"x": 1}
while not valor(e):
    print(f"{mostra(e):55} memória {m}")
    e, m = passo(e, m)
print(f"{mostra(e):55} memória {m}")
```

Prevê quantos passos são e o valor final. Cada linha corresponde à aplicação de uma regra.

## Para que serve

- **Responder a perguntas exatas:** em que ordem se avaliam os argumentos? O que acontece numa divisão por zero? Duas implementações de uma linguagem têm de dar o mesmo resultado?
- **Provar propriedades:** por exemplo, que um programa bem tipado nunca fica "encravado" (lição 4).
- **Verificar compiladores:** o **CompCert** é um compilador de C com uma prova (em Rocq) de que o código gerado se comporta como o código fonte, segundo a semântica formal das duas linguagens.
- **Comportamento indefinido em C:** a norma deixa alguns casos sem semântica (`i = i++ + ++i`); a semântica formal torna esses buracos visíveis.
