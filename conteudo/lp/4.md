Um **sistema de tipos** classifica as expressões de um programa (inteiro, texto, função de inteiro para inteiro…) e recusa as combinações sem sentido antes de o programa correr. A promessa, nas palavras de Robin Milner: **"programas bem tipados não correm mal"**. Esta lição mostra o que isso quer dizer exatamente, e como se prova.

## Regras de tipos

Também se escrevem como regras de inferência. Γ (o **contexto**) diz o tipo de cada variável; Γ ⊢ e : T lê-se "no contexto Γ, e tem tipo T".

```
                      Γ ⊢ e₁ : Int    Γ ⊢ e₂ : Int          Γ ⊢ c : Bool   Γ ⊢ e₁ : T   Γ ⊢ e₂ : T
 ──────────────      ─────────────────────────────          ───────────────────────────────────────
 Γ ⊢ n : Int               Γ ⊢ e₁ + e₂ : Int                       Γ ⊢ if c then e₁ else e₂ : T

    x : T ∈ Γ              Γ, x : T₁ ⊢ e : T₂                Γ ⊢ f : T₁ → T₂    Γ ⊢ a : T₁
 ─────────────       ───────────────────────────            ──────────────────────────────
  Γ ⊢ x : T           Γ ⊢ (λx: T₁. e) : T₁ → T₂                      Γ ⊢ f a : T₂
```

A regra do `if` exige que os dois ramos tenham o **mesmo** tipo: o resultado tem de ter um tipo conhecido sem saber que ramo vai ser escolhido.

## Segurança de tipos = progresso + preservação

Prova-se (por indução nas regras) que, se ⊢ e : T, então:

1. **Progresso:** e é um valor, ou consegue dar um passo (nunca fica "encravado" numa situação sem regra, como `true + 1`).
2. **Preservação:** se e → e', então ⊢ e' : T (o tipo mantém-se durante a execução).

Juntos: um programa bem tipado ou termina num valor do tipo certo, ou continua a correr para sempre. Nunca chega a um erro de tipos em execução. (Divisões por zero e índices fora dos limites continuam possíveis, salvo em sistemas de tipos mais ricos.)

## Um verificador

```python run
INT, BOOL = "Int", "Bool"

def tipo(e, ctx):
    k = e[0]
    if k == "num": return INT
    if k == "bool": return BOOL
    if k == "var":
        if e[1] not in ctx: raise TypeError(f"variável livre {e[1]}")
        return ctx[e[1]]
    if k in ("+", "*"):
        a, b = tipo(e[1], ctx), tipo(e[2], ctx)
        if (a, b) != (INT, INT): raise TypeError(f"'{k}' precisa de Int e Int, recebeu {a} e {b}")
        return INT
    if k == "<":
        tipo_esq, tipo_dir = tipo(e[1], ctx), tipo(e[2], ctx)
        if (tipo_esq, tipo_dir) != (INT, INT): raise TypeError("'<' precisa de dois Int")
        return BOOL
    if k == "if":
        c, t, f = tipo(e[1], ctx), tipo(e[2], ctx), tipo(e[3], ctx)
        if c != BOOL: raise TypeError(f"a condição do if é {c}, não Bool")
        if t != f: raise TypeError(f"os ramos do if têm tipos diferentes: {t} e {f}")
        return t
    if k == "lambda":                       # ("lambda", nome, tipo_do_parametro, corpo)
        _, x, tx, corpo = e
        return ("→", tx, tipo(corpo, {**ctx, x: tx}))
    if k == "app":
        tf, ta = tipo(e[1], ctx), tipo(e[2], ctx)
        if not (isinstance(tf, tuple) and tf[0] == "→"): raise TypeError(f"{tf} não é uma função")
        if tf[1] != ta: raise TypeError(f"a função espera {tf[1]}, recebeu {ta}")
        return tf[2]

def mostra(t):
    return t if isinstance(t, str) else f"({mostra(t[1])} → {mostra(t[2])})"

inc = ("lambda", "x", INT, ("+", ("var", "x"), ("num", 1)))
exemplos = {
    "inc 41": ("app", inc, ("num", 41)),
    "inc": inc,
    "inc true": ("app", inc, ("bool", True)),
    "if 1 < 2 then 3 else true": ("if", ("<", ("num", 1), ("num", 2)), ("num", 3), ("bool", True)),
    "(λf: Int→Int. f (f 3)) inc": ("app", ("lambda", "f", ("→", INT, INT),
                                    ("app", ("var", "f"), ("app", ("var", "f"), ("num", 3)))), inc),
    "1 2": ("app", ("num", 1), ("num", 2)),
}
for nome, e in exemplos.items():
    try:
        print(f"{nome:30} : {mostra(tipo(e, {}))}")
    except TypeError as erro:
        print(f"{nome:30} ✗ {erro}")
```

Prevê, para cada exemplo, o tipo ou o erro.

## O preço: programas corretos recusados

Um sistema de tipos estático é **conservador**: recusa alguns programas que nunca dariam erro. `if true then 1 else "olá"` nunca devolve o texto, mas a regra do `if` recusa-o. Os sistemas de tipos evoluem para recusar menos: **polimorfismo** (lição 5), **tipos união** (TypeScript: `number | string`), **estreitamento** por fluxo (`if (typeof x === "string")`), **tipos dependentes** (o tipo pode depender de valores: "vetor de comprimento n").

## Estático, dinâmico, gradual

- **Estático** (Java, Rust, Haskell): erros antes de correr; mais segurança, documentação e ferramentas (autocompletar, refatorar).
- **Dinâmico** (Python, JavaScript): mais flexibilidade e protótipos rápidos; erros só em execução.
- **Gradual** (TypeScript, Python com anotações e `mypy`): tipos opcionais, introduzidos aos poucos. Hoje, a maioria dos projetos grandes em Python e JavaScript usa-os.
