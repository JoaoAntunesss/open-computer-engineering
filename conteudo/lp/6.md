Uma **continuação** é "o resto do cálculo": a partir de um ponto do programa, tudo o que ainda falta fazer com o valor que está a ser calculado. Tornar as continuações explícitas explica, de uma só vez, exceções, `return` antecipado, geradores, `async`/`await` e corrotinas. As linguagens modernas tratam tudo isto como **efeitos**, e algumas permitem programá-los diretamente (**efeitos algébricos**).

## A continuação, à vista

Em `1 + (2 * 3)`, quando se está a calcular `2 * 3`, a continuação é "pega no resultado e soma-lhe 1". Em código:

- **Estilo direto:** `def quadrado(x): return x * x`.
- **Estilo de passagem de continuações (CPS):** a função recebe a continuação k e, em vez de devolver, chama-a: `def quadrado(x, k): k(x * x)`.

Em CPS, cada função diz explicitamente "o que acontece a seguir". Os compiladores de linguagens funcionais usam CPS como representação intermédia, e era assim que se escrevia código assíncrono em JavaScript antes das promessas (os *callbacks*).

## Exceções, geradores e async como continuações

```python run
# 1. Fatorial em CPS: cada chamada passa "o que fazer com o resultado"
def fat_cps(n, k):
    if n == 0:
        return k(1)
    return fat_cps(n - 1, lambda r: k(n * r))
print("fatorial em CPS:", fat_cps(6, lambda r: r))

# 2. Exceções com duas continuações: uma para o sucesso, outra para o erro
def divide(a, b, ok, erro):
    return erro("divisão por zero") if b == 0 else ok(a / b)

def media_ponderada(xs, ws, ok, erro):
    return divide(sum(x * w for x, w in zip(xs, ws)), sum(ws), ok, erro)

media_ponderada([10, 20], [1, 3], lambda v: print("média:", v), lambda m: print("erro:", m))
media_ponderada([10, 20], [0, 0], lambda v: print("média:", v), lambda m: print("erro:", m))

# 3. Um gerador é uma função que guarda a sua continuação entre chamadas
def contagem():
    print("  (início)")
    for i in range(3):
        recebido = yield i                    # suspende aqui; a continuação fica guardada
        print(f"  (retomado com {recebido})")
    print("  (fim)")

g = contagem()
print("primeiro:", next(g))
print("segundo:", g.send("olá"))
print("terceiro:", g.send("adeus"))
try:
    g.send("último")
except StopIteration:
    print("o gerador terminou")
```

Prevê a ordem das mensagens do gerador: o código depois do `yield` só corre quando alguém o retoma com `send`. É exatamente o mecanismo do `async`/`await`: em cada `await`, a função suspende-se e a sua continuação fica registada até o resultado chegar.

## Continuações de primeira classe

Em Scheme e Racket, `call/cc` captura a continuação atual como um valor que se pode chamar mais tarde (para sair de vários níveis de uma vez, implementar *backtracking*, corrotinas). É poderoso e difícil de usar; as linguagens modernas preferem formas mais restritas (exceções, geradores, async, continuações delimitadas).

## Efeitos e mónadas

Um **efeito** é tudo o que uma função faz além de devolver um valor: ler ou escrever estado, lançar exceções, fazer E/S, ser não determinista, suspender-se. Formas de os tratar:

- **Embutidos na linguagem** (a maioria): exceções, `async`, variáveis mutáveis.
- **Mónadas** (Haskell): o tipo diz que efeitos há (`IO`, `Maybe`, `State`), e o `do` encadeia (Programação Funcional, lição 8).
- **Efeitos algébricos e handlers** (OCaml 5, Koka, Unison, Eff): uma função "pede" um efeito (`perform Ler`), e um **handler** mais acima decide o que fazer, recebendo a continuação. Com um único mecanismo, implementam-se exceções, geradores, async e estado. Em OCaml 5, é a base das *fibras* para concorrência.
