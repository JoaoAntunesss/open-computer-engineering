Um **paradigma** é uma forma de pensar sobre programas: o que é um programa, o que é computar, como se organiza o código. As linguagens reais misturam vários, mas cada uma tem um "centro de gravidade". Conhecer os grandes paradigmas ajuda a escolher a ferramenta certa e, sobretudo, a pensar em soluções que não ocorreriam a quem só conhece um.

## Imperativo

Um programa é uma **sequência de ordens** que alteram o **estado** (variáveis, memória). C, Pascal, e o estilo básico de Python e Java. Próximo do funcionamento da máquina; fácil de seguir passo a passo; difícil de raciocinar quando o estado é partilhado e muda em muitos sítios.

## Orientado a objetos

O programa é um conjunto de **objetos** que guardam estado e comunicam por **mensagens** (métodos). Encapsulamento, herança, polimorfismo (POO). Java, C#, Ruby, Smalltalk (o original, em que tudo é um objeto). Bom para modelar domínios com muitas entidades e comportamentos.

## Funcional

O programa é uma **composição de funções puras**; os dados são imutáveis; as funções são valores (Programação Funcional, Linguagens, lições 1 e 2). Haskell, OCaml, Elixir, Clojure, F#, e cada vez mais as outras (streams de Java, map/filter de JavaScript, o React). Fácil de testar e de paralelizar; os efeitos têm de ser tratados com cuidado.

## Lógico

O programa é um conjunto de **factos e regras**; executar é **fazer perguntas**, e o sistema procura as respostas por unificação e retrocesso. Prolog (em Lógica e IA), Datalog. Descreves **o quê**, não **como**. Bom para regras, sistemas periciais, verificação, análise de programas (o CodeQL usa uma linguagem do estilo Datalog).

## Concorrente

Muitas atividades ao mesmo tempo. Dois modelos dominantes:

- **Memória partilhada com trincos** (threads em Java, C, Python): o mais comum, e o mais propenso a erros (Sistemas Operativos, lição 4).
- **Passagem de mensagens:** os processos não partilham memória; comunicam por mensagens.
  - **Atores** (Erlang, Elixir, Akka): cada ator tem uma caixa de correio e o seu estado privado. O WhatsApp corria em Erlang com poucas dezenas de engenheiros para centenas de milhões de utilizadores.
  - **CSP / canais** (Go): goroutines comunicam por canais. "Não comuniques partilhando memória; partilha memória comunicando."

## O mesmo problema em vários paradigmas

Total das marcações confirmadas de cada cliente:

```python run
marcacoes = [("Ana", 15, True), ("Rui", 45, False), ("Ana", 20, True), ("Eva", 45, True), ("Rui", 15, True)]

# imperativo: ciclos e um dicionário que vai mudando
totais = {}
for cliente, preco, confirmada in marcacoes:
    if confirmada:
        if cliente not in totais:
            totais[cliente] = 0
        totais[cliente] += preco
print("imperativo: ", totais)

# funcional: filtrar, agrupar e reduzir, sem mutar nada
from functools import reduce
from itertools import groupby
confirmadas = sorted(filter(lambda m: m[2], marcacoes))
funcional = {c: reduce(lambda acc, m: acc + m[1], grupo, 0)
             for c, grupo in groupby(confirmadas, key=lambda m: m[0])}
print("funcional:  ", funcional)

# orientado a objetos: o comportamento vive nos objetos
class Cliente:
    def __init__(self, nome): self.nome, self._marcacoes = nome, []
    def marca(self, preco, confirmada): self._marcacoes.append((preco, confirmada))
    def total(self): return sum(p for p, c in self._marcacoes if c)
clientes = {}
for nome, preco, conf in marcacoes:
    clientes.setdefault(nome, Cliente(nome)).marca(preco, conf)
print("objetos:    ", {n: c.total() for n, c in clientes.items()})

# lógico/declarativo: diz-se o quê (em SQL, o paradigma declarativo mais usado)
import sqlite3
db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE m (cliente, preco, confirmada)")
db.executemany("INSERT INTO m VALUES (?, ?, ?)", marcacoes)
print("declarativo:", dict(db.execute("SELECT cliente, SUM(preco) FROM m WHERE confirmada GROUP BY cliente")))

# atores (simulado): cada cliente é um ator que só reage a mensagens
from collections import deque
caixas = {n: deque() for n in {m[0] for m in marcacoes}}
estado = {n: 0 for n in caixas}
for c, p, conf in marcacoes:
    caixas[c].append(("marcou", p, conf))                 # enviar mensagem
for nome, caixa in caixas.items():                        # cada ator processa a sua caixa
    while caixa:
        _, p, conf = caixa.popleft()
        if conf: estado[nome] += p
print("atores:     ", dict(sorted(estado.items())))
```

Prevê se as cinco versões dão o mesmo resultado (e a ordem das chaves em cada uma). Repara no que muda: onde está o estado, quem o altera, e o que tens de ler para perceber o resultado.

## Escolher

Não há paradigma "melhor": há problemas que encaixam melhor num do que noutro. Regras de negócio → declarativo; transformação de dados → funcional; um domínio com entidades e ciclos de vida → objetos; muitas ligações simultâneas → atores ou canais; código perto do hardware → imperativo. As boas linguagens atuais (Rust, Kotlin, Scala, Swift, TypeScript, Python) deixam-te misturar.
