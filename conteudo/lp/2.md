O **cálculo lambda** (Alonzo Church, 1936) é a linguagem de programação mais pequena possível: só tem **variáveis**, **funções** e **aplicação**. Não tem números, nem booleanos, nem ciclos, e mesmo assim consegue exprimir qualquer cálculo que uma máquina de Turing faça. É a base teórica da programação funcional (Haskell, OCaml, Lisp) e das lambdas que todas as linguagens modernas têm.

## A sintaxe inteira

```
e ::= x            variável
    | λx. e        função (abstração): recebe x, devolve e
    | e₁ e₂        aplicação: chamar e₁ com o argumento e₂
```

Convenções: a aplicação associa à esquerda (`f a b` = `(f a) b`); o corpo de λ estende-se o mais possível para a direita. Funções de vários argumentos fazem-se com **currying**: λx. λy. x + y.

## Computar: redução β

Aplicar uma função é **substituir** o parâmetro pelo argumento no corpo:

(λx. e) a  →β  e[x := a]

```
(λx. x x) (λy. y)
→ (λy. y) (λy. y)
→ λy. y
```

Cuidado com a **captura de variáveis**: ao substituir, renomeiam-se as variáveis ligadas que colidiriam (conversão α: λx. x é o mesmo que λz. z).

## Tudo a partir de funções: codificações de Church

- **Booleanos:** VERDADE = λa. λb. a ; FALSO = λa. λb. b ; SE = λc. λa. λb. c a b.
- **Números:** n é "aplicar f n vezes": 0 = λf. λx. x ; 1 = λf. λx. f x ; 2 = λf. λx. f (f x).
- **Sucessor:** SUC = λn. λf. λx. f (n f x). **Soma:** λm. λn. λf. λx. m f (n f x).
- **Pares**, listas, e tudo o resto.

As lambdas do Python são suficientes para experimentar:

```python run
VERDADE = lambda a: lambda b: a
FALSO   = lambda a: lambda b: b
SE      = lambda c: lambda a: lambda b: c(a)(b)
E       = lambda p: lambda q: p(q)(p)
NAO     = lambda p: p(FALSO)(VERDADE)

ZERO = lambda f: lambda x: x
SUC  = lambda n: lambda f: lambda x: f(n(f)(x))
SOMA = lambda m: lambda n: lambda f: lambda x: m(f)(n(f)(x))
MULT = lambda m: lambda n: lambda f: m(n(f))

para_int = lambda n: n(lambda k: k + 1)(0)               # para ver o resultado
para_bool = lambda b: b(True)(False)

UM, DOIS = SUC(ZERO), SUC(SUC(ZERO))
TRES = SOMA(UM)(DOIS)
print("1 + 2 =", para_int(TRES))
print("3 × 3 =", para_int(MULT(TRES)(TRES)))
print("não (verdade e falso) =", para_bool(NAO(E(VERDADE)(FALSO))))
print("se verdade então 1 senão 2 =", para_int(SE(VERDADE)(UM)(DOIS)))
```

Prevê as quatro linhas. Nenhuma das "funções" usa números ou `if` do Python: tudo é aplicação de funções.

## Recursão sem nomes: o combinador Y

Sem `def` nem nomes, como é que uma função se chama a si própria? Com um **combinador de ponto fixo**: Y f = f (Y f). Numa linguagem que avalia os argumentos primeiro (como o Python), usa-se a versão Z:

```python run
Z = lambda f: (lambda x: f(lambda v: x(x)(v)))(lambda x: f(lambda v: x(x)(v)))

fatorial = Z(lambda auto: lambda n: 1 if n == 0 else n * auto(n - 1))
fib = Z(lambda auto: lambda n: n if n < 2 else auto(n - 1) + auto(n - 2))
print(fatorial(10), [fib(i) for i in range(10)])
```

`fatorial` nunca se refere a si própria pelo nome: o Z dá-lhe uma cópia de si mesma como argumento (`auto`). É uma ideia profunda: a recursão não precisa de estar "embutida" na linguagem.

## Ordens de avaliação

- **Ordem normal** (redex mais à esquerda e mais exterior primeiro, sem avaliar argumentos antes): se existe forma normal, encontra-a. Base da avaliação preguiçosa do Haskell.
- **Ordem aplicativa** (argumentos primeiro): a das linguagens comuns. Pode não terminar em casos onde a normal termina: `(λx. 1) Ω`, com Ω = (λx. x x)(λx. x x), que nunca acaba de reduzir.

## Cálculo lambda com tipos

O cálculo lambda **simplesmente tipado** acrescenta tipos (λx: Int. x + 1) e garante que os programas bem tipados terminam, mas perde o Y (e a Turing-completude). Sistemas de tipos mais ricos (System F, tipos dependentes) estão na base do Haskell, do Rocq e do Lean (lição 4 e Métodos Formais).
