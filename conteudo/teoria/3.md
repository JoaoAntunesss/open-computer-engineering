Nem todas as linguagens são regulares. "Palavras com o mesmo número de a e de b", "parênteses equilibrados", "palíndromos": nenhum autómato finito as reconhece, porque precisam de **contar sem limite**, e um autómato só tem memória finita. O **lema da bombagem** é a ferramenta para **provar** que uma linguagem não é regular. É também a explicação de porque é que não se deve tentar analisar HTML com expressões regulares.

## A intuição

Um AFD com p estados, ao ler uma palavra com p ou mais símbolos, passa por p + 1 estados (contando o inicial). Pelo **princípio da gaiola dos pombos**, repete algum estado. O pedaço entre as duas visitas é um **ciclo**: pode ser percorrido 0, 1, 2, … vezes, e o autómato continua a aceitar.

## O lema

Se L é regular, existe um número p (o comprimento de bombagem) tal que **toda** a palavra w ∈ L com |w| ≥ p se pode dividir em w = xyz com:

1. |y| ≥ 1 (o pedaço repetido não é vazio)
2. |xy| ≤ p (o ciclo aparece nos primeiros p símbolos)
3. xyⁱz ∈ L para **todo** i ≥ 0 (bombear para cima ou para baixo continua em L)

## Como se usa (prova por contradição)

O lema diz uma coisa sobre linguagens regulares. Para provar que L **não** é regular:

1. Supõe que L é regular, com comprimento de bombagem p.
2. **Escolhe** uma palavra w ∈ L com |w| ≥ p (bem escolhida, dependendo de p).
3. Mostra que, para **qualquer** divisão w = xyz que cumpra 1 e 2, há um i com xyⁱz ∉ L.
4. Contradição: L não é regular.

É como um jogo: o adversário escolhe p, tu escolhes w, o adversário escolhe a divisão, tu escolhes i e ganhas.

## Exemplo: L = { aⁿbⁿ : n ≥ 0 }

Supõe L regular, com p. Escolhe w = aᵖbᵖ. Como |xy| ≤ p, x e y estão **só nos a**: y = aᵏ com k ≥ 1. Bombeia com i = 2: xy²z = aᵖ⁺ᵏbᵖ, que tem mais a do que b: não está em L. Contradição.

Consequência prática: parênteses equilibrados (que contêm (ⁿ)ⁿ) não são regulares. Um validador de expressões, de JSON ou de HTML precisa de uma **pilha** (gramáticas, lição seguinte).

## Ver o lema a acontecer

Para uma linguagem regular, há sempre uma divisão que bombeia. Para aⁿbⁿ, nenhuma serve. O código procura divisões válidas para uma palavra dada:

```python run
import re

def divisoes_que_bombeiam(w, pertence, p):
    boas = []
    for i in range(0, p):                    # |x| = i
        for j in range(i + 1, p + 1):        # |xy| = j <= p, |y| >= 1
            x, y, z = w[:i], w[i:j], w[j:]
            if all(pertence(x + y * k + z) for k in range(0, 5)):
                boas.append((x, y, z))
    return boas

anbn = lambda s: bool(re.fullmatch(r"a*b*", s)) and s.count("a") == s.count("b")
par_de_as = lambda s: s.count("a") % 2 == 0
acaba_em_b = lambda s: s.endswith("b")

p = 4
print("aⁿbⁿ:", divisoes_que_bombeiam("a" * p + "b" * p, anbn, p))
print("número par de a:", divisoes_que_bombeiam("abbabb", par_de_as, p)[:3])
print("acaba em b:", divisoes_que_bombeiam("abab", acaba_em_b, p)[:3])
```

Prevê o primeiro resultado. Atenção: encontrar divisões para **uma** palavra e **um** p não prova que a linguagem é regular. O lema só serve num sentido.

## Outros exemplos de linguagens não regulares

- Palíndromos: escolhe w = aᵖbaᵖ.
- { aⁿ : n é um quadrado perfeito }: os comprimentos ficam cada vez mais afastados, e bombear dá um comprimento que não é quadrado.
- Palavras com o mesmo número de a e de b: se fosse regular, a interseção com a\*b\* (que é regular) também seria, mas essa interseção é aⁿbⁿ.

Este último truque é útil: as linguagens regulares são **fechadas** para a interseção, a união, o complemento e a concatenação. Muitas vezes, em vez do lema, usa-se o fecho para reduzir a um caso já conhecido.
