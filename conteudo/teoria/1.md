A teoria da computação pergunta o que é possível calcular, e com que recursos. Começa por uma ideia simples: um problema é uma **linguagem**, um conjunto de palavras. "Este texto é um email válido?" é perguntar se a palavra pertence à linguagem dos emails válidos. As **expressões regulares** descrevem a família mais simples de linguagens, e são das ferramentas mais usadas por programadores.

## Alfabetos, palavras e linguagens

- **Alfabeto** Σ: um conjunto finito de símbolos. {0, 1}, {a, …, z}, os caracteres Unicode.
- **Palavra:** uma sequência finita de símbolos. ε é a palavra vazia.
- **Linguagem:** um conjunto de palavras (pode ser infinito). Exemplos sobre {0, 1}:
  - L₁ = palavras que acabam em 0 (os números binários pares)
  - L₂ = palavras com o mesmo número de 0 e de 1
  - L₃ = palavras que são palíndromos

Operações sobre linguagens: **união** (L ∪ M), **concatenação** (LM: uma palavra de L seguida de uma de M) e **fecho de Kleene** (L*: zero ou mais palavras de L concatenadas).

## Expressões regulares (a definição formal)

São construídas a partir de:

- ∅, ε e cada símbolo a do alfabeto;
- se r e s são expressões regulares: **r | s** (união), **rs** (concatenação), **r*** (zero ou mais vezes).

Mais nada. Exemplos sobre {0, 1}:

| Expressão | Linguagem |
|---|---|
| (0\|1)*0 | acabam em 0 |
| 0*10* | têm exatamente um 1 |
| (0\|1)*11(0\|1)* | contêm 11 |
| (01)* | ε, 01, 0101, 010101, … |
| 1*(01+)* | não contêm 00 (ver os exercícios) |

## As expressões regulares na prática

As linguagens de programação acrescentam abreviaturas (que não aumentam o poder, só a comodidade):

- `+` (uma ou mais), `?` (zero ou uma), `{2,4}` (de 2 a 4 vezes)
- `[a-z]`, `[0-9]`, `\d` (dígito), `\w` (letra, dígito ou _), `\s` (espaço), `.` (qualquer carácter)
- `^` e `$` (início e fim)

E algumas extensões, como as **referências para trás** (`(a+)b\1`), que vão **além** das linguagens regulares e podem tornar a pesquisa exponencial.

```python run
import re

testes = {
    r"[01]*0":               ["10", "11", "0", ""],
    r"0*10*":                ["1", "0100", "0110", "000"],
    r"\d{4}-\d{3}":          ["4450-123", "4450123", "445-1234"],
    r"[A-Z]{2}-\d{2}-[A-Z]{2}": ["AA-00-BB", "aa-00-bb", "AB-12-CD"],
    r"[^@\s]+@[^@\s]+\.\w+":  ["ana@uab.pt", "ana@uab", "a b@c.pt"],
}
for padrao, palavras in testes.items():
    print(padrao, [(p, bool(re.fullmatch(padrao, p))) for p in palavras])
```

Prevê cada `True`/`False` antes de correr. `fullmatch` exige que a palavra **inteira** corresponda (como `^...$`).

## Cuidado com expressões que "parecem certas"

- Validar emails com expressões regulares é notoriamente difícil; a expressão acima aceita muita coisa inválida. Para validar a sério, envia um email de confirmação.
- **Retrocesso catastrófico:** `(a+)+$` aplicado a "aaaaaaaaaaaaaaaaaaaaaaaab" pode demorar segundos ou anos, porque o motor experimenta todas as formas de dividir os "a". Já deitou abaixo serviços (Cloudflare em 2019, Stack Overflow em 2016). Evita quantificadores encaixados sobre o mesmo texto.
