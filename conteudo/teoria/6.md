Há perguntas sobre programas que **nenhum** programa consegue responder, por mais rápido que seja o computador ou mais esperto o programador. A mais famosa é o **problema da paragem**: dado um programa e uma entrada, o programa termina ou fica a correr para sempre? Turing provou em 1936 que não existe algoritmo que responda sempre corretamente. É um limite da própria computação, não da tecnologia.

## Decidível, reconhecível

- Uma linguagem (um problema de sim/não) é **decidível** se existe uma máquina de Turing que **para sempre**, com a resposta certa.
- É **reconhecível** (semi-decidível) se existe uma máquina que para e diz "sim" quando a resposta é sim, mas pode ficar a correr para sempre quando é não.

Exemplos decidíveis: "este número é primo?", "este AFD aceita alguma palavra?", "esta palavra pertence a esta gramática?".

## O problema da paragem

**HALT** = { (P, x) : o programa P, com a entrada x, termina }.

HALT é reconhecível (corre P com x; se terminar, diz sim). Mas **não é decidível**.

## A prova (por diagonalização)

Supõe que existia uma função `para(programa, entrada)` que devolve sempre `True` ou `False` corretamente. Constrói-se este programa:

```python
def do_contra(p):
    if para(p, p):        # se p, aplicado a si próprio, termina...
        while True:       # ...fico em ciclo infinito
            pass
    else:
        return            # ...senão, termino
```

Pergunta: `do_contra(do_contra)` termina?

- Se termina, então `para(do_contra, do_contra)` é `True`, e por isso entra no ciclo infinito: **não termina**. Contradição.
- Se não termina, então `para(...)` é `False`, e por isso faz `return`: **termina**. Contradição.

Logo, a função `para` não pode existir. É o mesmo argumento do paradoxo do mentiroso ("esta frase é falsa") e da diagonal de Cantor.

## "Mas os programas param ou não, é só ver"

Experimenta a conjetura de **Collatz**: começa num número; se for par, divide por 2; se for ímpar, multiplica por 3 e soma 1. Repete. Chega sempre a 1?

```python run
def collatz(n):
    passos = 0
    while n != 1:
        n = n // 2 if n % 2 == 0 else 3 * n + 1
        passos += 1
    return passos

for n in (6, 7, 27, 97, 871):
    print(n, collatz(n), "passos")
print("o maior até 10 000:", max(range(1, 10_001), key=collatz))
```

Este ciclo de 4 linhas termina para todos os números testados (até mais de 10²⁰), mas **ninguém sabe** se termina para todos. Se houvesse um decisor da paragem, resolvia este problema (e muitos outros da matemática) de uma vez.

## Reduções: espalhar a indecidibilidade

Para provar que um problema B é indecidível, mostra-se que, se B fosse decidível, HALT também seria (redução de HALT a B). Assim se prova que são indecidíveis:

- "Este programa alguma vez escreve 'olá'?"
- "Estes dois programas calculam a mesma função?"
- "Este programa tem um vírus?" (no sentido de "alguma vez faz X")

**Teorema de Rice:** qualquer propriedade **não trivial** do **comportamento** de um programa (da função que calcula, não do texto) é indecidível.

## Consequências práticas

- Nenhum compilador consegue avisar de **todos** os ciclos infinitos, nem de todo o código morto, nem de todas as divisões por zero.
- Analisadores estáticos (linters, verificadores de tipos, ferramentas de segurança) são sempre **aproximações**: ou dão falsos alarmes, ou deixam escapar erros, ou recusam alguns programas corretos. Os sistemas de tipos escolhem ser conservadores: recusam programas que talvez funcionassem.
- Antivírus usam assinaturas e heurísticas, porque detetar "comportamento malicioso" em geral é indecidível.
- Isto **não** quer dizer que não se possa provar que um programa **concreto** termina: só que não há um método que funcione para **todos**.
