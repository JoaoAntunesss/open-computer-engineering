Uma **redução** transforma um problema noutro. Se A se reduz a B em tempo polinomial, B é pelo menos tão difícil como A. Com reduções, a teoria constrói uma rede de problemas ligados entre si: os **NP-completos**, que são "os mais difíceis de NP". Nesta lição vês a prova de que o SAT está no centro dessa rede e fazes, em código, uma redução clássica: de 3-SAT a clique.

## Redução polinomial

A ≤ₚ B se existe uma função f, calculável em tempo polinomial, tal que:

x é uma instância "sim" de A ⇔ f(x) é uma instância "sim" de B.

Consequências:

- Se B ∈ P, então A ∈ P (resolve-se A transformando e resolvendo B).
- Se A é difícil, B também é (contrarrecíproco).

Cuidado com a direção: para provar que **B é difícil**, reduz-se um problema **difícil conhecido** **a** B.

## NP-difícil e NP-completo

- **NP-difícil:** todo o problema de NP se reduz a ele. (Pode nem estar em NP, como o problema da paragem.)
- **NP-completo:** NP-difícil **e** em NP.

## Cook-Levin: o SAT é NP-completo

Ideia da prova: seja A um problema qualquer de NP, com uma máquina de Turing não determinista M que o resolve em tempo p(n). Para uma entrada x, constrói-se uma fórmula booleana que descreve "existe uma execução de M sobre x que aceita": variáveis para "a célula i contém o símbolo s no passo t", "a cabeça está na posição i no passo t", "o estado é q no passo t", e cláusulas que obrigam cada passo a seguir a tabela de transições. A fórmula tem tamanho polinomial e é satisfazível se e só se M aceita x.

A partir daqui, cada problema novo prova-se NP-completo por redução a partir de um já conhecido. Uma pequena parte da árvore:

```
SAT → 3-SAT → Clique → Conjunto independente → Cobertura de vértices
          ↘ 3-coloração          ↘ Ciclo hamiltoniano → Caixeiro-viajante
          ↘ Soma de subconjunto → Mochila
```

## Redução de 3-SAT a clique

Dada uma fórmula com k cláusulas (cada uma com 3 literais), constrói-se um grafo:

- um vértice para **cada literal de cada cláusula** (3k vértices);
- uma aresta entre dois vértices **de cláusulas diferentes** que **não se contradigam** (não são x e ¬x).

A fórmula é satisfazível ⇔ o grafo tem um **clique de tamanho k**.

Porquê: um clique de tamanho k escolhe um literal por cláusula (vértices da mesma cláusula não estão ligados), e todos compatíveis entre si (não há x e ¬x): pôr esses literais a verdadeiro satisfaz todas as cláusulas. E ao contrário: de uma atribuição que satisfaz, escolhe-se em cada cláusula um literal verdadeiro; são compatíveis, logo formam um clique.

```python run
from itertools import combinations, product

def reduz(formula):
    vertices = [(i, lit) for i, clausula in enumerate(formula) for lit in clausula]
    arestas = {(u, v) for u, v in combinations(vertices, 2)
               if u[0] != v[0] and u[1] != -v[1]}
    return vertices, arestas, len(formula)

def tem_clique(vertices, arestas, k):
    for grupo in combinations(vertices, k):
        if all((u, v) in arestas or (v, u) in arestas for u, v in combinations(grupo, 2)):
            return grupo
    return None

def satisfazivel(formula):
    n = max(abs(l) for c in formula for l in c)
    return any(all(any((l > 0) == bits[abs(l) - 1] for l in c) for c in formula)
               for bits in product([False, True], repeat=n))

formulas = {
    "sim": [[1, 2, -3], [-1, 3, 2], [-2, -3, 1]],
    "não": [[1, 1, 1], [-1, -1, -1], [2, 3, 3]],
}
for nome, f in formulas.items():
    v, a, k = reduz(f)
    clique = tem_clique(v, a, k)
    print(nome, "| SAT:", satisfazivel(f), "| clique de", k, ":", clique)
```

Prevê as duas linhas. A redução é polinomial (no máximo (3k)² arestas); quem é exponencial é a procura do clique.

## Para que serve saber isto

Quando um problema do teu trabalho (horários, distribuição de turnos, alocação de salas) se revela NP-completo, deixa de fazer sentido procurar um algoritmo exato e rápido para todos os casos. Passas às alternativas: instâncias pequenas, casos especiais, aproximações, heurísticas, solvers SAT e de programação inteira.
