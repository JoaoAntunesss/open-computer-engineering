Desenhar um processador porta a porta é impossível. Os engenheiros descrevem o hardware em texto, com **linguagens de descrição de hardware** (HDL) como Verilog e VHDL, e ferramentas transformam essa descrição em circuitos reais ou em configurações de FPGA.

## Não é programação

Um programa executa instruções uma a seguir à outra. Uma descrição em HDL descreve **hardware que existe todo ao mesmo tempo**: cada linha é um pedaço de circuito a funcionar em paralelo.

## Verilog combinatório

```verilog
module somador4 (
    input  [3:0] a, b,
    input        cin,
    output [3:0] s,
    output       cout
);
    assign {cout, s} = a + b + cin;   // a ferramenta gera o somador
endmodule
```

**assign** descreve uma ligação contínua: s muda sempre que a ou b mudam.

## Verilog sequencial

```verilog
module contador (
    input            clk, reset,
    output reg [3:0] q
);
    always @(posedge clk) begin
        if (reset) q <= 4'd0;
        else       q <= q + 1;
    end
endmodule
```

**always @(posedge clk)** descreve flip-flops que mudam no flanco ascendente. O operador **<=** é uma atribuição não bloqueante: todos os registos atualizam ao mesmo tempo, como no hardware real.

## Testar com um *testbench*

Escreve-se um módulo que só existe na simulação, gera o relógio e as entradas, e verifica as saídas:

```verilog
module tb;
    reg clk = 0, reset = 1;
    wire [3:0] q;
    contador c (.clk(clk), .reset(reset), .q(q));
    always #5 clk = ~clk;
    initial begin
        $dumpfile("ondas.vcd"); $dumpvars(0, tb);
        #12 reset = 0;
        #100 $finish;
    end
endmodule
```

Compila e corre com o Icarus Verilog (**iverilog -o sim tb.v contador.v && vvp sim**) e vê as formas de onda no GTKWave.

## Síntese e FPGA

A **síntese** converte o Verilog em portas e flip-flops. Numa **FPGA**, esse circuito é carregado num chip reconfigurável; num chip feito de raiz (ASIC), vira máscaras de fabrico. Nem todo o Verilog é sintetizável: atrasos como **#5** e **$display** só existem na simulação.

## VHDL

VHDL faz o mesmo com uma sintaxe mais verbosa e mais tipos. É comum na Europa e na indústria aeroespacial; Verilog é mais comum nos EUA. As ideias são as mesmas.

## Erros comuns

- Usar **=** (bloqueante) em blocos sequenciais e obter um circuito diferente do pretendido.
- Esquecer um caso num bloco combinatório e gerar um trinco sem querer.
- Pensar que as linhas executam por ordem.
- Escrever código não sintetizável e só descobrir na síntese.
