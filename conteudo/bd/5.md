Uma base de dados não deve confiar nas aplicações para manter os dados corretos: há várias aplicações, há bugs, há pessoas a correr SQL à mão. As **restrições de integridade** fazem a própria base de dados recusar dados inválidos. Os **gatilhos** (*triggers*) correm código automaticamente quando os dados mudam. As **vistas** guardam consultas com nome, para simplificar e para controlar o acesso.

## Restrições

```sql
CREATE TABLE servico (
  id      INTEGER PRIMARY KEY,                    -- único e não nulo
  nome    TEXT NOT NULL UNIQUE,                   -- obrigatório e sem repetidos
  preco   NUMERIC NOT NULL CHECK (preco > 0),     -- regra de negócio
  duracao INTEGER NOT NULL DEFAULT 30 CHECK (duracao BETWEEN 5 AND 480)
);

CREATE TABLE marcacao (
  id         INTEGER PRIMARY KEY,
  cliente_id INTEGER NOT NULL REFERENCES cliente(id) ON DELETE CASCADE,
  servico_id INTEGER NOT NULL REFERENCES servico(id) ON DELETE RESTRICT,
  inicio     TEXT NOT NULL,
  UNIQUE (servico_id, inicio)                     -- restrição sobre várias colunas
);
```

**Chaves estrangeiras:** a marcação só pode referir um cliente que existe. E quando se apaga o cliente?

- `RESTRICT` / `NO ACTION`: não deixa apagar enquanto houver marcações.
- `CASCADE`: apaga também as marcações.
- `SET NULL`: põe a referência a `NULL`.

## Ver as restrições a trabalhar

Prevê quais destes comandos são recusados:

```python run
import sqlite3
db = sqlite3.connect(":memory:")
db.execute("PRAGMA foreign_keys = ON")       # no SQLite, as chaves estrangeiras são opcionais
db.executescript("""
CREATE TABLE cliente (id INTEGER PRIMARY KEY, nome TEXT NOT NULL);
CREATE TABLE servico (id INTEGER PRIMARY KEY, nome TEXT NOT NULL UNIQUE,
                      preco NUMERIC NOT NULL CHECK (preco > 0));
CREATE TABLE marcacao (id INTEGER PRIMARY KEY,
                       cliente_id INTEGER NOT NULL REFERENCES cliente(id) ON DELETE CASCADE,
                       servico_id INTEGER NOT NULL REFERENCES servico(id) ON DELETE RESTRICT);
CREATE TABLE registo (quando TEXT DEFAULT CURRENT_TIMESTAMP, mensagem TEXT);
CREATE TRIGGER aviso_preco AFTER UPDATE OF preco ON servico
WHEN NEW.preco > OLD.preco * 1.2
BEGIN
  INSERT INTO registo (mensagem) VALUES ('subida grande: ' || NEW.nome || ' ' || OLD.preco || ' -> ' || NEW.preco);
END;
INSERT INTO cliente VALUES (1, 'Ana'), (2, 'Rui');
INSERT INTO servico VALUES (1, 'Corte', 15), (2, 'Coloração', 45);
INSERT INTO marcacao VALUES (1, 1, 1), (2, 1, 2), (3, 2, 1);
""")

comandos = [
    "INSERT INTO servico VALUES (3, 'Manicure', -5)",
    "INSERT INTO servico VALUES (4, 'Corte', 20)",
    "INSERT INTO marcacao VALUES (4, 99, 1)",
    "DELETE FROM servico WHERE id = 1",
    "DELETE FROM cliente WHERE id = 1",
    "UPDATE servico SET preco = 60 WHERE id = 2",
]
for sql in comandos:
    try:
        db.execute(sql)
        print("OK      ", sql)
    except sqlite3.IntegrityError as e:
        print("RECUSADO", sql, "→", e)

print("marcações que sobram:", db.execute("SELECT id FROM marcacao").fetchall())
print("registo:", db.execute("SELECT mensagem FROM registo").fetchall())
```

## Gatilhos

Um gatilho corre automaticamente `BEFORE` ou `AFTER` um `INSERT`, `UPDATE` ou `DELETE`. Usos:

- **Auditoria:** guardar quem mudou o quê (como o `registo` acima).
- **Regras complexas** que um `CHECK` não consegue verificar, porque envolvem outras tabelas (por exemplo, impedir marcações sobrepostas para o mesmo funcionário).
- **Manter valores derivados** (um total numa tabela de encomendas).

Cuidado: gatilhos são lógica "escondida". Quem lê o código da aplicação não os vê, e gatilhos que disparam outros gatilhos tornam-se difíceis de seguir. Usa-os com moderação e documenta-os.

## Vistas

Uma vista é uma consulta com nome, que se usa como uma tabela:

```sql
CREATE VIEW agenda_hoje AS
SELECT m.inicio, c.nome AS cliente, s.nome AS servico
FROM marcacao m JOIN cliente c ON c.id = m.cliente_id JOIN servico s ON s.id = m.servico_id
WHERE date(m.inicio) = date('now');

SELECT * FROM agenda_hoje ORDER BY inicio;
```

- **Simplificam:** escondem junções repetidas.
- **Segurança:** dá-se a um utilizador acesso à vista, sem acesso às tabelas (por exemplo, sem a coluna do NIF).
- **Vistas materializadas** (PostgreSQL): guardam o resultado e atualizam-se quando se pede (`REFRESH MATERIALIZED VIEW`). Boas para relatórios pesados.
