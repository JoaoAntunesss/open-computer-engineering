**NoSQL** é o nome guarda-chuva para bases de dados que não usam o modelo relacional de tabelas e junções. Apareceram para casos em que o modelo relacional fica desajeitado ou não escala: milhões de escritas por segundo, dados com formas muito variáveis, relações em rede. O Firebase que usas nos sites é um exemplo. Não substituem o SQL: são ferramentas para problemas diferentes.

## Os quatro tipos principais

| Tipo | Modelo | Exemplos | Bom para |
|---|---|---|---|
| **Chave-valor** | um dicionário gigante | Redis, DynamoDB, etcd | cache, sessões, contadores |
| **Documentos** | documentos JSON agrupados em coleções | MongoDB, Firestore, CouchDB | perfis, catálogos, conteúdos com forma variável |
| **Colunas largas** | linhas com colunas variáveis, por partição | Cassandra, HBase, Bigtable | séries temporais, escrita massiva |
| **Grafos** | nós e arestas com propriedades | Neo4j, Amazon Neptune | redes sociais, recomendações, fraude |

## Documentos: desenhar para a leitura

No modelo relacional, normaliza-se e junta-se na consulta. Num documento, junta-se **na escrita**: guarda-se junto o que se lê junto.

```json
{
  "_id": "marcacao_123",
  "dia": "2026-11-09T10:00",
  "cliente": { "id": "c1", "nome": "Ana", "telefone": "912345678" },
  "servicos": [
    { "nome": "Corte", "preco": 15 },
    { "nome": "Coloração", "preco": 45 }
  ],
  "estado": "confirmada"
}
```

Uma leitura traz tudo, sem junções. O preço: o nome da Ana está copiado em cada marcação. Se mudar, é preciso atualizar muitos documentos (ou aceitar que os antigos fiquem com o nome antigo). A regra prática:

- **Embutir** o que pertence ao documento e se lê sempre com ele (as linhas de uma encomenda).
- **Referenciar** (guardar só o id) o que é partilhado e muda (o perfil do cliente).

## Chave-valor e cache

O Redis guarda tudo em memória: leituras e escritas em microssegundos. Uso clássico, a **cache** à frente de uma base de dados lenta:

```python run
import time
base_de_dados = {"produto:1": "Champô", "produto:2": "Condicionador"}
cache, expira = {}, {}

def ler_lento(chave):
    time.sleep(0.05)                 # simula uma consulta de 50 ms
    return base_de_dados.get(chave)

def ler(chave, validade=60):
    agora = time.time()
    if chave in cache and expira[chave] > agora:
        return cache[chave], "cache"
    valor = ler_lento(chave)
    cache[chave], expira[chave] = valor, agora + validade
    return valor, "base de dados"

for chave in ["produto:1", "produto:1", "produto:2", "produto:1"]:
    t = time.perf_counter()
    valor, origem = ler(chave)
    print(f"{chave}: {valor:14} de {origem:13} ({(time.perf_counter() - t) * 1000:.1f} ms)")

base_de_dados["produto:1"] = "Champô Novo"         # alguém muda o produto
print("depois da mudança:", ler("produto:1"))
```

Prevê de onde vem cada leitura. A última linha mostra o problema mais difícil das caches: **invalidação**. A cache continua a dar o valor antigo até expirar.

## Grafos

Em SQL, "amigos de amigos de amigos" são três junções de uma tabela consigo mesma, cada vez mais lentas. Numa base de grafos, seguir arestas é a operação base. Em Cypher (Neo4j):

```
MATCH (eu:Pessoa {nome: 'Ana'})-[:AMIGO*2..3]-(sugestao)
WHERE NOT (eu)-[:AMIGO]-(sugestao)
RETURN sugestao.nome, count(*) AS em_comum ORDER BY em_comum DESC
```

## O teorema CAP

Num sistema distribuído, quando há uma **partição** de rede (P), tem de se escolher entre **consistência** (C: todos veem os mesmos dados, ou o sistema recusa responder) e **disponibilidade** (A: responde sempre, mesmo com dados possivelmente desatualizados).

- Muitas bases NoSQL escolhem **disponibilidade** e **consistência eventual**: as réplicas acabam por convergir, mas durante uns instantes podes ler um valor antigo. Bom para "gostos" e contadores de visualizações; mau para saldos bancários.
- Outras (e as relacionais distribuídas, como o Spanner ou o CockroachDB) escolhem consistência.

## Quando escolher o quê

- Dados com muitas relações, integridade importante, consultas variadas e imprevistas: **relacional** (PostgreSQL é a escolha segura por omissão; até guarda JSON com `jsonb`).
- Acesso por chave, velocidade extrema, dados que podem ser perdidos e reconstruídos: **chave-valor**.
- Documentos auto-contidos, esquema variável, sincronização em tempo real com aplicações móveis: **documentos** (Firestore).
- Relações em rede, caminhos e recomendações: **grafos**.

Muitos sistemas usam várias (*persistência poliglota*): PostgreSQL para os dados principais, Redis para cache e sessões, Elasticsearch para pesquisa de texto.
