O **modelo relacional** é a base de quase todas as bases de dados usadas hoje (PostgreSQL, MySQL, SQLite, Oracle, SQL Server). Os dados guardam-se em **relações** (tabelas), e a **álgebra relacional** define as operações sobre elas. Perceber a álgebra é perceber o que o SQL faz por baixo, e como o otimizador o executa.

## Relações, tuplos e chaves

- Uma **relação** é uma tabela com nome e atributos (colunas) de tipos definidos.
- Cada linha é um **tuplo**. Numa relação pura não há linhas repetidas nem uma ordem.
- **Chave candidata:** conjunto mínimo de atributos que identifica cada tuplo. Uma delas é escolhida como **chave primária**.
- **Chave estrangeira:** atributo que referencia a chave primária de outra tabela. É assim que se ligam tabelas.

## Do modelo EA para tabelas

| No modelo EA | No modelo relacional |
|---|---|
| entidade | tabela com os seus atributos; a chave é a chave primária |
| associação 1:N | chave estrangeira do lado N (a marcação guarda `cliente_id`) |
| associação 1:1 | chave estrangeira num dos lados, com `UNIQUE` |
| associação N:M | **tabela nova** com as duas chaves estrangeiras (e os atributos da associação) |
| atributo multivalor | tabela nova (`telefones(cliente_id, numero)`) |

## As operações da álgebra relacional

Cada operação recebe relações e devolve uma relação, por isso combinam-se livremente.

| Operação | Símbolo | O que faz | Em SQL |
|---|---|---|---|
| Seleção | σ | fica com as linhas que cumprem uma condição | `WHERE` |
| Projeção | π | fica com algumas colunas | `SELECT a, b` |
| Produto cartesiano | × | todas as combinações de linhas | `FROM A, B` |
| Junção | ⋈ | produto + seleção pela condição de ligação | `JOIN … ON` |
| União, interseção, diferença | ∪ ∩ − | operações de conjuntos (mesmas colunas) | `UNION`, `INTERSECT`, `EXCEPT` |
| Renomeação | ρ | muda nomes | `AS` |

**Exemplo:** "nomes dos clientes que marcaram coloração":

π_nome(σ_servico='coloração'(Cliente ⋈ Marcacao ⋈ Servico))

## A álgebra em código

Uma relação pode ser vista como uma lista de dicionários, e cada operação como uma função. Prevê o resultado de cada linha:

```python run
clientes = [{"cid": 1, "nome": "Ana"}, {"cid": 2, "nome": "Rui"}, {"cid": 3, "nome": "Eva"}]
marcacoes = [{"cid": 1, "servico": "corte"}, {"cid": 1, "servico": "coloração"},
             {"cid": 3, "servico": "corte"}]

def selecao(r, cond):    return [t for t in r if cond(t)]
def projecao(r, attrs):  return [dict(s) for s in {tuple((a, t[a]) for a in attrs) for t in r}]
def juncao(r, s, attr):  return [{**t, **u} for t in r for u in s if t[attr] == u[attr]]
def diferenca(r, s):     return [t for t in r if t not in s]

j = juncao(clientes, marcacoes, "cid")
print(sorted(x["nome"] for x in projecao(selecao(j, lambda t: t["servico"] == "corte"), ["nome"])))
print(sorted(x["nome"] for x in projecao(j, ["nome"])))
com_marcacoes = projecao(j, ["cid", "nome"])
print([t["nome"] for t in diferenca(clientes, com_marcacoes)])
```

A projeção usa um conjunto, porque numa relação não há linhas repetidas. O SQL, por omissão, **mantém** as repetidas (é preciso `DISTINCT`).

## Junções

- **Junção interna** (`INNER JOIN`): só as linhas com correspondência dos dois lados. Rui, sem marcações, desaparece.
- **Junção externa à esquerda** (`LEFT JOIN`): todas as linhas da esquerda; quando não há correspondência, as colunas da direita ficam `NULL`. Útil para "clientes e o número de marcações, incluindo os que têm zero".
- **Junção natural:** junta pelas colunas com o mesmo nome. Perigosa: se alguém acrescentar uma coluna com um nome igual, a query muda de significado.

## Divisão: "todos"

"Clientes que já fizeram **todos** os serviços" é a **divisão** (÷). Não há operador em SQL; escreve-se com dupla negação: "clientes para os quais **não existe** serviço que eles **não** tenham feito".
