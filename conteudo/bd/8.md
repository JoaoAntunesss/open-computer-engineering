Uma **transação** é um grupo de operações que a base de dados trata como uma só: ou acontecem todas, ou nenhuma. É o que garante que uma transferência bancária não tira dinheiro de uma conta sem o pôr na outra, mesmo que o servidor falhe a meio ou que mil pessoas façam transferências ao mesmo tempo.

## ACID

- **Atomicidade:** tudo ou nada. Se algo falha a meio, desfaz-se o que foi feito (*rollback*).
- **Consistência:** a transação leva a base de dados de um estado válido para outro (as restrições continuam a ser cumpridas).
- **Isolamento:** transações concorrentes não se veem a meio; o resultado é como se tivessem corrido uma de cada vez (em maior ou menor grau, conforme o nível de isolamento).
- **Durabilidade:** depois do `COMMIT`, os dados sobrevivem a uma falha de energia.

```sql
BEGIN;
UPDATE conta SET saldo = saldo - 100 WHERE id = 1;
UPDATE conta SET saldo = saldo + 100 WHERE id = 2;
COMMIT;          -- ou ROLLBACK; para desistir
```

## Atomicidade em ação

Prevê o saldo final das duas contas:

```python run
import sqlite3
db = sqlite3.connect(":memory:", isolation_level=None)      # transações controladas à mão
db.executescript("""
CREATE TABLE conta (id INTEGER PRIMARY KEY, titular TEXT, saldo INTEGER CHECK (saldo >= 0));
INSERT INTO conta VALUES (1, 'Ana', 100), (2, 'Rui', 50);
""")

def transferir(de, para, valor):
    try:
        db.execute("BEGIN")
        db.execute("UPDATE conta SET saldo = saldo + ? WHERE id = ?", (valor, para))
        db.execute("UPDATE conta SET saldo = saldo - ? WHERE id = ?", (valor, de))   # pode violar o CHECK
        db.execute("COMMIT")
        print(f"transferidos {valor}")
    except sqlite3.IntegrityError as e:
        db.execute("ROLLBACK")
        print(f"falhou ({e}); nada mudou")

transferir(1, 2, 30)
transferir(1, 2, 500)
print(db.execute("SELECT titular, saldo FROM conta").fetchall())
```

Repara que a ordem dos `UPDATE` é a "errada" (primeiro deposita, depois levanta). Sem transação, a segunda transferência deixava o Rui com mais 500 € e a Ana com o mesmo saldo.

## Problemas de concorrência

Sem isolamento suficiente, aparecem anomalias:

- **Leitura suja:** ler dados que outra transação escreveu mas ainda não confirmou (e que podem ser desfeitos).
- **Leitura não repetível:** ler a mesma linha duas vezes e obter valores diferentes, porque outra transação a alterou entretanto.
- **Fantasmas:** repetir uma consulta e aparecerem linhas novas.
- **Atualização perdida:** duas transações leem o saldo 100, uma soma 10, a outra soma 20; a última a escrever ganha e fica 120 em vez de 130.

## Níveis de isolamento (SQL)

| Nível | Leitura suja | Não repetível | Fantasmas |
|---|---|---|---|
| Read uncommitted | possível | possível | possível |
| Read committed (omissão no PostgreSQL) | não | possível | possível |
| Repeatable read | não | não | possível (não no PostgreSQL) |
| Serializable | não | não | não |

Mais isolamento é mais seguro, mas com mais esperas ou mais transações abortadas que é preciso repetir.

## Como se implementa

- **Trincos em duas fases** (2PL): uma transação adquire trincos (partilhados para ler, exclusivos para escrever) e só os liberta no fim. Garante serializabilidade, mas pode dar **interbloqueios**, que a base de dados deteta e resolve abortando uma das transações.
- **MVCC** (controlo de concorrência multiversão, PostgreSQL, MySQL InnoDB, Oracle): cada escrita cria uma **nova versão** da linha; cada transação vê uma "fotografia" consistente dos dados do seu início. Leitores nunca bloqueiam escritores, nem o contrário. As versões antigas são limpas depois (`VACUUM` no PostgreSQL).

## Evitar a atualização perdida na prática

```sql
-- 1. Deixar a base de dados fazer a conta (atómico):
UPDATE conta SET saldo = saldo + 10 WHERE id = 1;

-- 2. Trancar a linha ao ler, se a lógica estiver na aplicação:
BEGIN;
SELECT saldo FROM conta WHERE id = 1 FOR UPDATE;
-- ... calcular ...
UPDATE conta SET saldo = 110 WHERE id = 1;
COMMIT;

-- 3. Controlo otimista: uma coluna de versão
UPDATE conta SET saldo = 110, versao = versao + 1 WHERE id = 1 AND versao = 7;
-- se afetou 0 linhas, alguém mudou primeiro: ler de novo e repetir
```
