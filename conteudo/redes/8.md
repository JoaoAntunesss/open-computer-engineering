O IPv4 tem cerca de 4,3 mil milhões de endereços, e há muito mais aparelhos do que isso. A Internet sobreviveu graças ao **NAT**, que põe redes inteiras atrás de um único endereço público. As **firewalls** decidem que tráfego entra e sai. E o **IPv6**, com endereços de sobra, é a solução de longo prazo, já usada por cerca de metade do tráfego da Google.

## NAT

Em casa, todos os aparelhos têm endereços **privados** (192.168.1.x), que não circulam na Internet. O router tem **um** endereço público e faz a tradução:

1. O PC 192.168.1.20, porta 51000, envia para 142.250.184.4:443.
2. O router troca a origem pelo seu IP público e por uma porta livre (por exemplo, 85.240.10.7:40001) e guarda a associação numa tabela.
3. A resposta chega a 85.240.10.7:40001; o router consulta a tabela e entrega a 192.168.1.20:51000.

```python run
import itertools

class RouterNAT:
    def __init__(self, ip_publico):
        self.ip_publico = ip_publico
        self.portas = itertools.count(40000)
        self.tabela = {}          # porta pública -> (ip privado, porta privada)
        self.inversa = {}

    def sai(self, origem, destino):
        if origem not in self.inversa:
            p = next(self.portas)
            self.tabela[p] = origem
            self.inversa[origem] = p
        return (self.ip_publico, self.inversa[origem]), destino

    def entra(self, origem, destino):
        ip, porta = destino
        if porta not in self.tabela:
            return None           # ninguém pediu isto: descartado
        return origem, self.tabela[porta]

r = RouterNAT("85.240.10.7")
print(r.sai(("192.168.1.20", 51000), ("142.250.184.4", 443)))
print(r.sai(("192.168.1.31", 51000), ("142.250.184.4", 443)))
print(r.entra(("142.250.184.4", 443), ("85.240.10.7", 40001)))
print(r.entra(("203.0.113.66", 22), ("85.240.10.7", 40500)))
```

Prevê as quatro linhas. A última mostra um efeito secundário útil do NAT: ligações que começam **de fora** não têm entrada na tabela e são descartadas.

**Consequências do NAT:**

- Para ter um servidor em casa (uma câmara, um servidor de jogos), é preciso **reencaminhar portas** no router: "o que chegar à porta 8080 vai para 192.168.1.50:80".
- Aplicações par-a-par (chamadas de vídeo) precisam de técnicas para atravessar o NAT (STUN, TURN, *hole punching*).
- Os fornecedores usam muitas vezes **CGNAT** (NAT do lado deles): vários clientes partilham o mesmo IP público, e nem o reencaminhamento de portas funciona.

## Firewalls

Uma firewall filtra tráfego segundo regras:

- **Sem estado:** olha para cada pacote isolado (IP, porta, protocolo). "Bloquear tudo para a porta 23."
- **Com estado** (a habitual): lembra-se das ligações. Deixa entrar as respostas a ligações iniciadas de dentro e bloqueia o resto. É o comportamento por omissão dos routers domésticos.
- **De aplicação** (WAF, proxies): entende HTTP e pode bloquear, por exemplo, tentativas de injeção de SQL.

Regras típicas de um servidor web (`ufw` no Linux):

```
ufw default deny incoming     # por omissão, nada entra
ufw default allow outgoing
ufw allow 443/tcp             # HTTPS
ufw allow 80/tcp              # HTTP (para redirecionar para HTTPS)
ufw allow from 85.240.10.7 to any port 22   # SSH só a partir de casa
ufw enable
```

Princípio do **menor privilégio**: fecha tudo e abre só o necessário. A base de dados (5432) nunca deve estar aberta à Internet.

## IPv6

- Endereços de **128 bits**: 3,4 × 10³⁸. Escrevem-se em hexadecimal: `2001:0db8:0000:0000:0000:ff00:0042:8329`, abreviado `2001:db8::ff00:42:8329` (zeros à esquerda omitidos, uma sequência de grupos a zero substituída por `::`).
- Cada rede local é normalmente um /64; os aparelhos configuram o seu endereço sozinhos (SLAAC).
- **Sem NAT:** todos os aparelhos têm endereço público. A proteção passa a ser só da firewall (que, nos routers domésticos, bloqueia por omissão as ligações vindas de fora).
- Cabeçalho mais simples; os routers não fragmentam pacotes.
- Convivência: a maioria das redes é **dual stack** (IPv4 e IPv6 ao mesmo tempo).
