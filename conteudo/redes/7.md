Um **socket** é a ponta de uma comunicação de rede, vista por um programa. A interface de sockets (criada no Unix de Berkeley, em 1983) é a mesma em C, Python, Java e quase todas as linguagens: todos os programas de rede, do browser ao servidor de base de dados, estão construídos sobre ela. Os exemplos desta lição usam a rede a sério, por isso **corre-os no teu computador** (o browser não abre sockets).

## Servidor e cliente TCP

O servidor: cria o socket, liga-o a uma porta (`bind`), fica à escuta (`listen`) e aceita ligações (`accept`). Cada `accept` devolve um socket novo, só para aquele cliente.

```python
# servidor.py
import socket

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:      # IPv4, TCP
    s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)        # reutilizar a porta logo
    s.bind(("127.0.0.1", 5000))
    s.listen()
    print("à escuta na porta 5000")
    while True:
        con, endereco = s.accept()                                  # bloqueia até chegar um cliente
        with con:
            print("ligação de", endereco)
            dados = con.recv(1024)
            con.sendall(dados.upper())                              # responde em maiúsculas
```

O cliente: cria o socket e liga-se (`connect`).

```python
# cliente.py
import socket

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.connect(("127.0.0.1", 5000))
    s.sendall("olá, servidor".encode())
    print(s.recv(1024).decode())                                    # OLÁ, SERVIDOR
```

Corre o servidor num terminal e o cliente noutro. Também podes testar o servidor com `nc 127.0.0.1 5000` (netcat).

## O TCP é um fluxo de bytes, não de mensagens

O erro mais comum: assumir que um `send` do outro lado corresponde a um `recv` deste lado. O TCP pode juntar duas mensagens num `recv` ou partir uma em vários. É preciso definir onde acaba cada mensagem (**enquadramento**):

- um **delimitador** (cada mensagem acaba em `\n`, como no HTTP e no SMTP);
- um **prefixo com o tamanho** (os primeiros 4 bytes dizem quantos bytes vêm a seguir).

Esta simulação reproduz o problema sem rede: as mensagens chegam partidas em pedaços arbitrários, e a função tem de as reconstruir.

```python run
import random

def envia(mensagens):
    fluxo = b"".join(len(m).to_bytes(4, "big") + m for m in mensagens)   # prefixo de 4 bytes
    pedacos, i = [], 0
    while i < len(fluxo):                                    # a rede parte como lhe apetece
        n = random.randint(1, 7)
        pedacos.append(fluxo[i:i + n]); i += n
    return pedacos

def recebe(pedacos):
    buffer, mensagens = b"", []
    for p in pedacos:                                       # cada p é o resultado de um recv()
        buffer += p
        while len(buffer) >= 4:
            tamanho = int.from_bytes(buffer[:4], "big")
            if len(buffer) < 4 + tamanho:
                break                                       # mensagem ainda incompleta
            mensagens.append(buffer[4:4 + tamanho])
            buffer = buffer[4 + tamanho:]
    return mensagens

enviadas = ["marcar corte 10h".encode(), "cancelar 12".encode(), "olá 👋".encode()]
pedacos = envia(enviadas)
print("pedaços recebidos:", len(pedacos), pedacos[:4], "...")
print("mensagens:", [m.decode() for m in recebe(pedacos)])
```

Prevê: as três mensagens chegam inteiras, sejam quais forem os pedaços? Repara que o emoji tem 4 bytes: o tamanho conta-se em **bytes**, não em caracteres.

## Vários clientes ao mesmo tempo

O servidor acima atende um cliente de cada vez. Alternativas:

- **Uma thread por cliente:** simples; não escala para dezenas de milhares.
- **E/S não bloqueante com `select`/`epoll`:** uma thread vigia muitos sockets e trata os que têm dados. É o que fazem o nginx, o Node.js e o `asyncio` do Python.

```python
# servidor_async.py
import asyncio

async def atende(leitor, escritor):
    while linha := await leitor.readline():          # mensagens delimitadas por \n
        escritor.write(linha.upper())
        await escritor.drain()
    escritor.close()

async def main():
    servidor = await asyncio.start_server(atende, "127.0.0.1", 5000)
    async with servidor:
        await servidor.serve_forever()

asyncio.run(main())
```

## UDP

```python
# UDP: sem ligação; cada sendto é um datagrama independente
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.sendto(b"ping", ("127.0.0.1", 6000))
dados, origem = s.recvfrom(2048)       # um datagrama inteiro, ou nada
```

No UDP, as fronteiras das mensagens mantêm-se, mas podem perder-se, chegar duplicadas ou fora de ordem.

## Cuidados

- `recv` pode devolver **menos** do que pediste; `b""` quer dizer que o outro lado fechou.
- Usa `sendall`, não `send` (que pode enviar só parte).
- Define **tempos limite** (`s.settimeout(5)`): sem isso, um cliente que não responde bloqueia o servidor para sempre.
- Nunca confies nos dados recebidos: valida tamanhos e conteúdos (um prefixo de tamanho de 4 GB enviado por um atacante esgota a memória).
- Em produção, quase sempre usas uma camada acima (HTTP, WebSockets, gRPC) em vez de sockets diretos.
