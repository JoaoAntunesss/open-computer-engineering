Uma rede é um sistema enorme e complicado: cabos, ondas de rádio, routers, protocolos, aplicações. Para o tornar compreensível, divide-se em **camadas**. Cada camada resolve um problema e oferece um serviço à de cima, usando a de baixo sem saber como funciona. É a ideia mais importante da cadeira: quase tudo o resto encaixa nela.

## O modelo TCP/IP (o da Internet)

| Camada | Resolve | Exemplos | Unidade |
|---|---|---|---|
| **Aplicação** | o que a aplicação quer dizer | HTTP, DNS, SMTP, SSH | mensagem |
| **Transporte** | de processo a processo, fiável ou não | TCP, UDP | segmento |
| **Rede** | de máquina a máquina, atravessando redes | IP, ICMP | pacote (datagrama) |
| **Ligação** | entre vizinhos diretos, no mesmo meio | Ethernet, Wi-Fi | trama |
| **Física** | bits como sinais (eletricidade, luz, rádio) | cabo, fibra, 802.11 | bit |

## O modelo OSI

Um modelo de referência com 7 camadas: física, ligação, rede, transporte, **sessão**, **apresentação**, aplicação. As duas extra quase não existem como protocolos separados na Internet (estão dentro das aplicações), mas os números ficaram no vocabulário: "um switch de nível 2", "um balanceador de nível 7".

## Encapsulamento

Quando envias um pedido HTTP, cada camada acrescenta o seu **cabeçalho** à frente do que recebeu de cima:

```
Aplicação:   [ GET /index.html HTTP/1.1 ... ]
Transporte:  [TCP: porta 51000 → 443][ GET /index.html ... ]
Rede:        [IP: 192.168.1.20 → 142.250.184.4][TCP...][GET...]
Ligação:     [Ethernet: MAC a1:.. → MAC router][IP...][TCP...][GET...][verificação]
Física:      0110100101010...
```

No destino, cada camada lê o seu cabeçalho, retira-o e passa o resto para cima. Cada router no caminho só abre até à camada de rede: vê o IP de destino e reencaminha; não lê o HTTP.

```python run
def encapsula(dados):
    segmento = {"porta_origem": 51000, "porta_destino": 443, "dados": dados}
    pacote = {"ip_origem": "192.168.1.20", "ip_destino": "142.250.184.4", "ttl": 64, "dados": segmento}
    trama = {"mac_origem": "a1:b2:c3:d4:e5:f6", "mac_destino": "00:11:22:33:44:55", "dados": pacote}
    return trama

def router(trama, mac_proximo):
    pacote = trama["dados"]               # tira o cabeçalho de ligação
    pacote["ttl"] -= 1                    # decrementa o tempo de vida
    return {"mac_origem": "00:11:22:33:44:55", "mac_destino": mac_proximo, "dados": pacote}

t = encapsula("GET / HTTP/1.1")
for salto, mac in enumerate(["aa:aa:aa:aa:aa:01", "bb:bb:bb:bb:bb:02", "cc:cc:cc:cc:cc:03"], 1):
    t = router(t, mac)
    print(f"salto {salto}: MAC destino {t['mac_destino']}, IP destino {t['dados']['ip_destino']}, TTL {t['dados']['ttl']}")
print("chega à aplicação:", t["dados"]["dados"]["dados"])
```

Prevê, antes de correr: em cada salto, o que muda e o que fica igual? O **endereço MAC** muda em cada ligação; o **endereço IP** de destino é o mesmo do princípio ao fim; o **TTL** desce 1 por router (e, se chegar a 0, o pacote é descartado: é assim que os ciclos de encaminhamento não duram para sempre).

## Porquê camadas

- **Independência:** o HTTP funciona igual por Wi-Fi, 5G ou fibra. Mudar a camada física não obriga a mudar a aplicação.
- **Cada problema no seu sítio:** o TCP trata das perdas; a aplicação não tem de se preocupar.
- **Diagnóstico por camadas:** "não abre o site" pode ser físico (cabo), de ligação (Wi-Fi sem associação), de rede (sem IP, sem rota), de transporte (porta bloqueada), ou de aplicação (servidor em baixo, DNS). Verificar de baixo para cima é a forma mais rápida de encontrar o problema.

## Ferramentas para ver as camadas

- `ping` (rede, ICMP): a máquina responde? Quanto tempo demora?
- `traceroute` / `tracert` (rede): por que routers passa? (Usa o TTL: envia pacotes com TTL 1, 2, 3… e cada router que o descarta identifica-se.)
- `ip addr` / `ipconfig` (ligação e rede): que IP e MAC tenho?
- `nslookup` / `dig` (aplicação, DNS).
- **Wireshark:** captura o tráfego e mostra cada camada de cada pacote. Captura enquanto abres um site e vê o DNS, o TCP e o TLS.
