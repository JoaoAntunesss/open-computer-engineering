A camada de aplicação é a que os utilizadores veem: a web, o email, a resolução de nomes. Três protocolos fazem quase tudo o que usas: o **DNS** traduz nomes em endereços, o **HTTP** transfere páginas e dados de APIs, e o **SMTP** (com IMAP) trata do email. Saber como funcionam explica metade dos problemas que vais diagnosticar num site.

## DNS

As pessoas usam nomes (`uab.pt`); a rede usa endereços IP. O **DNS** é uma base de dados distribuída e hierárquica que faz a tradução.

**Hierarquia:** raiz (`.`) → domínios de topo (`pt`, `com`) → domínios (`uab.pt`) → subdomínios (`elearning.uab.pt`). Cada nível delega no seguinte.

**Resolução de `elearning.uab.pt`:**

1. O teu PC pergunta ao **resolvedor** (do router, do fornecedor, ou 1.1.1.1, 8.8.8.8).
2. Se não tiver em cache, o resolvedor pergunta a um servidor **raiz**: "não sei, mas os de `.pt` estão aqui".
3. Pergunta aos servidores de `.pt`: "os de `uab.pt` estão aqui".
4. Pergunta aos de `uab.pt`: "elearning.uab.pt é 193.136.x.x".
5. Guarda a resposta em cache durante o **TTL** indicado e responde.

**Tipos de registos:**

| Tipo | Para quê | Exemplo |
|---|---|---|
| A / AAAA | nome → IPv4 / IPv6 | `aw.pt A 185.199.108.153` |
| CNAME | nome → outro nome | `www.aw.pt CNAME aw.pt` |
| MX | servidor de email do domínio | `aw.pt MX 10 mail.aw.pt` |
| TXT | texto livre (verificações, SPF, DKIM) | `aw.pt TXT "v=spf1 include:_spf.google.com ~all"` |
| NS | servidores que mandam no domínio | `aw.pt NS ns1.dominios.pt` |

Quando mudas um site de servidor e "ainda não aparece", é quase sempre o TTL: as caches ainda têm o valor antigo.

## HTTP

Um protocolo de pedido e resposta, em texto (até ao HTTP/1.1):

```
GET /api/marcacoes?dia=2026-11-09 HTTP/1.1
Host: salao.exemplo.pt
Accept: application/json
Authorization: Bearer eyJhbGciOi...

HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: max-age=60

[{"hora": "10:00", "servico": "Corte"}]
```

**Métodos:** `GET` (ler), `POST` (criar), `PUT`/`PATCH` (alterar), `DELETE` (apagar). `GET` não deve mudar nada.

**Códigos de estado:**

- **2xx** sucesso (200 OK, 201 Created, 204 No Content)
- **3xx** redirecionamento (301 permanente, 302/307 temporário, 304 não alterado)
- **4xx** erro do cliente (400 pedido mal feito, 401 sem autenticação, 403 sem permissão, 404 não existe, 429 demasiados pedidos)
- **5xx** erro do servidor (500 erro interno, 502/504 o servidor por trás não respondeu, 503 indisponível)

O HTTP **não guarda estado**: cada pedido é independente. Sessões e logins fazem-se com **cookies** ou **tokens** enviados em cada pedido.

**Versões:** HTTP/1.1 (texto, uma ligação por pedido de cada vez); **HTTP/2** (binário, vários pedidos em paralelo na mesma ligação); **HTTP/3** (sobre QUIC, em UDP: menos atraso a estabelecer a ligação e sem bloqueios quando se perde um pacote). E **HTTPS** = HTTP sobre **TLS** (cifrado e autenticado com certificados).

```python run
pedido_bruto = """POST /api/marcacoes HTTP/1.1\r
Host: salao.exemplo.pt\r
Content-Type: application/json\r
Content-Length: 41\r
\r
{"servico": "Corte", "hora": "2026-11-10"}"""

def analisa(texto):
    cabeca, _, corpo = texto.partition("\r\n\r\n")
    linhas = cabeca.split("\r\n")
    metodo, caminho, versao = linhas[0].split(" ")
    cabecalhos = dict(l.split(": ", 1) for l in linhas[1:])
    return metodo, caminho, versao, cabecalhos, corpo

m, c, v, h, corpo = analisa(pedido_bruto)
print(m, c, v)
print(h)
print("corpo:", corpo, "| tamanho real:", len(corpo.encode()), "| anunciado:", h["Content-Length"])
```

## Email: SMTP, IMAP

- **SMTP** envia: o teu programa entrega ao servidor de envio, que procura o registo **MX** do domínio do destinatário e entrega lá.
- **IMAP** (ou POP3) serve para o programa de email ler a caixa no servidor.
- **SPF, DKIM e DMARC** (registos TXT) dizem que servidores podem enviar em nome do domínio e assinam as mensagens. Sem eles, os emails de um site (confirmações de marcação, por exemplo) vão parar ao spam.

## Ferramentas

- `dig aw.pt A`, `dig aw.pt MX`, `nslookup`: consultas DNS.
- `curl -v https://exemplo.pt`: mostra o pedido e a resposta, com os cabeçalhos.
- As ferramentas de programador do browser (separador **Network**): todos os pedidos de uma página, com tempos, códigos e cabeçalhos.
