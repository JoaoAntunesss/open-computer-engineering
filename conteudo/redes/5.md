O IP leva pacotes de máquina a máquina, sem garantias. A **camada de transporte** leva dados de **processo a processo** (com as **portas**) e, no caso do TCP, transforma uma rede que perde e baralha pacotes num canal fiável e ordenado. O **UDP** é a alternativa simples e rápida, sem garantias.

## Portas

Um endereço IP identifica a máquina; a **porta** (16 bits, 0 a 65 535) identifica o programa. Uma ligação é identificada por cinco valores: protocolo, IP e porta de origem, IP e porta de destino.

Portas conhecidas: 22 (SSH), 53 (DNS), 80 (HTTP), 443 (HTTPS), 5432 (PostgreSQL). O cliente usa uma porta **efémera** aleatória (por exemplo, 51 000).

## UDP

- Cabeçalho de 8 bytes: portas, comprimento, verificação.
- Sem ligação, sem confirmações, sem ordem, sem controlo de fluxo.
- Usa-se quando a rapidez importa mais do que perder um pacote, ou quando a aplicação trata da fiabilidade à sua maneira: DNS, chamadas de voz e vídeo, jogos online, streaming em direto, e o **QUIC** (a base do HTTP/3).

## TCP: fiabilidade

**Estabelecer a ligação (aperto de mão em 3 vias):**

```
cliente → servidor   SYN, seq = 1000
servidor → cliente   SYN-ACK, seq = 5000, ack = 1001
cliente → servidor   ACK, ack = 5001
```

Custa uma ida e volta (RTT) antes de enviar dados. (Com TLS, mais uma ou duas.)

**Números de sequência e confirmações:** cada byte tem um número. O recetor confirma (**ACK**) até onde recebeu tudo seguido. Se falta um pedaço, as confirmações param ali.

**Retransmissão:** se a confirmação não chega a tempo (*timeout*, calculado a partir do RTT medido) ou chegam 3 ACKs duplicados, o emissor reenvia.

**Janela deslizante:** o emissor pode ter vários segmentos "em voo" sem esperar pela confirmação de cada um. Sem isto, com um RTT de 50 ms, só se enviava um segmento a cada 50 ms.

**Controlo de fluxo:** o recetor anuncia quanto espaço tem no buffer (a janela de receção), para o emissor não o afogar.

## Controlo de congestionamento

Se todos enviassem o mais depressa possível, os routers encheriam e descartariam pacotes, as retransmissões piorariam tudo e a rede colapsava (aconteceu em 1986). O TCP mantém uma **janela de congestionamento** (cwnd):

- **Arranque lento:** começa pequena e **duplica** a cada RTT, até um limiar.
- **Prevenção de congestionamento:** depois do limiar, cresce **1 segmento** por RTT (aumento aditivo).
- **Perda:** a janela é cortada para metade (diminuição multiplicativa) ou reiniciada.

Este **AIMD** produz o famoso "dente de serra", e faz as ligações que partilham uma rede convergirem para uma divisão justa. Variantes modernas: **CUBIC** (o do Linux) e **BBR** (da Google, que estima a largura de banda e o RTT em vez de reagir só às perdas).

```python run
def simula(rtts, limiar=16, perdas=(9, 17)):
    cwnd, historico = 1, []
    for t in range(rtts):
        historico.append(cwnd)
        if t in perdas:                    # perda detetada por ACKs duplicados
            limiar = max(cwnd // 2, 2)
            cwnd = limiar
        elif cwnd < limiar:
            cwnd *= 2                      # arranque lento
        else:
            cwnd += 1                      # prevenção de congestionamento
    return historico

h = simula(24)
print(h)
for t, c in enumerate(h):
    print(f"{t:2} {'#' * c}")
```

Prevê a forma do gráfico: onde é exponencial, onde é linear e onde cai.

## TCP ou UDP?

| | TCP | UDP |
|---|---|---|
| ligação | sim (aperto de mão) | não |
| fiável e ordenado | sim | não |
| controlo de congestionamento | sim | não (a aplicação deve ter cuidado) |
| cabeçalho | 20+ bytes | 8 bytes |
| usos | web, email, ficheiros, SSH, bases de dados | DNS, voz, vídeo, jogos, QUIC |
