Um **router** liga redes diferentes e decide, para cada pacote, para onde o enviar a seguir. A decisão vem da **tabela de encaminhamento**. Em casa, a tabela tem uma linha ("tudo para o fornecedor de Internet"); na Internet, os routers principais têm mais de um milhão de entradas e mantêm-nas atualizadas com **protocolos de encaminhamento**: RIP, OSPF e BGP.

## A tabela de encaminhamento

Cada linha diz: para os destinos deste prefixo, envia pela interface X, para o próximo router Y.

```
Destino            Próximo salto     Interface
192.168.1.0/24     ligado diretamente  eth0
10.0.0.0/8         192.168.1.254       eth0
10.20.0.0/16       172.16.0.2          eth1
0.0.0.0/0          203.0.113.1         eth2   ← rota por omissão
```

**Regra do prefixo mais longo:** se várias linhas servem, ganha a mais **específica** (prefixo maior). Um pacote para 10.20.5.5 cabe em 10.0.0.0/8 e em 10.20.0.0/16: vai pela /16. A rota 0.0.0.0/0 serve para tudo, mas só é usada quando nenhuma outra serve.

```python run
import ipaddress

tabela = [
    ("192.168.1.0/24", "direto (eth0)"),
    ("10.0.0.0/8", "192.168.1.254"),
    ("10.20.0.0/16", "172.16.0.2"),
    ("10.20.30.0/24", "172.16.0.9"),
    ("0.0.0.0/0", "203.0.113.1 (Internet)"),
]
rotas = [(ipaddress.ip_network(p), salto) for p, salto in tabela]

def encaminha(destino):
    ip = ipaddress.ip_address(destino)
    candidatas = [(rede, salto) for rede, salto in rotas if ip in rede]
    rede, salto = max(candidatas, key=lambda r: r[0].prefixlen)
    return f"{destino:15} → {salto:24} (por {rede})"

for d in ["192.168.1.50", "10.1.2.3", "10.20.5.5", "10.20.30.40", "8.8.8.8"]:
    print(encaminha(d))
```

Prevê o próximo salto de cada destino antes de correr.

## Rotas estáticas e dinâmicas

- **Estáticas:** escritas à mão. Simples e previsíveis, mas não se adaptam a falhas. Boas para redes pequenas e para a rota por omissão.
- **Dinâmicas:** os routers trocam informação e calculam as rotas. Adaptam-se quando uma ligação cai.

## Vetor de distâncias: RIP

Cada router conhece só os vizinhos. Periodicamente envia-lhes a sua tabela ("chego à rede X em 3 saltos"). Cada um atualiza: distância a X = mínimo de (1 + distância anunciada pelo vizinho). É o **Bellman-Ford distribuído** (Algoritmos, lição 5).

- Simples, mas lento a convergir.
- Problema da **contagem até ao infinito**: quando uma rede desaparece, os routers podem continuar a anunciar-se rotas uns aos outros, cada vez com mais saltos. O RIP limita a 15 saltos (16 = inalcançável), o que o torna inútil para redes grandes.

## Estado das ligações: OSPF

Cada router anuncia a **todos** (por inundação) o estado das suas ligações. Assim, cada um tem o **mapa completo** da rede e calcula os caminhos mais curtos com o **Dijkstra**. Converge depressa, usa custos (não só saltos) e é o mais usado **dentro** de uma organização ou de um fornecedor. Para redes grandes, divide-se em **áreas**.

## Entre redes: BGP

A Internet é feita de cerca de 75 000 **sistemas autónomos** (AS): fornecedores, grandes empresas, universidades, cada um com o seu número (a Google é o AS15169). O **BGP** liga-os.

- Os routers BGP anunciam aos vizinhos os prefixos que alcançam e o **caminho de AS** (`AS3243 AS1299 AS15169`). Evita ciclos: um router rejeita caminhos que já o contêm.
- A escolha não é "o mais curto", mas a que cumpre as **políticas** de cada AS (acordos comerciais: preferir clientes, evitar pagar trânsito).
- Funciona por confiança: anúncios errados (por engano ou de propósito) já desviaram tráfego de meio mundo (o Facebook desapareceu da Internet durante 6 horas em 2021 por uma alteração de BGP). O **RPKI** assina os anúncios para reduzir este risco.
