Uma **GPU** tem milhares de núcleos simples, desenhados para fazer a **mesma operação** sobre muitos dados ao mesmo tempo. Nasceu para os gráficos (calcular a cor de milhões de píxeis), mas hoje é o motor da aprendizagem automática, das simulações científicas e de muito processamento de dados. O **CUDA** (NVIDIA) é a forma mais usada de a programar diretamente; o **OpenCL**, o **SYCL** e o **HIP** (AMD) são alternativas.

## CPU contra GPU

| | CPU | GPU |
|---|---|---|
| núcleos | poucos (8–64), muito potentes | milhares, simples |
| otimizada para | latência (uma tarefa o mais depressa possível) | débito (muitas tarefas iguais ao mesmo tempo) |
| controlo | previsão de saltos, execução fora de ordem, caches grandes | pouco: as threads de um grupo executam a mesma instrução |
| memória | dezenas a centenas de GB/s | 1 a 5 TB/s (HBM) |

## O modelo de programação CUDA

O programa principal corre na CPU (o *host*) e lança **kernels** na GPU (o *device*). Um kernel é executado por uma **grelha** de **blocos**, cada um com centenas de **threads**. Cada thread calcula a sua posição a partir dos índices:

```c
// soma_vetores.cu — nvcc soma_vetores.cu -o soma
__global__ void soma(const float *a, const float *b, float *c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;     // o índice global desta thread
    if (i < n) c[i] = a[i] + b[i];                     // cada thread trata um elemento
}

int main(void) {
    int n = 1 << 24;                                   // 16 milhões de elementos
    float *a, *b, *c;
    cudaMallocManaged(&a, n * sizeof(float));          // memória acessível à CPU e à GPU
    cudaMallocManaged(&b, n * sizeof(float));
    cudaMallocManaged(&c, n * sizeof(float));
    for (int i = 0; i < n; i++) { a[i] = 1.0f; b[i] = 2.0f; }

    int porBloco = 256, blocos = (n + porBloco - 1) / porBloco;
    soma<<<blocos, porBloco>>>(a, b, c, n);           // lança 16 milhões de threads
    cudaDeviceSynchronize();                           // espera que a GPU acabe

    printf("c[0] = %f, c[n-1] = %f\n", c[0], c[n - 1]);
    cudaFree(a); cudaFree(b); cudaFree(c);
}
```

## O que torna uma GPU rápida (ou lenta)

1. **Paralelismo suficiente:** milhares de threads em voo, para esconder a latência da memória (enquanto umas esperam, outras calculam).
2. **Acessos coalescidos:** threads vizinhas a ler posições vizinhas da memória, que a GPU junta num só acesso. Ler com saltos (por colunas numa matriz guardada por linhas) desperdiça a largura de banda.
3. **Pouca divergência:** as threads executam em grupos de 32 (*warps*) que seguem a mesma instrução. Um `if` em que metade vai para cada lado executa os dois ramos, um de cada vez.
4. **Memória partilhada do bloco:** uma memória pequena e muito rápida, partilhada pelas threads de um bloco; usada para reutilizar dados (multiplicação de matrizes por blocos).
5. **Transferências CPU ↔ GPU:** pelo PCIe, muito mais lentas do que a memória da GPU. Copiar dados para uma operação pequena pode demorar mais do que fazê-la na CPU.

```python run
# estimativa: vale a pena levar uma operação para a GPU?
pcie = 25e9            # bytes/s (PCIe 4.0 x16, na prática)
gpu_mem = 1.5e12       # bytes/s, memória da GPU
cpu_mem = 50e9         # bytes/s, memória da CPU

def compara(n, operacoes_por_elemento, gflops_cpu=200e9, gflops_gpu=20e12):
    bytes_ = 3 * 4 * n                                   # ler 2 vetores de float, escrever 1
    t_cpu = max(bytes_ / cpu_mem, n * operacoes_por_elemento / gflops_cpu)
    t_gpu = max(bytes_ / gpu_mem, n * operacoes_por_elemento / gflops_gpu)
    t_copia = bytes_ / pcie
    return t_cpu, t_gpu, t_copia

for n, ops, nome in [(1_000_000, 1, "somar 1M floats"), (100_000_000, 1, "somar 100M floats"),
                     (100_000_000, 1000, "100M elementos, 1000 operações cada")]:
    cpu, gpu, copia = compara(n, ops)
    print(f"{nome:38} CPU {cpu * 1000:8.2f} ms | GPU {gpu * 1000:7.2f} ms + cópias {copia * 1000:7.2f} ms"
          f" → {'GPU' if gpu + copia < cpu else 'CPU'}")
```

Prevê em que casos compensa. Para operações simples, o custo de copiar os dados pelo PCIe domina; a GPU compensa quando há muito cálculo por cada byte (multiplicação de matrizes, redes neuronais) ou quando os dados já estão lá e ficam para várias operações.

## Na prática, raramente se escreve CUDA

- **Bibliotecas:** cuBLAS (álgebra linear), cuDNN (redes neuronais), cuFFT, Thrust.
- **Python:** CuPy (como o NumPy, mas na GPU), Numba (`@cuda.jit`), e sobretudo o **PyTorch** e o **JAX**, que enviam as operações para a GPU sem escreveres um kernel.
- No browser, o **WebGPU** permite computação na GPU a partir de JavaScript.
