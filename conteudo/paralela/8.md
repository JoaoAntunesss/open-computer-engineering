Código paralelo é fácil de escrever e difícil de ler corretamente: o mesmo código pode dar resultados diferentes conforme o número de threads e a ordem em que correm. Ler este código exige identificar, linha a linha, que dados são **partilhados** e quem os escreve.

## Ler e prever: OpenMP

```c
#include <stdio.h>
#include <omp.h>

int main(void) {
    int n = 1000000;
    long soma = 0;
    #pragma omp parallel for
    for (int i = 1; i <= n; i++) {
        soma += i;
    }
    printf("%ld\n", soma);
    return 0;
}
```

Compila com `gcc -fopenmp soma.c -o soma` e corre várias vezes. Antes de correr: qual devia ser o resultado? Vai dar sempre o mesmo?

## Encontra o erro: speedup que não aparece

Uma equipa paralelizou um programa com 8 threads e só ficou 2,5 vezes mais rápido. Ao ler o código, viram que 30% do tempo era passado a ler um ficheiro grande, de forma sequencial, antes da parte paralela. Usa a lei de Amdahl para explicar o resultado:

```python run
def amdahl(fracao_paralela, nucleos):
    return 1 / ((1 - fracao_paralela) + fracao_paralela / nucleos)

for n in (2, 4, 8, 16, 1000):
    print(n, round(amdahl(0.7, n), 2))
```
