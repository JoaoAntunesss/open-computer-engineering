Quando os dados ou o cálculo não cabem numa máquina, usa-se um **cluster**: dezenas a milhares de computadores, cada um com a sua memória, ligados por uma rede rápida. Não há memória partilhada: os processos comunicam **enviando mensagens**. O **MPI** (*Message Passing Interface*) é o padrão para isto em computação científica: simulações de clima, de fluidos, de proteínas, nos supercomputadores (como o Deucalion, em Guimarães).

## O modelo SPMD

*Single Program, Multiple Data*: o mesmo programa corre em N processos; cada um sabe o seu **rank** (0 a N − 1) e trata da sua parte dos dados.

```c
// ola_mpi.c — mpicc ola_mpi.c -o ola && mpirun -np 4 ./ola
#include <mpi.h>
#include <stdio.h>

int main(int argc, char **argv) {
    MPI_Init(&argc, &argv);
    int rank, n;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &n);

    // cada processo soma uma parte de 1..N
    long N = 1000000, inicio = rank * N / n + 1, fim = (rank + 1) * N / n;
    long parcial = 0;
    for (long i = inicio; i <= fim; i++) parcial += i;

    long total = 0;
    MPI_Reduce(&parcial, &total, 1, MPI_LONG, MPI_SUM, 0, MPI_COMM_WORLD);   // junta no rank 0
    if (rank == 0) printf("total = %ld\n", total);

    MPI_Finalize();
    return 0;
}
```

## Comunicação

**Ponto a ponto:** `MPI_Send(buffer, n, tipo, destino, etiqueta, comunicador)` e `MPI_Recv(…)`. Cuidado: se dois processos fazem `Send` um ao outro ao mesmo tempo e os envios bloqueiam, ficam em **interbloqueio**. Usam-se `MPI_Sendrecv` ou as versões não bloqueantes (`MPI_Isend`/`MPI_Irecv` + `MPI_Wait`), que também permitem **sobrepor** comunicação e cálculo.

**Coletivas** (todos os processos participam):

- `MPI_Bcast`: um envia a todos.
- `MPI_Scatter` / `MPI_Gather`: dividir um vetor pelos processos / juntar.
- `MPI_Reduce` / `MPI_Allreduce`: combinar (somar, máximo) e entregar a um / a todos.
- `MPI_Barrier`: esperar que todos cheguem.

As coletivas estão otimizadas (em árvore: log₂ N passos em vez de N).

## O custo da comunicação

Um modelo simples: enviar uma mensagem de m bytes custa α + β·m (latência + tempo de transferência). Numa rede InfiniBand, α ≈ 1 µs; na Ethernet comum, dezenas de µs. Muitas mensagens pequenas são piores do que uma grande.

```python run
import math

alfa, beta = 2e-6, 1e-9          # 2 µs de latência, 1 GB/s
calculo_total = 10.0             # segundos de cálculo, divisível por igual

def tempo(p, estrategia, dados_por_proc=8_000_000):
    calculo = calculo_total / p
    if estrategia == "sequencial (o 0 recebe de todos)":
        comunicacao = (p - 1) * (alfa + beta * 8)
    elif estrategia == "árvore (MPI_Reduce)":
        comunicacao = math.ceil(math.log2(p)) * (alfa + beta * 8) if p > 1 else 0
    elif estrategia == "troca de fronteiras a cada passo (1000 passos)":
        comunicacao = 1000 * 2 * (alfa + beta * 8_000)   # cada processo troca 8 KB com 2 vizinhos
    return calculo + comunicacao

for estrategia in ("sequencial (o 0 recebe de todos)", "árvore (MPI_Reduce)",
                   "troca de fronteiras a cada passo (1000 passos)"):
    print(estrategia)
    for p in (1, 16, 256, 4096):
        t = tempo(p, estrategia)
        print(f"   p = {p:5}: {t * 1000:9.2f} ms   ganho {calculo_total / t:7.1f}")
```

Prevê em que estratégia e para que p a comunicação passa a dominar. Na terceira, típica de simulações em grelha (cada processo tem um pedaço e troca as bordas com os vizinhos a cada passo), a comunicação por passo é constante, e com muitos processos acaba por pesar mais do que o cálculo.

## Decomposição do problema

- **De dados** (o mais comum): dividir a grelha, a matriz ou os dados pelos processos. Equilibrar a carga e minimizar as fronteiras (dividir em blocos quadrados, não em tiras finas).
- **De tarefas:** processos diferentes fazem coisas diferentes (um *pipeline*), ou um mestre distribui tarefas por trabalhadores (bom com tarefas de custo imprevisível).

## MPI e o resto

Em clusters modernos, combinam-se os modelos: MPI entre nós, OpenMP (ou threads) dentro de cada nó, e CUDA nas GPUs de cada nó. Para processamento de dados (não científico), em vez de MPI usa-se Spark ou Dask (Sistemas Distribuídos, lição 9), mais tolerantes a falhas e mais fáceis.
