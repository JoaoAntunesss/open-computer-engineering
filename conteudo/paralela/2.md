Num computador com vários núcleos, todas as threads veem a mesma memória. O **OpenMP** é a forma mais simples de aproveitar isso em C, C++ e Fortran: acrescentam-se diretivas (`#pragma`) a um programa sequencial, e o compilador divide o trabalho pelas threads. Não muda o algoritmo, só o distribui; e herda todos os perigos da memória partilhada.

## O modelo fork-join

O programa começa com uma thread. Numa **região paralela**, cria-se uma equipa de threads; no fim da região, juntam-se e continua só uma.

```c
// ola_omp.c — compilar com: gcc -fopenmp ola_omp.c -o ola
#include <stdio.h>
#include <omp.h>

int main(void) {
    #pragma omp parallel
    {
        int id = omp_get_thread_num(), n = omp_get_num_threads();
        printf("olá da thread %d de %d\n", id, n);
    }
    return 0;
}
```

O número de threads escolhe-se com `OMP_NUM_THREADS=4 ./ola`. A ordem das mensagens muda em cada execução.

## Ciclos paralelos

```c
// soma_omp.c
#include <stdio.h>
#include <omp.h>

int main(void) {
    const long N = 100000000;
    double soma = 0.0;
    double t = omp_get_wtime();
    #pragma omp parallel for reduction(+:soma) schedule(static)
    for (long i = 1; i <= N; i++) {
        soma += 1.0 / ((double)i * i);          // converge para π²/6
    }
    t = omp_get_wtime() - t;
    printf("soma = %.12f (π²/6 = 1.644934066848)  em %.3f s com %d threads\n",
           soma, t, omp_get_max_threads());
    return 0;
}
```

- `parallel for` divide as iterações pelas threads.
- `reduction(+:soma)`: cada thread tem a sua soma privada; no fim, somam-se. Sem isto, todas escrevem na mesma variável e há uma condição de corrida (a lição de leitura de código desta cadeira).
- `schedule(static)`: blocos iguais e fixos. `dynamic`: as threads vão buscar blocos à medida que acabam (melhor quando as iterações demoram tempos diferentes). `guided`: blocos que vão diminuindo.

## Variáveis partilhadas e privadas

- Por omissão, as variáveis declaradas **fora** da região são **partilhadas**; as declaradas **dentro** (e o índice do ciclo) são **privadas**.
- `private(x)`, `firstprivate(x)`, `shared(x)` e `default(none)` (obriga a declarar tudo, e apanha erros).
- Secções críticas: `#pragma omp critical` (uma thread de cada vez), `#pragma omp atomic` (para uma operação simples, mais rápido), `#pragma omp barrier`.

## Escalonamento e desequilíbrio

Quando as iterações têm custos diferentes, a distribuição importa. Prevê qual demora menos:

```python run
import heapq

custos = [i for i in range(1, 101)]          # a iteração i custa i unidades (triangular)
threads = 4

def estatico(custos, p):
    bloco = len(custos) // p
    return max(sum(custos[k * bloco:(k + 1) * bloco]) for k in range(p))

def dinamico(custos, p, tamanho=1):
    livres = [(0, t) for t in range(p)]                     # (quando fica livre, thread)
    for k in range(0, len(custos), tamanho):
        fim, t = heapq.heappop(livres)                       # a primeira a ficar livre leva o bloco seguinte
        heapq.heappush(livres, (fim + sum(custos[k:k + tamanho]), t))
    return max(f for f, _ in livres)

def ciclico(custos, p):                                       # schedule(static, 1): iteração i para a thread i % p
    return max(sum(custos[t::p]) for t in range(p))

ideal = sum(custos) / threads
for nome, tempo in [("static (blocos)", estatico(custos, threads)),
                    ("static,1 (cíclico)", ciclico(custos, threads)),
                    ("dynamic,1", dinamico(custos, threads)),
                    ("dynamic,10", dinamico(custos, threads, 10))]:
    print(f"{nome:20} tempo {tempo:5}  (ideal {ideal:.0f}, eficiência {ideal / tempo:.0%})")
```

Com blocos estáticos, a última thread fica com as iterações mais caras e todas as outras esperam por ela.

## Armadilhas

- **Condições de corrida:** escrever em variáveis partilhadas sem proteção.
- **Falsa partilha:** threads a escrever em posições vizinhas de um vetor (na mesma linha de cache), com o desempenho a cair (lição 7).
- Regiões paralelas pequenas demais: o custo de criar e sincronizar threads é maior do que o trabalho.
- Dependências entre iterações (`a[i] = a[i-1] + …`): o ciclo não pode ser paralelizado diretamente.
