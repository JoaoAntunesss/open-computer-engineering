Quando um programa cresce, deixa de caber na cabeça como uma lista de instruções. As funções servem para lhe dar **nomes**: em vez de 40 linhas, lês `limpar_dados()`, `calcular_totais()`, `mostrar_relatorio()` e percebes a história toda.

## Quando criar uma função

- Quando copias e colas o mesmo bocado de código: transforma-o numa função e chama-a duas vezes.
- Quando um bloco faz **uma coisa** que consegues descrever com um verbo: "valida o email", "calcula o IVA".
- Quando queres testar uma parte sozinha.

## Antes e depois

```python run
# Antes: tudo seguido
encomendas = [("Ana", 30, "Porto"), ("Rui", 120, "Lisboa"), ("Sofia", 75, "Porto")]
total = 0
for nome, valor, cidade in encomendas:
    if valor > 100:
        portes = 0
    elif cidade == "Porto":
        portes = 3
    else:
        portes = 5
    total += valor + portes
print(total)
```

```python run
# Depois: cada decisão com o seu nome
def portes(valor, cidade):
    if valor > 100:
        return 0
    return 3 if cidade == "Porto" else 5

def total_encomenda(valor, cidade):
    return valor + portes(valor, cidade)

encomendas = [("Ana", 30, "Porto"), ("Rui", 120, "Lisboa"), ("Sofia", 75, "Porto")]
print(sum(total_encomenda(v, c) for _, v, c in encomendas))
```

O resultado é o mesmo, mas agora a regra dos portes tem um sítio só seu. Quando a regra mudar, sabes onde mexer, e podes testá-la sem criar encomendas.

## Boas funções

- **Nome com verbo** que diz o que faz: `calcula_portes`, não `func2` nem `processa`.
- **Recebe tudo o que precisa por parâmetros** e **devolve o resultado com `return`**. Evita funções que leem e mudam variáveis globais: são as mais difíceis de perceber e de testar.
- **Curtas**: se precisas de rolar o ecrã para a ler toda, provavelmente são duas funções.
- **Fazem uma coisa**: se o nome precisa de "e" (`valida_e_guarda`), separa.
