Quando pedes código à IA, ela salta logo para a solução. Quem programa bem faz quase o contrário: passa mais tempo a perceber o problema e a fazer um plano do que a escrever código. Esta lição ensina-te o passo que falta entre "tenho uma ideia" e "tenho código".

## Decompor

Um problema grande é sempre vários problemas pequenos. Exemplo: *"quero saber quanto gastei em cada categoria este mês, a partir de uma lista de despesas"*.

Parte-o em perguntas a que sabes responder:

1. Como estão os dados? (uma lista de despesas, cada uma com valor, categoria e data)
2. Quais interessam? (só as deste mês)
3. Como agrupo? (por categoria)
4. O que faço em cada grupo? (somo os valores)
5. Como mostro? (uma linha por categoria, da maior para a menor)

Cada uma destas é pequena o suficiente para escreveres sozinho.

## Pseudocódigo

Antes do código, escreve os passos em português, como comentários. É o teu plano, e é muito mais fácil corrigir um plano do que corrigir código.

```python
# despesas: lista de (valor, categoria, mês)
# totais começa vazio
# para cada despesa:
#     se o mês for o que quero:
#         soma o valor ao total da categoria
# ordena as categorias do maior total para o menor
# mostra cada categoria e o total
```

Depois, preenches por baixo de cada comentário:

```python run
despesas = [(12.5, "comida", 11), (40, "transportes", 11), (8, "comida", 11), (60, "casa", 10), (15, "lazer", 11)]
mes = 11

# totais começa vazio
totais = {}
# para cada despesa:
for valor, categoria, m in despesas:
    # se o mês for o que quero:
    if m == mes:
        # soma o valor ao total da categoria
        totais[categoria] = totais.get(categoria, 0) + valor
# ordena as categorias do maior total para o menor
ordenadas = sorted(totais.items(), key=lambda par: par[1], reverse=True)
# mostra cada categoria e o total
for categoria, total in ordenadas:
    print(f"{categoria:12} {total:7.2f} €")
```

Repara: cada comentário passou a 1 ou 2 linhas de código. Se não souberes como escrever um dos passos, é **esse** passo (e só esse) que pesquisas ou perguntas.

## Exemplos à mão primeiro

Antes de escrever, resolve o problema **à mão** com dados pequenos. Se não o consegues fazer no papel, também não o consegues explicar ao computador. E o resultado à mão passa a ser o teu "esperado" para testar.

## O plano é para mudar

Ao escrever, vais descobrir coisas que o plano não previa ("e se o valor vier como texto?", "e se houver categorias com maiúsculas?"). Isso é normal: volta ao plano, acrescenta o passo e continua.
