Segurança não é uma fase do projeto nem trabalho só para especialistas. É um conjunto de hábitos que um sénior aplica todos os dias, e que espera ver nas revisões de código. A referência mais usada é o **OWASP Top 10**.

## Os erros mais comuns em aplicações web

| Problema | Exemplo | Defesa |
|---|---|---|
| **Controlo de acessos falhado** | Mudar `/marcacoes/41` para `/42` e ver a de outro cliente | Verificar permissões no servidor, em todos os endpoints |
| **Injeção** | SQL montado com texto do utilizador | Queries com parâmetros, ORMs, validação |
| **XSS** | Comentário com `<script>` mostrado como HTML | Escapar a saída, `textContent`, Content Security Policy |
| **Configurações inseguras** | Painel de admin aberto, modo debug em produção | Listas de verificação, configuração revista |
| **Componentes vulneráveis** | Biblioteca com falha conhecida | Atualizações e alertas automáticos (Dependabot) |
| **Falhas de autenticação** | Sem limite de tentativas, passwords fracas | Serviço de autenticação testado, 2FA |
| **Segredos expostos** | Chave de API no GitHub | Variáveis de ambiente, gestor de segredos, *secret scanning* |

## Hábitos diários

- **Nunca confies no cliente.** Tudo o que vem do browser ou da app pode ser alterado. Valida e autoriza no servidor.
- **Menor privilégio.** Cada serviço e cada pessoa só com o acesso de que precisa. A API não precisa de ser dona da base de dados.
- **Segredos fora do código** e com rotação. Se uma chave foi para o Git, considera-a comprometida: revoga e cria outra (apagar o commit não chega).
- **Dependências atualizadas** e com alertas ligados (o GitHub faz isto gratuitamente).
- **Cabeçalhos de segurança** (Content-Security-Policy, HSTS) e HTTPS sempre.
- **Dados pessoais**: guarda só o que precisas, pelo tempo que precisas (RGPD), e nunca nos logs.

## Segurança e IA

O código gerado por IA repete os erros que aparecem em muito código público: SQL montado com texto, HTML sem escapar, segredos no código, permissões em falta. Na revisão, procura estes padrões de propósito. Ferramentas de análise estática (como o CodeQL do GitHub ou o Semgrep) apanham muitos automaticamente.

## Modelação de ameaças, em versão simples

Antes de uma funcionalidade nova, 15 minutos com estas perguntas:

1. O que estamos a construir?
2. O que pode correr mal? (Quem pode abusar? Que dados podem fugir?)
3. O que fazemos em relação a isso?
4. Fizemos bem? (Testes, revisão.)

## Exercício

Faz uma auditoria a um projeto teu com o OWASP Top 10 ao lado: liga o Dependabot e o secret scanning no GitHub, procura todos os sítios onde dados do utilizador chegam ao HTML ou a queries, e confirma que cada endpoint verifica permissões. Escreve o que encontraste e o que corrigiste.
