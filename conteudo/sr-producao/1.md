Um sistema é **observável** quando, olhando de fora, consegues perceber o que está a acontecer lá dentro, incluindo problemas que nunca tinhas imaginado. Os três pilares são **logs**, **métricas** e **traces**.

## Os três pilares

| Pilar | Responde a | Exemplo |
|---|---|---|
| **Logs** | O que aconteceu neste caso concreto? | `marcacao criada id=41 salao=12 duracao_ms=83` |
| **Métricas** | Como se comporta o sistema ao longo do tempo? | pedidos por segundo, percentagem de erros, tempo de resposta |
| **Traces** | Por onde passou este pedido, e onde gastou tempo? | API 120 ms → base de dados 95 ms → email 15 ms |

## Métricas que importam: os quatro sinais

O livro de SRE da Google sugere começar por quatro "sinais dourados" em cada serviço:

1. **Latência**: quanto tempo demoram os pedidos (olha para o percentil 95 ou 99, não para a média: a média esconde os utilizadores com pior experiência).
2. **Tráfego**: quantos pedidos.
3. **Erros**: que percentagem falha.
4. **Saturação**: quão perto do limite estão os recursos (CPU, memória, ligações à base de dados).

## Traces distribuídos

Quando um pedido passa por vários serviços, um **trace** junta tudo com um identificador comum, e mostra uma "cascata" com o tempo gasto em cada parte. É a forma mais rápida de responder a "porque é que isto está lento?". O padrão aberto é o **OpenTelemetry**, suportado por quase todas as ferramentas.

## Ferramentas

- **Grafana + Prometheus** (open source, ou Grafana Cloud com plano gratuito) para métricas e painéis.
- **Sentry** para erros e desempenho.
- **OpenTelemetry** para instrumentar o código uma vez e enviar para qualquer ferramenta.
- Os serviços de cloud (Cloud Run, por exemplo) já trazem logs e métricas básicas.

## Painéis úteis

Um bom painel responde a "está tudo bem?" em 5 segundos: os quatro sinais de cada serviço, com a mesma escala de tempo, e marcas nos deploys (muitos problemas começam num deploy). Muitos gráficos bonitos que ninguém percebe não ajudam ninguém às 3 da manhã.

## Exercício

Instrumenta a API de marcações com OpenTelemetry (ou com as métricas do serviço onde a puseste) e cria um painel com os quatro sinais. Depois simula carga (por exemplo com a ferramenta `hey` ou o `locust`) e observa como os gráficos mudam.
