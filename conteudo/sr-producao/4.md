"Está lento" é uma das queixas mais comuns e das mais mal resolvidas. O erro clássico é otimizar o que **achamos** que é lento. Quase sempre estamos errados. A regra: **mede, encontra o estrangulamento, corrige, mede outra vez**.

## Medir antes de mexer

- **Onde está o tempo?** Um trace (lição de observabilidade) ou um *profiler* mostra a resposta.
- **Para quem?** O percentil 95 do tempo de resposta conta mais do que a média.
- **Qual é o objetivo?** "Mais rápido" não é objetivo; "página de marcação em menos de 1 s para 95% dos pedidos" é.

## Profilers

Em Python, para ver onde um script gasta tempo:

```text
python -m cProfile -s cumtime script.py
```

Para um servidor a correr, o **py-spy** espreita sem parar nada:

```text
py-spy top --pid 12345
py-spy record -o perfil.svg --pid 12345
```

O `perfil.svg` é um *flame graph*: cada barra é uma função e a largura é o tempo. Procura as barras largas.

No browser: F12 → **Performance** e o relatório do **Lighthouse** para sites.

## Os suspeitos habituais

1. **Queries sem índice** (vê a fase Júnior). De longe o mais comum.
2. **O problema N+1**: uma query para a lista, e depois uma query para cada elemento.

```python
# 1 + N queries: 101 idas à base de dados para 100 marcações
marcacoes = db.query("SELECT * FROM marcacoes WHERE dia = %s", (dia,))
for m in marcacoes:
    m.cliente = db.query_one("SELECT * FROM clientes WHERE id = %s", (m.cliente_id,))

# 1 query
marcacoes = db.query("""
    SELECT m.*, c.nome AS cliente_nome
    FROM marcacoes m JOIN clientes c ON c.id = m.cliente_id
    WHERE m.dia = %s""", (dia,))
```

   Os ORMs (e o código gerado por IA) criam isto com muita facilidade.
3. **Trabalho feito no pedido que podia ir para uma fila** (emails, PDFs).
4. **Respostas enormes**: devolver 10 000 registos sem paginação.
5. **No frontend**: imagens pesadas, JavaScript a mais, pedidos em série que podiam ser em paralelo.

## Otimizar só o que importa

Uma função que passa de 2 ms para 1 ms não interessa se a query ao lado demora 800 ms. Ataca o maior estrangulamento, mede, e pára quando atingires o objetivo. Código otimizado é normalmente mais difícil de ler, por isso só vale a pena onde faz diferença.

## Exercício

Na API de marcações, cria de propósito um endpoint com o problema N+1 e 1000 marcações de teste. Mede o tempo e o número de queries, corrige com um JOIN, e mede outra vez. Faz o mesmo com o Lighthouse num site teu e corrige as duas maiores sugestões.
