Na fase Júnior aprendeste a fazer code review. Como sénior, a revisão muda de foco: menos pormenores de estilo, mais **riscos, desenho e ensino**. E passas a ser responsável por manter a qualidade de todo o código, não só do teu.

## O que um sénior procura

1. **O problema certo**: o PR resolve o problema real, ou um sintoma?
2. **Desenho**: a solução encaixa na arquitetura? Vai ser fácil de mudar daqui a um ano? Cria dependências que não devia?
3. **Riscos**: o que acontece com dados reais, com muita carga, com falhas? A migração é segura? Dá para reverter?
4. **Segurança e dados pessoais.**
5. **Testes que provam o que importa**, não só que aumentam a cobertura.
6. **Coisas que faltam**: logs, métricas, documentação, avisos a outras equipas.

O estilo é para os linters. Se te apanhares a comentar espaços, automatiza.

## Rever para ensinar

Com colegas mais novos, a revisão é o principal momento de ensino. Em vez de reescreveres a solução nos comentários:

- Faz perguntas que levem a pessoa a encontrar o problema: "O que acontece se dois clientes marcarem ao mesmo tempo?"
- Explica o princípio, não só a correção: "Validamos no servidor porque o cliente pode ser alterado."
- Aponta para exemplos no próprio código ou para documentação.
- Separa claramente o que bloqueia o merge do que é sugestão.

## Rever depressa

Um PR à espera de revisão durante dias bloqueia uma pessoa e gera conflitos. Muitas equipas definem uma regra (por exemplo, primeira resposta no mesmo dia). Se um PR é grande demais para rever bem, pede que seja dividido: é uma revisão legítima.

## Rever código gerado por IA

Com mais código gerado, as revisões ficam maiores e mais "plausíveis". Procura em especial: código que funciona mas não segue os padrões do projeto, abstrações desnecessárias, testes que só confirmam o que o código faz, e dependências novas que ninguém discutiu. Se o autor não consegue explicar uma parte, a revisão não deve aprovar.

## Exercício

Escolhe um PR grande e já fechado de um projeto open source. Escreve uma revisão "de sénior": no máximo 5 comentários, focados em desenho e riscos, cada um com o princípio por trás. Compara com a revisão real.
