Para desenhar uma cena 3D num ecrã 2D, é preciso decidir **de onde** se olha (a câmara) e **como** o 3D é achatado (a projeção). Cada vértice passa por uma cadeia de transformações, todas matrizes 4×4: do espaço do objeto para o mundo, do mundo para a câmara, da câmara para o espaço de recorte, e daí para os píxeis do ecrã.

## A cadeia de transformações

```
coordenadas do objeto
  │ matriz do modelo (onde o objeto está no mundo)
coordenadas do mundo
  │ matriz de vista (onde está a câmara)
coordenadas da câmara (a câmara na origem, a olhar para −z)
  │ matriz de projeção
coordenadas de recorte → divisão por w → coordenadas normalizadas (−1 a 1)
  │ viewport
píxeis do ecrã
```

No código: `posição = projeção · vista · modelo · vértice`. É exatamente o que um *vertex shader* calcula para cada vértice (lição 4).

## A câmara (matriz de vista)

Define-se com "onde está o olho", "para onde olha" e "que direção é para cima" (a função **lookAt**). A matriz de vista é a **inversa** da transformação que levaria a câmara para a sua posição: em vez de mover a câmara, move-se o mundo inteiro no sentido contrário.

## Projeção em perspetiva

Objetos mais longe aparecem mais pequenos. Para uma câmara na origem a olhar para −z, com o plano de projeção à distância d:

x_ecrã = d · x / (−z),   y_ecrã = d · y / (−z)

A divisão por z não é linear, mas as coordenadas homogéneas resolvem isso: a matriz de projeção põe −z na coordenada w, e a GPU divide x, y e z por w depois (a **divisão perspetiva**). Parâmetros: **campo de visão** (FOV), proporção do ecrã, planos **próximo** e **distante** (o que fica fora deles é cortado).

## Projeção ortográfica

Sem perspetiva: linhas paralelas continuam paralelas, os objetos não diminuem com a distância. Usada em desenho técnico, CAD, jogos isométricos e interfaces 2D.

```python run
import math

def projeta(p, fov_graus=60, largura=40, altura=20):
    x, y, z = p                                       # câmara na origem, a olhar para -z
    if z >= -0.1:
        return None                                   # atrás da câmara: não se vê
    f = 1 / math.tan(math.radians(fov_graus) / 2)
    xn, yn = f * x / -z, f * y / -z                   # coordenadas normalizadas (-1 a 1)
    return round((xn + 1) / 2 * (largura - 1)), round((1 - yn) / 2 * (altura - 1))

def cubo(cx, cy, cz, l):
    h = l / 2
    return [(cx + dx * h, cy + dy * h, cz + dz * h) for dx in (-1, 1) for dy in (-1, 1) for dz in (-1, 1)]

ecra = [[" "] * 40 for _ in range(20)]
for (cx, cz, marca) in ((-1.5, -4, "#"), (1.5, -9, "o")):          # um cubo perto, outro longe
    vs = cubo(cx, 0, cz, 1.5)
    for a in vs:
        for b in vs:                                  # arestas: vértices que diferem numa só coordenada
            if sum(u != v for u, v in zip(a, b)) == 1:
                for k in range(21):
                    p = [u + (v - u) * k / 20 for u, v in zip(a, b)]
                    r = projeta(p)
                    if r and 0 <= r[0] < 40 and 0 <= r[1] < 20:
                        ecra[r[1]][r[0]] = marca
print("\n".join("".join(l) for l in ecra))
print("o vértice (0, 0, -5) cai em", projeta((0, 0, -5)), " e (0, 0, 2) está atrás da câmara:", projeta((0, 0, 2)))
```

Prevê qual dos dois cubos (do mesmo tamanho) aparece maior. O "#" está a 4 unidades; o "o", a 9.

## Profundidade

Depois da projeção, ainda é preciso saber o que está à frente do quê. O **z-buffer** guarda, para cada píxel, a profundidade do que lá foi desenhado; um fragmento novo só é desenhado se estiver mais perto. A precisão do z-buffer depende dos planos próximo e distante: um plano próximo demasiado perto (0,0001) provoca *z-fighting* (superfícies próximas a piscar).
