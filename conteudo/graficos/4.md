Um **shader** é um pequeno programa que corre na GPU, em paralelo, para cada vértice ou para cada píxel. É assim que se programam a iluminação, as sombras, a água, o desfoque e quase todos os efeitos visuais de um jogo ou de um site em WebGL. A linguagem do OpenGL e do WebGL é o **GLSL**, parecida com C, com tipos para vetores e matrizes.

## Vertex shader

Corre uma vez por vértice. Recebe os atributos do vértice (posição, normal, coordenadas de textura) e calcula a posição no ecrã:

```glsl
// vertex shader (WebGL 2)
#version 300 es
in vec3 posicao;
in vec3 normal;
uniform mat4 modelo, vista, projecao;    // iguais para todos os vértices de um objeto
out vec3 vNormal;                         // passa para o fragment shader (interpolado)

void main() {
    vNormal = mat3(modelo) * normal;
    gl_Position = projecao * vista * modelo * vec4(posicao, 1.0);
}
```

## Fragment shader

Corre uma vez por fragmento (píxel candidato). Recebe os valores interpolados e devolve uma cor:

```glsl
#version 300 es
precision highp float;
in vec3 vNormal;
uniform vec3 direcaoLuz;
uniform vec3 corBase;
out vec4 cor;

void main() {
    float difusa = max(dot(normalize(vNormal), normalize(-direcaoLuz)), 0.0);
    cor = vec4(corBase * (0.15 + 0.85 * difusa), 1.0);
}
```

## Tipos e operações

- `float`, `int`, `bool`; vetores `vec2`, `vec3`, `vec4`; matrizes `mat3`, `mat4`; texturas `sampler2D`.
- **Swizzling:** `v.xyz`, `cor.rgb`, `v.zyx`, `v.xx` para escolher e reordenar componentes.
- Funções embutidas: `dot`, `cross`, `normalize`, `length`, `mix` (interpolação), `clamp`, `smoothstep`, `reflect`, `texture`.
- **Uniforms:** valores iguais para todos (matrizes, tempo, posição da luz), definidos pelo JavaScript.
- **in/out:** passam valores do vertex para o fragment shader, interpolados pela rasterização.

## Pensar em paralelo

Um shader não sabe nada dos píxeis vizinhos e não guarda estado entre imagens: é uma **função pura** de (coordenadas, uniforms) para cor. Muitos efeitos 2D escrevem-se só com o fragment shader, como no [Shadertoy](https://www.shadertoy.com). Esta simulação faz o mesmo em Python: a função `shader` é chamada para cada "píxel" e só sabe as suas coordenadas e o tempo:

```python run
import math

def shader(u, v, tempo):
    # u, v entre -1 e 1; desenha um círculo cujo raio pulsa, com um anel à volta
    d = math.sqrt(u * u + v * v)
    raio = 0.5 + 0.1 * math.sin(tempo)
    if d < raio:
        return 1.0 - d / raio                           # mais claro no centro
    anel = abs(d - 0.85)
    return max(0.0, 1.0 - anel * 12)                    # anel suave

def mostra(tempo, largura=40, altura=20):
    rampa = " .:-=+*#%@"
    for y in range(altura):
        linha = ""
        for x in range(largura):
            u = (x + 0.5) / largura * 2 - 1
            v = ((y + 0.5) / altura * 2 - 1)
            linha += rampa[min(9, int(shader(u, v, tempo) * 9.99))]
        print(linha)

mostra(tempo=0.0)
print("-" * 40)
mostra(tempo=math.pi / 2)
```

Prevê a diferença entre as duas imagens (em tempo = π/2, sin vale 1). Na GPU, a função correria para os dois milhões de píxeis de um ecrã Full HD ao mesmo tempo.

## Desempenho

- Evita `if` que dependem de valores diferentes em píxeis vizinhos: os núcleos da GPU executam em grupos, e ramos divergentes são executados um de cada vez.
- Faz no vertex shader o que puderes (há muito menos vértices do que píxeis).
- Ler texturas é caro; reutiliza.
