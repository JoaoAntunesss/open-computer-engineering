O **pipeline gráfico** é a sequência de etapas que a placa gráfica (GPU) percorre para transformar triângulos 3D em píxeis coloridos, 60 ou mais vezes por segundo. Algumas etapas são programáveis (os *shaders*), outras são fixas e feitas em hardware. A mais importante das fixas é a **rasterização**: descobrir que píxeis cada triângulo cobre.

## As etapas

```
vértices (posições, normais, cores, coordenadas de textura)
  │ vertex shader (programável): transforma cada vértice (modelo-vista-projeção)
  │ montagem de primitivas: junta os vértices em triângulos
  │ recorte (clipping): corta o que sai do volume de visão
  │ divisão perspetiva e viewport
  │ rasterização (fixa): que píxeis cobre cada triângulo? → fragmentos
  │ fragment shader (programável): a cor de cada fragmento
  │ testes de profundidade (z-buffer), mistura (transparências)
  ▼
imagem no ecrã
```

Tudo é feito em **paralelo** massivo: milhares de vértices e milhões de fragmentos ao mesmo tempo, em milhares de núcleos simples.

## Porquê triângulos

Três pontos definem sempre um plano, o triângulo é sempre convexo, e qualquer superfície se aproxima com triângulos suficientes. Um personagem de um jogo atual tem dezenas de milhares.

## Rasterização com funções de aresta

Para saber se um píxel (x, y) está dentro do triângulo ABC, calcula-se, para cada aresta, de que lado está o ponto (é o produto vetorial em 2D, como na lição de leitura de código):

E_AB(P) = (B.x − A.x)(P.y − A.y) − (B.y − A.y)(P.x − A.x)

O ponto está dentro se as três funções tiverem o mesmo sinal. As GPU fazem isto para blocos de píxeis em paralelo.

Os mesmos valores, normalizados, dão as **coordenadas baricêntricas** (α, β, γ): quanto o píxel "pertence" a cada vértice. Servem para **interpolar** qualquer atributo (cor, profundidade, coordenadas de textura) ao longo do triângulo.

```python run
def aresta(a, b, p):
    return (b[0] - a[0]) * (p[1] - a[1]) - (b[1] - a[1]) * (p[0] - a[0])

def rasteriza(A, B, C, cores, largura=32, altura=16):
    area = aresta(A, B, C)
    linhas = []
    for y in range(altura):
        linha = ""
        for x in range(largura):
            p = (x + 0.5, y + 0.5)                     # centro do píxel
            w0, w1, w2 = aresta(B, C, p), aresta(C, A, p), aresta(A, B, p)
            if (w0 >= 0 and w1 >= 0 and w2 >= 0) or (w0 <= 0 and w1 <= 0 and w2 <= 0):
                a, b, c = w0 / area, w1 / area, w2 / area          # baricêntricas
                # interpolar uma "cor" (aqui, um nível de 0 a 9) entre os três vértices
                nivel = a * cores[0] + b * cores[1] + c * cores[2]
                linha += str(int(nivel))
            else:
                linha += "."
        linhas.append(linha)
    return linhas

for l in rasteriza((2, 1), (29, 6), (8, 15), cores=(0, 9, 5)):
    print(l)
```

Prevê: que número aparece perto de cada vértice? Os valores mudam de forma suave entre eles: é assim que a GPU interpola cores, normais e coordenadas de textura.

## Anti-aliasing

Um píxel ou está dentro ou está fora, por isso as arestas inclinadas ficam em "escada" (*aliasing*). Soluções: **MSAA** (testar vários pontos por píxel e misturar), **FXAA**/**TAA** (filtros sobre a imagem final, ou usando as imagens anteriores).

## APIs

- **OpenGL** e **WebGL** (no browser): as clássicas, mais simples.
- **Vulkan**, **Direct3D 12**, **Metal**, **WebGPU**: modernas, de baixo nível, mais controlo e menos custo por chamada.
- **Three.js**, **Babylon.js**, motores como **Unity**, **Unreal** e **Godot** escondem a maior parte disto.
