A dedução natural é boa para pessoas. Para máquinas, há um método com uma só regra que basta para tudo: a **resolução**. É a base dos solvers SAT, que hoje resolvem problemas industriais com milhões de variáveis, e do Prolog.

## A regra de resolução

Trabalha com cláusulas (disjunções de literais, como na FNC). De duas cláusulas em que uma tem `p` e a outra tem `¬p`, conclui-se a cláusula com tudo o resto:

```text
  (p ∨ A)     (¬p ∨ B)
  --------------------
         A ∨ B
```

A ideia: ou `p` é falso, e então `A` tem de ser verdade, ou `p` é verdadeiro, e então `B` tem de ser verdade. Em qualquer caso, `A ∨ B`.

Casos particulares:

- de `p` e `¬p ∨ q` resolve-se `q`: é o *modus ponens*;
- de `p` e `¬p` resolve-se a **cláusula vazia** `□`, que é uma contradição.

## Provar por refutação

Para mostrar que `Γ ⊨ C`:

1. Junta às hipóteses a **negação** da conclusão: `Γ ∪ {¬C}`.
2. Põe tudo em FNC e separa em cláusulas.
3. Aplica resolução até obteres a cláusula vazia `□`.

Se chegaste a `□`, o conjunto é insatisfazível, logo `Γ ⊨ C`.

**Exemplo**: `p → q, q → r, p ⊨ r`

Cláusulas: `{¬p, q}`, `{¬q, r}`, `{p}`, e a conclusão negada `{¬r}`.

```text
1. {¬p, q}
2. {¬q, r}
3. {p}
4. {¬r}
5. {q}          de 1 e 3 (sobre p)
6. {r}          de 2 e 5 (sobre q)
7. □            de 4 e 6 (sobre r)
```

## SAT: o problema central

**SAT**: dada uma fórmula em FNC, existe uma valoração que a torne verdadeira? É o primeiro problema que se provou ser **NP-completo** (teorema de Cook-Levin, 1971): não se conhece nenhum algoritmo rápido para todos os casos e, se se encontrasse um, P seria igual a NP. Mesmo assim, os solvers modernos resolvem enormes instâncias reais em segundos.

### DPLL, o algoritmo por trás dos solvers

```text
DPLL(cláusulas):
  propaga cláusulas unitárias: se há {x}, x tem de ser V; simplifica
  se há uma cláusula vazia: devolve INSATISFAZÍVEL
  se não sobram cláusulas: devolve SATISFAZÍVEL
  escolhe uma variável x
  tenta DPLL(cláusulas com x = V); se falhar, tenta x = F
```

Em Python, de forma compacta (cada cláusula é um conjunto de inteiros; `-3` é `¬x3`):

```python
def dpll(clausulas, atribuicao=()):
    clausulas = [set(c) for c in clausulas]
    atribuicao = list(atribuicao)
    while True:                                   # propagação unitária
        unit = next((c for c in clausulas if len(c) == 1), None)
        if unit is None:
            break
        lit = next(iter(unit))
        atribuicao.append(lit)
        clausulas = [c - {-lit} for c in clausulas if lit not in c]
        if any(len(c) == 0 for c in clausulas):
            return None
    if not clausulas:
        return atribuicao
    lit = next(iter(clausulas[0]))
    for escolha in (lit, -lit):
        r = dpll(clausulas + [{escolha}], atribuicao)
        if r is not None:
            return r
    return None

# (x1 ∨ x2) ∧ (¬x1 ∨ x3) ∧ (¬x2 ∨ ¬x3) ∧ (¬x3)
print(dpll([{1, 2}, {-1, 3}, {-2, -3}, {-3}]))   # [-3, -1, 2]: x3=F, x1=F, x2=V
```

Os solvers reais (MiniSat, CaDiCaL, Kissat) juntam a isto aprendizagem de cláusulas a partir de conflitos (CDCL), boas heurísticas de escolha e reinícios.

## Usar um solver a sério

Com o Z3 (`pip install z3-solver`), escreves restrições e ele encontra uma solução:

```python
from z3 import Bools, Solver, Or, Not, Implies, sat

a, b, c = Bools("a b c")
s = Solver()
s.add(Or(a, b), Implies(a, c), Not(c))
if s.check() == sat:
    print(s.model())    # [c = False, a = False, b = True]
```

Problemas como horários escolares, configurações de produtos, verificação de circuitos e Sudoku descrevem-se como "estas condições têm de ser todas verdadeiras", e o solver faz o resto.

## Erros comuns

- Esquecer de negar a conclusão antes de fazer resolução.
- Resolver sobre duas variáveis ao mesmo tempo: de `{p, q}` e `{¬p, ¬q}` **não** se obtém `□`; resolve-se uma de cada vez (dá `{q, ¬q}`, que é sempre verdadeira e não ajuda).
- Esperar que "NP-completo" signifique "impossível na prática": significa apenas que não há garantia de rapidez para todos os casos.
