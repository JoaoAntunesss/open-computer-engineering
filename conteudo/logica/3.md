As tabelas de verdade verificam fórmulas, mas crescem `2ⁿ` e não explicam *porquê* algo é verdade. Uma **prova** é uma sequência de passos, cada um justificado por uma regra, que leva das hipóteses à conclusão. A **dedução natural** é o sistema de regras que mais se parece com a forma como raciocinamos, e é a base dos provadores de teoremas como Lean e Rocq.

## A ideia

Cada conectivo tem dois tipos de regras:

- **introdução**: como *provar* uma fórmula com esse conectivo;
- **eliminação**: como *usar* uma fórmula com esse conectivo que já temos.

Escrevemos `Γ ⊢ A` para "a partir das hipóteses Γ, prova-se A".

## As regras

**Conjunção**

- ∧I: de `A` e `B`, conclui `A ∧ B`.
- ∧E: de `A ∧ B`, conclui `A` (ou `B`).

**Implicação**

- →E (*modus ponens*): de `A → B` e `A`, conclui `B`.
- →I: se, **supondo** `A`, consegues provar `B`, então concluis `A → B` e a suposição deixa de estar ativa (diz-se que é descarregada).

**Disjunção**

- ∨I: de `A`, conclui `A ∨ B` (ou `B ∨ A`).
- ∨E (análise de casos): de `A ∨ B`, de uma prova `A ... C` e de uma prova `B ... C`, conclui `C`.

**Negação e absurdo** (⊥ é a contradição)

- ¬I: se, supondo `A`, chegas a `⊥`, concluis `¬A`.
- ¬E: de `A` e `¬A`, conclui `⊥`.
- ⊥E: de `⊥`, conclui qualquer coisa.
- RAA (redução ao absurdo): se, supondo `¬A`, chegas a `⊥`, concluis `A`. Esta regra é o que torna a lógica "clássica".

## Provas em formato de lista

Vamos escrever as provas numeradas, com caixas de suposição indicadas pela indentação.

**Exemplo 1**: `p ∧ q ⊢ q ∧ p`

```text
1. p ∧ q        hipótese
2. p            ∧E 1
3. q            ∧E 1
4. q ∧ p        ∧I 3, 2
```

**Exemplo 2**: `p → q, q → r ⊢ p → r` (transitividade)

```text
1. p → q        hipótese
2. q → r        hipótese
3.   p          suposição
4.   q          →E 1, 3
5.   r          →E 2, 4
6. p → r        →I 3–5
```

A suposição de 3 só vale dentro do bloco 3 a 5. Depois do →I, `p` já não está disponível.

**Exemplo 3**: `p → q ⊢ ¬q → ¬p` (contrarrecíproco)

```text
1. p → q        hipótese
2.   ¬q         suposição
3.     p        suposição
4.     q        →E 1, 3
5.     ⊥        ¬E 4, 2
6.   ¬p         ¬I 3–5
7. ¬q → ¬p      →I 2–6
```

**Exemplo 4**: `p ∨ q, ¬p ⊢ q` (silogismo disjuntivo), por casos

```text
1. p ∨ q        hipótese
2. ¬p           hipótese
3.   p          suposição (caso 1)
4.   ⊥          ¬E 3, 2
5.   q          ⊥E 4
6.   q          suposição (caso 2)
7. q            ∨E 1, 3–5, 6–6
```

## Estratégia para encontrar provas

1. Olha para a **conclusão**. Se é `A → B`, supõe `A` e tenta chegar a `B`. Se é `¬A`, supõe `A` e procura `⊥`. Se é `A ∧ B`, prova cada parte.
2. Olha para as **hipóteses**. Se tens `A ∧ B`, separa. Se tens `A ∨ B`, faz casos. Se tens `A → B`, procura `A`.
3. Se nada funciona, tenta redução ao absurdo: supõe a negação da conclusão.

## Correção e completude, em duas linhas

O sistema é **correto**: tudo o que se prova é logicamente verdadeiro (se `Γ ⊢ A` então `Γ ⊨ A`). E é **completo**: tudo o que é logicamente verdadeiro tem prova. A lição 8 explica o que isto quer dizer.

## Provas que o computador verifica

Em Lean 4, a transitividade da implicação escreve-se assim, e o Lean confirma cada passo:

```lean
example (p q r : Prop) (hpq : p → q) (hqr : q → r) : p → r := by
  intro hp          -- →I: supõe p
  apply hqr         -- para ter r, basta ter q
  exact hpq hp      -- →E: de p → q e p, q
```

O jogo **Natural Number Game** ensina Lean desta forma, nível a nível.

## Erros comuns

- Usar uma suposição fora da caixa em que foi feita.
- Aplicar →E ao contrário: de `A → B` e `B` **não** se conclui `A`.
- Esquecer que ∨E exige que **os dois** casos cheguem à mesma conclusão.
