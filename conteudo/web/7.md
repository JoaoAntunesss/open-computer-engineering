Quando uma interface cresce, atualizar o DOM à mão torna-se difícil de manter: cada ação muda várias partes da página, e é fácil esquecer uma. As **frameworks de front-end** (React, Vue, Svelte, Angular) resolvem isto com a mesma ideia: descreves **como a interface deve ser para um dado estado**, e a framework trata de atualizar o DOM quando o estado muda.

## Componentes

A interface divide-se em componentes reutilizáveis, cada um com as suas entradas (*props*) e o seu estado.

```jsx
// React
import { useState } from "react";

function Servico({ nome, preco, escolhido, onAlterna }) {
  return (
    <button className={escolhido ? "servico ativo" : "servico"} onClick={onAlterna}
            aria-pressed={escolhido}>
      {nome} — {preco} €
    </button>
  );
}

export default function Marcacao({ servicos }) {
  const [escolhidos, setEscolhidos] = useState([]);
  const total = servicos.filter(s => escolhidos.includes(s.id)).reduce((t, s) => t + s.preco, 0);
  const alterna = id => setEscolhidos(e => e.includes(id) ? e.filter(x => x !== id) : [...e, id]);
  return (
    <section>
      <h2>Escolha os serviços</h2>
      {servicos.map(s => (
        <Servico key={s.id} {...s} escolhido={escolhidos.includes(s.id)} onAlterna={() => alterna(s.id)} />
      ))}
      <p>Total: {total} €</p>
    </section>
  );
}
```

- **JSX:** HTML dentro de JavaScript (é transformado em chamadas de funções).
- **Estado** (`useState`): quando muda, o componente volta a ser desenhado.
- **Dados descem, eventos sobem:** o pai passa dados aos filhos por props; os filhos avisam o pai chamando funções que receberam.
- `key`: identifica cada elemento de uma lista, para a framework saber o que mudou.
- **Nunca alterar o estado diretamente** (`escolhidos.push(id)`): cria-se um valor novo, senão a framework não deteta a mudança.

O mesmo em **Vue** usa modelos HTML com diretivas (`v-for`, `v-if`, `@click`) e estado reativo (`ref`); em **Svelte**, o compilador gera o código que atualiza o DOM.

## Como funciona por dentro (a ideia)

O React mantém uma representação leve da interface (o "DOM virtual"). Quando o estado muda, gera uma nova, compara com a anterior e aplica ao DOM real só as diferenças. Uma versão minúscula dessa comparação:

```js run
function diferencas(antes, depois, caminho = "raiz") {
  const mudancas = [];
  if (antes === undefined) return [`criar ${caminho}: ${JSON.stringify(depois)}`];
  if (depois === undefined) return [`remover ${caminho}`];
  if (typeof antes !== "object" || typeof depois !== "object") {
    return antes === depois ? [] : [`alterar ${caminho}: ${JSON.stringify(antes)} → ${JSON.stringify(depois)}`];
  }
  if (antes.tag !== depois.tag) return [`substituir ${caminho}`];
  const chaves = new Set([...Object.keys(antes.props || {}), ...Object.keys(depois.props || {})]);
  for (const k of chaves) mudancas.push(...diferencas(antes.props?.[k], depois.props?.[k], `${caminho}.${k}`));
  const n = Math.max(antes.filhos?.length || 0, depois.filhos?.length || 0);
  for (let i = 0; i < n; i++) mudancas.push(...diferencas(antes.filhos?.[i], depois.filhos?.[i], `${caminho}[${i}]`));
  return mudancas;
}

const ui = (escolhidos, total) => ({
  tag: "section", filhos: [
    { tag: "button", props: { class: escolhidos.includes("corte") ? "ativo" : "" }, filhos: ["Corte"] },
    { tag: "button", props: { class: escolhidos.includes("cor") ? "ativo" : "" }, filhos: ["Coloração"] },
    { tag: "p", filhos: [`Total: ${total} €`] },
  ],
});
console.log(diferencas(ui([], 0), ui(["corte"], 15)).join("\n"));
console.log("---");
console.log(diferencas(ui(["corte"], 15), ui(["corte"], 15)).join("\n") || "(nada a mudar)");
```

Prevê as mudanças que a primeira comparação encontra. Em vez de redesenhar a página, só se mexe em dois sítios.

## Quando usar uma framework

- **Sim:** aplicações com muita interação e estado (um painel de gestão, um editor, uma app que funciona como aplicação).
- **Talvez não:** sites sobretudo de conteúdo (a página de um salão, um portfólio). HTML, CSS e um pouco de JavaScript são mais rápidos a carregar e mais simples de manter. Geradores de sites estáticos (Astro, Eleventy) são um bom meio-termo.
- **Meta-frameworks** (Next.js, Nuxt, SvelteKit) juntam o front-end com renderização no servidor (melhor para SEO e para o primeiro carregamento) e rotas.

??? Soluções
1: `alterar raiz[0].class: "" → "ativo"` e `alterar raiz[2][0]: "Total: 0 €" → "Total: 15 €"`; depois `(nada a mudar)`.

2: `push` altera a mesma lista, e `setEscolhidos` recebe o mesmo objeto: o React compara as referências, vê que são iguais e não redesenha. É preciso uma lista nova (`[...escolhidos, id]`).

3: `<button type="button" onClick={() => setEscolhidos([])}>Limpar</button>`.

4: provavelmente não para o site todo: o conteúdo não precisa de framework, e carregar React torna a primeira visita mais lenta. O formulário de marcação, se for muito interativo, pode ser um componente isolado (ou JavaScript simples).
