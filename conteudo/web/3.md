O **DOM** (*Document Object Model*) é a página carregada, vista pelo JavaScript como uma árvore de objetos. Com ele, o JavaScript lê e muda o conteúdo, responde a cliques e teclas, e vai buscar dados ao servidor sem recarregar a página. É a base de todas as interfaces web, incluindo as feitas com React ou Vue (que, por baixo, mexem no DOM por ti).

## Selecionar e alterar

```js
const titulo = document.querySelector("h1");               // o primeiro que corresponde
const botoes = document.querySelectorAll(".servico button"); // todos (NodeList)

titulo.textContent = "Marcar um serviço";      // texto (seguro)
titulo.classList.add("destaque");              // classes: add, remove, toggle
document.querySelector("#total").hidden = false;

const item = document.createElement("li");
item.textContent = "Corte — 15 €";
document.querySelector("#carrinho").append(item);
```

**Cuidado:** `elemento.innerHTML = textoDoUtilizador` interpreta o texto como HTML. Se alguém escrever `<img src=x onerror="roubar()">` no nome, esse código corre na página de todos os que a virem (**XSS**, lição 8). Para texto, usa sempre `textContent`.

## Eventos

```js
const form = document.querySelector("#marcacao");
form.addEventListener("submit", async (evento) => {
  evento.preventDefault();                       // não recarregar a página
  const dados = Object.fromEntries(new FormData(form));
  const r = await fetch("/api/marcacoes", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(dados),
  });
  mostrarMensagem(r.ok ? "Marcação feita!" : "Não foi possível marcar.");
});
```

**Delegação de eventos:** em vez de um ouvinte por botão (que tem de ser acrescentado a cada botão novo), um só no contentor:

```js
document.querySelector("#servicos").addEventListener("click", (e) => {
  const botao = e.target.closest("button[data-id]");
  if (botao) escolherServico(botao.dataset.id);
});
```

## Assíncrono: o ciclo de eventos

O JavaScript no browser corre numa **única thread**. Para não bloquear a página enquanto espera pela rede, as operações lentas são **assíncronas**: o código continua, e uma função é chamada quando o resultado chegar. `async`/`await` deixa escrever isto como se fosse sequencial.

Prevê a ordem das mensagens antes de correr:

```js run
console.log("1. início");

setTimeout(() => console.log("2. setTimeout de 0 ms"), 0);

Promise.resolve().then(() => console.log("3. promessa resolvida"));

(async () => {
  console.log("4. dentro da função async, antes do await");
  await null;
  console.log("5. depois do await");
})();

console.log("6. fim do código");
```

A regra: primeiro corre todo o código síncrono; depois as **microtarefas** (promessas, o que vem depois de um `await`); só depois as **tarefas** (temporizadores, eventos, respostas de rede). Por isso o `setTimeout` de 0 ms é o último.

## Estado e interface

O erro clássico em JavaScript "à mão" é guardar o estado espalhado pelo DOM e atualizá-lo aos bocados, até ficar inconsistente. Um padrão simples, que é a ideia por trás do React: **guardar o estado num objeto e redesenhar a partir dele**.

```js run
const estado = { escolhidos: [], servicos: { corte: 15, cor: 45, mani: 20 } };

function render() {                       // a interface é uma função do estado
  const total = estado.escolhidos.reduce((t, s) => t + estado.servicos[s], 0);
  return `Escolhidos: ${estado.escolhidos.join(", ") || "nenhum"} | Total: ${total} €`;
}

function alterna(s) {
  const i = estado.escolhidos.indexOf(s);
  if (i >= 0) estado.escolhidos.splice(i, 1); else estado.escolhidos.push(s);
  console.log(render());                  // no browser: elemento.textContent = render()
}

alterna("corte"); alterna("cor"); alterna("corte"); alterna("mani");
```
