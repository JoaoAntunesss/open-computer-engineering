Um site só existe para os outros quando está **publicado**: num servidor acessível, com um **domínio**, por **HTTPS**. Hoje isto é barato (muitas vezes gratuito) e rápido, mas há escolhas a fazer: onde alojar, como ligar o domínio, como fazer deploy sem medo, e como saber se o site está em baixo.

## O caminho de um pedido

```
o browser escreve salaoaurora.pt
  → DNS: salaoaurora.pt é 185.199.108.153?
  → ligação TCP + TLS (certificado válido para salaoaurora.pt?)
  → pedido HTTP ao servidor (ou à CDN mais próxima)
  → resposta
```

Cada passo pode falhar, e cada um tem a sua configuração.

## Domínios

- Compra-se num registador (para `.pt`, um registador acreditado pela DNS.pt; para `.com`, Cloudflare, Namecheap, OVH…). Cerca de 10–20 € por ano.
- No painel de DNS, apontas o domínio para o alojamento:
  - `A` / `AAAA` para um IP;
  - `CNAME` para outro nome (`www` → `salaoaurora.pt`, ou → `meu-site.web.app`);
  - `TXT` para provar que o domínio é teu (o alojamento pede-o) e para o email (SPF, DKIM).
- As alterações demoram até ao TTL a chegar a toda a gente (lição 6 de Redes).

## HTTPS

Obrigatório, mesmo em sites sem login: sem ele, o browser mostra "Não seguro", os formulários ficam expostos, e o Google penaliza.

- O certificado prova que o servidor é mesmo dono do domínio. É emitido por uma autoridade de certificação; o **Let's Encrypt** emite-os gratuitamente e renova-os automaticamente (validade de 90 dias).
- Os alojamentos modernos (Firebase Hosting, Netlify, Vercel, Cloudflare Pages, GitHub Pages) tratam disto sozinhos.
- Redireciona sempre HTTP → HTTPS, e ativa o HSTS.

## Onde alojar

| Tipo | Exemplos | Bom para |
|---|---|---|
| **Estático + CDN** | GitHub Pages, Firebase Hosting, Netlify, Cloudflare Pages | sites de conteúdo, SPAs; gratuito ou quase |
| **Backend gerido (BaaS)** | Firebase, Supabase | dados, autenticação e funções sem gerir servidores |
| **Plataforma (PaaS)** | Render, Railway, Fly.io, Google Cloud Run | uma aplicação Node/Python/PHP com base de dados |
| **Servidor virtual (VPS)** | Hetzner, DigitalOcean, OVH | controlo total, a gestão (atualizações, segurança, backups) é tua |
| **Alojamento partilhado** | muitos fornecedores nacionais | WordPress e PHP simples |

Uma **CDN** guarda cópias dos ficheiros em servidores espalhados pelo mundo: o utilizador recebe-os do mais próximo.

## Desempenho

O tempo de carregamento afeta as conversões e o SEO. As métricas do Google (**Core Web Vitals**): LCP (o elemento principal aparece em < 2,5 s), INP (resposta a cliques em < 200 ms) e CLS (sem saltos de layout).

```js run
// Quanto pesa uma página típica, e quanto demora numa ligação móvel fraca?
const recursos = {
  "HTML": 18, "CSS": 45, "JavaScript": 380, "fonte (2 pesos)": 90,
  "imagem do topo (JPEG 2000px)": 650, "6 fotografias da galeria": 1800,
};
const totalKB = Object.values(recursos).reduce((a, b) => a + b, 0);
const ligacoes = { "4G bom (20 Mb/s)": 20, "3G (1,6 Mb/s)": 1.6 };
console.log("total:", totalKB, "KB");
for (const [nome, mbps] of Object.entries(ligacoes))
  console.log(`${nome}: ${(totalKB * 8 / 1000 / mbps).toFixed(1)} s só a transferir`);

// otimizado: imagens em AVIF/WebP no tamanho certo, galeria com loading="lazy", menos JS
const otimizado = { ...recursos, "JavaScript": 60, "imagem do topo (JPEG 2000px)": 90, "6 fotografias da galeria": 0 };
const t2 = Object.values(otimizado).reduce((a, b) => a + b, 0);
console.log("otimizado:", t2, "KB →", (t2 * 8 / 1000 / 1.6).toFixed(1), "s em 3G");
```

Prevê os tempos. As imagens são quase sempre o maior peso; `srcset`, formatos modernos e `loading="lazy"` resolvem a maior parte.

## Deploy e operação

- **Deploy automático** a partir do Git (lição 7 de Engenharia de Software): `git push` → testes → publicação.
- **Pré-visualizações:** cada pull request com o seu URL temporário (Netlify, Vercel, Firebase Hosting channels) para o cliente aprovar antes.
- **Monitorização:** um serviço que visita o site de minuto a minuto e avisa se cair (UptimeRobot, Better Stack), e registo de erros do JavaScript (Sentry).
- **Backups** da base de dados, testados.
- **Legal (UE):** política de privacidade, banner de cookies se usares cookies não essenciais (analytics, publicidade), e o livro de reclamações eletrónico para negócios em Portugal.
