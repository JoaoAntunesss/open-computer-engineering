**Autenticação** é saber **quem** é o utilizador; **autorização** é saber **o que** pode fazer. O HTTP não guarda estado entre pedidos, por isso, depois do login, cada pedido tem de levar uma prova de quem o faz: um **cookie de sessão** ou um **token**. Erros aqui são das falhas de segurança mais graves e mais comuns.

## Guardar palavras-passe

**Nunca** em texto, nem cifradas com uma chave (quem tiver a chave lê todas). Guarda-se um **hash lento com sal**:

- **Sal:** um valor aleatório por utilizador, guardado ao lado do hash. Palavras-passe iguais dão hashes diferentes, e as tabelas pré-calculadas deixam de servir.
- **Lento de propósito:** Argon2id, bcrypt ou scrypt. SHA-256 é rápido demais: um atacante com a base de dados testa milhares de milhões por segundo.

```python run
import hashlib, os, time, hmac

def guarda(password):
    sal = os.urandom(16)
    h = hashlib.pbkdf2_hmac("sha256", password.encode(), sal, 200_000)   # 200 mil iterações
    return sal.hex() + "$" + h.hex()

def verifica(password, guardado):
    sal_hex, h_hex = guardado.split("$")
    h = hashlib.pbkdf2_hmac("sha256", password.encode(), bytes.fromhex(sal_hex), 200_000)
    return hmac.compare_digest(h.hex(), h_hex)          # comparação em tempo constante

t = time.perf_counter()
a = guarda("Primavera2026!")
print(f"um hash demora {(time.perf_counter() - t) * 1000:.0f} ms")
b = guarda("Primavera2026!")
print("mesma palavra-passe, hashes iguais?", a == b)
print("verifica certa:", verifica("Primavera2026!", a), "| errada:", verifica("primavera2026!", a))

t = time.perf_counter()
for _ in range(1000): hashlib.sha256(b"Primavera2026!").digest()
print(f"1000 SHA-256 simples: {(time.perf_counter() - t) * 1000:.2f} ms")
```

Prevê as linhas. A lentidão do PBKDF2 é imperceptível num login, mas multiplica por centenas de milhares o trabalho de um atacante. (Em produção, prefere Argon2id, com a biblioteca `argon2-cffi`, ou bcrypt.)

## Sessões com cookies

1. O utilizador faz login; o servidor verifica a palavra-passe.
2. Cria uma **sessão** (um identificador aleatório e longo, guardado no servidor com o id do utilizador).
3. Envia-a num cookie: `Set-Cookie: sessao=8f3a…; HttpOnly; Secure; SameSite=Lax; Max-Age=1209600`.
4. O browser envia o cookie em cada pedido; o servidor consulta a sessão.

As opções do cookie são essenciais:

- `HttpOnly`: o JavaScript da página não o consegue ler (protege contra roubo por XSS).
- `Secure`: só vai por HTTPS.
- `SameSite=Lax`: não é enviado em pedidos vindos de outros sites (protege contra CSRF).

Para terminar a sessão, apaga-se no servidor (logout real em todos os sítios).

## Tokens (JWT)

Um **JWT** é um objeto JSON assinado pelo servidor: `cabeçalho.dados.assinatura`, em base64.

- O servidor não precisa de guardar nada: verifica a assinatura e confia nos dados (`{"sub": 42, "papel": "dona", "exp": 1762700000}`).
- Bom para APIs usadas por apps móveis e entre serviços.
- Desvantagens: não se revoga facilmente antes de expirar (usa validades curtas, com um *refresh token*); os dados são **legíveis** por qualquer pessoa (assinados, não cifrados).
- Guardar o token em `localStorage` expõe-no a qualquer XSS; num cookie `HttpOnly` fica mais protegido.

O **Firebase Auth** usa exatamente isto: o SDK obtém um JWT (o *ID token*) que vale uma hora e renova-o sozinho.

## Autorização

Depois de saber quem é, verifica **em cada pedido** se pode fazer aquilo:

- **Por papel:** a dona vê todas as marcações; uma cliente só as suas.
- **Por dono do recurso:** `PATCH /api/marcacoes/42` só se a marcação 42 for da pessoa autenticada (ou se for a dona). Esquecer esta verificação é a falha nº 1 da lista OWASP (*Broken Access Control*): mudar o 42 para 43 no URL e ver os dados de outra pessoa.

## Outras boas práticas

- **2FA** (código no telemóvel ou chave física) e, cada vez mais, **passkeys** (sem palavra-passe).
- Limitar tentativas de login (e atrasar as falhadas).
- Recuperação de conta por email, com um token aleatório de uso único que expira em minutos.
- Mensagens de erro iguais para "utilizador não existe" e "palavra-passe errada".
- Usar **OAuth** ("Entrar com Google") em vez de guardar palavras-passe, quando faz sentido.
