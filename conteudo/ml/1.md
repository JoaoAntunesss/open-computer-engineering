A **aprendizagem automática** (*machine learning*) constrói programas a partir de **exemplos** em vez de regras escritas à mão: em vez de programar "um email é spam se…", mostram-se milhares de emails classificados e o algoritmo encontra os padrões. Mas o mais importante não é o algoritmo: é preparar bem os dados e **avaliar honestamente**. A maioria dos modelos que falham em produção falhou aqui.

## O vocabulário

- **Exemplos** (linhas) com **características** (*features*, colunas) e, na aprendizagem supervisionada, um **alvo** (*label*): o preço da casa, spam ou não.
- **Regressão:** o alvo é um número. **Classificação:** o alvo é uma categoria.
- **Não supervisionada:** sem alvo; procura estrutura (grupos, dimensões principais).
- **Modelo:** uma função com **parâmetros** ajustados aos dados (o treino). **Hiperparâmetros:** escolhas feitas antes do treino (o grau de um polinómio, o k do k-vizinhos).

## Preparar os dados

- **Valores em falta:** remover, ou preencher (com a mediana, por exemplo), e às vezes acrescentar uma coluna "estava em falta".
- **Variáveis categóricas:** transformar em números. *One-hot*: a cidade passa a três colunas (é_Porto, é_Lisboa, é_Braga), em vez de 1, 2, 3 (que sugeriria uma ordem que não existe).
- **Escalas:** muitos algoritmos (k-vizinhos, SVM, redes neuronais, descida do gradiente) são sensíveis a escalas diferentes. **Normalizar** (média 0, desvio 1) ou pôr entre 0 e 1.
- **Valores absurdos:** idades de 200 anos, preços negativos.

## Treino, validação e teste

Um modelo avaliado nos mesmos dados com que foi treinado parece sempre bom: pode simplesmente ter decorado. Divide-se:

- **Treino** (≈ 60–80%): para ajustar os parâmetros.
- **Validação** (≈ 10–20%): para escolher hiperparâmetros e comparar modelos.
- **Teste** (≈ 10–20%): usado **uma única vez**, no fim, para estimar o desempenho real. Se o usares para decidir, deixa de ser um teste.

**Validação cruzada** (k-fold): divide os dados em k partes; treina k vezes, cada vez avaliando numa parte diferente; faz a média. Usa melhor dados escassos.

## Fugas de informação (*data leakage*)

O erro mais traiçoeiro: informação do conjunto de teste (ou do futuro) entra no treino.

- Normalizar com a média de **todos** os dados antes de dividir.
- Exemplos repetidos (o mesmo cliente) em treino e teste.
- Usar uma variável que só se conhece depois do que se quer prever ("prever se o cliente vai faltar" usando "pagou taxa de falta").
- Em séries temporais, dividir ao acaso em vez de treinar no passado e testar no futuro.

## Métricas

Para classificação, a **exatidão** (fração de acertos) engana quando as classes estão desequilibradas. Prevê os números:

```python run
import numpy as np
rng = np.random.default_rng(1)

# 1000 marcações; só 5% são faltas. Um "modelo" que diz sempre "não falta":
real = rng.random(1000) < 0.05
sempre_nao = np.zeros(1000, dtype=bool)

# um modelo um pouco melhor: apanha 60% das faltas, mas dá 8% de falsos alarmes
previsto = np.where(real, rng.random(1000) < 0.6, rng.random(1000) < 0.08)

def metricas(real, prev):
    vp = np.sum(real & prev); fp = np.sum(~real & prev)
    fn = np.sum(real & ~prev); vn = np.sum(~real & ~prev)
    exatidao = (vp + vn) / len(real)
    precisao = vp / (vp + fp) if vp + fp else 0
    sensibilidade = vp / (vp + fn)
    return f"exatidão {exatidao:.1%} | precisão {precisao:.1%} | sensibilidade {sensibilidade:.1%}"

print("sempre 'não falta':", metricas(real, sempre_nao))
print("modelo:            ", metricas(real, previsto))
```

- **Precisão:** dos que o modelo marcou como falta, quantos faltaram?
- **Sensibilidade** (*recall*): das faltas reais, quantas o modelo apanhou?
- **F1:** a média harmónica das duas. **Matriz de confusão:** a tabela completa.
- Para regressão: erro absoluto médio (MAE), erro quadrático médio (RMSE), R².

Compara sempre com uma **linha de base** simples (a classe mais frequente, a média, a regra que já se usa). Um modelo que não bate a linha de base não serve.
