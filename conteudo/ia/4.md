Muitos problemas são "encontra valores para estas variáveis que cumpram todas estas regras": horários de aulas, escalas de turnos, sudoku, coloração de mapas, atribuição de salas. São **problemas de satisfação de restrições** (CSP). Em vez de escrever um algoritmo para cada um, descreve-se o problema de forma declarativa e usa-se um solucionador genérico, que é muito mais rápido do que experimentar tudo.

## A formulação

- **Variáveis:** X₁, …, Xₙ (as turmas, as funcionárias de cada turno, as casas do sudoku).
- **Domínios:** os valores possíveis de cada uma (salas, pessoas, 1 a 9).
- **Restrições:** que combinações são permitidas ("duas turmas não podem estar na mesma sala à mesma hora", "a Ana não trabalha ao domingo").

Uma **solução** atribui a cada variável um valor do seu domínio sem violar nenhuma restrição.

## Retrocesso (backtracking)

Atribui uma variável de cada vez; se uma atribuição viola uma restrição, desfaz e tenta o valor seguinte. Muito melhor do que gerar todas as combinações, porque abandona cedo os ramos impossíveis. E fica muito mais rápido com três ideias:

1. **Ordem das variáveis — MRV** (*minimum remaining values*): escolher primeiro a variável com **menos** valores possíveis. Falha cedo, se tiver de falhar.
2. **Ordem dos valores — LCV**: tentar primeiro o valor que **menos** restringe as outras.
3. **Verificação para a frente** (*forward checking*): depois de atribuir, retirar dos domínios dos vizinhos os valores que ficaram impossíveis. Se algum domínio ficar vazio, voltar atrás já.

A **consistência de arcos** (AC-3) vai mais longe, propagando as consequências até nada mudar. Num sudoku fácil, só a propagação resolve tudo, sem pesquisa.

## Escalar turnos

```python run
dias = ["seg", "ter", "qua", "qui", "sex", "sáb"]
pessoas = {"Ana": {"seg", "ter", "qua", "qui", "sex"},     # dias em que pode trabalhar
           "Bia": {"ter", "qui", "sáb"},
           "Rui": {"seg", "qua", "sex", "sáb"},
           "Eva": {"seg", "ter", "qua", "qui", "sex", "sáb"}}
MAX_DIAS = 2                                              # cada pessoa no máximo 2 dias

passos = 0
def resolve(atribuicao, dominios):
    global passos
    if len(atribuicao) == len(dias):
        return atribuicao
    # MRV: o dia por atribuir com menos pessoas possíveis
    dia = min((d for d in dias if d not in atribuicao), key=lambda d: len(dominios[d]))
    for p in sorted(dominios[dia]):
        passos += 1
        if list(atribuicao.values()).count(p) >= MAX_DIAS:
            continue
        nova = {**atribuicao, dia: p}
        # verificação para a frente: quem já tem 2 dias sai dos outros domínios
        cheios = {q for q in pessoas if list(nova.values()).count(q) >= MAX_DIAS}
        novos_dom = {d: (dominios[d] - cheios) for d in dias if d not in nova}
        if all(novos_dom.values()):                        # nenhum domínio vazio
            r = resolve(nova, novos_dom)
            if r:
                return r
    return None

dominios = {d: {p for p, disp in pessoas.items() if d in disp} for d in dias}
solucao = resolve({}, dominios)
print({d: solucao[d] for d in dias} if solucao else "impossível")
print("valores experimentados:", passos)
```

## Em projetos reais

Usa um solucionador: **OR-Tools CP-SAT** (Google, gratuito), **MiniZinc**, **python-constraint**, ou um solucionador SAT. Descreves variáveis e restrições, e ele trata da pesquisa com técnicas muito mais avançadas.

```python
from ortools.sat.python import cp_model
m = cp_model.CpModel()
x = {(p, d): m.NewBoolVar(f"{p}_{d}") for p in pessoas for d in dias}
for d in dias:
    m.AddExactlyOne(x[p, d] for p in pessoas if d in pessoas[p])
    for p in pessoas:
        if d not in pessoas[p]: m.Add(x[p, d] == 0)
for p in pessoas:
    m.Add(sum(x[p, d] for d in dias) <= MAX_DIAS)
```
