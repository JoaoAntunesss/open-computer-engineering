Em inteligência artificial clássica, os algoritmos de procura e de jogo são curtos mas muito fáceis de ler mal: a ordem pela qual se exploram os estados decide tudo. Ler e prever esse código é a forma de perceber porque é que a BFS encontra o caminho mais curto e a DFS não.

## Ler e prever: BFS num labirinto

```python run
from collections import deque

grelha = [
    "S.#.",
    "..#.",
    "...G",
]

def bfs():
    linhas, cols = len(grelha), len(grelha[0])
    fila = deque([((0, 0), 0)])
    visto = {(0, 0)}
    while fila:
        (r, c), d = fila.popleft()
        if grelha[r][c] == "G":
            return d
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < linhas and 0 <= nc < cols and grelha[nr][nc] != "#" and (nr, nc) not in visto:
                visto.add((nr, nc))
                fila.append(((nr, nc), d + 1))
    return None

print(bfs())
```

Antes de correr: conta à mão o caminho mais curto de S até G (só para cima, baixo, esquerda e direita, sem passar nos `#`).

## Encontra o erro: a mesma procura, mas nunca acaba

Numa versão do código acima, alguém tirou a linha `visto.add((nr, nc))` "para simplificar". Lê o código sem essa linha e explica o que acontece com a fila numa grelha sem paredes de 50 × 50. Porque é que, mesmo assim, num caso pequeno pode chegar a dar a resposta certa?
