Muitos problemas de IA são problemas de **pesquisa**: há um estado inicial, ações que mudam o estado e um objetivo. Resolver é encontrar uma sequência de ações que leva ao objetivo, de preferência a mais barata. O GPS, os puzzles, o planeamento de robôs e a pesquisa de jogadas em jogos funcionam assim. A diferença entre as técnicas está na **ordem** em que exploram os estados.

## Formular um problema

- **Estados** e **estado inicial**.
- **Ações** possíveis em cada estado e o seu **custo**.
- **Teste de objetivo.**

Exemplo: o puzzle de 8 peças. Estado = posição das peças; ações = mover o espaço vazio; custo = 1 por movimento.

## Pesquisa não informada

Não sabe nada sobre onde está o objetivo:

- **Largura (BFS):** explora por camadas. Encontra o caminho com **menos passos**. Gasta muita memória.
- **Custo uniforme:** expande sempre o estado com menor custo acumulado (é o Dijkstra). Encontra o caminho **mais barato**.
- **Profundidade (DFS):** vai a fundo por um caminho. Pouca memória, mas não garante o melhor caminho (e pode perder-se em ramos infinitos).
- **Aprofundamento iterativo:** DFS com limites 1, 2, 3… Junta a pouca memória da DFS com a garantia da BFS.

## Pesquisa informada: A*

Usa uma **heurística** h(n): uma estimativa do custo que falta de n até ao objetivo. O A* expande sempre o estado com menor

f(n) = g(n) + h(n)

(custo já gasto + estimativa do que falta). Se a heurística for **admissível** (nunca sobrestima o custo real), o A* encontra o caminho ótimo, e explora muito menos estados do que o custo uniforme.

Heurísticas típicas numa grelha: a **distância de Manhattan** (|Δx| + |Δy|) quando só há movimentos horizontais e verticais; a distância em linha reta num mapa.

```python run
import heapq

mapa = [
    "S....#....",
    ".##..#.##.",
    ".#...#..#.",
    ".#.###..#.",
    ".#......#.",
    ".######.#G",
    "..........",
]
L, C = len(mapa), len(mapa[0])
inicio = next((r, c) for r in range(L) for c in range(C) if mapa[r][c] == "S")
fim = next((r, c) for r in range(L) for c in range(C) if mapa[r][c] == "G")

def vizinhos(p):
    r, c = p
    for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        nr, nc = r + dr, c + dc
        if 0 <= nr < L and 0 <= nc < C and mapa[nr][nc] != "#":
            yield (nr, nc)

def pesquisa(h):
    fila = [(h(inicio), 0, inicio)]
    custo, pai, expandidos = {inicio: 0}, {inicio: None}, 0
    while fila:
        f, g, p = heapq.heappop(fila)
        if g > custo[p]:
            continue
        expandidos += 1
        if p == fim:
            caminho = []
            while p:
                caminho.append(p); p = pai[p]
            return g, expandidos, caminho[::-1]
        for v in vizinhos(p):
            if g + 1 < custo.get(v, 1e9):
                custo[v], pai[v] = g + 1, p
                heapq.heappush(fila, (g + 1 + h(v), g + 1, v))

manhattan = lambda p: abs(p[0] - fim[0]) + abs(p[1] - fim[1])
for nome, h in (("custo uniforme (h = 0)", lambda p: 0), ("A* com Manhattan", manhattan)):
    g, exp, caminho = pesquisa(h)
    print(f"{nome}: custo {g}, estados expandidos {exp}")

desenho = [list(l) for l in mapa]
for r, c in caminho[1:-1]:
    desenho[r][c] = "*"
print("\n".join("".join(l) for l in desenho))
```

Prevê: os dois encontram o mesmo custo? Qual expande menos estados?

## Escolher a heurística

- **Admissível:** nunca sobrestima (garante o ótimo).
- **Consistente:** h(n) ≤ custo(n, n') + h(n') (garante que cada estado só precisa de ser expandido uma vez).
- Quanto mais **informativa** (mais perto do custo real, sem passar), menos estados se exploram. h = 0 é admissível, mas inútil: dá o custo uniforme.
- Inventa-se relaxando o problema: no puzzle de 8, "quantas peças estão fora do sítio" e "soma das distâncias de Manhattan de cada peça" são custos de versões mais fáceis do puzzle.
