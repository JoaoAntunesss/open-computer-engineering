Quando os dados não cabem num computador (terabytes de registos, milhares de milhões de páginas web), é preciso processá-los em **muitos** computadores ao mesmo tempo. O **MapReduce** (Google, 2004) tornou isto acessível com uma ideia simples: o programador escreve duas funções, **map** e **reduce**, e o sistema trata da distribuição, das falhas e da movimentação dos dados. Hoje usam-se sucessores mais rápidos (Spark, Flink, BigQuery), mas a ideia é a mesma.

## O modelo

1. **Map:** aplicado a cada registo de entrada, de forma independente; produz pares (chave, valor).
2. **Shuffle** (feito pelo sistema): agrupa todos os valores com a mesma chave e envia cada grupo para uma máquina.
3. **Reduce:** aplicado a cada chave com a lista dos seus valores; produz o resultado.

O exemplo clássico, contar palavras:

```
map("o gato e o cão")  → (o,1) (gato,1) (e,1) (o,1) (cão,1)
shuffle               → o: [1,1]   gato: [1]   e: [1]   cão: [1]
reduce("o", [1,1])    → (o, 2)
```

## Um MapReduce em miniatura

```python run
from collections import defaultdict
from itertools import chain

def mapreduce(entradas, mapear, reduzir, n_maquinas=3):
    # 1. map: cada "máquina" trata uma parte das entradas
    partes = [entradas[i::n_maquinas] for i in range(n_maquinas)]
    intermedios = list(chain.from_iterable(mapear(x) for parte in partes for x in parte))
    # 2. shuffle: agrupar por chave (a chave decide para que máquina vai: hash % n)
    grupos = defaultdict(list)
    for chave, valor in intermedios:
        grupos[chave].append(valor)
    destino = {c: hash(c) % n_maquinas for c in grupos}
    # 3. reduce
    return {c: reduzir(c, vs) for c, vs in sorted(grupos.items())}, len(intermedios)

registos = [  # registos de acesso de um site de marcações: (dia, página, ms)
    ("2026-11-02", "/marcar", 120), ("2026-11-02", "/servicos", 80), ("2026-11-02", "/marcar", 340),
    ("2026-11-03", "/marcar", 95), ("2026-11-03", "/", 40), ("2026-11-03", "/marcar", 210),
    ("2026-11-03", "/servicos", 60), ("2026-11-04", "/marcar", 180), ("2026-11-04", "/", 35),
]

# pergunta 1: quantos acessos por página?
r, n = mapreduce(registos, lambda r: [(r[1], 1)], lambda c, vs: sum(vs))
print("acessos por página:", r, f"({n} pares intermédios)")

# pergunta 2: tempo médio de resposta por página
r, _ = mapreduce(registos, lambda r: [(r[1], r[2])], lambda c, vs: round(sum(vs) / len(vs)))
print("tempo médio (ms):", r)

# pergunta 3: em cada dia, quantas visitas a /marcar?
r, _ = mapreduce(registos, lambda r: [(r[0], 1)] if r[1] == "/marcar" else [],
                 lambda c, vs: len(vs))
print("visitas a /marcar por dia:", r)
```

Prevê as três respostas. Repara que `mapear` e `reduzir` não sabem nada de máquinas nem de rede: é isso que torna o modelo fácil.

## Tolerância a falhas

Com milhares de máquinas, alguma falha durante quase todos os trabalhos. Como as funções map e reduce são **determinísticas** e sem efeitos secundários, o sistema simplesmente **repete** a tarefa noutra máquina. Os dados de entrada estão replicados num sistema de ficheiros distribuído (GFS, HDFS) e os resultados intermédios em disco. Também se lançam cópias das tarefas mais lentas (*stragglers*) e usa-se a que acabar primeiro.

## Princípios que ficaram

- **Levar o cálculo aos dados**, não os dados ao cálculo: os mapas correm nas máquinas que já têm os blocos dos ficheiros.
- **Funções puras** facilitam repetir e paralelizar (a ligação à programação funcional não é coincidência: map e fold).
- O **shuffle** é a parte cara (tudo passa pela rede). Um **combinador** (um reduce local antes do shuffle) poupa muito: em vez de enviar mil pares (o, 1), envia (o, 1000).

## Os sucessores

- **Apache Spark:** mantém os dados em memória entre etapas (o MapReduce escrevia tudo em disco), e tem uma API muito mais rica (filtrar, juntar, agrupar, SQL, aprendizagem automática). Dezenas de vezes mais rápido em trabalhos iterativos.
- **Processamento de fluxos** (Flink, Kafka Streams, Spark Streaming): os dados chegam continuamente e os resultados atualizam-se em tempo real (janelas de tempo, "visitas nos últimos 5 minutos").
- **Armazéns de dados na cloud** (BigQuery, Snowflake, Redshift): escreves SQL e o sistema distribui por milhares de máquinas, sem gerires nada.
