Algumas coisas só podem ser feitas por uma máquina de cada vez (escrever num ficheiro partilhado, correr a tarefa diária de enviar lembretes), e alguns sistemas precisam de um **líder** que coordena os outros (quem distribui o trabalho, quem aceita as escritas). Num só computador usam-se trincos; num sistema distribuído, sem memória partilhada e com falhas, é preciso combinar por mensagens.

## Exclusão mútua distribuída

Requisitos: **segurança** (no máximo um na secção crítica), **vivacidade** (quem pede acaba por entrar), e de preferência **justiça** (por ordem de pedido).

Abordagens:

1. **Coordenador central:** um processo concede o acesso (como um trinco num servidor). Simples, 3 mensagens por entrada; o coordenador é um ponto único de falha.
2. **Ricart-Agrawala:** quem quer entrar pede a **todos**, com um carimbo de Lamport; cada um responde "ok" já, ou depois de sair, se tiver um pedido mais antigo. Entra quando todos responderem. 2(n − 1) mensagens; sem coordenador, mas basta um processo morto para bloquear tudo.
3. **Anel com testemunho** (*token ring*): um testemunho circula; só quem o tem pode entrar. Se o testemunho se perde, é preciso recriá-lo.

Na prática, usa-se um serviço de coordenação (ZooKeeper, etcd, Consul) ou a base de dados (`SELECT … FOR UPDATE`, *advisory locks* no PostgreSQL), com **arrendamentos** (*leases*): o trinco expira ao fim de um tempo, para um processo que morre não o deixar preso para sempre.

## O perigo dos trincos que expiram

```
1. o processo P obtém o trinco (válido por 10 s)
2. P fica parado 15 s (pausa do coletor de lixo, máquina sobrecarregada)
3. o trinco expira; Q obtém-no e escreve
4. P acorda, acha que ainda tem o trinco, e escreve por cima
```

Solução: **fichas de vedação** (*fencing tokens*). Cada vez que o trinco é concedido, vem com um número que aumenta sempre. O recurso guarda o maior número que já viu e recusa escritas com números menores.

```python run
class Armazenamento:
    def __init__(self):
        self.valor, self.maior_ficha = None, -1
    def escreve(self, valor, ficha, quem):
        if ficha < self.maior_ficha:
            return f"{quem}: RECUSADO (ficha {ficha} < {self.maior_ficha})"
        self.maior_ficha, self.valor = ficha, valor
        return f"{quem}: escreveu '{valor}' com a ficha {ficha}"

class ServicoTrincos:
    def __init__(self):
        self.ficha = 0
    def obtem(self):
        self.ficha += 1
        return self.ficha

trincos, disco = ServicoTrincos(), Armazenamento()
fp = trincos.obtem()                     # P obtém o trinco (ficha 1)...
# ... P fica parado; o trinco expira; Q obtém-no (ficha 2) e escreve
fq = trincos.obtem()
print(disco.escreve("agenda de Q", fq, "Q"))
# P acorda e tenta escrever com a ficha antiga
print(disco.escreve("agenda de P", fp, "P"))
print("valor final:", disco.valor)
```

## Eleição de líder

Quando o líder falha, os outros têm de escolher um novo, e **todos têm de concordar** em quem é.

- **Algoritmo do valentão** (*bully*): quem deteta a falha envia "eleição" a todos os processos com identificador maior. Se nenhum responde, declara-se líder; se algum responde, esse assume a eleição. Ganha sempre o maior identificador vivo.
- **Algoritmo em anel:** a mensagem de eleição dá a volta ao anel, recolhendo os identificadores; no fim, o maior é o líder.

```python run
def bully(vivos, quem_deteta, todos):
    mensagens = 0
    candidato = quem_deteta
    while True:
        maiores = [p for p in todos if p > candidato]
        mensagens += len(maiores)                    # envia "eleição" a todos os maiores
        respondem = [p for p in maiores if p in vivos]
        mensagens += len(respondem)                  # os vivos respondem "ok"
        if not respondem:
            mensagens += len(vivos) - 1              # anuncia "sou o líder" aos outros
            return candidato, mensagens
        candidato = min(respondem)                   # o próximo continua a eleição

todos = [1, 2, 3, 4, 5, 6]
print(bully(vivos={1, 2, 3, 4, 5}, quem_deteta=2, todos=todos))   # o 6 (antigo líder) morreu
print(bully(vivos={1, 2, 3}, quem_deteta=1, todos=todos))
```

## O problema das partições

Se a rede se divide em dois grupos, cada um pode eleger o seu líder: **cérebro dividido** (*split brain*), com dois líderes a aceitar escritas contraditórias. A solução robusta é exigir uma **maioria** (quórum): só é líder quem tem o apoio de mais de metade dos processos. Numa partição, no máximo um dos lados tem maioria. É exatamente o que fazem o Raft e o Paxos (lição 6).
