Num sistema distribuído não há um relógio comum. Cada máquina tem o seu, e eles **derivam** (adiantam-se ou atrasam-se uns microssegundos por segundo); mesmo sincronizados com NTP, ficam com diferenças de milissegundos. Para ordenar acontecimentos ("quem marcou primeiro a última vaga?"), os relógios físicos não chegam. Os **relógios lógicos** ordenam acontecimentos sem precisar da hora real.

## O problema da ordem

O servidor A regista uma marcação às 10:00:00,120 (no seu relógio); o servidor B regista outra para a mesma vaga às 10:00:00,115 (no dele). Qual foi primeiro? Se o relógio de B estiver 10 ms adiantado, foi a de A. Não há forma de saber só com as horas.

## A relação "aconteceu antes"

Lamport (1978) definiu a → b ("a aconteceu antes de b") assim:

1. a e b no mesmo processo, e a vem primeiro;
2. a é o envio de uma mensagem e b é a sua receção;
3. transitividade: se a → b e b → c, então a → c.

Se nem a → b nem b → a, os acontecimentos são **concorrentes** (a ∥ b): nenhum pode ter influenciado o outro.

## Relógios de Lamport

Cada processo tem um contador C:

- antes de cada acontecimento, C = C + 1;
- ao enviar, a mensagem leva C;
- ao receber uma mensagem com o valor m: C = max(C, m) + 1.

Garante: se a → b, então C(a) < C(b). Mas **não** o contrário: C(a) < C(b) não quer dizer que a → b (podem ser concorrentes). Com o desempate pelo identificador do processo, dá uma **ordem total** que respeita a causalidade, útil para decidir de forma igual em todas as máquinas.

## Relógios vetoriais

Cada processo guarda um vetor com uma entrada por processo: "quantos acontecimentos de cada processo já conheço".

- No próprio acontecimento: V[eu] += 1.
- Ao enviar, a mensagem leva o vetor.
- Ao receber: V = máximo, posição a posição, dos dois vetores; depois V[eu] += 1.

Comparar dois vetores diz tudo: V(a) ≤ V(b) em todas as posições (e diferente) ⇔ a → b. Se nenhum é ≤ ao outro, são **concorrentes**. É assim que se detetam escritas em conflito (versões de um documento editado em dois sítios sem ligação).

```python run
class Processo:
    def __init__(self, nome, nomes):
        self.nome, self.lamport = nome, 0
        self.vetor = {n: 0 for n in nomes}
    def evento(self, descricao):
        self.lamport += 1; self.vetor[self.nome] += 1
        return self._regista(descricao)
    def envia(self, descricao):
        self.lamport += 1; self.vetor[self.nome] += 1
        return self._regista(descricao), (self.lamport, dict(self.vetor))
    def recebe(self, msg, descricao):
        l, v = msg
        self.lamport = max(self.lamport, l) + 1
        for k in self.vetor: self.vetor[k] = max(self.vetor[k], v[k])
        self.vetor[self.nome] += 1
        return self._regista(descricao)
    def _regista(self, d):
        return (d, self.lamport, tuple(self.vetor.values()))

nomes = ["A", "B", "C"]
A, B, C = (Processo(n, nomes) for n in nomes)
eventos = []
eventos.append(A.evento("A: cliente abre a agenda"))
e, m1 = A.envia("A: envia 'reservar 10h' a B"); eventos.append(e)
eventos.append(C.evento("C: dona bloqueia a tarde"))
eventos.append(B.recebe(m1, "B: recebe a reserva"))
e, m2 = B.envia("B: confirma a C"); eventos.append(e)
eventos.append(C.recebe(m2, "C: recebe a confirmação"))
eventos.append(A.evento("A: cliente fecha a página"))

for d, l, v in eventos:
    print(f"{d:30} Lamport {l}  vetor {v}")

def compara(v1, v2):
    if all(a <= b for a, b in zip(v1, v2)) and v1 != v2: return "aconteceu antes de"
    if all(b <= a for a, b in zip(v1, v2)) and v1 != v2: return "aconteceu depois de"
    return "é concorrente com"
print()
print("'dona bloqueia' ", compara(eventos[2][2], eventos[3][2]), "'B recebe a reserva'")
print("'dona bloqueia' ", compara(eventos[2][2], eventos[5][2]), "'C recebe a confirmação'")
print("'cliente fecha' ", compara(eventos[6][2], eventos[5][2]), "'C recebe a confirmação'")
```

Prevê os valores e as três comparações. Repara que "a dona bloqueia a tarde" tem um Lamport menor do que outros acontecimentos com que é concorrente: Lamport dá uma ordem, mas não diz se houve causalidade. Os vetores dizem.

## Relógios físicos, mesmo assim

- **NTP:** sincroniza com servidores de tempo, compensando o atraso da rede; precisão de milissegundos na Internet.
- **PTP:** microssegundos numa rede local (bolsas, telecomunicações).
- **TrueTime** (Google Spanner): relógios atómicos e GPS em cada centro de dados, e uma API que devolve um **intervalo** de incerteza ("agora está entre t e t + 7 ms"). O Spanner espera que o intervalo passe antes de confirmar, e consegue ordem global consistente.
- **Relógios lógicos híbridos** (HLC): juntam a hora física com um contador de Lamport (CockroachDB, MongoDB).
