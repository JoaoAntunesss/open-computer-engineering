Código de sistemas distribuídos tem uma dificuldade extra: a rede atrasa, perde e duplica mensagens, e cada máquina tem o seu relógio. Ler este código obriga a perguntar em cada linha: "e se esta mensagem chegar duas vezes, tarde ou nunca?"

## Ler e prever: tentar outra vez

```python run
import random
random.seed(3)

saldo = {"conta": 100}
def debitar(valor):
    # o servidor aplica o débito, mas a resposta pode perder-se na rede
    saldo["conta"] -= valor
    if random.random() < 0.5:
        raise TimeoutError("sem resposta")
    return "ok"

def pagar_com_retentativas(valor, tentativas=3):
    for i in range(tentativas):
        try:
            return debitar(valor)
        except TimeoutError:
            print("tentativa", i + 1, "sem resposta")
    return "falhou"

print(pagar_com_retentativas(30), saldo)
```

Antes de correr: se o cliente só vê "sem resposta", sabe se o débito aconteceu? Quanto pode ser debitado no pior caso com 3 tentativas?

## Encontra o erro: relógios diferentes

Dois servidores guardam a última versão de um documento e ficam com a de **maior** hora:

```python run
def junta(a, b):
    return a if a["hora"] >= b["hora"] else b

servidor_a = {"texto": "versão nova", "hora": 1000.0}
servidor_b = {"texto": "versão antiga", "hora": 1003.5}   # relógio de B adiantado 5 s
print(junta(servidor_a, servidor_b)["texto"])
```

A versão nova foi escrita **depois**, mas perde. Porquê, e porque é que "sincronizar melhor os relógios" não resolve o problema de raiz?

**Ler e prever:** não sabe: o timeout só diz que a resposta não chegou. Como `debitar` aplica o valor antes de "perder" a resposta, cada nova tentativa debita outra vez. No pior caso, 3 × 30 = 90.

**Encontra o erro:** decidir por relógios de máquinas diferentes não é fiável: um relógio adiantado ganha sempre. Mesmo com NTP há desvios de milissegundos e saltos. A solução de raiz é usar ordem lógica (contadores de versão, relógios de Lamport ou vetoriais) ou um único sítio que decide a ordem.

```python
processadas = {}
def debitar(valor, chave):

        saldo["conta"] -= valor
        processadas[chave] = "ok"
    if random.random() < 0.5:
        raise TimeoutError("sem resposta")
    return processadas[chave]
```
O cliente gera uma chave (por exemplo um UUID) uma vez e reenvia-a em todas as tentativas.
