Num único programa, chamar uma função é trivial. Entre máquinas, é preciso transformar a chamada numa mensagem, enviá-la pela rede, esperar a resposta e lidar com tudo o que pode falhar. Há dois grandes estilos: **pedido-resposta** (RPC, REST, gRPC), em que quem chama espera, e **mensagens assíncronas** (filas, eventos), em que quem envia continua sem esperar.

## RPC: chamadas remotas

A ideia do RPC (*remote procedure call*) é fazer uma chamada remota parecer uma chamada local:

```python
saldo = banco.consultar_saldo(conta=42)     # na verdade, vai pela rede
```

Por baixo, um **stub** (gerado automaticamente):

1. **Serializa** os argumentos (transforma-os em bytes: JSON, Protocol Buffers).
2. Envia o pedido ao servidor.
3. O servidor desserializa, chama a função verdadeira, serializa o resultado.
4. O stub do cliente recebe e devolve o resultado como se fosse local.

Mas uma chamada remota **não é** igual a uma local: é milhares de vezes mais lenta, pode falhar a meio sem se saber se a operação foi feita, e os argumentos são copiados (não há apontadores partilhados). Esconder isto demais é perigoso: o programador esquece-se de tratar os erros.

## Semânticas de entrega

Quando há falhas e repetições, o que é garantido?

- **No máximo uma vez:** não se repete; pode perder-se.
- **Pelo menos uma vez:** repete-se até haver resposta; pode executar-se mais do que uma vez.
- **Exatamente uma vez:** o que se quer, mas impossível só com a rede; consegue-se com "pelo menos uma vez" + **operações idempotentes** ou **desduplicação** (o servidor lembra-se dos identificadores dos pedidos já processados).

## gRPC

O RPC moderno mais usado entre microsserviços (Google). Define-se o contrato num ficheiro `.proto`:

```protobuf
syntax = "proto3";
service Marcacoes {
  rpc Criar (PedidoMarcacao) returns (Marcacao);
  rpc Seguir (FiltroAgenda) returns (stream Marcacao);   // o servidor envia uma sequência
}
message PedidoMarcacao {
  string cliente_id = 1;
  string servico = 2;
  int64 inicio_unix = 3;
}
message Marcacao { string id = 1; string estado = 2; }
```

O compilador gera clientes e servidores em Go, Java, Python, C#, etc. Usa HTTP/2 e Protocol Buffers (binário, compacto, com versões compatíveis: podes acrescentar campos sem partir clientes antigos).

## Mensagens assíncronas

Em vez de chamar diretamente, o produtor deixa uma mensagem numa **fila** (ou publica um **evento** num tópico), e um ou mais consumidores tratam dela quando puderem.

- **Desacoplamento:** o produtor não precisa de saber quem consome, nem que estejam ligados.
- **Absorver picos:** se chegam 10 000 pedidos de uma vez, a fila guarda-os e os consumidores processam ao seu ritmo.
- **Tolerância a falhas:** se o consumidor estiver em baixo, as mensagens esperam.

Ferramentas: **RabbitMQ** (filas), **Kafka** (um registo de eventos persistente que se pode reler), **Amazon SQS**, **Google Pub/Sub**, **Redis Streams**.

```python run
import random
from collections import deque
random.seed(1)

fila = deque()
processados, repetidos = set(), 0
enviados = 0

def produtor(t):
    global enviados
    for _ in range(random.choice([0, 0, 1, 5, 12])):       # chegam em rajadas
        enviados += 1
        fila.append({"id": f"m{enviados}", "tentativas": 0})

def consumidor():
    global repetidos
    for _ in range(3):                                      # trata no máximo 3 por instante
        if not fila:
            return
        msg = fila.popleft()
        if msg["id"] in processados:                        # desduplicação
            repetidos += 1
            continue
        if random.random() < 0.15:                          # falhou antes de confirmar:
            msg["tentativas"] += 1
            fila.append(msg)                                # volta à fila (pelo menos uma vez)
            if random.random() < 0.5:
                processados.add(msg["id"])                  # ... mas às vezes já tinha feito o trabalho
            continue
        processados.add(msg["id"])

maior_fila = 0
for t in range(60):
    produtor(t); consumidor()
    maior_fila = max(maior_fila, len(fila))
while fila:
    consumidor()
print("enviadas:", enviados, "| processadas:", len(processados), "| duplicados descartados:", repetidos,
      "| maior fila:", maior_fila)
```

Prevê: alguma mensagem se perde? Algum trabalho é feito duas vezes? A fila chega a crescer muito? Sem a desduplicação, os duplicados seriam processados outra vez.

## Padrões úteis

- **Tempos limite** em todas as chamadas, e **repetições com espera exponencial** (*exponential backoff*) e um pouco de aleatoriedade, para não afogar um servidor que está a recuperar.
- **Disjuntor** (*circuit breaker*): depois de muitas falhas seguidas, deixa de chamar o serviço durante algum tempo e falha logo.
- **Fila de mensagens mortas** (*dead letter queue*): as mensagens que falham muitas vezes vão para uma fila à parte, para análise.
- **Outbox:** gravar o evento na mesma transação da base de dados que a alteração, e publicá-lo depois, para não haver alterações sem evento (nem eventos sem alteração).
