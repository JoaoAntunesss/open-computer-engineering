Uma **interface** diz **o que** um objeto sabe fazer, sem dizer **como**. Uma **classe abstrata** é uma classe incompleta: tem parte da implementação e deixa o resto para as subclasses. Programar contra interfaces em vez de classes concretas é o que torna o código fácil de testar e de mudar.

## Interfaces

```java
// Pagamentos.java
import java.util.List;

public class Pagamentos {
    public static void main(String[] args) {
        List<MetodoPagamento> metodos = List.of(new MBWay("912345678"), new Cartao("4111111111111111"));
        Loja loja = new Loja();
        for (MetodoPagamento m : metodos) {
            loja.cobrar(m, 19.90);
        }
    }
}

interface MetodoPagamento {
    boolean pagar(double valor);                    // abstrato: cada classe implementa
    default String descricao() { return getClass().getSimpleName(); }   // com implementação
}

class MBWay implements MetodoPagamento {
    private final String telemovel;
    MBWay(String telemovel) { this.telemovel = telemovel; }
    public boolean pagar(double valor) {
        System.out.println("Pedido MB WAY de " + valor + " para " + telemovel);
        return true;
    }
}

class Cartao implements MetodoPagamento {
    private final String numero;
    Cartao(String numero) { this.numero = numero; }
    public boolean pagar(double valor) {
        System.out.println("Cartão terminado em " + numero.substring(numero.length() - 4) + ": " + valor);
        return true;
    }
    @Override public String descricao() { return "Cartão de crédito"; }
}

class Loja {
    void cobrar(MetodoPagamento metodo, double valor) {      // não sabe qual é a classe
        if (metodo.pagar(valor)) System.out.println("Pago com " + metodo.descricao());
    }
}
```

- `implements` declara que uma classe cumpre a interface.
- Uma classe pode implementar **várias** interfaces (mas só estende uma classe).
- Métodos `default` têm implementação e podem ser redefinidos.
- `Loja` não depende de MB WAY nem de cartões: amanhã acrescentas `PayPal` sem tocar em `Loja`.

## Classes abstratas

Úteis quando várias classes partilham **estado e código**, e só uma parte muda:

```java
abstract class Relatorio {
    // método-modelo: o esqueleto é fixo
    public final String gerar() {
        return cabecalho() + "\n" + corpo() + "\n-- fim --";
    }
    protected String cabecalho() { return "Relatório " + java.time.LocalDate.now(); }
    protected abstract String corpo();           // cada relatório preenche isto
}

class RelatorioVendas extends Relatorio {
    protected String corpo() { return "Vendas: 1250 €"; }
}
```

Uma classe abstrata não pode ser instanciada (`new Relatorio()` não compila).

## Interface ou classe abstrata?

| | interface | classe abstrata |
|---|---|---|
| estado (atributos de instância) | não | sim |
| construtor | não | sim |
| herança múltipla | sim (implementa várias) | não (estende uma) |
| quando usar | um **papel** ou capacidade (`Comparable`, `Runnable`, `MetodoPagamento`) | uma **família** que partilha código |

Na dúvida, começa por uma interface.

## Interfaces que vais usar sempre

- `Comparable<T>`: `compareTo` define a ordem natural (usada por `Collections.sort`).
- `Comparator<T>`: uma ordem alternativa, passada de fora: `lista.sort(Comparator.comparing(Aluno::nota).reversed())`.
- `Runnable`, `Callable`: tarefas para threads.
- `Iterable<T>`: permite usar o objeto num `for`-each.

## Interfaces funcionais e lambdas

Uma interface com **um único** método abstrato pode ser implementada com uma lambda:

```java
MetodoPagamento teste = valor -> { System.out.println("simulado: " + valor); return true; };
loja.cobrar(teste, 5.0);
```

É assim que se fazem objetos falsos (*mocks*) para testes, sem precisar de cobrar dinheiro a sério.

3. Porque é que `Loja` recebe um `MetodoPagamento` e não um `MBWay`?

```java
interface Desconto { double aplicar(double preco); }

class Percentagem implements Desconto {
    private final double p;
    Percentagem(double p) { this.p = p; }
    public double aplicar(double preco) { return preco * (1 - p / 100); }
}

class ValorFixo implements Desconto {
    private final double v;
    ValorFixo(double v) { this.v = v; }
    public double aplicar(double preco) { return Math.max(0, preco - v); }
}
```
