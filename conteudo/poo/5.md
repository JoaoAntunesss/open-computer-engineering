As **coleções** de Java guardam grupos de objetos: listas, conjuntos e mapas. Os **genéricos** dizem que tipo de objetos lá estão (`List<String>`), para o compilador apanhar erros e para não ser preciso fazer conversões. Escolher a coleção certa é como escolher a estrutura de dados em Algoritmos: muda a complexidade do programa.

## As interfaces e as implementações

| Interface | Para quê | Implementações | Custos típicos |
|---|---|---|---|
| `List<E>` | sequência com ordem e repetidos | `ArrayList`, `LinkedList` | `get(i)` O(1) no `ArrayList` |
| `Set<E>` | sem repetidos | `HashSet`, `LinkedHashSet`, `TreeSet` | `contains` O(1) (hash) ou O(log n) (tree) |
| `Map<K,V>` | chave → valor | `HashMap`, `LinkedHashMap`, `TreeMap` | `get` O(1) (hash) ou O(log n) (tree) |
| `Deque<E>` | pilha e fila | `ArrayDeque` | pôr e tirar nas pontas O(1) |

Declara as variáveis com o tipo da **interface**: `List<String> nomes = new ArrayList<>();`. Assim podes trocar a implementação sem mudar mais nada.

- `Hash…`: sem ordem garantida, o mais rápido.
- `LinkedHash…`: mantém a ordem de inserção.
- `Tree…`: mantém a ordem natural (ou a de um `Comparator`).

## Um exemplo completo

```java
// Turma.java
import java.util.*;

public class Turma {
    record Aluno(String nome, String curso, double nota) {}

    public static void main(String[] args) {
        List<Aluno> alunos = new ArrayList<>(List.of(
            new Aluno("Rita", "LEI", 16.5), new Aluno("Rui", "LEI", 11.0),
            new Aluno("Ana", "LEGI", 18.0), new Aluno("Tiago", "LEGI", 9.0)));

        // ordenar: por nota, da maior para a menor
        alunos.sort(Comparator.comparingDouble(Aluno::nota).reversed());
        System.out.println(alunos.get(0).nome());

        // agrupar num mapa: curso -> lista de nomes
        Map<String, List<String>> porCurso = new TreeMap<>();
        for (Aluno a : alunos) {
            porCurso.computeIfAbsent(a.curso(), k -> new ArrayList<>()).add(a.nome());
        }
        System.out.println(porCurso);

        // conjunto: cursos sem repetidos
        Set<String> cursos = new HashSet<>();
        for (Aluno a : alunos) cursos.add(a.curso());
        System.out.println(cursos.size());

        // streams: média dos aprovados
        double media = alunos.stream().filter(a -> a.nota() >= 9.5)
                             .mapToDouble(Aluno::nota).average().orElse(0);
        System.out.printf("%.2f%n", media);
    }
}
```

`record` cria uma classe imutável com construtor, getters, `equals`, `hashCode` e `toString` automáticos. Ideal para dados simples.

## Genéricos

Antes dos genéricos, uma `List` guardava `Object` e era preciso converter (`(String) lista.get(0)`), com erros só em tempo de execução. Com genéricos, o compilador verifica.

Podes escrever as tuas classes e métodos genéricos:

```java
class Par<A, B> {
    private final A primeiro; private final B segundo;
    Par(A primeiro, B segundo) { this.primeiro = primeiro; this.segundo = segundo; }
    A getPrimeiro() { return primeiro; }
    B getSegundo() { return segundo; }
}

static <T extends Comparable<T>> T maximo(List<T> lista) {
    T m = lista.get(0);
    for (T x : lista) if (x.compareTo(m) > 0) m = x;
    return m;
}
```

`<T extends Comparable<T>>` lê-se: "para qualquer tipo T que se saiba comparar com outro T".

**Wildcards:** `List<? extends Number>` aceita `List<Integer>` e `List<Double>`, para **ler**. `List<? super Integer>` aceita listas onde se pode **escrever** inteiros. Regra: "produtor extends, consumidor super".

## Armadilhas

- Modificar uma lista enquanto a percorres com for-each dá `ConcurrentModificationException`. Usa `removeIf` ou um `Iterator`.
- `List.of(...)` é **imutável**: `add` dá exceção. Por isso o exemplo faz `new ArrayList<>(List.of(...))`.
- Objetos guardados em `HashSet` ou como chave de `HashMap` precisam de `equals` e `hashCode` coerentes (os `record` já os têm).
- `list.remove(1)` numa `List<Integer>` remove o índice 1, não o valor 1. Para o valor: `remove(Integer.valueOf(1))`.
