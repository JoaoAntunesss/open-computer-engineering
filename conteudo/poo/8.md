A **UML** (Unified Modeling Language) é uma notação gráfica para desenhar software. Na prática, dois diagramas resolvem quase tudo: o **diagrama de classes** (a estrutura) e o **diagrama de sequência** (quem chama quem, e por que ordem). Servem para pensar antes de programar, para explicar um desenho a outras pessoas e, nos trabalhos da faculdade, quase sempre fazem parte da entrega.

## Diagrama de classes

Cada classe é uma caixa com três partes: nome, atributos, métodos.

```
┌─────────────────────────┐
│ Conta                   │
├─────────────────────────┤
│ - titular: String       │
│ - saldo: double         │
├─────────────────────────┤
│ + depositar(v: double)  │
│ + levantar(v: double): boolean │
│ + getSaldo(): double    │
└─────────────────────────┘
```

Visibilidade: `+` público, `-` privado, `#` protegido. Itálico (ou `{abstract}`) para abstratos; sublinhado para `static`.

## Relações

| Relação | Símbolo | Significado | Em Java |
|---|---|---|---|
| Herança | seta com triângulo vazio | "é um" | `extends` |
| Realização | tracejado com triângulo vazio | implementa | `implements` |
| Associação | linha simples | "conhece" | atributo com referência |
| Agregação | losango vazio | "tem", as partes vivem sozinhas | lista de objetos recebidos de fora |
| Composição | losango cheio | "é feito de", as partes morrem com o todo | objetos criados e geridos pelo todo |
| Dependência | seta tracejada | "usa" temporariamente | parâmetro ou variável local |

**Multiplicidades** nas pontas das linhas: `1`, `0..1`, `*` (zero ou mais), `1..*`.

Exemplo, uma biblioteca: um `Socio` tem `0..*` `Emprestimo`s; cada `Emprestimo` refere `1` `Livro`; uma `Biblioteca` é composta por `Livro`s (se a biblioteca desaparece, os registos dos livros também).

## Desenhar com texto: PlantUML

Em vez de arrastar caixas, escreve-se o diagrama em texto e uma ferramenta desenha-o. Fica no Git ao lado do código, e o IntelliJ e o VS Code mostram a pré-visualização.

```
@startuml
abstract class Forma {
  - nome: String
  + {abstract} area(): double
}
class Circulo {
  - raio: double
  + area(): double
}
class Retangulo {
  - largura: double
  - altura: double
  + area(): double
}
interface Desenhavel {
  + desenhar(): void
}
Forma <|-- Circulo
Forma <|-- Retangulo
Desenhavel <|.. Circulo
class Desenho {
  + adicionar(f: Forma): void
}
Desenho "1" *-- "0..*" Forma : contém
@enduml
```

Cola isto em [plantuml.com](https://www.plantuml.com/plantuml) para ver o desenho. O [Mermaid](https://mermaid.live) tem uma sintaxe parecida e é desenhado diretamente pelo GitHub nos ficheiros `.md`.

## Diagrama de sequência

Mostra as mensagens entre objetos ao longo do tempo, de cima para baixo. Cada objeto tem uma linha vertical (a linha de vida); as setas são chamadas de métodos e as tracejadas são respostas.

```
@startuml
actor Cliente
Cliente -> Loja : comprar(carrinho)
Loja -> Stock : reservar(itens)
Stock --> Loja : ok
Loja -> Pagamento : pagar(total)
alt pagamento aceite
  Pagamento --> Loja : confirmado
  Loja --> Cliente : recibo
else recusado
  Pagamento --> Loja : recusado
  Loja -> Stock : libertar(itens)
  Loja --> Cliente : erro
end
@enduml
```

`alt`/`else` mostra alternativas; `loop` mostra repetições.

## Do código para o diagrama, e o contrário

- **Ler** um diagrama de classes é como ler a lista de ficheiros de um projeto antes de abrir cada um: vês quem depende de quem.
- Um diagrama que não bate certo com o código é pior do que nenhum. Desenha só o que ajuda a decidir ou a explicar, e mantém-no no repositório.
- O IntelliJ (Ultimate) e plugins como o PlantUML Parser geram diagramas a partir do código existente.
