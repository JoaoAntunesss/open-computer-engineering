O **conjunto de instruções** (ISA, *Instruction Set Architecture*) é o contrato entre o software e o hardware: a lista de instruções que o processador sabe executar, os registos que existem e a forma como se acede à memória. Um compilador gera código para uma ISA; qualquer processador que a implemente corre esse código. Nesta cadeira usamos **RISC-V**, aberto e simples, e comparamos com **x86-64** (os PC) e **ARM** (telemóveis, Macs recentes).

## RISC e CISC

- **RISC** (*Reduced Instruction Set Computer*): poucas instruções, simples, todas do mesmo tamanho. Só `load` e `store` acedem à memória; as operações aritméticas trabalham só com registos. RISC-V, ARM, MIPS.
- **CISC** (*Complex*): muitas instruções, de tamanhos variáveis, algumas fazem muito trabalho de uma vez (uma instrução pode ler da memória, somar e escrever). x86.

Hoje a diferença esbate-se: os processadores x86 traduzem internamente as instruções complexas em micro-operações simples, tipo RISC.

## Os registos do RISC-V (RV32I)

32 registos de 32 bits, `x0` a `x31`, com nomes que indicam o uso por convenção:

| Registo | Nome | Uso |
|---|---|---|
| x0 | `zero` | vale sempre 0 |
| x1 | `ra` | endereço de retorno |
| x2 | `sp` | apontador da pilha |
| x10–x17 | `a0`–`a7` | argumentos e valores de retorno |
| x5–x7, x28–x31 | `t0`–`t6` | temporários (quem chama não conta com eles) |
| x8–x9, x18–x27 | `s0`–`s11` | guardados (a função tem de os preservar) |

Mais o `pc` (*program counter*), com o endereço da instrução atual.

## Tipos de instruções

```asm
# aritméticas e lógicas (registo-registo)
add  t0, t1, t2      # t0 = t1 + t2
sub  t0, t1, t2      # t0 = t1 - t2
and  t0, t1, t2      # E bit a bit
sll  t0, t1, t2      # desloca à esquerda t2 bits

# com imediato (constante de 12 bits na instrução)
addi t0, t1, -5      # t0 = t1 - 5
slli t0, t1, 2       # t0 = t1 * 4

# memória: só load e store
lw   t0, 8(a0)       # t0 = memória[a0 + 8] (palavra de 4 bytes)
sw   t0, 0(sp)       # memória[sp + 0] = t0
lb   t0, 0(a0)       # carrega um byte, com sinal

# saltos condicionais
beq  t0, t1, rotulo  # se t0 == t1, salta
blt  t0, t1, rotulo  # se t0 < t1 (com sinal)

# saltos incondicionais
jal  ra, funcao      # salta e guarda o endereço de retorno em ra
jalr zero, 0(ra)     # salta para o endereço em ra (é o "ret")
```

Pseudo-instruções que o assembler traduz: `li t0, 100` (carrega constante), `mv t0, t1` (`addi t0, t1, 0`), `j rotulo`, `ret`, `nop`.

## Formato binário

Todas as instruções RV32I têm 32 bits. Por exemplo, `add t0, t1, t2` é do formato R:

```
funct7   rs2    rs1    funct3  rd     opcode
0000000  00111  00110  000     00101  0110011
```

`rs1` = 6 (t1), `rs2` = 7 (t2), `rd` = 5 (t0). O processador olha para o `opcode` e os `funct` para saber o que fazer.

## Prever o efeito de instruções

Uma ISA é só uma máquina de estados: registos e memória antes, registos e memória depois. Simula estas instruções e prevê os valores finais:

```python run
r = {"zero": 0, "t0": 0, "t1": 0, "t2": 0}
prog = [
    ("addi", "t0", "zero", 7),
    ("addi", "t1", "zero", 3),
    ("add",  "t2", "t0", "t1"),
    ("slli", "t2", "t2", 2),
    ("sub",  "t0", "t2", "t0"),
    ("addi", "zero", "t0", 1),      # escrever em zero não tem efeito
]
for op, rd, a, b in prog:
    if op == "add":  v = r[a] + r[b]
    if op == "sub":  v = r[a] - r[b]
    if op == "addi": v = r[a] + b
    if op == "slli": v = r[a] << b
    if rd != "zero":
        r[rd] = v
    print(f"{op:5} {rd},{a},{b}  ->  {r}")
```
