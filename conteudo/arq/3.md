O compilador traduz C para assembly seguindo padrões fixos. Quando os reconheces, consegues ler o que o compilador gerou, perceber porque é que uma versão é mais rápida do que outra e encontrar bugs que só aparecem com otimizações. A ferramenta para isto é o [Compiler Explorer](https://godbolt.org): escreves C à esquerda e vês o assembly à direita, para qualquer compilador e arquitetura.

## Variáveis e expressões

As variáveis locais vivem em registos sempre que possível. Uma expressão vira uma sequência de instruções com temporários:

```c
int f(int a, int b, int c) {
    return (a + b) * 4 - c;
}
```

```asm
f:  add  a0, a0, a1     # a + b
    slli a0, a0, 2      # * 4 (multiplicar por potência de 2 = deslocar)
    sub  a0, a0, a2     # - c
    ret
```

Os argumentos chegam em `a0`, `a1`, `a2` (convenção de chamada) e o resultado sai em `a0`.

## if / else

```c
int abs_dif(int a, int b) {
    if (a > b) return a - b;
    else return b - a;
}
```

```asm
abs_dif:
    ble  a0, a1, senao     # condição invertida: salta para o else
    sub  a0, a0, a1
    ret
senao:
    sub  a0, a1, a0
    ret
```

O compilador **inverte a condição**: salta por cima do bloco `then` quando a condição é falsa.

## Ciclos

```c
int soma(int *v, int n) {
    int s = 0;
    for (int i = 0; i < n; i++) s += v[i];
    return s;
}
```

Com `-O2`, o compilador costuma gerar algo como:

```asm
soma:
    li   t0, 0               # s = 0
    blez a1, fim             # n <= 0: não entra no ciclo
    slli a1, a1, 2
    add  a1, a0, a1          # a1 = &v[n] (endereço de fim)
ciclo:
    lw   t1, 0(a0)           # t1 = *v
    add  t0, t0, t1
    addi a0, a0, 4           # v++ (avança o apontador)
    bne  a0, a1, ciclo       # até chegar ao fim
fim:
    mv   a0, t0
    ret
```

Repara que o `i` **desapareceu**: o compilador trocou o índice por um apontador que avança 4 bytes de cada vez, e testa a condição no fim (um salto a menos por volta).

## Vetores e estruturas

- `v[i]` com `int` (4 bytes) é `lw` em `v + i*4`.
- Num `struct`, cada campo tem um deslocamento fixo: em `struct P { int x; int y; }`, `p->y` é `lw t0, 4(a0)`.
- `char` usa `lb`/`lbu`; `long` em RV64 usa `ld`.

## Chamadas de funções

```c
int g(int x) { return f(x, x, 1) + x; }
```

```asm
g:  addi sp, sp, -16
    sw   ra, 12(sp)
    sw   s0, 8(sp)
    mv   s0, a0            # x tem de sobreviver à chamada: vai para s0
    mv   a1, a0
    li   a2, 1
    jal  ra, f
    add  a0, a0, s0
    lw   s0, 8(sp)
    lw   ra, 12(sp)
    addi sp, sp, 16        # a pilha fica alinhada a 16 bytes
    ret
```

Com otimização, o compilador pode **embutir** (*inline*) `f` dentro de `g` e eliminar a chamada.

## Otimizações que vais ver

- **Propagação de constantes:** `int x = 3 * 4;` vira `li a0, 12`.
- **Redução de força:** multiplicar por 8 vira `slli 3`; dividir por uma constante vira uma multiplicação e um deslocamento.
- **Eliminação de código morto:** cálculos cujo resultado não é usado desaparecem. É por isso que um *benchmark* mal escrito "corre em 0 segundos".
- **Comportamento indefinido:** em C, overflow de `int` com sinal é indefinido, e o compilador pode assumir que nunca acontece. `if (x + 1 < x)` pode ser apagado inteiro.
