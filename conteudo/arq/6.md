O processador faz uma operação em menos de um nanossegundo; ir buscar um valor à memória principal demora 50 a 100 ns. Sem um truque, o processador passaria quase todo o tempo à espera. O truque é a **hierarquia de memória**: memórias pequenas e rápidas (caches) perto do processador, com cópias dos dados mais usados. Perceber as caches explica porque é que dois programas com a mesma complexidade podem ter tempos 10 vezes diferentes.

## A hierarquia

| Nível | Tamanho típico | Tempo de acesso |
|---|---|---|
| Registos | ~1 KB | < 1 ns |
| Cache L1 | 32–64 KB por núcleo | ~1 ns |
| Cache L2 | 256 KB – 2 MB | ~4 ns |
| Cache L3 | 8–64 MB, partilhada | ~15 ns |
| RAM | 8–64 GB | ~80 ns |
| SSD | ~1 TB | ~100 000 ns |

## Localidade

As caches funcionam porque os programas têm **localidade**:

- **Temporal:** o que foi usado agora vai ser usado outra vez em breve (variáveis num ciclo).
- **Espacial:** o que está ao lado do que foi usado vai ser usado em breve (elementos seguintes de um vetor).

Por isso a cache não traz um byte de cada vez: traz um **bloco** (linha de cache), tipicamente 64 bytes.

## Como funciona uma cache

O endereço divide-se em três partes:

```
| etiqueta (tag) | índice | deslocamento no bloco |
```

- **Deslocamento:** que byte dentro do bloco (6 bits para blocos de 64 bytes).
- **Índice:** em que conjunto da cache procurar.
- **Etiqueta:** para confirmar que o bloco guardado é mesmo o deste endereço.

Organizações:

- **Mapeamento direto:** cada bloco só pode ir para um sítio. Simples, mas dois endereços que disputam o mesmo sítio expulsam-se mutuamente (falhas de **conflito**).
- **Associativa por conjuntos** (*n-way*): cada bloco pode ir para n sítios dentro do conjunto. É o mais comum (L1 de 8 vias).
- **Totalmente associativa:** qualquer sítio. Cara; usa-se em caches pequenas como a TLB.

Quando o conjunto está cheio, substitui-se normalmente o bloco usado há mais tempo (**LRU**).

## Escritas

- **Write-through:** escreve na cache e na memória. Simples, mas gera muito tráfego.
- **Write-back:** escreve só na cache e marca o bloco como "sujo"; só vai para a memória quando o bloco é expulso. Mais rápido; é o habitual.

## Tempo médio de acesso

TMA = tempo de acerto + taxa de falhas × penalidade de falha.

Com L1 de 1 ns, 5% de falhas e penalidade de 80 ns: 1 + 0,05 × 80 = 5 ns. Baixar as falhas para 2% dá 2,6 ns: quase o dobro da velocidade.

## O efeito na prática: linhas contra colunas

Em C e em Python (com `numpy`), as matrizes guardam-se por linhas. Percorrer por linhas usa cada bloco inteiro; percorrer por colunas salta de bloco em bloco. Esta simulação conta as falhas numa cache de mapeamento direto pequena. Prevê qual tem mais falhas e quantas vezes mais:

```python run
def simula(enderecos, linhas_cache=64, bloco=64):
    cache = [None] * linhas_cache
    falhas = 0
    for e in enderecos:
        b = e // bloco
        i = b % linhas_cache
        if cache[i] != b:
            cache[i] = b
            falhas += 1
    return falhas

N = 256                                    # matriz 256 x 256 de int (4 bytes)
por_linhas  = [(i * N + j) * 4 for i in range(N) for j in range(N)]
por_colunas = [(i * N + j) * 4 for j in range(N) for i in range(N)]
fl, fc = simula(por_linhas), simula(por_colunas)
print("acessos:", N * N)
print("falhas por linhas:", fl, f"({fl / N / N:.1%})")
print("falhas por colunas:", fc, f"({fc / N / N:.1%})")
```

Por linhas, cada bloco de 64 bytes (16 inteiros) dá 1 falha e 15 acertos. Por colunas, cada acesso está num bloco diferente, e quando se volta à coluna seguinte o bloco já foi expulso.

3. Na simulação, o que acontece às falhas por colunas se a cache tiver 512 linhas em vez de 64? Porquê?
4. Porque é que uma lista ligada é mais lenta a percorrer do que um vetor, mesmo sendo ambas O(n)?
