Programar em assembly é escrever cada passo que o processador executa. Não vais fazê-lo no dia a dia, mas é a melhor forma de perceber o que custa realmente uma chamada de função, um ciclo ou um acesso a um vetor. Usa o simulador **RARS** (RISC-V, em Java) ou o **Venus** (no browser): mostram os registos e a memória a mudar instrução a instrução.

## Estrutura de um programa

```asm
        .data
msg:    .string "Soma: "
vetor:  .word 4, -2, 7, 1, 10
n:      .word 5

        .text
        .globl main
main:
        la   a0, vetor        # endereço do vetor
        lw   a1, n            # número de elementos
        jal  ra, soma         # chama soma(vetor, n)
        mv   s0, a0           # guarda o resultado

        la   a0, msg
        li   a7, 4            # chamada ao sistema 4: imprimir string
        ecall
        mv   a0, s0
        li   a7, 1            # chamada ao sistema 1: imprimir inteiro
        ecall
        li   a7, 10           # chamada ao sistema 10: terminar
        ecall

# int soma(int *v, int n)
soma:
        li   t0, 0            # total
        li   t1, 0            # i
ciclo:  bge  t1, a1, fim
        slli t2, t1, 2        # deslocamento = i * 4
        add  t2, a0, t2
        lw   t3, 0(t2)
        add  t0, t0, t3
        addi t1, t1, 1
        j    ciclo
fim:    mv   a0, t0
        ret
```

- `.data` declara dados na memória; `.text`, o código.
- `ecall` pede um serviço ao sistema (no RARS, o número do serviço vai em `a7`).
- Este programa mostra `Soma: 20`.

## Convenção de chamada

Para que funções escritas por pessoas diferentes (ou por compiladores diferentes) se possam chamar umas às outras, há regras:

1. Os argumentos vão em `a0`–`a7`; o resultado volta em `a0` (e `a1`).
2. `jal ra, f` salta para `f` e guarda em `ra` o endereço da instrução seguinte. `ret` volta para lá.
3. Os registos `t*` e `a*` podem ser estragados pela função chamada (*caller-saved*): se quem chama precisa deles depois, guarda-os antes.
4. Os registos `s*` e `sp` têm de estar iguais quando a função volta (*callee-saved*): se a função os usa, guarda-os na pilha no início e repõe-nos no fim.

## A pilha

A pilha cresce para endereços **mais baixos**. Para guardar coisas, a função subtrai a `sp` e escreve; no fim, repõe e soma.

Uma função que chama outra **tem de guardar `ra`**, porque o próximo `jal` vai escrevê-lo por cima:

```asm
# int fatorial(int n)
fatorial:
        addi sp, sp, -8        # reserva 8 bytes
        sw   ra, 4(sp)         # guarda o endereço de retorno
        sw   s0, 0(sp)         # vamos usar s0: guarda-o
        mv   s0, a0            # s0 = n
        li   t0, 1
        ble  s0, t0, base      # se n <= 1, devolve 1
        addi a0, s0, -1
        jal  ra, fatorial      # a0 = fatorial(n - 1)
        mul  a0, a0, s0        # a0 = n * fatorial(n - 1)
        j    sai
base:   li   a0, 1
sai:    lw   s0, 0(sp)         # repõe
        lw   ra, 4(sp)
        addi sp, sp, 8
        ret
```

Cada chamada recursiva cria um novo **registo de ativação** (*stack frame*) na pilha, com o seu `ra` e o seu `s0`. É exatamente isto que acontece numa recursão em C ou Java, e é por isso que recursão muito profunda dá *stack overflow*.

## Simular a pilha do fatorial

Prevê quantos registos de ativação existem ao mesmo tempo no ponto mais fundo de `fatorial(4)`, e o valor mínimo de `sp`:

```python run
sp = 0x7FFF_FFF0
memoria = {}
profundidade_max, sp_min = 0, sp

def fatorial(n, prof=1):
    global sp, profundidade_max, sp_min
    sp -= 8                              # addi sp, sp, -8
    memoria[sp + 4] = f"ra (nível {prof})"
    memoria[sp] = f"s0 = {n}"
    profundidade_max = max(profundidade_max, prof)
    sp_min = min(sp_min, sp)
    r = 1 if n <= 1 else n * fatorial(n - 1, prof + 1)
    sp += 8                              # addi sp, sp, 8
    return r

print(fatorial(4), profundidade_max, hex(sp_min), hex(sp))
```
