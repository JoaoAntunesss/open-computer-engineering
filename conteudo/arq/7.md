Cada programa acha que tem a memória toda para si: o código começa sempre no mesmo endereço, a pilha está sempre no mesmo sítio, e nenhum programa consegue ler a memória de outro. Isto é possível graças à **memória virtual**: os endereços que o programa usa são traduzidos, em hardware, para endereços físicos na RAM. A tradução é feita em **páginas**, e a cache que a torna rápida chama-se **TLB**.

## Endereços virtuais e físicos

- O programa só vê **endereços virtuais**.
- A **MMU** (*Memory Management Unit*), dentro do processador, traduz cada acesso para um **endereço físico**.
- O sistema operativo define a tradução de cada processo numa **tabela de páginas**.

Vantagens:

1. **Isolamento:** um processo não consegue sequer endereçar a memória de outro.
2. **Simplicidade:** cada programa tem o mesmo espaço de endereços, contínuo.
3. **Memória maior do que a RAM:** páginas pouco usadas vão para o disco (*swap*).
4. **Partilha controlada:** bibliotecas como a `libc` existem uma vez na RAM e aparecem no espaço de vários processos.
5. **Proteção:** cada página tem permissões (ler, escrever, executar). O código não pode ser alterado e a pilha não pode ser executada.

## Páginas

A memória divide-se em páginas de tamanho fixo, normalmente **4 KB**. Um endereço virtual divide-se em:

```
| número da página virtual (VPN) | deslocamento (12 bits para 4 KB) |
```

A tabela de páginas diz, para cada VPN, o número da página física (PPN) e as permissões. O deslocamento não muda.

**Exemplo** (páginas de 4 KB = 0x1000): o endereço virtual `0x00403A10` tem VPN = `0x403` e deslocamento = `0xA10`. Se a tabela disser que a página `0x403` está na página física `0x1F2`, o endereço físico é `0x1F2A10`.

## Tabelas de páginas multinível

Com 32 bits e páginas de 4 KB, há 2²⁰ páginas: uma tabela simples teria 4 MB **por processo**, quase toda vazia. Usa-se uma árvore: a tabela de 1.º nível aponta para tabelas de 2.º nível, que só existem para as zonas usadas. O RISC-V Sv39 e o x86-64 usam 3 a 5 níveis.

## A TLB

Com tabelas multinível, cada acesso à memória precisaria de vários acessos extra para traduzir. A **TLB** (*Translation Lookaside Buffer*) é uma cache pequena (64 a 2048 entradas) das traduções recentes. Graças à localidade, acerta em mais de 99% dos acessos.

## Falta de página (*page fault*)

Quando a página não está na RAM (ou o acesso não é permitido), a MMU gera uma exceção e o sistema operativo é chamado:

- Página no swap: lê-a do disco, atualiza a tabela e repete a instrução. Muito lento (milhões de ciclos).
- Página nunca usada (por exemplo, memória acabada de pedir com `malloc`): arranja uma página física com zeros. É assim que a memória é atribuída "preguiçosamente".
- Acesso inválido: o processo recebe um sinal e termina. É o famoso **segmentation fault**.

## Simular a tradução

Prevê o endereço físico de cada acesso, e quais dão falta de página ou de permissão:

```python run
PAGINA = 4096
tabela = {                   # VPN -> (PPN, permissões)
    0x400: (0x1F2, "rx"),     # código
    0x401: (0x1F3, "r"),      # constantes
    0x7FF: (0x0A0, "rw"),     # pilha
}

def traduz(endereco, acesso):
    vpn, desl = endereco // PAGINA, endereco % PAGINA
    if vpn not in tabela:
        return "falta de página"
    ppn, perm = tabela[vpn]
    if acesso not in perm:
        return f"violação de proteção ({acesso} numa página '{perm}')"
    return hex(ppn * PAGINA + desl)

for end, ac in ((0x400123, "x"), (0x401FFC, "r"), (0x401004, "w"),
                (0x7FFF00, "w"), (0x500000, "r")):
    print(hex(end), ac, "->", traduz(end, ac))
```

2. Traduz `0x00401ABC` com a tabela da simulação. E `0x00402000`?
3. Porque é que mudar de processo pode tornar o programa seguinte mais lento por uns instantes?
4. Um programa faz `int *p = NULL; *p = 5;`. Explica o que acontece, do processador ao terminal.

??? Soluções
1: 32 − 12 = 20 bits; 2²⁰ ≈ um milhão de páginas.

2: `0x00401ABC` → VPN 0x401 → PPN 0x1F3 → `0x1F3ABC`. `0x00402000` → VPN 0x402, que não está na tabela: falta de página.

3: as traduções na TLB (e os dados nas caches) eram do processo anterior. O novo processo começa com muitas falhas até as caches voltarem a ter os seus dados. (TLBs modernas marcam as entradas com o identificador do processo para reduzir isto.)

4: o endereço 0 está numa página que o sistema operativo deixa de propósito sem mapeamento. A MMU não encontra a tradução e gera uma exceção; o sistema operativo vê que é um acesso inválido e envia o sinal SIGSEGV ao processo, que termina; a shell mostra "Segmentation fault".
