Há erros que nenhuma pessoa devia ter de procurar: uma variável que nunca é usada, um import esquecido, aspas diferentes em cada ficheiro, uma função chamada com o tipo errado. Para isso existem ferramentas automáticas que correm em segundos.

## As três famílias

| Ferramenta | O que faz | Python | JavaScript |
|---|---|---|---|
| **Formatador** | Arruma o código sempre da mesma forma | ruff format, black | Prettier |
| **Linter** | Aponta erros prováveis e más práticas | ruff | ESLint |
| **Verificador de tipos** | Confirma que os tipos batem certo antes de correr | mypy, pyright | TypeScript |

## Formatador: acabar com discussões

Com um formatador, ninguém discute espaços, aspas ou quebras de linha: a ferramenta decide, e os diffs só mostram mudanças reais. Configura o editor para formatar ao guardar.

```text
pip install ruff
ruff format .
```

## Linter: erros antes de correr

```python
import os

def total(itens):
    soma = 0
    for i in itens:
        soma += i["preco"]
    resultado = soma * 1.23
    return soma
```

O `ruff check` aponta: `os` importado e não usado, `resultado` atribuída e não usada. A segunda é provavelmente um bug: querias devolver `resultado`?

## Tipos: dizer o que entra e o que sai

```python
def preco_com_iva(preco: float, taxa: float = 0.23) -> float:
    return preco * (1 + taxa)

preco_com_iva("12.5")   # o mypy avisa: str não é float
```

As anotações (`: float`, `-> float`) não mudam como o Python corre, mas o mypy lê-as e apanha erros de tipo **antes** de chegarem aos utilizadores. Em JavaScript, o equivalente é o TypeScript. Em projetos grandes, os tipos são também documentação que nunca fica desatualizada.

## Com IA

Estas ferramentas são excelentes a apanhar erros típicos de código gerado: imports de coisas que não existem, variáveis esquecidas, tipos misturados. Correr o linter e os tipos sobre código gerado é uma revisão automática grátis.

## Configurar uma vez

Põe a configuração no repositório (`pyproject.toml`, `.eslintrc`, `tsconfig.json`), corre as ferramentas no CI e, se quiseres, antes de cada commit com o **pre-commit**. Assim ninguém se esquece.

## Exercício

Num projeto teu em Python ou JavaScript, corre o linter pela primeira vez. Conta os avisos, agrupa-os por tipo e corrige os que são bugs verdadeiros. Depois acrescenta-o ao CI.
