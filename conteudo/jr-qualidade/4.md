**Integração contínua** (CI) quer dizer: sempre que alguém envia código, um servidor corre automaticamente os testes e as verificações. Se algo falhar, o PR fica vermelho e não entra. Acaba com o "na minha máquina funciona".

## GitHub Actions: o mínimo

Cria o ficheiro `.github/workflows/testes.yml` no repositório:

```yaml
name: Testes
on:
  push:
    branches: [main]
  pull_request:

jobs:
  testes:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: pip install pytest ruff
      - run: ruff check .
      - run: pytest -q
```

Faz commit e push. No separador **Actions** do GitHub vês cada execução, os passos e os erros. É grátis para repositórios públicos.

## Como se lê

- `on`: quando corre (push no `main` e em todos os PRs).
- `runs-on`: numa máquina Ubuntu nova, criada para esta execução.
- `steps`: os passos por ordem. `uses` usa uma ação pronta; `run` corre um comando.
- Se qualquer passo devolver erro, a execução falha e o PR fica marcado.

## Proteger o main

Em **Settings → Branches → Branch protection**, ativa "Require status checks to pass" para o `main`. A partir daí, nada entra sem testes verdes. É assim que equipas grandes mantêm o código estável.

## Para JavaScript

```yaml
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run lint
      - run: npm test
```

## O que mais pode correr no CI

- Linters e formatadores (lição seguinte).
- Verificação de tipos (mypy, TypeScript).
- Cobertura de testes.
- Construção do projeto (o site compila? a app gera o APK?).
- Deploy automático quando o `main` muda (isso já é *continuous delivery*).

## Quando o CI falha

Lê o registo do passo que falhou como lês um traceback: de baixo para cima. Corre o mesmo comando na tua máquina. Se só falha no CI, desconfia de diferenças de ambiente: versões, variáveis de ambiente, ficheiros que não fizeste commit.

## Exercício

Põe o CI a correr num projeto teu com testes. Abre um PR que parta um teste de propósito e confirma que fica vermelho. Depois ativa a proteção do `main`.
