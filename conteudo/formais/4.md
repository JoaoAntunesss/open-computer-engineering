**Alloy** e **TLA+** são as duas ferramentas de especificação formal mais usadas fora da academia. As duas verificam automaticamente modelos pequenos e devolvem contraexemplos. O Alloy é bom para **estruturas** (relações, permissões, modelos de dados); o TLA+, para **comportamentos** ao longo do tempo (protocolos, algoritmos distribuídos). A Amazon, a Microsoft, a Intel e a MongoDB usam TLA+ para desenhar sistemas críticos antes de os programar.

## Alloy: estruturas e relações

Descrevem-se conjuntos (assinaturas) e relações, com restrições (factos), e pede-se à ferramenta que procure exemplos ou contraexemplos num universo pequeno:

```alloy
sig Cliente {}
sig Funcionario {}
sig Hora {}
sig Marcacao { cliente: one Cliente, func: one Funcionario, hora: one Hora }

// facto: um funcionário não tem duas marcações à mesma hora
fact SemSobreposicao {
  all disj m1, m2: Marcacao | m1.func = m2.func implies m1.hora != m2.hora
}

// afirmação a verificar: um cliente também nunca tem duas marcações à mesma hora?
assert ClienteSemSobreposicao {
  all disj m1, m2: Marcacao | m1.cliente = m2.cliente implies m1.hora != m2.hora
}
check ClienteSemSobreposicao for 4
```

O Alloy encontra logo um contraexemplo: o mesmo cliente com dois funcionários diferentes à mesma hora (corte e manicure ao mesmo tempo). Ou é um erro nos requisitos, ou falta um facto.

## TLA+: comportamentos

Em TLA+, o sistema é um **estado inicial** e uma **relação de passo** (que estados podem seguir-se a cada estado). As propriedades são invariantes e propriedades temporais, e o verificador **TLC** explora todos os estados.

```tla
---- MODULE Reservas ----
EXTENDS Naturals
CONSTANTS Clientes, Lugares
VARIABLES livres, reservas

Init == livres = Lugares /\ reservas = {}

Reserva(c) == \E l \in livres:
                 /\ livres' = livres \ {l}
                 /\ reservas' = reservas \cup {<<c, l>>}

Cancela(c) == \E r \in reservas:
                 /\ r[1] = c
                 /\ reservas' = reservas \ {r}
                 /\ livres' = livres \cup {r[2]}

Next == \E c \in Clientes: Reserva(c) \/ Cancela(c)

\* invariante: um lugar nunca está ao mesmo tempo livre e reservado
Coerente == \A r \in reservas: r[2] \notin livres
====
```

## A mesma ideia, em Python

A essência do TLC é uma pesquisa em largura pelos estados alcançáveis. Esta versão modela reservas feitas por dois servidores que **leem** os lugares livres e **depois** escrevem (sem transação), e verifica a invariante "nenhum lugar tem duas reservas":

```python run
from collections import deque

LUGARES = (1, 2)
# estado: (reservas: tuplo de (cliente, lugar), passo de cada servidor, lugar que cada um leu como livre)
inicial = ((), ("ler", "ler"), (None, None))

def livres(reservas):
    return [l for l in LUGARES if all(l != r[1] for r in reservas)]

def seguintes(estado):
    reservas, passos, lidos = estado
    for s in (0, 1):
        cliente = "AB"[s]
        if passos[s] == "ler" and livres(reservas):
            novo_passos = list(passos); novo_lidos = list(lidos)
            novo_passos[s], novo_lidos[s] = "escrever", livres(reservas)[0]
            yield (reservas, tuple(novo_passos), tuple(novo_lidos))
        elif passos[s] == "escrever":
            novo_passos = list(passos); novo_passos[s] = "fim"
            yield (reservas + ((cliente, lidos[s]),), tuple(novo_passos), lidos)

def invariante(estado):
    lugares = [l for _, l in estado[0]]
    return len(lugares) == len(set(lugares))

vistos, fila, pai = {inicial}, deque([inicial]), {inicial: None}
while fila:
    e = fila.popleft()
    if not invariante(e):
        caminho = []
        while e: caminho.append(e[0]); e = pai[e]
        print("invariante violada! reservas ao longo do caminho:", list(reversed(caminho)))
        break
    for p in seguintes(e):
        if p not in vistos:
            vistos.add(p); pai[p] = e; fila.append(p)
else:
    print("invariante cumprida em", len(vistos), "estados")
print("estados explorados:", len(vistos))
```

Prevê se a invariante se cumpre. O contraexemplo é o clássico "ler, ler, escrever, escrever": os dois servidores leem o lugar 1 como livre antes de qualquer um escrever.

## Como se usam no trabalho

1. Escreve-se a especificação do desenho (não do código), com poucas centenas de linhas.
2. Verifica-se com universos pequenos (2–3 clientes, 2–3 servidores).
3. Corrige-se o **desenho** até não haver contraexemplos; só depois se programa.

Os engenheiros da Amazon relatam erros graves em protocolos (DynamoDB, S3) encontrados assim, que exigiam sequências de dezenas de passos e nunca tinham aparecido nos testes.
