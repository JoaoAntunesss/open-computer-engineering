Uma **especificação formal** descreve, em matemática ou numa linguagem com semântica precisa, **o que** um sistema deve fazer, sem dizer **como**. Ao contrário de um texto em português, não tem ambiguidades, e pode ser verificada por ferramentas. É usada onde os erros são muito caros: aviação, comboios, chips, protocolos distribuídos, criptografia e os serviços da Amazon (que usa TLA+ desde 2011).

## Especificar com pré e pós-condições

Uma função especifica-se pelo que exige à entrada (**pré-condição**) e pelo que garante à saída (**pós-condição**):

```
ordena(v):
  pré:  v é uma lista de inteiros
  pós:  resultado é uma permutação de v
        e para todo o i, resultado[i] ≤ resultado[i+1]
```

Repara que a especificação não diz nada sobre o algoritmo (quicksort, merge sort…), e que esquecer "é uma permutação de v" deixaria passar uma função que devolve sempre `[]`. Escrever especificações completas é difícil, e é aí que se descobrem muitos erros de requisitos.

## Invariantes do sistema

Para sistemas com estado, especificam-se **invariantes**: propriedades que têm de ser verdadeiras **sempre**.

- "Nunca há duas marcações confirmadas para o mesmo funcionário com horas sobrepostas."
- "O saldo de uma conta nunca é negativo."
- "No máximo um processo está na secção crítica."

## Especificações executáveis

Uma especificação também se pode usar para **testar**: geram-se muitos casos e verifica-se a pós-condição (testes por propriedades, como o QuickCheck e o Hypothesis).

```python run
import random
from collections import Counter

def especificacao_ordena(entrada, resultado):
    permutacao = Counter(entrada) == Counter(resultado)
    ordenado = all(resultado[i] <= resultado[i + 1] for i in range(len(resultado) - 1))
    return permutacao and ordenado

def bolha_uma_passagem(v):                  # só faz UMA passagem do bubble sort
    w = list(v)
    for i in range(len(w) - 1):
        if w[i] > w[i + 1]:
            w[i], w[i + 1] = w[i + 1], w[i]
    return w

candidatas = {
    "sorted (correta)": sorted,
    "sem repetidos": lambda v: sorted(set(v)),
    "devolve vazia": lambda v: [],
    "bolha com erro": bolha_uma_passagem,
}
random.seed(1)
for nome, f in candidatas.items():
    falha = None
    for _ in range(500):
        v = [random.randint(0, 5) for _ in range(random.randint(0, 6))]
        if not especificacao_ordena(v, f(v)):
            falha = v; break
    print(f"{nome:18}", "passa os 500 testes" if falha is None else f"FALHA com {falha} → {f(falha)}")
```

Prevê quais falham. A "bolha com erro" só faz uma passagem: ordena alguns casos e falha outros. Os testes encontram contraexemplos, mas não provam a correção: para isso, verificação (lições seguintes).

## Linguagens de especificação

- **Z, B, VDM:** clássicas, baseadas em conjuntos e lógica. O método B foi usado no metro automático de Paris (linha 14).
- **TLA+:** para sistemas concorrentes e distribuídos (lição 4).
- **Alloy:** modelos de estruturas e relações, com verificação automática em pequenos universos.
- **Contratos no próprio código:** Dafny, SPARK (Ada), Eiffel, JML.
