Escrever a prova num assistente separado do código é caro. Linguagens como **Dafny** (e também F*, SPARK/Ada, Verus para Rust, Liquid Haskell) juntam as duas coisas: escreves o programa com as suas **pré-condições**, **pós-condições** e **invariantes**, e o compilador usa um solucionador SMT (Z3) para provar automaticamente que o código cumpre a especificação. Se não consegue provar, dá erro de compilação.

## Um método verificado

```dafny
method Maximo(a: array<int>) returns (m: int)
  requires a.Length > 0                                   // pré-condição
  ensures forall k :: 0 <= k < a.Length ==> a[k] <= m     // m é maior ou igual a todos
  ensures exists k :: 0 <= k < a.Length && a[k] == m      // e é um dos elementos
{
  m := a[0];
  var i := 1;
  while i < a.Length
    invariant 1 <= i <= a.Length
    invariant forall k :: 0 <= k < i ==> a[k] <= m
    invariant exists k :: 0 <= k < i && a[k] == m
  {
    if a[i] > m { m := a[i]; }
    i := i + 1;
  }
}
```

Dafny verifica que: (1) os invariantes valem à entrada do ciclo, (2) cada iteração os preserva, (3) à saída implicam as pós-condições, (4) não há acessos fora do array, (5) o ciclo termina (encontra sozinho a medida `a.Length - i`). Se tirares o segundo invariante, a verificação falha, porque a pós-condição deixa de se poder deduzir.

## A mesma ideia em Python

Não temos Z3 no browser, mas podemos escrever os contratos como verificações e testá-los exaustivamente para entradas pequenas. É a versão «pobre»: encontra erros, mas não prova a ausência deles.

```python run
from itertools import product

def maximo(a):
    assert len(a) > 0                                          # requires
    m, i = a[0], 1
    while i < len(a):
        assert all(a[k] <= m for k in range(i))                # invariante
        if a[i] > m:
            m = a[i]
        i += 1
    assert all(x <= m for x in a) and m in a                   # ensures
    return m

def maximo_errado(a):          # começa em 0 em vez de a[0]
    m = 0
    for x in a:
        if x > m:
            m = x
    return m

def verifica(f, valores=range(-2, 3), n_max=3):
    for n in range(1, n_max + 1):
        for a in product(valores, repeat=n):
            m = f(list(a))
            if not (all(x <= m for x in a) and m in a):
                return f"contraexemplo: {list(a)} -> {m}"
    return "todos os casos passam"

print(verifica(maximo))
print(verifica(maximo_errado))
```

O contraexemplo aparece logo: com só números negativos, `maximo_errado` devolve 0, que nem está na lista. Dafny rejeitaria esta função na compilação, porque a pós-condição `exists k :: a[k] == m` não se prova.

## Onde se usa

- **AWS**: partes do serviço de autorização (Cedar) e de criptografia escritas em Dafny e verificadas.
- **Microsoft**: o IronFleet e o IronClad (sistemas distribuídos verificados) em Dafny.
- **Rust**: Verus e Kani verificam código Rust de sistemas.
- **Aviação e ferrovia**: SPARK/Ada em software de controlo.

O custo é real (anotações, invariantes, por vezes lemas auxiliares), mas muito menor do que provas num assistente separado, e o código final é o que corre.
