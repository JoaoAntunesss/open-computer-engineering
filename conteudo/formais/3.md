A **verificação de modelos** (*model checking*) explora **todos** os estados que um sistema pode atingir e verifica se uma propriedade é sempre cumprida. Se não for, devolve um **contraexemplo**: a sequência exata de passos que leva ao erro. É automática (não é preciso escrever provas), e encontra erros de concorrência que os testes quase nunca apanham. Os seus inventores receberam o Prémio Turing em 2007.

## O sistema como um grafo de estados

Um estado é o valor de todas as variáveis (incluindo onde está cada processo). As transições são os passos possíveis. Com processos concorrentes, há uma transição para cada processo que pode avançar: o número de intercalações cresce depressa, mas um computador consegue percorrê-las todas (para modelos pequenos).

## Lógica temporal

As propriedades falam do **tempo**:

- **Segurança** (□, "sempre"): algo mau nunca acontece. □ ¬(p1 na crítica ∧ p2 na crítica).
- **Vivacidade** (◇, "algum dia"): algo bom acaba por acontecer. □ (p1 quer entrar → ◇ p1 na crítica).

Na lógica LTL: □ (sempre), ◇ (algum dia), ○ (no estado seguinte), U (até).

## Verificar uma exclusão mútua

Duas tentativas de exclusão mútua com flags. Prevê qual tem erro:

```python run
from collections import deque

def explora(passo, inicial, mau):
    vistos, fila, pai = {inicial}, deque([inicial]), {inicial: None}
    while fila:
        e = fila.popleft()
        if mau(e):
            caminho = []
            while e: caminho.append(e); e = pai[e]
            return f"ERRO após {len(caminho) - 1} passos: " + " → ".join(map(str, reversed(caminho)))
        for prox in passo(e):
            if prox not in vistos:
                vistos.add(prox); pai[prox] = e; fila.append(prox)
    return f"seguro: {len(vistos)} estados explorados, nenhum mau"

# estado: (pc0, pc1, flag0, flag1, vez); pc: 0 = fora, 1 = a pedir, 2 = na secção crítica
def ingenuo(e):                       # "verifico se o outro quer, depois levanto a minha flag"
    *pc, f0, f1, v = e
    f = [f0, f1]
    for i in (0, 1):
        o, novo_pc, nf = 1 - i, list(pc), list(f)
        if pc[i] == 0 and not f[o]:   novo_pc[i] = 1            # o outro não quer: vou
        elif pc[i] == 1:              nf[i] = True; novo_pc[i] = 2
        elif pc[i] == 2:              nf[i] = False; novo_pc[i] = 0
        else: continue
        yield (*novo_pc, *nf, v)

def peterson(e):
    *pc, f0, f1, v = e
    f = [f0, f1]
    for i in (0, 1):
        o, novo_pc, nf, nv = 1 - i, list(pc), list(f), v
        if pc[i] == 0:                                nf[i] = True; nv = o; novo_pc[i] = 1   # quero, mas cedo a vez
        elif pc[i] == 1 and (not f[o] or v == i):     novo_pc[i] = 2                         # entro se o outro não quer ou é a minha vez
        elif pc[i] == 2:                              nf[i] = False; novo_pc[i] = 0
        else: continue
        yield (*novo_pc, *nf, nv)

os_dois_dentro = lambda e: e[0] == 2 and e[1] == 2
inicio = (0, 0, False, False, 0)
print("ingénuo: ", explora(ingenuo, inicio, os_dois_dentro))
print("Peterson:", explora(peterson, inicio, os_dois_dentro))
```

No ingénuo, o verificador encontra a intercalação em que os dois veem a flag do outro em baixo antes de levantarem as suas. O algoritmo de **Peterson** acrescenta a variável "vez" e é seguro em **todos** os estados alcançáveis.

## Ferramentas

- **SPIN** (linguagem Promela): protocolos e concorrência. Usado na NASA.
- **TLA+ / TLC** (lição seguinte), **NuSMV**, **UPPAAL** (sistemas com tempo real), **CBMC** (verificação de programas em C com limites).

## O limite: explosão de estados

O número de estados cresce exponencialmente com o número de processos e variáveis. Técnicas: redução por ordem parcial, simetria, representações simbólicas (BDD, SAT/SMT), e **modelos pequenos**: a "hipótese do pequeno âmbito" diz que a maioria dos erros aparece já com poucos processos e valores pequenos.
