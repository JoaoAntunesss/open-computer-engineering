Um **assistente de provas** é um programa em que escreves definições e teoremas, e provas que o computador **verifica passo a passo**. Se a prova é aceite, o teorema é verdadeiro (com uma confiança muito maior do que qualquer revisão humana). **Lean**, **Rocq** (antigo Coq) e **Isabelle** são os mais usados. Com eles se verificaram o compilador CompCert, o micronúcleo seL4, o teorema das quatro cores e, recentemente, matemática de ponta (o projeto Liquid Tensor, em Lean).

## Proposições como tipos

A ideia central (correspondência de Curry-Howard): uma **proposição** é um **tipo**, e uma **prova** é um **programa** desse tipo.

| Lógica | Programação |
|---|---|
| A → B (implicação) | função de A para B |
| A ∧ B (e) | par (A, B) |
| A ∨ B (ou) | tipo soma (Either A B) |
| ∀x. P(x) | função que recebe x e devolve uma prova de P(x) |
| verdadeiro | tipo com um valor (unit) |
| falso | tipo vazio (sem valores) |

Provar A → B é escrever uma função que transforma qualquer prova de A numa prova de B. O verificador de tipos verifica a prova.

## Lean 4

```lean
-- uma função e uma propriedade sobre ela
def soma : List Nat → Nat
  | []      => 0
  | x :: xs => x + soma xs

-- teorema: a soma de duas listas concatenadas é a soma das somas
theorem soma_append (xs ys : List Nat) : soma (xs ++ ys) = soma xs + soma ys := by
  induction xs with
  | nil => simp [soma]                          -- caso base: soma [] = 0
  | cons x xs hi => simp [soma, hi, Nat.add_assoc]   -- passo: usa a hipótese de indução

-- teorema simples, provado com uma tática automática
theorem e_comuta (p q : Prop) (hp : p) (hq : q) : q ∧ p := ⟨hq, hp⟩
```

É a mesma prova por indução de Programação Funcional (lição 9), mas verificada pela máquina. As **táticas** (`induction`, `simp`, `omega`, `decide`) automatizam os passos rotineiros.

Experimenta no browser em [live.lean-lang.org](https://live.lean-lang.org), e aprende com o jogo *Natural Number Game*.

## O que o computador verifica

```python run
# Um verificador minúsculo para provas em lógica proposicional (estilo dedução natural).
# Cada linha: (fórmula, regra, linhas usadas). Fórmulas: "A", ("→", A, B), ("∧", A, B).
def verifica(premissas, prova):
    linhas = []
    for i, (f, regra, usa) in enumerate(prova, 1):
        ok = False
        if regra == "premissa":
            ok = f in premissas
        elif regra == "∧-intro":
            a, b = (linhas[k - 1] for k in usa); ok = f == ("∧", a, b)
        elif regra == "∧-elim":
            (c,) = (linhas[k - 1] for k in usa); ok = isinstance(c, tuple) and c[0] == "∧" and f in c[1:]
        elif regra == "→-elim":                      # modus ponens: de A e A → B conclui B
            a, imp = (linhas[k - 1] for k in usa); ok = imp == ("→", a, f)
        if not ok:
            return f"linha {i} inválida: {f} não segue de {regra} {usa}"
        linhas.append(f)
    return f"prova aceite: {linhas[-1]}"

premissas = ["chove", ("→", "chove", "molhado"), ("∧", "frio", "vento")]
prova_boa = [
    ("chove", "premissa", []),
    (("→", "chove", "molhado"), "premissa", []),
    ("molhado", "→-elim", [1, 2]),
    (("∧", "frio", "vento"), "premissa", []),
    ("vento", "∧-elim", [4]),
    (("∧", "molhado", "vento"), "∧-intro", [3, 5]),
]
prova_ma = prova_boa[:2] + [("vento", "→-elim", [1, 2])]
print(verifica(premissas, prova_boa))
print(verifica(premissas, prova_ma))
```

Prevê as duas linhas. Um assistente de provas é isto em grande escala: cada passo tem de ser justificado por uma regra, e o núcleo que verifica é pequeno o suficiente para se confiar nele.

## Custos e uso

Provar formalmente é caro: o seL4 (cerca de 10 000 linhas de C) exigiu cerca de 20 pessoas-ano de provas. Por isso usa-se onde a correção vale muito: núcleos de sistemas, compiladores, criptografia (o código de criptografia do Firefox e do Linux tem partes verificadas, como o HACL*), contratos inteligentes, e cada vez mais matemática. Os modelos de linguagem estão a começar a ajudar a escrever provas (que o assistente verifica), o que pode baixar muito o custo.
