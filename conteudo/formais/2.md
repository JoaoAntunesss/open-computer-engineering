A **lógica de Hoare** (1969) é a forma clássica de **provar** que um programa cumpre a especificação. Escreve-se {P} C {Q}: "se P é verdade antes de executar C, e C termina, então Q é verdade depois". Para os ciclos, a chave é a **invariante**: uma propriedade que é verdade antes de cada iteração e que, no fim, junto com a condição de saída, implica o resultado.

## As regras principais

- **Atribuição:** {Q[x := e]} x := e {Q}. Para saber o que tem de ser verdade antes, substitui-se x por e na pós-condição. Ex.: {y + 1 > 0} x := y + 1 {x > 0}.
- **Sequência:** de {P} C₁ {R} e {R} C₂ {Q}, conclui-se {P} C₁; C₂ {Q}.
- **Condicional:** {P ∧ b} C₁ {Q} e {P ∧ ¬b} C₂ {Q} dão {P} if b then C₁ else C₂ {Q}.
- **Ciclo:** se {I ∧ b} C {I}, então {I} while b do C {I ∧ ¬b}. I é a invariante.
- **Consequência:** pode-se reforçar a pré-condição e enfraquecer a pós-condição.

Para provar a **terminação** (correção total), acrescenta-se uma **variante**: uma quantidade inteira, ≥ 0, que diminui em cada iteração.

## Exemplo: soma de 1 a n

```
{ n ≥ 0 }
i := 0; s := 0
while i < n do
  { invariante: s = 0 + 1 + … + i  e  0 ≤ i ≤ n }
  i := i + 1
  s := s + i
{ s = n(n+1)/2 }
```

1. **Inicialização:** com i = 0 e s = 0, a invariante é verdadeira (soma vazia).
2. **Preservação:** se s = 1 + … + i e i < n, depois de i := i + 1 e s := s + i, s = 1 + … + i (novo) e i ≤ n.
3. **Saída:** invariante e ¬(i < n) dão i = n e s = 1 + … + n = n(n+1)/2.
4. **Terminação:** a variante n − i diminui 1 em cada iteração e é ≥ 0.

## Verificar invariantes em execução

Uma prova cobre todos os casos; verificar com `assert` em muitos casos não prova, mas apanha invariantes erradas depressa. Prevê qual dos três candidatos a invariante é a correta:

```python run
def verifica(invariante, n):
    i, s = 0, 0
    if not invariante(i, s, n): return "falha na inicialização"
    while i < n:
        i += 1
        s += i
        if not invariante(i, s, n): return f"falha a meio (i={i}, s={s})"
    return "ok" if s == n * (n + 1) // 2 else "invariante ok, mas não chega para o resultado"

candidatas = {
    "s = i(i+1)/2 e 0 ≤ i ≤ n": lambda i, s, n: s == i * (i + 1) // 2 and 0 <= i <= n,
    "s ≥ i":                    lambda i, s, n: s >= i,
    "s = i²":                   lambda i, s, n: s == i * i,
}
for nome, inv in candidatas.items():
    resultados = {verifica(inv, n) for n in range(0, 30)}
    print(f"{nome:28} → {resultados}")
```

A segunda é verdadeira mas **fraca**: preserva-se, e não chega para provar o resultado (repara que os testes não o mostram). A terceira é falsa. Encontrar a invariante certa é a parte criativa da prova (as ferramentas fazem o resto).

## Para lá de Hoare

- **Lógica de separação:** para programas com apontadores e memória dinâmica (é a base do Infer, do Facebook, e de ferramentas de verificação de Rust).
- **Pré-condição mais fraca** (Dijkstra): calcular automaticamente o que tem de ser verdade antes de um programa. É o que o Dafny faz (lição 6).
