Em Python escreves um ficheiro e corres. Em C há um passo pelo meio: o **compilador** traduz o teu código para instruções da máquina, e o resultado é um executável que corre sem precisar do compilador. Perceber as etapas dessa tradução ajuda-te a ler as mensagens de erro e a organizar programas com vários ficheiros.

## O primeiro programa

```c
// ola.c
#include <stdio.h>

int main(void) {
    printf("Olá, mundo!\n");
    return 0;
}
```

```bash
gcc -Wall -Wextra -std=c17 -o ola ola.c
./ola
```

- `#include <stdio.h>` traz as declarações de `printf`.
- `main` é onde o programa começa; o valor devolvido é o **código de saída** (0 = sucesso). Vês-o com `echo $?`.
- `-Wall -Wextra` ligam avisos úteis. **Compila sempre com avisos** e trata-os como erros.
- `-std=c17` fixa a versão da linguagem. `-o ola` dá o nome ao executável.

## As quatro etapas

1. **Pré-processamento** (`gcc -E`): trata as linhas começadas por `#` — copia o conteúdo dos `#include`, substitui as macros `#define`, resolve `#if`. O resultado continua a ser C.
2. **Compilação** (`gcc -S`): traduz C para assembly da arquitetura (x86-64, ARM…).
3. **Montagem** (`gcc -c`): traduz assembly para código máquina num **ficheiro objeto** `.o`. Ainda faltam as funções que estão noutros ficheiros.
4. **Ligação** (*linking*): junta os `.o` e as bibliotecas (como a `libc`, onde está o `printf`) num executável.

```bash
gcc -E ola.c | tail -5     # ver o código depois do pré-processador
gcc -S ola.c               # cria ola.s (assembly)
gcc -c ola.c               # cria ola.o (objeto)
gcc ola.o -o ola           # ligação
```

Saber em que etapa falhou ajuda muito: um erro de **sintaxe** vem do compilador; um `undefined reference to 'f'` vem do **ligador** e quer dizer que declaraste `f` mas ninguém a definiu (ou esqueceste-te de um ficheiro ou de uma biblioteca, como `-lm` para `math.h`).

## Vários ficheiros: declarações e definições

Um programa real divide-se em módulos. Cada módulo tem um **cabeçalho** `.h` com as declarações (o que existe) e um `.c` com as definições (como funciona):

```c
// mat.h
#ifndef MAT_H
#define MAT_H
int quadrado(int x);
#endif
```

```c
// mat.c
#include "mat.h"
int quadrado(int x) { return x * x; }
```

```c
// main.c
#include <stdio.h>
#include "mat.h"
int main(void) {
    printf("%d\n", quadrado(7));
    return 0;
}
```

```bash
gcc -Wall -c mat.c
gcc -Wall -c main.c
gcc mat.o main.o -o programa
```

O par `#ifndef / #define / #endif` é uma **guarda de inclusão**: impede que o mesmo cabeçalho seja incluído duas vezes no mesmo ficheiro. As aspas (`"mat.h"`) procuram primeiro na pasta do projeto; os parênteses angulares (`<stdio.h>`), nas pastas do sistema.

## Make: só recompilar o que mudou

Com dezenas de ficheiros, recompilar tudo a cada alteração é lento. O **make** lê um ficheiro `Makefile` com regras do tipo "alvo: dependências" e só refaz o que está desatualizado (compara datas de modificação).

```make
CC = gcc
CFLAGS = -Wall -Wextra -std=c17 -g

programa: main.o mat.o
	$(CC) $(CFLAGS) -o $@ $^

%.o: %.c mat.h
	$(CC) $(CFLAGS) -c $<

clean:
	rm -f *.o programa
```

- `$@` é o alvo, `$^` todas as dependências, `$<` a primeira.
- As linhas de comandos **têm de começar por um Tab**, não espaços.
- `make` constrói o primeiro alvo; `make clean` apaga os gerados.
- `-g` inclui informação de depuração (para o gdb, na lição 9).

## Erros comuns

- Ignorar avisos: muitos erros graves em C (variáveis por inicializar, formatos errados no `printf`) aparecem primeiro como avisos.
- Esquecer o `\n` no fim do `printf` e o texto não aparecer logo (a saída fica em memória até ao fim da linha).
- Definir funções num `.h`: se dois ficheiros o incluírem, a ligação falha com "multiple definition".
- Usar espaços em vez de Tab no Makefile ("missing separator").
- Esquecer `-lm` ao usar funções de `math.h` como `sqrt`.

## Exercícios

1. Compila o `ola.c` e vê o tamanho do executável com `ls -l`. Depois compila com `-O2` e com `-static`. O que muda?
2. Tira o `#include <stdio.h>` do `ola.c` e compila com `-Wall`. Que mensagem aparece e de que etapa vem?
3. No exemplo com `mat.c`, apaga a definição de `quadrado` e compila. Em que etapa falha?
4. Escreve um Makefile para um projeto com `main.c`, `lista.c` e `lista.h`, com alvos `all`, `clean` e `run`.

??? Soluções
1: `-O2` otimiza o código (pode ficar ligeiramente diferente em tamanho e é mais rápido); `-static` inclui a biblioteca de C dentro do executável, que passa de alguns KB para centenas de KB ou mais, mas deixa de depender da `libc` instalada.

2: o compilador avisa de uma **declaração implícita** de `printf` (em C17 com `gcc` é um aviso, e o gcc sugere incluir `<stdio.h>`). Vem da etapa de **compilação**. Nunca ignores este aviso.

3: compila cada `.c` sem problemas, mas a **ligação** falha com `undefined reference to 'quadrado'`.

4:

```make
CC = gcc
CFLAGS = -Wall -Wextra -std=c17 -g

all: programa

programa: main.o lista.o
	$(CC) $(CFLAGS) -o $@ $^

%.o: %.c lista.h
	$(CC) $(CFLAGS) -c $<

run: programa
	./programa

clean:
	rm -f *.o programa

.PHONY: all run clean
```
