Sozinho, o Git é um botão de "guardar versão". Em equipa, é a forma como várias pessoas mexem no mesmo código ao mesmo tempo sem se atropelarem. O fluxo mais comum chama-se **GitHub Flow**.

## O fluxo

```text
git switch main
git pull                         # traz o que os outros fizeram
git switch -c corrige-portes     # um ramo para a tua tarefa
# ... alterações e commits pequenos ...
git push -u origin corrige-portes
# abre um Pull Request (PR) no GitHub
# revisão, CI, alterações pedidas, aprovação
# merge para main (normalmente pelo botão do PR)
```

Regras de ouro: **nunca** trabalhes diretamente no `main`; um ramo por tarefa; ramos de vida curta (dias, não semanas).

## Bons commits

- Pequenos e com uma intenção cada.
- Mensagem no imperativo, que diga o quê e porquê: `Corrige portes grátis acima de 100 € (era >= em vez de >)`.
- Sem ficheiros que não interessam (`.env`, `node_modules`, ficheiros do editor): é para isso que serve o `.gitignore`.

## Bons Pull Requests

Um PR é um pedido para juntar o teu trabalho ao `main`. A descrição devia responder a:

- **O quê**: o que muda.
- **Porquê**: o problema ou o ticket.
- **Como testar**: passos para o revisor confirmar.
- **Riscos**: o que pode partir.

PRs pequenos (menos de ~300 linhas alteradas) são revistos mais depressa e com mais atenção. Se o teu está a ficar enorme, divide-o.

## Conflitos

Acontecem quando tu e outra pessoa mudaram as mesmas linhas. O Git marca-os assim:

```text
<<<<<<< HEAD
portes = 3
=======
portes = 4
>>>>>>> main
```

Não escolhas à sorte: percebe o que cada lado queria (lê os dois PRs ou pergunta) e escreve a versão que respeita os dois. Depois `git add`, `git commit` (ou `git rebase --continue`) e corre os testes.

## merge contra rebase

- `git merge main` junta as histórias e cria um commit de merge. Seguro e simples.
- `git rebase main` reescreve os teus commits por cima do `main`, com uma história linear. Mais limpo, mas **nunca** faças rebase de commits que outras pessoas já usam.

A equipa costuma ter uma regra; segue-a.

## Exercício

Num repositório teu, simula uma equipa: cria dois ramos a partir do `main` que mudem a mesma linha de formas diferentes, abre dois PRs, faz merge de um e resolve o conflito do outro.
