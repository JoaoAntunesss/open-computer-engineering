No primeiro emprego vais receber acesso a um repositório com centenas de milhares de linhas, escritas por dezenas de pessoas ao longo de anos. Ninguém espera que percebas tudo. Espera-se que consigas **encontrar o caminho** até à parte que te pediram para mudar, sem partir o resto.

## Primeira semana: o que fazer

1. **Pôr o projeto a correr na tua máquina.** Segue o README à letra. Onde falhar, anota o problema e a solução: é a tua primeira contribuição (melhorar o README).
2. **Correr os testes.** Se passam, tens uma rede de segurança. Se não passam, pergunta antes de mexer em alguma coisa.
3. **Desenhar o mapa.** Que pastas existem? Onde está o ponto de entrada? Onde estão as rotas, os modelos, os testes?
4. **Seguir um pedido de ponta a ponta.** Escolhe uma ação simples (por exemplo "fazer login") e segue-a desde o botão até à base de dados e de volta, com o depurador ou com prints.
5. **Fazer uma alteração minúscula** que vá até produção (corrigir um texto, um aviso). Aprendes o processo todo: ramo, PR, revisão, CI, deploy.

## Ferramentas para te orientares

- **Procura global** (Ctrl+Shift+F no VS Code): procura o texto que vês no ecrã ("Palavra-passe errada") e chegas ao código que o mostra.
- **Ir para a definição** (F12) e **ver onde é usado** (Shift+F12).
- **`git log -p ficheiro`** e **`git blame`**: quem mudou esta linha, quando e com que mensagem. Muitas vezes a mensagem do commit explica o porquê.
- **Os testes**: um teste é um exemplo de utilização de uma função, escrito por quem a conhece.
- **IA com o repositório aberto**: "onde é que neste projeto se calcula o IVA?" é um bom uso, desde que confirmes no código.

## O que não fazer

- Reescrever código que não percebes porque "está feio". Normalmente há uma razão (um cliente, um bug antigo, uma limitação).
- Mudar formatação de ficheiros inteiros no mesmo commit que uma correção. Torna a revisão impossível.
- Ficar dias bloqueado sem dizer nada (vê a lição sobre pedir ajuda).

## Exercício

Escolhe um projeto open source médio que uses (por exemplo uma biblioteca Python ou uma app web). Põe-no a correr localmente, corre os testes e escreve uma página com: as pastas principais e o que contêm, o ponto de entrada e o caminho de um pedido do início ao fim.
