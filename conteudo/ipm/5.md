As **heurísticas de Nielsen** são dez princípios gerais de usabilidade, publicados por Jakob Nielsen em 1994 e ainda hoje a lista mais usada. Servem para a **avaliação heurística**: um método rápido e barato em que alguns avaliadores percorrem a interface e anotam onde cada princípio é violado. Encontra muitos problemas antes de haver testes com utilizadores.

## As dez heurísticas

1. **Visibilidade do estado do sistema.** O sistema mostra sempre o que está a acontecer, com feedback em tempo útil. Barra de progresso no envio, "A guardar…" → "Guardado", o carrinho que mostra o número de artigos.
2. **Correspondência com o mundo real.** Usa as palavras e conceitos do utilizador, não os do sistema. "Marcação" e não "registo de agendamento"; "a sua morada" e não "endereço_entrega".
3. **Controlo e liberdade.** Saídas de emergência claras: desfazer, refazer, cancelar, voltar atrás. "Anular envio" no Gmail.
4. **Consistência e normas.** A mesma palavra e o mesmo aspeto para a mesma coisa; seguir as convenções da plataforma (o logótipo leva à página inicial, o X fecha).
5. **Prevenção de erros.** Melhor do que boas mensagens de erro é não deixar errar: desativar datas passadas no calendário, confirmar antes de apagar, sugerir enquanto se escreve.
6. **Reconhecer em vez de lembrar.** Opções visíveis; o sistema lembra-se por ti (últimas pesquisas, campos preenchidos).
7. **Flexibilidade e eficiência.** Atalhos para quem já sabe (teclas de atalho, "repetir última encomenda"), sem atrapalhar os novos.
8. **Estética e desenho minimalista.** Cada informação extra compete com a importante. Mostra só o necessário para a tarefa.
9. **Ajudar a reconhecer, diagnosticar e recuperar de erros.** Mensagens em linguagem simples, que dizem o problema e como resolver. "Este email já tem conta. Queres entrar ou recuperar a palavra-passe?" em vez de "Erro 409".
10. **Ajuda e documentação.** Idealmente desnecessária, mas, se existir, fácil de encontrar, focada na tarefa, com passos concretos.

## Como fazer uma avaliação heurística

1. **3 a 5 avaliadores**, cada um sozinho (um só encontra cerca de 35% dos problemas; cinco encontram cerca de 75%).
2. Cada um percorre a interface (pelo menos duas vezes: uma para ter a visão geral, outra para os detalhes), com tarefas típicas.
3. Para cada problema: onde está, que heurística viola, e a **gravidade**:
   - 0: não é problema
   - 1: cosmético
   - 2: menor (corrigir com baixa prioridade)
   - 3: grave (corrigir com prioridade)
   - 4: catástrofe (corrigir antes de lançar)
4. Junta-se tudo numa lista, sem repetidos, e ordena-se por gravidade.

## Exemplo: avaliar mensagens de erro

As mensagens de erro são onde mais se veem as heurísticas a falhar. Este pequeno "verificador" aplica algumas regras simples (da heurística 9) a mensagens reais:

```js run
const mensagens = [
  "Erro 500",
  "Ocorreu um erro. Tente novamente.",
  "NullPointerException em ReservaService.java:142",
  "O email não tem @. Verifica se escreveste bem, por exemplo ana@exemplo.pt.",
  "Data inválida!",
  "Já não há vagas às 10h. Escolhe outra hora: 11h ou 14h30 estão livres.",
];
const regras = [
  ["tem código técnico", m => /\d{3}|Exception|\.java|null/i.test(m)],
  ["é vaga (sem dizer o quê)", m => /^(Ocorreu um erro|Erro|Data inválida)/i.test(m)],
  ["não diz como resolver", m => !/(verifica|escolhe|tenta|experimenta|por exemplo)/i.test(m)],
];
for (const m of mensagens) {
  const falhas = regras.filter(([, teste]) => teste(m)).map(([nome]) => nome);
  console.log((falhas.length ? "✗ " : "✓ ") + m + (falhas.length ? "  ← " + falhas.join("; ") : ""));
}
```

Prevê que mensagens passam. (Atenção: a segunda diz "Tente novamente", o que é uma sugestão, mas não ajuda: tentar de novo o quê?) Um verificador destes é só um apoio; a avaliação faz-se a olhar para a interface.

## Limites

- Os avaliadores não são os utilizadores: encontram problemas que talvez não incomodem ninguém e falham outros que só aparecem com pessoas reais.
- Funciona melhor com avaliadores que conhecem as heurísticas **e** o domínio.
- Complementa os testes com utilizadores (lição seguinte); não os substitui.
