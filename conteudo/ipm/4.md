Um **protótipo** é uma versão incompleta de uma interface, feita para testar ideias antes de as programar. Quanto mais cedo se encontra um problema, mais barato é corrigi-lo: apagar um esboço em papel custa um minuto; reescrever um ecrã já programado custa dias. A **fidelidade** de um protótipo é o quão parecido é com o produto final.

## Baixa fidelidade

Esboços em papel, *wireframes* em cinzento, ou ferramentas como o Balsamiq.

- **Rápidos:** dezenas de alternativas numa tarde.
- **Baratos de deitar fora:** ninguém se apega a um esboço.
- **Focam a estrutura:** que informação existe em cada ecrã, por que ordem, que ações. Não se discute a cor do botão.
- As pessoas criticam mais à vontade algo que parece inacabado.

**Teste com papel:** uma pessoa faz de "computador" e troca as folhas conforme o participante "carrega" nos botões com o dedo. Funciona surpreendentemente bem.

**Crazy 8s:** dobra uma folha em 8 e desenha 8 versões de um ecrã em 8 minutos. Obriga a sair da primeira ideia.

## Alta fidelidade

Protótipos que parecem (quase) o produto final: Figma, Penpot, ou código (HTML/CSS).

- Testam detalhes visuais, textos, microinterações, legibilidade.
- Com **interatividade** (ligações entre ecrãs no Figma), simulam fluxos completos.
- Servem de **especificação** para quem vai programar.
- Riscos: demoram mais, e as pessoas comentam as cores em vez do fluxo. A equipa também fica mais relutante em deitar fora.

## Escolher a fidelidade

| Pergunta | Fidelidade |
|---|---|
| O fluxo faz sentido? Falta algum passo? | baixa |
| Os utilizadores encontram a opção X? | baixa ou média |
| O texto é claro? A hierarquia visual funciona? | alta |
| A animação ajuda ou atrapalha? | alta, ou código |
| Convencer um cliente ou investidor | alta |

Não é preciso o mesmo nível em tudo: um protótipo pode ser fiel no ecrã que se está a testar e esboçado no resto.

## Wireframes: a estrutura sem estilo

```
┌─────────────────────────────┐
│ ←  Escolher serviço          │
├─────────────────────────────┤
│ ┌─────────────────────────┐ │
│ │ Corte          15 € 30m │ │
│ └─────────────────────────┘ │
│ ┌─────────────────────────┐ │
│ │ Coloração      45 € 90m │ │
│ └─────────────────────────┘ │
│ ┌─────────────────────────┐ │
│ │ Manicure       20 € 45m │ │
│ └─────────────────────────┘ │
│                             │
│ [ Continuar ]               │
└─────────────────────────────┘
```

Um wireframe responde: que informação aparece, com que prioridade, e que ações existem. Desenha-se em cinzento de propósito.

## Protótipos em código

Para algumas coisas, o mais rápido é um protótipo em HTML: interações complexas, dados reais, comportamento em telemóveis diferentes. A regra é a mesma: é para deitar fora. Não se escreve com o cuidado de código de produção.

Exemplo: um protótipo mínimo de "escolher serviço" com feedback imediato:

```js run
const servicos = [
  { nome: "Corte", preco: 15, min: 30 },
  { nome: "Coloração", preco: 45, min: 90 },
  { nome: "Manicure", preco: 20, min: 45 },
];
let escolhidos = [];
function alterna(nome) {
  escolhidos = escolhidos.includes(nome) ? escolhidos.filter(n => n !== nome) : [...escolhidos, nome];
  const sel = servicos.filter(s => escolhidos.includes(s.nome));
  const total = sel.reduce((t, s) => t + s.preco, 0);
  const tempo = sel.reduce((t, s) => t + s.min, 0);
  console.log(`[${escolhidos.join(", ") || "nada"}] → ${total} €, ${Math.floor(tempo / 60)}h${String(tempo % 60).padStart(2, "0")}`);
}
alterna("Corte");
alterna("Coloração");
alterna("Corte");
alterna("Manicure");
```

Prevê as quatro linhas. Num protótipo, mostrar logo o total e a duração responde a uma dúvida que, nas entrevistas, muitos clientes tinham.

## Erros comuns

- Começar diretamente em alta fidelidade e passar uma semana a afinar pormenores de um fluxo errado.
- Fazer um único protótipo. Compara pelo menos 2 ou 3 alternativas: as pessoas dão melhores opiniões quando podem comparar.
- Protótipos com texto "Lorem ipsum": o texto é parte da interface. Usa conteúdo realista.
