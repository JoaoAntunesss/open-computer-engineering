**Acessibilidade** é garantir que pessoas com deficiência conseguem usar o que fazes: pessoas cegas que usam leitores de ecrã, pessoas com pouca visão ou daltonismo, pessoas que não usam rato, pessoas surdas, pessoas com dificuldades cognitivas. Também beneficia toda a gente: quem tem o braço partido, quem está ao sol, quem está num sítio barulhento. Na União Europeia, o **Ato Europeu de Acessibilidade** obriga, desde junho de 2025, muitos serviços digitais (lojas online, bancos, transportes) a cumprir as normas.

## WCAG

As **Web Content Accessibility Guidelines** (W3C) são a norma de referência. A versão 2.2 organiza-se em quatro princípios (POUR):

1. **Percetível:** a informação chega por mais de um sentido. Texto alternativo nas imagens, legendas nos vídeos, contraste suficiente, não depender só da cor.
2. **Operável:** tudo funciona com teclado, há tempo suficiente, nada pisca de forma perigosa, a navegação é clara.
3. **Compreensível:** texto legível, comportamento previsível, ajuda a evitar e corrigir erros.
4. **Robusto:** funciona com tecnologias de apoio, graças a HTML correto.

Três níveis: A (mínimo), **AA** (o exigido pela lei na maioria dos casos), AAA.

## O mais importante na prática

**Contraste:** texto normal precisa de uma relação de contraste de pelo menos **4,5:1** com o fundo (nível AA); texto grande, 3:1.

```js run
// Contraste WCAG entre duas cores em hexadecimal
function luminancia(hex) {
  const [r, g, b] = [0, 2, 4].map(i => parseInt(hex.slice(1 + i, 3 + i), 16) / 255)
    .map(c => (c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4));
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
}
function contraste(a, b) {
  const [l1, l2] = [luminancia(a), luminancia(b)].sort((x, y) => y - x);
  return (l1 + 0.05) / (l2 + 0.05);
}
const pares = [
  ["#000000", "#ffffff"], ["#777777", "#ffffff"], ["#767676", "#ffffff"],
  ["#aaaaaa", "#ffffff"], ["#ffffff", "#0a66c2"], ["#ff0000", "#00aa00"],
];
for (const [texto, fundo] of pares) {
  const c = contraste(texto, fundo);
  console.log(texto, "sobre", fundo, c.toFixed(2) + ":1", c >= 4.5 ? "AA ✓" : "falha");
}
```

Prevê quais passam. O cinzento #767676 é famoso: é o mais claro que passa sobre branco.

**Teclado:** tudo tem de funcionar só com Tab, Shift+Tab, Enter, Espaço e setas. O **foco** tem de estar sempre visível (nunca `outline: none` sem alternativa). A ordem do Tab segue a ordem lógica.

**HTML semântico:** usa os elementos certos, e o leitor de ecrã sabe o que cada coisa é.

```html
<!-- mau: um div não é focável nem anunciado como botão -->
<div class="botao" onclick="marcar()">Marcar</div>

<!-- bom: funciona com teclado e leitores de ecrã sem mais nada -->
<button type="button" onclick="marcar()">Marcar</button>

<!-- cada campo com o seu rótulo -->
<label for="tel">Telemóvel</label>
<input id="tel" type="tel" autocomplete="tel" required aria-describedby="tel-ajuda">
<p id="tel-ajuda">Enviamos o lembrete para este número.</p>

<!-- imagens: alt descreve a função; decorativas com alt vazio -->
<img src="salao.jpg" alt="Interior do salão, com três cadeiras e espelhos">
<img src="ornamento.svg" alt="">
```

Títulos (`h1`…`h6`) por ordem, listas como listas, tabelas de dados com `th`, zonas com `header`, `nav`, `main`, `footer`. Os leitores de ecrã deixam saltar entre títulos e zonas.

**ARIA** só quando o HTML não chega (componentes personalizados como separadores ou menus). Primeira regra do ARIA: se há um elemento HTML que faz o mesmo, usa-o.

**Não depender só da cor:** um campo com erro precisa de uma mensagem ou ícone, não só de ficar vermelho (cerca de 8% dos homens têm alguma forma de daltonismo).

**Movimento:** respeita `prefers-reduced-motion`; nada a piscar mais de 3 vezes por segundo.

## Testar

1. **Navega só com o teclado** por todo o site. É o teste mais rápido e revela muito.
2. **Ferramentas automáticas:** Lighthouse (no Chrome), axe DevTools, WAVE. Encontram cerca de 30–40% dos problemas (contraste, `alt` em falta, rótulos em falta).
3. **Leitor de ecrã:** VoiceOver (Mac, iPhone), NVDA (Windows, gratuito), TalkBack (Android). Fecha os olhos e tenta marcar uma consulta.
4. Se possível, testa com pessoas com deficiência.
